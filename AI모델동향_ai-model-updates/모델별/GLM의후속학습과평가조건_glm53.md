# GLM-5.3의 후속 학습과 평가 조건

| 항목 | 확인한 범위 |
| --- | --- |

| 배포물 | zai-org/GLM-5.3, 텍스트 생성 모델 |
| 발표일 | 확인한 공식 카드에 명시되지 않아 출시일을 별도로 단정하지 않습니다. |
| 비교 대상 | GLM-5.2 기반 후속 학습과 별도 구조의 GLM-5.3-Flash |

## 모델 크기보다 후속 학습이 달라진 경우

GLM-5.3의 공식 카드는 GLM-5.2와 같은 기반 모델을 사용하며 성능 변화가 후속 학습에서 나왔다고 설명합니다. 모델 번호가 올라갈 때마다 신경망을 더 크게 만들었다고 해석할 수 없는 사례입니다. 후속 학습은 이미 학습한 기반 모델에 지시 수행·도구 사용·작업 결과 평가 등을 더 익히게 하는 단계입니다. [공식 카드의 도입부](https://huggingface.co/zai-org/GLM-5.3)

평가 결과에는 에이전트의 실행 조건이 중요합니다. 공식 카드의 Terminal-Bench 3.0 조건은 max reasoning effort, 작업당 세 번 실행한 평균, 최대 600턴과 10시간 제한 등을 명시합니다. 도구를 쓰는 모델 평가는 모델·하네스·시간·판정기를 묶은 실험입니다. 점수만 옮기면 재현에 필요한 조건이 빠집니다. [공식 카드 Footnotes](https://huggingface.co/zai-org/GLM-5.3#footnotes)

카드는 reasoning_effort를 low·high·max로 조정할 수 있고 생략하면 max가 된다고 설명합니다. 더 많은 추론은 더 많은 시간과 출력량을 사용할 수 있으므로, 최고 점수를 낸 설정과 서비스의 일상 설정을 분리해야 합니다. 같은 코딩 오류 수정 과제를 여러 설정에서 실행하고 해결 여부·회귀 오류·시간·비용을 함께 측정하는 방식이 적절합니다. 이는 이 저장소의 제안이며 실행 결과는 아닙니다.

펌웨어 수정 과제라면 빌드 성공, 기존 테스트 통과, 경계 조건의 회귀 검사와 실제 보드 동작은 서로 다른 확인 단계입니다. 에이전트가 패치를 만들었다는 사실만으로 모든 단계가 끝났다고 평가하지 않습니다. 모델 점수에 앞서 무엇을 성공으로 판정할지 정해 두면, 긴 작업을 빨리 마친 경우와 검증을 생략한 경우를 구분할 수 있습니다.

GLM-5.3과 GLM-5.3-Flash도 같은 모델을 단순히 빠르게 실행한 두 옵션으로 보면 안 됩니다. 공식 저장소는 전자를 GLM-5.2 기반의 후속 학습 모델, 후자를 새로 사전 학습하고 sparse·linear attention을 섞은 별도 설계로 설명합니다. Flash라는 접미사만 보고 같은 구조·동일한 기능이라고 추정하지 않습니다. [공식 GLM-5 저장소](https://github.com/zai-org/GLM-5)

라이선스도 이 판본을 따로 확인해야 합니다. GLM-5.3 License에는 일정 규모 이상 MaaS 사업자의 보안 심사 조건이 있습니다. 앞선 GLM-5의 이용 조건이나 MIT라는 인상을 그대로 이어 쓰면 안 됩니다. [공식 LICENSE](https://huggingface.co/zai-org/GLM-5.3/blob/main/LICENSE)

## 총 크기·활성 계산·저장 공간

공식 저장소의 Download Model 표는 GLM-5.3과 GLM-5.3-BF16을 `744B-A40B`로 안내합니다. 이는 제공사의 명목상 전체 744B·활성 40B 표기입니다. 한편 확인한 배포물의 허브 텐서 집계는 약 753B로 표시됩니다. 서로 다른 집계를 같은 수치로 합치거나 차이의 원인을 추정하지 않습니다. [공식 다운로드 표](https://github.com/zai-org/GLM-5#download-model) · [배포물의 텐서 집계](https://huggingface.co/zai-org/GLM-5.3)

설정 파일에는 routed expert 256개 중 토큰당 8개를 선택하고 shared expert 1개를 사용하는 값이 있습니다. 전문가 개수의 비율만으로 활성 크기를 다시 계산하면 attention·공유 층·임베딩 등의 계산을 빠뜨립니다. [공식 배포 설정](https://huggingface.co/zai-org/GLM-5.3/blob/main/config.json)

예를 들어 허브의 약 753B 집계를 모두 1바이트로 저장한다고 단순 가정하면 가중치만 약 753GB입니다. 이는 실제 파일 크기나 필요한 GPU 수를 측정한 결과가 아닙니다. 정밀도가 섞인 가중치·양자화 스케일·KV 캐시·여러 요청·통신 버퍼를 더 고려해야 합니다. 활성 전문가 수가 줄었다고 저장해야 할 모든 전문가가 사라지는 것은 아닙니다.
