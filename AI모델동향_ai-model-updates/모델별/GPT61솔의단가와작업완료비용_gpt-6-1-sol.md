# GPT-6.1 Sol의 단가와 작업 완료 비용

| 항목 | 확인한 내용 |
| --- | --- |
| API 출시 기록 | 2026년 9월 29일 |
| API 모델 ID | `gpt-6.1-sol` |
| 자료 확인일 | 2026년 10월 29일 |
| 이 글의 범위 | API 사양과 제품 설정의 차이, 단가를 이용한 자체 계산 |

OpenAI는 GPT-6.1 Sol을 복잡한 코딩·컴퓨터 사용·전문 업무에서 Astra에 가까운 능력을 낮은 비용으로 제공하는 모델로 소개합니다. ‘가깝다’는 제공사의 비교 설명이며, 특정 회사의 업무에서 같은 성공률을 측정했다는 뜻은 아닙니다. 출시 날짜와 ID는 9월 29일 API 변경 기록에서 확인됩니다. [공식 출시 기록: September 29](https://developers.openai.com/api/docs/changelog)

## 같은 모델 이름이라도 사용 경로가 다릅니다

Sol API 카드는 1,050,000토큰 문맥과 최대 128,000토큰 출력을 안내합니다. 동시에 Codex·ChatGPT Work의 기본 문맥은 500K라고 따로 명시합니다. API의 최대 사양을 제품 화면의 기본 설정과 동일하게 설명하면 혼동을 줍니다. API의 추론 수준은 `low`부터 `max`까지이며 기본값은 `medium`입니다. [Sol 모델 카드](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

모델은 결과를 만드는 핵심 구성 요소이고, 제품은 여기에 실행 환경·도구·사용량 관리·대화 상태 보존을 묶습니다. 예를 들어 같은 모델이 연결됐더라도 한 환경에는 시험을 실행할 셸이 있고 다른 환경에는 없을 수 있습니다. 따라서 모델 이름만으로 실제 작업 절차를 설명할 수 없습니다.

## 토큰 단가와 총비용

토큰은 모델의 문장 처리 단위입니다. 입력과 출력의 단가가 다르며, 캐시에 있는 입력을 다시 읽는 비용도 구분됩니다. 캐시는 앞서 처리한 동일한 자료를 다시 활용하는 방식입니다. 모든 입력이 자동으로 캐시 요금이 되는 것은 아닙니다.

아래는 2026년 10월 29일 두 공식 모델 카드의 Standard 단가를 이용한 직접 계산입니다. 캐시 없는 입력 10만 토큰과 청구 출력 1만 토큰을 가정합니다. 입력은 장문 할증 구간인 272K 이하이며, 검색·코드 실행 등 도구의 별도 비용은 제외했습니다. [Astra 가격과 장문 조건](https://developers.openai.com/api/docs/models/gpt-6-astra), [Sol 가격과 장문 조건](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

| 모델 | 입력 계산 | 출력 계산 | 합계 |
| --- | --- | --- | --- |
| Astra | 0.1 × $10 = $1.00 | 0.01 × $50 = $0.50 | $1.50 |
| Sol | 0.1 × $2 = $0.20 | 0.01 × $10 = $0.10 | $0.30 |

이 가정에서는 청구액이 80% 작습니다. 그러나 같은 작업에서 두 모델이 실제로 같은 양을 사용한다는 뜻은 아닙니다. 더 많은 재시도나 더 긴 출력이 필요하다면 단가 차이와 총비용 차이는 달라집니다. 예제의 출력량은 청구되는 출력량을 가정한 값이며, 화면에서 보이는 답변 글자 수로 치환하지 않습니다.

## 작업 하나를 끝내는 비용으로 비교하기

모델을 한 번 호출하는 비용보다 성공한 작업 하나당 비용이 실무에 더 가까운 지표입니다. 다음 역시 설명용 산술이며 모델의 실제 성공률 측정값은 아닙니다.

과제의 난도와 합격 기준을 먼저 고정해야 가격을 비교할 때 서로 다른 결과를 같은 성공으로 세지 않을 수 있습니다.

단가가 낮은 설정에서 한 번에 $0.30을 쓰고 네 번 시도해야 완료한다면 호출 비용은 $1.20입니다. 다른 설정이 $0.80으로 한 번에 완료하면 그 작업에서는 후자가 더 저렴합니다. 반면 단순한 문서 형식 변환을 모두 첫 시도에 끝낼 수 있다면 비싼 설정의 이점이 작을 수 있습니다. 어느 경우인지는 같은 합격 기준으로 시험해야 알 수 있습니다.

사람이 결과를 고친 시간도 따로 기록합니다. 모델이 만든 코드를 다섯 분 만에 검토할 수 있는지, 파일을 모두 다시 읽어야 하는지는 토큰 청구서에 나타나지 않습니다. ‘작업 완료 비용’은 모델 요금과 검토·재작업 비용을 연결해서 보는 관점입니다.

## 평가 예제: 보고서에서 수치 찾기

서로 다른 연도의 보고서에서 특정 지표를 뽑는 작업을 가정합니다. 판정 기준은 숫자가 그럴듯한지가 아니라 연도·단위·표 위치가 맞는지입니다. 백만 원을 억 원으로 잘못 옮겼다면 짧고 읽기 좋은 답이라도 실패입니다. 모델을 바꿀 때에는 같은 문서와 정답표를 사용하고, 정답률·근거 누락·재질문 횟수·청구량을 함께 남깁니다.

Sol을 사용한다는 사실과 이러한 검증이 자동으로 이루어진다는 것은 다릅니다. 이 글은 API 호출이나 두 모델의 성능을 직접 측정한 글이 아니며, 내부 파라미터 수와 학습 자료도 추정하지 않습니다.
