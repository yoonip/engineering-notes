Anthropic은 Claude Opus 5.5에서 장시간 코딩·전문 업무의 성능과 실행 효율을 강조합니다. 대규모 코드 이전과 감사 사례를 소개하지만, 기업의 초기 사용담과 개발사 시험을 모든 사용자의 결과로 확대하지 않습니다. 이 글에서는 출시 기사, API 모델 목록과 가격표를 구분해 읽습니다. [공식 출시 기사](https://www.anthropic.com/claude-opus-5-5), [공식 모델 목록](https://platform.claude.com/docs/en/models/overview)

## 긴 작업에서 중요한 것은 중간 상태입니다

긴 업무는 긴 답변과 다릅니다. 여러 저장소의 코드를 고친다면 어느 파일까지 확인했는지, 어떤 시험이 끝났는지, 실패한 항목이 무엇인지 계속 보존해야 합니다. 첫 단계에서 잘못 세운 가정을 뒤의 단계들이 반복해서 사용하면 결과가 길어질수록 오류도 커집니다.

다음은 장기 작업의 평가를 위해 구성한 예제이며 Opus 5.5를 실행한 사례는 아닙니다. 오래된 직렬화 함수를 새 버전으로 옮기는 업무를 가정합니다. 새 코드가 컴파일되더라도 기존 파일을 읽지 못하면 이전 작업은 실패입니다. 결과를 평가하려면 기존 파일 읽기, 새 파일 쓰기, 경계값 처리처럼 동작별 기대값이 필요합니다.

이런 업무에서 성공적인 검증은 모델이 자신 있게 ‘완료’라고 말했는지가 아니라 실제 자료와 시험에 남습니다. 실행 속도가 빨라진 경우에도 시험 범위를 줄여 얻은 결과인지, 같은 범위에서 재시도가 줄어든 결과인지 구분해야 합니다.

## 40%와 20%는 다른 수치입니다

공식 발표는 전형적인 작업의 총비용이 Opus 5보다 약 40% 낮다고 설명합니다. 같은 발표의 입력·출력 단가는 20%, 캐시 읽기 단가는 60% 낮아졌다고 구분되어 있습니다. 따라서 모든 요청에 고정된 40% 할인을 적용하는 것으로 읽으면 안 됩니다. 처리량과 재시도 수, 캐시 사용 비중이 함께 영향을 줍니다. [출시 기사: Cost and speed·Pricing](https://www.anthropic.com/claude-opus-5-5)

캐시는 이전에 처리한 같은 입력을 다시 사용하는 방식입니다. 매번 같은 저장소 설명을 보내는 업무라면 캐시 읽기가 큰 비중을 차지할 수 있습니다. 반면 매번 새로운 자료를 넣는 작업은 같은 효과를 얻지 못할 수 있습니다. 캐시에 쓰는 비용과 읽는 비용도 구분합니다.

2026년 10월 29일 Standard 가격은 백만 토큰당 신규 입력 $4, 출력 $20, 캐시 읽기 $0.20입니다. 새 캐시를 보관하는 시간에 따라 쓰기 단가도 달라집니다. 다른 서비스의 계약·지역·실행 등급까지 같은 가격이라고 가정하지 않습니다. [공식 API 가격표](https://platform.claude.com/docs/en/about-claude/pricing)

## 같은 입력량으로 계산한 예

아래는 개발사의 평균 작업량을 재현한 시험이 아니라 고정된 토큰 수를 이용한 산술 예입니다. 캐시 읽기 8만, 신규 입력 2만, 청구 출력 5천 토큰을 가정합니다. 캐시 쓰기·별도 도구 비용은 제외합니다. 이전 모델 가격은 출시 기사의 Opus 5 비교 표를 사용했습니다.

| 항목 | Opus 5 | Opus 5.5 |
| --- | --- | --- |
| 캐시 읽기 | 0.08 × $0.50 = $0.040 | 0.08 × $0.20 = $0.016 |
| 신규 입력 | 0.02 × $5 = $0.100 | 0.02 × $4 = $0.080 |
| 출력 | 0.005 × $25 = $0.125 | 0.005 × $20 = $0.100 |
| 합계 | $0.265 | $0.196 |

이 예의 감소율은 약 26%입니다. 공식 발표의 40%와 다르다고 계산이 모순되는 것은 아닙니다. 예제는 두 모델의 사용량을 고정했지만 실제 업무에서는 토큰 사용량 자체도 달라질 수 있기 때문입니다. 실제 절감률을 판단하려면 같은 합격 기준으로 완료한 업무의 총청구량을 비교해야 합니다.

## 평가표를 그대로 종합 순위로 만들지 않는 이유

출시 기사에는 개발사 자체 평가, 다른 개발사가 보고한 수치, 외부 기관의 평가가 섞여 있습니다. Terminal-Bench 각주는 반복 횟수·오차 범위·비교 모델의 수치 출처를 따로 설명합니다. 시험 도구와 추론 수준이 다르면 같은 이름의 시험이라도 결과를 그대로 나란히 놓기 어렵습니다. [출시 기사: 평가 표와 각주](https://www.anthropic.com/claude-opus-5-5)

같은 출시 기사에서도 코딩 평가의 표와 설명문이 사용하는 추론 수준이 다릅니다. FrontierCode·CursorBench 본문의 `medium`과 표에서 사용한 `max`·일부 `xhigh` 조건을 구분해야 합니다. 조건이 다른 수치를 같은 측정의 오타로 처리하거나 하나만 골라 확정 순위를 만들지 않습니다. 또한 공개 문서만으로 내부 층 수나 전체 학습 자료를 추정하지 않습니다.

이 글은 Opus 5.5 API 호출, 작업 시간 측정이나 벤치마크 재현 결과가 아닙니다. 제공사의 주장, 문서에서 확인한 API 조건, 직접 계산한 예제를 구분했습니다.
