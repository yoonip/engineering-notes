# 새 모델의 성능·비용·공개 범위 읽기 | Reading model releases

새 모델을 비교할 때에는 이름과 순위만 모으기보다 무엇이 배포됐고 어떤 조건에서 평가됐는지 확인해야 합니다. 회사의 발표, API로 받는 서비스, 내려받는 가중치가 서로 다른 구성을 가질 수 있습니다.

## 같은 이름 아래 구분할 대상

| 대상 | 확인할 항목 |
| --- | --- |
| 제품 화면 | 제품이 선택한 모델, 기본 문맥, 제공 도구와 계정별 기능 |
| API | 정확한 모델 ID·판본·입출력·요청 조건 |
| 공개 가중치 | 저장소 revision·구조 설정·tokenizer·라이선스 |
| 실행 환경 | 서버·메모리·자료형·양자화·병렬화·도구 연결 |

API는 프로그램이 서비스에 요청을 보내는 통로입니다. 가중치는 모델이 학습한 수치들의 묶음입니다. 같은 브랜드가 붙었다고 공개 가중치와 API의 입력 방식·문맥 크기까지 같다고 가정하지 않습니다. 각 글에는 확인한 대상과 제공 시점을 따로 적습니다.

## 용어를 짧게 이해하기

문맥 창은 한 요청에서 다룰 수 있는 자료의 예산입니다. 긴 자료를 넣을 수 있다는 것과 그 자료의 모든 사실을 정확히 회수하는 것은 다릅니다. 출력 예산은 답변을 만들 수 있는 분량이며 입력 가능한 총량과도 구분합니다.

추론 설정은 답을 만들 때 어느 정도 계산을 사용할지 정하는 조건입니다. 모델 이름이 같더라도 이 조건과 도구 사용 여부가 다르면 속도·비용·성공률이 달라질 수 있습니다. 에이전트는 모델의 출력과 실제 도구 실행을 연결해 작업을 이어 가는 프로그램을 뜻합니다. 모델이 도구 호출 문장을 생성한 것과 파일 수정·시험이 실제로 성공한 것은 별도 확인 사항입니다.

MoE는 토큰마다 내부 전문가 일부를 선택해 계산하는 구조입니다. 활성 파라미터는 그 순간 계산에 참여하는 수이며, 전체 가중치의 저장량을 대신하지 않습니다. 예를 들어 가상의 100B 모델에서 토큰마다 10B가 활성화돼도 가중치를 10B만 저장하면 된다고 계산하지 않습니다. 실제 메모리는 가중치 표현과 추가 버퍼·문맥 저장량·분산 방식에도 영향을 받습니다. 자세한 구조는 [기존 모델 문서](../AI모델과수치실험_ai-models/models/README.md)에 연결합니다.

## 벤치마크를 비교하는 순서

먼저 같은 시험·같은 판본인지 확인합니다. 그다음 추론 예산, 사용 도구, 입력·출력 길이, 재시도 수와 판정 방법을 맞춥니다. 여러 번 시도한 결과에서 좋은 답을 고르는 조건과 한 번의 답을 평가하는 조건을 같은 성공률로 읽지 않습니다.

제공사가 발표한 수치는 그 제공사의 평가 결과로 표기합니다. 독립 기관의 시험과 이 저장소의 직접 실행은 별도로 구분합니다. 발표 페이지 안에서 표와 설명의 수치가 다르면 먼저 추론 수준과 평가 조건이 같은지 확인합니다. 다른 조건의 값을 하나의 측정으로 합치거나 임의로 한 숫자를 골라 확정 순위를 만들지 않습니다.

## 단가보다 완료한 업무의 비용

다음은 제공사의 실측 결과가 아닌 자체 계산입니다. 모델 A의 호출 단가를 1, 성공률을 80%로 두고 독립적인 재시도가 가능하다고 단순 가정하면 성공 1건당 기대 호출 비용은 1 ÷ 0.8 = 1.25입니다. 모델 B는 단가 0.6, 성공률 40%라고 가정하면 0.6 ÷ 0.4 = 1.5입니다. 호출 단가가 낮아도 완료 비용은 더 클 수 있습니다.

현실의 재시도는 서로 독립적이지 않을 수 있고, 실패를 발견하지 못한 비용과 사람의 재검토 시간도 있습니다. 이 계산은 선택 방법을 설명하는 예제이며 어느 실제 모델의 우열이나 청구액을 말하지 않습니다.

## 새 발표에서 확인할 변화

입출력 종류, 문맥과 출력 예산, 도구 사용, 응답 속도, 가격 구간, 제공 지역·계정, 공개 가중치와 라이선스를 이전 판본과 비교합니다. 공개 예정은 이미 공개된 상태와 구분하고, API alias가 어느 판본을 가리키는지도 확인합니다. 공식적으로 설명하지 않은 층 수·학습 자료·내부 실행 방법을 다른 모델에서 추정해 채우지 않습니다.

이 기준을 적용한 글은 [모델별 분석](README.md)에 모았습니다. 분석에 사용한 공식 발표·카드·라이선스는 각 글의 주장 가까이에 연결합니다.
