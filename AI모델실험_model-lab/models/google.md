## 구조와 용도

Gemma는 직접 내려받는 모델 계열이며 Gemini API와 별도 배포물입니다. Gemma 3의 큰 모델에 이미지 입력이 있다고 해서 1B 모델에도 같은 기능이 있다고 판단하면 안 됩니다. 1B의 문맥 한도는 32k이며 4B·12B·27B의 128k와 다릅니다.

## 재현 방법과 비교 항목

공식 모델 카드에서 1B 예제를 선택하고 사용 조건에 동의한 뒤 tokenizer의 chat template을 적용합니다. 한국어 요약에서는 같은 문서의 핵심 사실 보존과 근거 없는 문장 추가를 따로 셉니다. 긴 문맥 실험에서는 입력 토큰과 생성 토큰의 합을 기록합니다.

## 결과를 해석할 때

모델 카드의 계열 설명과 개별 크기의 기능을 구분해야 합니다. 저장소에서는 가중치를 받지 않았으며 이미지 처리나 한국어 점수를 측정하지 않았습니다.

## 1B 텍스트 모델의 대화 흐름

대화 메시지는 template과 tokenizer를 거쳐 정수 ID가 되고, 1B 언어 모델은 앞선 ID를 조건으로 다음 ID를 생성합니다. 디코딩은 그 ID를 글자로 되돌리는 일입니다. 이 배포물의 입력에 이미지 블록을 붙이는 것은 모델을 더 크게 만드는 방법이 아닙니다. 해당 1B 텍스트 경로와 큰 멀티모달 모델의 처리기를 구별해야 합니다. [Gemma 3의 크기별 입력 범위](https://ai.google.dev/gemma/docs/core/model_card_3#inputs_and_outputs)

문맥에는 문서뿐 아니라 대화 지시·템플릿·이전 대화·생성할 답의 공간도 관련됩니다. 자체 예산을 30,000토큰으로 정하고 문서 28,000, 나머지 입력 500, 답 공간 1,500을 배정하면 합은 30,000입니다. 이는 예산 산술 예이며 실제 문서를 tokenizer로 잰 결과나 이 모델의 최대 출력 설정이 아닙니다. 한국어 글자 수를 토큰 수로 대신하여 같은 예산을 계산하지 않습니다.

## 직접 만든 일정 요약 예

평가 입력을 “A 실험은 11월 4일 시작합니다. B 실험은 취소되었습니다. C 실험의 시작일은 정하지 않았습니다. 세 실험의 상태를 한 줄씩 요약해 주세요.”로 정하겠습니다. 모델을 실행한 응답은 없으며 다음 표가 자체 정답 기준입니다.

| 항목 | 남겨야 할 정보 | 구체적 실패 |
| --- | --- | --- |
| A | 시작일 11월 4일입니다. | 다른 실험에도 이 날짜를 붙이면 오답입니다. |
| B | 취소 상태입니다. | 예정·연기 상태로 바꾸면 원문과 다릅니다. |
| C | 시작일이 미정입니다. | 문맥에 없는 날짜를 쓰면 정보 추가입니다. |

원문의 세 항목 중 두 개만 요약하면 그럴듯한 문장이라도 누락이 있습니다. 원문을 전부 복사한 긴 답은 사실을 유지할 수 있지만 ‘한 줄씩 요약’이라는 요구를 얼마나 지켰는지는 별도입니다. 요약에서는 줄 수·사실 보존·추가 사실을 각각 봅니다.

장문으로 확장하려면 동일한 핵심 사실을 문서 앞·중간·뒤에 옮기고 다른 문장은 방해 자료로 고정할 수 있습니다. 다만 입력을 잘라낼 때 정답 문장 자체가 사라졌다면 모델의 회수 실패로 세지 않습니다. 32k 범위에 들어온 사실과 필요한 내용을 실제로 이용한 사실은 다르므로 길이만으로 요약 품질을 인정하지 않습니다.
