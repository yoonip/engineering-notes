## 구조와 용도

공식 README는 batch 1의 720×1280·129프레임에 GPU peak memory 60GB, 544×960·129프레임에 45GB를 제시합니다. 이는 문서의 특정 조건이며 이 저장소의 측정값이 아닙니다. 텍스트 모델의 토큰 수만으로 영상 메모리를 설명할 수 없습니다.

## 재현 방법과 비교 항목

공식 Linux·CUDA 설치 경로에서 가중치와 텍스트 인코더를 준비합니다. seed·해상도·프레임 수·step 수를 고정하고 장면 일치·움직임·시간적 일관성을 따로 봅니다. 저해상도와 고해상도 결과는 같은 비용 조건의 비교가 아닙니다.

## 결과를 해석할 때

정지 프레임 하나가 선명해도 시간에 따른 물체 형태가 유지된다는 뜻은 아닙니다. 코드를 공개했다는 사실만으로 다른 모델과 같은 라이선스라고 판단하지 않습니다.

## 영상에서는 시간도 배열의 축입니다

공식 구조는 텍스트 조건과 잡음에서 latent를 만들고 3D VAE로 영상·이미지를 복원하는 흐름입니다. VAE가 시간과 공간을 압축하기 때문에 최종 프레임의 픽셀 배열과 본체가 처리하는 latent 배열은 크기가 다릅니다. 공개 설명의 prompt 재작성도 입력의 표현을 바꾸는 별도 단계이며 원래 조건이 그대로 보존되는지 따로 봐야 합니다. [전체 구조·3D VAE·Prompt Rewrite](https://github.com/Tencent-Hunyuan/HunyuanVideo#hunyuanvideo-overall-architecture)

자체 시간 계산으로 프레임을 0부터 번호 매기고 초당 24장 간격으로 129장을 둔다면, 마지막 128번의 표본 시점은 128/24=약 5.333초입니다. 이는 프레임 간격의 계산이며 생성한 영상의 재생 길이를 측정한 값이 아닙니다. 파일의 fps·컨테이너 재생 설정을 확인하지 않고 ‘129프레임=항상 몇 초’라고 고정하지 않습니다.

## 직접 만든 움직임·동일성 판정 예

자체 입력은 “고정된 카메라 앞의 탁자 위에서 빨간 장난감 자동차 한 대가 왼쪽에서 오른쪽으로 움직입니다. 자동차의 색과 모양은 유지됩니다.”입니다. 영상은 생성하지 않았으며 다음 표는 평가 기준입니다.

| 확인 시점 | 볼 내용 | 구체적 실패 |
| --- | --- | --- |
| 시작 | 자동차 한 대와 이동 시작 위치를 봅니다. | 두 대로 늘어나면 수량 오류입니다. |
| 중간 | 같은 차가 이어서 이동하는지 봅니다. | 색·바퀴 수가 바뀌면 시간적 동일성 오류입니다. |
| 끝 | 오른쪽으로 이동했는지 봅니다. | 배경만 움직인 장면을 차의 이동으로 오해하면 안 됩니다. |

세 정지 화면이 모두 그럴듯해도 그 사이의 프레임에서 물체가 사라질 수 있습니다. 연속 재생과 구간 검사를 함께 보아야 하며, 선명한 한 프레임을 전체 영상의 일관성 점수로 쓰지 않습니다. 고정 카메라라는 조건은 카메라 이동과 자동차 이동을 혼동하지 않도록 넣었습니다.

공식 60GB·45GB 요구값은 지정 해상도·129프레임·배치 1의 안내입니다. 가로·세로·시간축이 달라진 결과를 같은 비용 조건으로 비교하거나, 원본 대신 다른 경량화 구현의 수치를 이 요구값과 같은 측정으로 섞지 않습니다. 이 자체 예는 시간축 판정의 방법을 설명하며 실제 GPU 실행 기록은 아닙니다.
