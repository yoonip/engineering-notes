# 전자제품·시스템 개발의 업무와 결과물 | Product and system engineering roles

[직무 목차](README.md) · [업무·기술·근거](00-직무와기술을읽는법_roles-and-technical-work.md) · [반도체 설계·제조](02-반도체설계와제조의직무_semiconductor-design-manufacturing-roles.md) · [직무별 업무 사례](사례_cases/06-직무별사례와담당범위_role-case-map.md)

전자제품은 회로·기구·펌웨어·응용 소프트웨어·서비스가 함께 동작하는 시스템입니다. 모바일·가전·로봇·통신 장비처럼 제품이 달라져도, 요구를 정하고 구현한 뒤 조건을 맞춰 검사하고 생산·운영으로 넘기는 흐름은 연결됩니다. 이 글은 그 과정에서 맡는 대상과 결과물로 업무를 나눕니다. 조직 이름과 담당 범위는 제품·기업에 따라 달라질 수 있습니다.

## 1. 제품 안에서 업무의 위치를 찾습니다

| 제품의 경계 | 들어오는 것과 나가는 것 | 설계·개발에서 정할 내용 | 남길 결과물 |
| --- | --- | --- | --- |
| 물리 대상→회로 | 온도·빛·힘·전파→전압·전류·디지털 표본입니다. | 센서·입력 범위·잡음·대역·전원·환경 조건입니다. | 회로도·부품 명세·취득 조건·측정 결과입니다. |
| 회로→펌웨어 | 레지스터·인터럽트·표본→장치 상태·처리 결과입니다. | 초기화·버퍼·메모리·실행 기한·오류 처리입니다. | 드라이버·설정·단위 시험·타이밍 기록입니다. |
| 장치→플랫폼 | 장치 사건·통신 자료→공통 API·메시지·서비스입니다. | 자료 형식·버전·동시성·연결 중단·복구 의미입니다. | 인터페이스 명세·통합 시험·로그입니다. |
| 플랫폼→사용자·업무 | 요청·센서 정보→화면·알림·기능·거래 결과입니다. | 사용 시나리오·응답·권한·판정·데이터 보존입니다. | 기능 명세·평가 자료·배포와 운영 기록입니다. |
| 개발→생산·서비스 | 설계 판본→반복 제조·검사·정비입니다. | 검사 범위·변경·제품 식별·불량 재현 조건입니다. | 검사 프로그램·제조 이력·고장 조사·수정 후 대조입니다. |

같은 ‘통신 오류’도 RF 입력, 프레임 전달, 드라이버 큐, 서비스 처리에서 생길 수 있습니다. 어느 경계의 입력·출력을 관측했는지 적어야 서로 다른 담당자가 같은 사건을 비교할 수 있습니다. [산업별 시스템](../산업별전자와컴퓨팅_industry-systems/README.md)은 자동차·선박·가전·플랜트 등 제품별 구성을 설명합니다.

## 2. 회로·보드·시스템 개발

| 업무군 | 직접 다루는 대상 | 검사·분석의 관점 | 결과물과 이어서 읽을 내용 |
| --- | --- | --- | --- |
| 디지털·전원 회로 | 프로세서·메모리·전원·클록·입출력과 부품 연결입니다. | 전원 순서·리플·전압 강하·신호 파형·온도·부하를 함께 봅니다. | 회로도·BOM·측정 조건·원시 파형입니다. [제품 회로 검사](04-제품회로와시스템검사_product-circuit-system-tests.md)로 이어집니다. |
| RF·무선 회로 | 필터·증폭·주파수 변환·안테나와 전파 경로입니다. | 주파수·출력·정합·잡음·변조 품질·기준면을 맞춥니다. | 시료·케이블/보정·파형 조건·측정량입니다. [RF·전자기학](../전자컴퓨터공학_ece/29-전자기학-RF_electromagnetics-rf/README.md)으로 이어집니다. |
| PCB·하드웨어 통합 | 부품 배치·배선·리턴 경로·커넥터·기구·방열입니다. | SI·PI·열·조립·기계 환경을 분리하고 함께 비교합니다. | PCB 판본·설계 제약·시뮬레이션·실측의 대응입니다. [PCB 설계](../전자컴퓨터공학_ece/12-PCB하드웨어설계_pcb-hardware/README.md)로 이어집니다. |
| 로봇·구동 시스템 | 센서·모터·전력변환·통신·컴퓨팅 보드입니다. | 명령과 전류·위치·속도의 응답, 취득부터 구동까지의 시간을 봅니다. | 입출력·제어 요구·구동/센서 시험·이상 상태 기록입니다. [제어·신호 처리](../전자컴퓨터공학_ece/21-신호처리제어_signals-control/README.md)로 이어집니다. |
| 통신 시스템 | 여러 장치·프로토콜·처리 경로가 연결된 기능입니다. | RF 부품 특성과 처리량·지연·안정성·호환성을 별도 항목으로 둡니다. | 망/장치 구성·트래픽·설정·기능 및 성능 결과입니다. [통신 이론](../전자컴퓨터공학_ece/30-통신이론무선시스템_communications-wireless/README.md)으로 이어집니다. |

SI는 signal integrity, 신호가 필요한 파형·시점으로 전달되는지를 다루며 PI는 power integrity, 전력이 필요한 전압·안정성으로 전달되는지를 다룹니다. 하나의 보드에서 둘이 영향을 주고받더라도 같은 시험 이름으로 합치지 않습니다.

전원 리플을 보는 경우에도 측정계가 결과에 영향을 줍니다. 프로브의 감쇠·대역·입력 부하·연결 방식과 잡음을 함께 확인해야 합니다. [Tektronix의 전원 프로빙 설명](https://www.tek.com/en/documents/application-note/probing-techniques-accurate-voltage-measurements-power-converters-oscillos)은 작은 전원 변동을 관측할 때의 이러한 조건을 설명합니다. 회사의 제품 합격값은 해당 제품 요구에서 따로 정합니다.

## 3. 펌웨어·플랫폼·서버·응용 소프트웨어

| 업무군 | 구현하는 기능 | 실제로 확인할 경계 | 대표 결과물 |
| --- | --- | --- | --- |
| 드라이버·HAL·BSP | 장치 초기화·입출력·인터럽트와 보드 지원입니다. | 레지스터 상태·장치 오류·버퍼 소유권·메모리 접근·시작/종료입니다. | 장치 인터페이스·보드별 설정·오류 재현·단위 시험입니다. |
| 실시간·로봇 플랫폼 | 태스크·제어 주기·통신·센서와 구동을 연결합니다. | 우선순위·공유 자원·최악 지연·큐 적체·기한 초과입니다. | 실행 경로·스케줄링 조건·시각 기록·부하별 결과입니다. |
| 미들웨어·공통 라이브러리 | 메시지·직렬화·자원 접근·공통 기능을 제공합니다. | API 계약·판본 호환·동시성·기한·취소·중복·복구입니다. | 인터페이스 명세·통합 시험·오류 전파·호환 표입니다. |
| 서버·운영 플랫폼 | 상태·작업·데이터·자원과 서비스를 관리합니다. | DB·권한·부분 실패·재시도·배포·서비스 준비 상태입니다. | 데이터 모델·API·부하 시험·배포/복구·관측 기록입니다. |
| 기기·네트워크 응용 | 사용자 기능·통신 처리·장치 관리를 구현합니다. | 처리 경로의 정확성·자원 사용·설정 변경·사용 흐름입니다. | 기능 시험·성능 분석·사용 시나리오·실패 기록입니다. |

HAL은 hardware abstraction layer, 하드웨어 차이를 가리는 인터페이스 계층입니다. BSP는 board support package, 특정 보드에서 운영체제와 장치를 사용할 수 있게 하는 지원 묶음입니다. 미들웨어는 응용 사이의 통신과 공통 기능을 이어 주는 소프트웨어입니다. 서로 연결되지만 같은 범위를 가리키지는 않습니다.

[Zephyr의 Threads 문서](https://docs.zephyrproject.org/latest/kernel/services/threads/index.html)는 스레드의 실행·스택·우선순위와 상태를 설명합니다. [Linux DMA mapping Guide](https://docs.kernel.org/core-api/dma-api-howto.html)는 CPU와 장치가 보는 주소·메모리 사용 경계를 구분합니다. 공개 문서의 구조를 공부한 뒤 실제 보드·드라이버·부하에서 확인한 결과를 별도로 기록합니다. 상세 검사는 [펌웨어·소프트웨어 검증](05-펌웨어와소프트웨어검증_firmware-software-validation.md)에서 이어집니다.

Cloud Native는 컨테이너·자동화·분산 플랫폼 등을 활용해 서비스를 개발·운영하는 접근과 연결됩니다. 이중화는 장애에 대비해 자원을 나누는 설계이며, 컨테이너를 쓴다는 사실만으로 상태 복구와 데이터 일관성까지 입증되지는 않습니다. [기업 IT·인프라](../산업별전자와컴퓨팅_industry-systems/07-기업IT와데이터센터및통신_enterprise-it-infrastructure.md)는 이 경계를 더 설명합니다.

## 4. AI·영상·기기 내 모델

AI 업무는 모델 학습만으로 끝나지 않습니다. 자료 수집·라벨·평가 분리·전처리·추론·기능 연동·업데이트까지 연결됩니다. 생성형 서비스와 영상 검사, 로봇의 인식은 입력과 실패 영향이 다르므로 같은 정답률 하나로 비교하기 어렵습니다.

| 세부 업무 | 먼저 구분할 내용 | 평가·구현 결과물 |
| --- | --- | --- |
| 모델·알고리즘 | 학습 자료·목표·모델 구조·추론 출력을 구분합니다. | 데이터 분할·평가 조건·모델 판본·오류 유형입니다. |
| 기기 내 최적화 | 제한된 메모리·전력·지연에서 모델을 실행합니다. | 정확도·지연·메모리·양자화·런타임 조건의 비교입니다. |
| 검색 결합 생성 RAG | 검색한 근거를 생성 입력에 연결합니다. | 검색 결과·문서 판본·근거 적합성·응답 평가입니다. |
| 도구 사용 Agent | 모델의 판단을 도구 호출·상태 변화와 연결합니다. | 호출 입력·권한·실행 결과·오류·재시도·중단 기록입니다. |
| LoRA 등 조정 | 모델 일부에 추가 파라미터를 두는 방식 등으로 학습을 수행합니다. | 기반 모델·조정 자료·설정·평가 결과와 적용 범위입니다. |
| 배포·개인화·운영 | 모델과 사용자/장치 상태·서비스 판본을 연결합니다. | 자료 처리 조건·배포/복구·입력 변화·지연과 품질 이력입니다. |

관련 기반은 [AI 평가](../전자컴퓨터공학_ece/46-AI응용에이전트평가_ai-agents-evaluation/README.md), [엣지 AI](../전자컴퓨터공학_ece/47-엣지AI-TinyML_edge-tinyml/README.md), [컴퓨터 비전](../전자컴퓨터공학_ece/43-컴퓨터비전_computer-vision/README.md)에 있습니다. 알고리즘 성능과 실제 기능의 성공을 구분하는 예는 [AI·제조 IT](09-AI데이터와제조IT_ai-data-manufacturing-it.md)로 이어집니다.

## 5. 시험·품질·서비스

개발 검증은 요구에 맞는 동작을 조사하고, 품질 활동은 개발·생산·출하·사용 중 확보해야 하는 근거를 연결합니다. 시험 장치와 프로그램 자체도 결과를 틀리게 만들 수 있으므로 제품 불량과 시험계 오류를 함께 조사합니다.

| 업무 | 입력과 관측 | 결과물 |
| --- | --- | --- |
| 기능·성능 시험 | 요구 기능·부하·구성·시간 조건을 정하고 결과를 관측합니다. | 지원 범위·성공/실패·원시 자료·재현 조건입니다. |
| 호환성·통합 | 상대 장치·옵션·프로토콜·HW/SW 판본을 조합합니다. | 조합별 지원·제한·실패 경계입니다. |
| 신뢰성·환경 | 사용 환경과 시험의 스트레스·시간을 연결합니다. | 시료·조건·시간·전후 특성·고장과 조사 결과입니다. |
| AI·IoT·보안 검증 | 입력 자료와 네트워크·권한·업데이트·서비스 동작을 봅니다. | 평가 자료·권한 조건·실패/복구·모델/설정 판본입니다. |
| 시험 자동화 | 설정·입력·수집·비교·보고를 프로그램으로 연결합니다. | 장비 식별·설정 읽기·원시값·판정 규칙·실행 환경입니다. |
| 서비스·고장 분석 | 사용 중 증상·이력과 개발/제조 정보를 연결합니다. | 제품 식별·재현·원인 후보·조치·수정 뒤 대조입니다. |

[AOSP VTS](https://source.android.com/docs/core/tests/vts)는 호스트의 시험 실행 관리와 기기에서 실행되는 C++·커널 시험 등을 구분하는 공개 예입니다. 이처럼 어느 코드가 어느 장치에서 무엇을 확인하는지 먼저 읽으면 언어와 검사가 연결됩니다. 실제 발췌와 이용 조건은 [공개 코드 사례](사례_cases/README.md)에 모았습니다.

## 6. 언어·도구를 실행 위치로 구분합니다

| 실행 위치 | 언어·도구가 맡을 수 있는 역할 | 확인할 점 |
| --- | --- | --- |
| 장치·성능 경로 | C/C++ 등의 드라이버·실시간 처리·메모리·통신 구현입니다. | 자료형·경계·소유권·실행 시간·오류 처리를 봅니다. |
| 시험 PC·호스트 | Python 등의 장비 제어·입력 생성·로그 정리·통계·보고입니다. | 장비 명령·설정·동기·판정 규칙을 봅니다. |
| 서버·기기 응용 | Java·C/C++·Python·JavaScript 등으로 서비스와 응용을 구현할 수 있습니다. | 플랫폼·API·자료 계약·자원·배포·상태 관리를 봅니다. |
| 데이터 저장·분석 | SQL로 자료를 질의하고 분석 도구로 결과를 비교합니다. | 키·단위·기간·중복·결측·분모를 확인합니다. |
| 회로·시뮬레이션 | CAD·SPICE·전자기 해석·측정 도구를 사용합니다. | 모델·경계 조건·설정·실측과의 차이를 봅니다. |

이는 언어의 활용 위치이며 모든 업무의 공통 필수 언어 목록이 아닙니다. 도구·운영체제·프레임워크·프로그래밍 언어도 서로 다른 분류입니다. 구체적인 입력·처리·출력은 [C·Python의 사용 위치](10-C와Python이쓰이는위치_languages-in-the-workflow.md)에 정리했습니다.

## 7. 개발과 사업·생산·시설의 협업

| 업무 | 기술 자료를 사용하는 판단 | 공유할 자료 |
| --- | --- | --- |
| 제품·서비스 기획 | 기능의 사용 가치·제약·수명주기·출시 순서를 정합니다. | 사용자 시나리오·성능 조건·목표/실제·비용과 지원 범위입니다. |
| 기술 영업·마케팅 | 고객 요구를 사양·기능·공급·지원 책임으로 구체화합니다. | 비교 조건·고객 검증·일정·판매/사용량·수익성의 기준입니다. |
| 구매·SCM | 부품·제조·재고·조달 기간과 공급 위험을 관리합니다. | BOM·부품 승인·수요·재고 시점·변경·대체 시험입니다. |
| 생산·서비스 | 반복 제조·현장 문제·정비를 제품 판본과 연결합니다. | 검사·작업 이력·제품 식별·증상·조치와 재평가입니다. |
| 시설·에너지 | 제품 개발·제조가 사용하는 전력·공조·설비를 관리합니다. | 부하·용량·공급 품질·계측·고장과 유지관리 이력입니다. |
| 안전·보건·환경 | 위험원·작업자 노출·환경 영향을 구분해 관리합니다. | 대상·기준·측정·변경·교육·사고 조사와 적용 절차입니다. |

BOM은 bill of materials, 부품 종류·수량·식별자를 담은 자재 명세입니다. 같은 저항값·메모리 용량의 부품도 허용오차·패키지·전압·온도·지원 기능은 다를 수 있습니다. 대체 부품을 검토하는 학습 상황에서는 구매가 공급 조건을, 설계·품질이 호환성과 재시험을, 사업 담당자가 고객 약속의 영향을 연결합니다. 이 상황은 협업 관계를 설명하는 예이며 특정 회사의 승인 절차가 아닙니다.
