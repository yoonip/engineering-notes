## 1. 정비 뒤 신호가 일정해 보이는 설비

### 장비와 먼저 읽을 개념

압력·온도·전류 센서가 바뀌지 않는 값을 보인다고 가정합니다. 실제 공정이 안정된 경우, 센서가 멈춘 경우, 통신이 끊겨 이전 값이 남은 경우는 화면만 보면 비슷할 수 있습니다.

| 구성 요소 | 역할 | 함께 확인할 항목 |
| --- | --- | --- |
| 압력계·온도계·전류 센서 등 | 물리량을 전기적 신호나 디지털 값으로 바꿉니다. | 측정 범위·단위·교정·오버레인지·센서 상태입니다. |
| DAQ·장치 제어기 | 센서 값을 읽고 시각·상태와 함께 제공합니다. | 실제 변환 속도, 필터·평균·스캔 주기와 장치 오류입니다. |
| IOC | EPICS의 input/output controller이며 장치 I/O와 로컬 제어를 맡는 서버입니다. | 연결한 장치·record 설정·처리 주기입니다. |
| PV | process variable이며 이름으로 찾는 측정값·설정값·상태 등의 항목입니다. | 이름이 가리키는 물리량, 시각·단위·경보·접속 상태입니다. |
| Python 클라이언트 | PV를 읽거나 변경 통지를 받아 분석·기록으로 연결합니다. | 어떤 값을 언제 받았는지, 누락과 재접속이 있었는지입니다. |

EPICS는 가속기·대형 실험·망원경 등의 분산 제어에 사용되는 공개 시스템입니다. [공식 소개의 IOC·Channel Access·APS 운용 설명](https://epics-controls.org/about-epics/)으로 실제 사용 분야를 확인할 수 있습니다. 아래 코드는 그 생태계의 Python 인터페이스이며, 반도체 팹이 EPICS를 쓴다는 채택 주장은 아닙니다.

### 출처가 있는 Python 모니터 예제

출처는 PyEpics 3.5.8의 `doc/overview.rst` 383–394행입니다. [고정 원문](https://github.com/pyepics/pyepics/blob/4a4caebd92b75ee21c774cfc33c05ae77f4d1f97/doc/overview.rst#L383-L394)은 변경 통지를 파일에 저장하는 대화형 예제입니다. 원문 PV는 DMM의 계산값 예시 이름이며, 압력 PV로 임의 교체하지 않았습니다.

먼저 다음 세 줄을 실행하는 구조입니다. 원문의 `>>>` 프롬프트를 제거하고 한국어 주석을 붙였습니다. 실행문·PV 이름·파일 이름은 그대로입니다.

```python
import epics  # import는 모듈을 불러오며, epics는 Channel Access 통신 기능을 제공합니다.
fh = open('PV1.log','w')  # open은 파일을 열며, 'w'는 쓰기 모드이고 fh는 파일 객체입니다.
epics.camonitor('XXX:DMM1Ch2_calc.VAL',writer=fh.write)  # 함수 호출로 변경 통지를 등록하고 writer에 파일의 write 메서드를 넘깁니다.
```

원문은 여기서 값의 변화를 기다리라고 설명합니다. 그 문구는 실행 가능한 Python 문장이 아니므로 코드 블록에 넣지 않았습니다. 관찰을 마친 뒤 다음 두 줄을 실행하여 모니터와 파일을 닫는 순서입니다.

```python
epics.camonitor_clear('XXX:DMM1Ch2_calc.VAL')  # 같은 PV의 모니터를 해제하여 이후 통지 처리를 중지합니다.
fh.close()  # 파일 객체의 close 메서드로 버퍼를 마무리하고 파일을 닫습니다.
```

이 발췌는 교육용 공식 예제입니다. 모듈의 전체 장치 드라이버나 장시간 운영용 데이터 수집기를 복제한 코드는 아닙니다. 실제 기록 체계에서는 예외·파일 보존·연결 이력도 관리해야 합니다. Copyright 2010 Matthew Newville, The University of Chicago. 주석을 추가하고 대화형 단계를 나누었습니다. [EPICS Open License 전문](licenses/pyepics-3.5.8-LICENSE.txt)과 [원본 라이선스](https://github.com/pyepics/pyepics/blob/4a4caebd92b75ee21c774cfc33c05ae77f4d1f97/LICENSE)를 함께 제공합니다.

### 모니터 기록과 원래 장치의 샘플링은 다릅니다

모니터는 모든 ADC 변환 값을 빠짐없이 저장한다는 뜻이 아닙니다. 통지 조건·스캔·네트워크·클라이언트의 처리에 따라 관측이 달라질 수 있습니다. PyEpics의 `caget`도 기본적으로 모니터의 최근 캐시 값을 사용할 수 있고, 실패할 때는 `None`을 반환합니다. [공식 caget의 반환값·use_monitor 설명](https://pyepics.github.io/pyepics/overview.html#caget)을 확인하시면 됩니다.

`None`은 0이라는 물리량이 아니라 값을 얻지 못했다는 상태입니다. PV에 붙은 시각과 클라이언트가 받은 시각도 구분해야 합니다. PV의 시각이 실제 장치의 취득 시각인지 확인하려면 record의 `TSE`·`TSEL`과 device support 구현을 살펴야 합니다. 설정에 따라 현재 시각·다른 record의 시각·하드웨어 시각 등을 사용할 수 있습니다. [EPICS Base 7.0.9, TIME·TSE·TSEL 설명](https://docs.epics-controls.org/projects/base/en/r7.0.9/dbCommonRecord.html#miscellaneous-fields)이 그 차이를 설명합니다.

### 결과에서 원인으로 좁히는 순서

| 관찰한 현상 | 가능한 설명 | 원인을 나눌 확인 |
| --- | --- | --- |
| 로그에 새 행이 없습니다. | 값이 통지 조건을 넘지 않았거나, IOC·네트워크·클라이언트가 중단됐을 수 있습니다. | 접속 상태·IOC 처리 상태·원시 장치 갱신과 서로 다른 PV를 함께 봅니다. |
| 값은 일정한데 PV에 붙은 시각이 오래됐습니다. | 값·record의 갱신 중단이나 시각 출처의 차이가 후보입니다. | 로컬 장치 표시와 record 처리 상태, TSE·TSEL·device support의 시각 출처를 대조합니다. |
| 장치에는 변화가 있는데 수집된 값은 거칩니다. | 통지·평균·읽기 주기가 변화보다 느릴 수 있습니다. | 장치의 취득 기록과 수집·통지 설정을 비교합니다. |
| 센서 교체 후 일정 비율로 값이 달라졌습니다. | 실제 공정 변화 외에 범위·단위·변환 계수 차이가 후보입니다. | 같은 기준 입력을 연결해 표시값·원시값·설정 판본을 비교합니다. |
| 센서 두 개가 동시에 급변했습니다. | 공통 전원·통신·공정 사건 등이 후보입니다. | 다른 측정 경로와 설비 사건의 시간 관계를 확인합니다. |

이 표는 진단을 위한 자체 구성입니다. 특정 증상을 특정 고장으로 확정한 회사 사례가 아닙니다. 예를 들어 센서·장치·수집 경로가 모두 정상임을 확인한 뒤 압력 변화가 반복된다면 펌프·밸브·누설·가스 조건을 조사할 근거가 생깁니다. 반대로 오래된 값의 재표시였다면 공정 레시피를 바꾸기보다 연결·갱신·기록의 결함을 먼저 고쳐야 합니다.

수정 후에는 알려진 입력 변화가 장치·IOC·클라이언트까지 같은 순서로 전달되는지, 연결 중단을 정상값으로 처리하지 않는지, 복구 뒤 중단 구간을 표시하는지 재확인합니다. 남길 결과는 값의 그래프뿐 아니라 PV 정의·단위·처리/통지 설정·장치 상태·PV 시각과 그 출처·클라이언트 수집 시각·수정 이력입니다.

### C와 Python을 쓰는 위치

센서의 레지스터·ADC·장치 프로토콜을 처리하는 드라이버와, 수집한 자료를 기록·분석하는 호스트 프로그램은 다른 계층입니다. Python 예제는 호스트 측 통신·기록을 보여 줍니다. 이 PV의 실제 장치 드라이버 구현은 공개 예제의 범위에 포함되지 않습니다. [C·Python의 실행 위치](../10-C와Python이쓰이는위치_languages-in-the-workflow.md)에서 언어와 실행 대상의 차이를 이어서 읽으실 수 있습니다.

## 2. 패키지 접속 저항의 산포가 달라 보이는 경우

### 무엇을 측정해야 하는지 먼저 정합니다

패키지·모듈의 접속 경로를 비교할 때는 어느 두 지점 사이의 저항을 재는지부터 정해야 합니다. 직렬로 연결한 여러 접점을 한 번에 재는 daisy chain은 전체 경로의 연속성과 저항 변화를 관찰하는 시험 구조입니다. 전체 경로가 변했다는 결과만으로 어느 접합 하나가 원인인지 바로 알 수는 없습니다.

| 구성·자료 | 측정 항목 | 필요한 이유 |
| --- | --- | --- |
| 4선 저항 측정이 가능한 DMM·SMU, Kelvin fixture | 저항 Ω, 인가 전류 A, 측정 전압 V입니다. | 전류를 흘리는 선과 전압을 읽는 선을 나누어 리드 저항의 영향을 줄입니다. |
| 반복 접촉·기준 저항·장비 교차 측정 | 같은 시료의 반복값·영점·시간 변화입니다. | 시료 차이와 프로브·fixture·장비 차이를 분리합니다. |
| 시료 온도·전류·취득 조건 | °C·A·측정 범위·평균·대기 시간입니다. | 온도·자기 발열·설정 차이를 공정 차이로 오인하지 않게 합니다. |
| 시료·lot·조립 조건·위치 ID | 각각의 측정과 제품 이력의 대응 관계입니다. | 여러 제품·공정 조건이 섞인 산포를 구분합니다. |
| 필요에 따른 초음파·X선·단면 분석 | 박리·빈 공간·접속 형상 등의 근거입니다. | 전기적 변화의 물리적 원인을 확인하는 별도 관측입니다. |

Keithley의 [Application Note 3176, 1쪽 Figure 1·2](https://download.tek.com/document/2110_2Wire4WireKelvinResistanceAppNote.pdf)는 2선식에서 측정에 리드 경로가 포함되는 이유와 4선 연결을 설명합니다. 이 자료는 Keithley 2110·2400/2600 계열 등 실제 장비의 측정 원리를 다룹니다. Sonix의 [패키지 초음파 검사](https://www.sonix.com/applications/packageinspection/encapsulatedic/)는 비접합·박리·void·균열 등의 관측 대상을 설명합니다. 초음파 영상과 전기 저항은 서로 다른 증거입니다.

### 산포는 평균과 다른 질문입니다

평균은 값이 모이는 위치이고, 산포는 값들이 얼마나 퍼져 있는지입니다. 평균이 비슷해도 일부 제품의 저항이 넓게 퍼질 수 있습니다. 반대로 산포가 비슷해도 평균이 모두 높아져 규격을 벗어날 수 있습니다.

여기서는 Levene 검정을 산포 비교의 공개 구현으로 읽습니다. 검정은 여러 집단의 분산이 같다는 가설과 자료가 얼마나 맞지 않는지를 평가합니다. 기본 `center='median'`은 각 집단의 중앙값에서 얼마나 떨어졌는지를 사용합니다. 중앙값은 값을 정렬했을 때 가운데 위치입니다. [NIST의 Levene 정의·중앙값 방식](https://www.itl.nist.gov/div898/handbook/eda/section3/eda35a.htm)에서 목적과 식을 확인할 수 있습니다.

이 검정은 SPC 관리도도, 접합 불량을 자동 판정하는 모델도 아닙니다. 비교할 제품·조건·표본과 측정 경로를 정한 뒤 분포 차이를 조사하는 도구입니다.

### 실제 라이브러리 내부의 Python 계산

출처는 SciPy 1.15.3의 [scipy/stats/_morestats.py, levene 함수 3036–3058행](https://github.com/scipy/scipy/blob/e29dcb65a2040f04819b426a04b60d44a8f69c04/scipy/stats/_morestats.py#L3036-L3058)입니다. 공개 라이브러리에서 실행되는 구현의 연속 구간을 발췌했습니다. 함수 앞부분에서 `samples`, 집단별 크기 `Ni`, 선택한 중심 `Yci`, 전체 크기 `Ntot`, 집단 수 `k`를 준비합니다. 아래 부분만으로 실행하는 독립 프로그램은 아닙니다.

```python
Zij = [None] * k  # []는 리스트이며, 집단마다 편차 배열을 넣을 자리를 k개 준비합니다.
for i in range(k):  # for는 반복문이고 range(k)는 0부터 k-1까지 집단 번호를 만듭니다.
    Zij[i] = abs(asarray(samples[i]) - Yci[i])  # 배열로 바꾼 관측값에서 집단 중심을 빼고 abs로 거리만 남깁니다.
Zbari = np.empty(k, 'd')  # np.empty는 double 배열의 공간을 준비하며, 다음 반복에서 값을 채웁니다.
Zbar = 0.0  # 실수 누적값을 0으로 초기화합니다.
for i in range(k):  # 집단별로 절대 편차의 평균을 계산합니다.
    Zbari[i] = np.mean(Zij[i], axis=0)  # mean은 평균이며 axis=0 방향으로 집단의 편차를 합칩니다.
    Zbar += Zbari[i] * Ni[i]  # +=는 기존 값에 더하며 집단 크기로 가중한 합을 만듭니다.
Zbar /= Ntot  # /=는 나눈 값을 다시 저장하며 전체 가중 평균을 구합니다.
numer = (Ntot - k) * np.sum(Ni * (Zbari - Zbar)**2, axis=0)  # **2는 제곱이며 집단 사이의 차이를 집계합니다.
dvar = 0.0  # 집단 안의 변동을 누적할 변수를 만듭니다.
for i in range(k):  # 각 집단 내부의 변동을 더합니다.
    dvar += np.sum((Zij[i] - Zbari[i])**2, axis=0)  # 집단 평균 편차 주변에서 얼마나 퍼지는지 제곱합으로 계산합니다.
denom = (k - 1.0) * dvar  # 집단 내부 변동과 집단 수로 분모를 계산합니다.
W = numer / denom  # /는 나눗셈이며 집단 사이와 내부 변동을 비교하는 검정통계량을 만듭니다.
pval = distributions.f.sf(W, k-1, Ntot-k)  # F분포의 sf는 W 이상 꼬리 확률을 계산합니다.
```

실행문은 원본과 같고, 바깥 함수의 들여쓰기와 빈 줄·영문 구분 주석을 제거한 뒤 줄별 설명을 붙였습니다. Copyright (c) 2001–2002 Enthought, Inc. 2003–2024, SciPy Developers. [BSD 3-Clause 라이선스 전문](licenses/scipy-1.15.3-LICENSE.txt)과 [원본 라이선스](https://github.com/scipy/scipy/blob/e29dcb65a2040f04819b426a04b60d44a8f69c04/LICENSE.txt)를 제공합니다.

### 공개 실측 자료로 계산을 확인한 결과

계산 검토에는 NIST의 [GEAR.DAT](https://www.itl.nist.gov/div898/handbook/datasets/GEAR.DAT)를 사용했습니다. 원본은 gear 지름을 10개 batch에서 각각 10개씩 측정한 100행 자료입니다. 반도체·패키지 측정값이 아니며, 이 자료의 단위를 임의로 Ω로 바꾸지 않았습니다. [NIST의 자료 설명](https://www.itl.nist.gov/div898/handbook/eda/section3/eda3581.htm)과 [원본 R 계산](https://www.itl.nist.gov/div898/handbook/eda/section3/eda35a.r)으로 입력과 비교 기준을 확인할 수 있습니다.

| 구분 | 결과와 의미 |
| --- | --- |
| NIST 본문 | 중앙값 방식의 W=1.705910, 유의수준 0.05, F 임계값 약 1.9855입니다. |
| NIST R 출력 | W=1.7059, p≈0.09908입니다. |
| 이 글의 로컬 재계산 | 원본 100행을 SciPy 1.15.3·NumPy 2.2.6으로 계산해 W=1.705917693, p=0.099082976, 임계값=1.985594964를 얻었습니다. |
| 독립 대조 | NIST의 식을 별도로 계산한 W=1.705917693과 SciPy가 수치 오차 범위에서 일치했습니다. |
| 판정 | p가 0.05보다 커서 이 자료에서는 분산 차이가 있다는 가설을 뒷받침할 근거가 부족합니다. 분산이 완전히 같다는 증명은 아닙니다. |

원문 W와 재계산 W의 마지막 자릿수는 구분해 남겼습니다. 어느 쪽도 임계값을 넘지 않으며, NIST R 출력의 표시 정밀도와 판정은 같습니다. 이는 통계 구현과 공개 자료의 재계산 결과이고 패키지 장비의 검증 결과는 아닙니다.

## English

The cases connect an official PyEpics monitoring example to equipment-signal diagnosis and SciPy's production Levene implementation to resistance-distribution studies. The NIST gear dataset is actual public metrology data, not semiconductor data. Its local recalculation, the original NIST result and hypothetical package failure hypotheses are identified separately. No equipment or company-internal production program was executed.
