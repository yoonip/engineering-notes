# 직무와 기술을 읽는 방법 | Understanding technical roles and work

[직무 목차](README.md) · [원문과 확인 범위](출처와검토범위_SOURCES.md)

회로·펌웨어·평가·공정·AI·IT는 제품을 만드는 과정의 서로 다른 부분을 담당합니다. 만드는 대상과 해결할 문제를 먼저 찾고 입력·출력·측정 방법을 적으면 C·Python·회로·통계가 왜 함께 쓰이는지 연결할 수 있습니다.

## 1. 직무 이름보다 대상과 동사를 먼저 읽습니다

업무는 제품·대상·수행 작업·판단 기준·실행 환경·결과물로 나누어 읽습니다. 같은 직무명이라도 조직과 제품에 따라 직접 다루는 대상이 달라집니다.

| 읽을 항목 | 구체적으로 적을 내용 | 예 |
| --- | --- | --- |
| 조직·제품 | 어느 사업부의 어떤 제품인지 적습니다. | 모바일 보드, 통신 장비, 메모리 셀, SSD, 팹 설비, 보안 시스템입니다. |
| 대상 | 코드·회로·시편·장비·데이터 중 직접 바꾸는 것을 적습니다. | PHY IP, 전원 회로, 공정 조건, 테스트 프로그램, 데이터 파이프라인입니다. |
| 수행 동사 | 설계·구현·측정·분석·운영 중 맡는 일을 나눕니다. | 기능 구현과 성능 계측, 불량 원인 분리는 서로 다른 작업입니다. |
| 판단 기준 | 개선하려는 물리량·기능·운영 지표를 적습니다. | 누설전류, 타이밍 여유, 처리량, 오탐률, 설비 정지 시간입니다. |
| 언어·도구 | 어느 컴퓨터에서 무엇을 실행하는지 적습니다. | DUT의 C 펌웨어, 호스트 PC의 Python 계측, RTL 검증 환경의 SystemVerilog입니다. |
| 남길 근거 | 다른 사람이 확인할 산출물을 적습니다. | 사양, 회로도, 시험 계획, 원시 파형, 분석 결과, 수정 전후 대조입니다. |

예를 들어 ‘시스템 설계’는 통신 신호 처리, 임베디드 장치 구성, 서비스 인프라 설계 등 서로 다른 대상을 가리킬 수 있습니다. 제목만으로 묶기보다 실제 입출력·제약·검사 방법을 살펴봅니다. [전자제품·시스템 개발](01-전자제품과시스템개발의직무_product-system-roles.md), [반도체 설계·제조](02-반도체설계와제조의직무_semiconductor-design-manufacturing-roles.md), [메모리 제품·양산](03-메모리제품과양산의직무_memory-product-production-roles.md)에서 각 업무의 연결을 읽으실 수 있습니다.

## 2. 기능·제약·구현·평가를 구분합니다

| 구분 | 업무에서의 의미 | 확인할 내용 |
| --- | --- | --- |
| 기능 | 제품이나 시스템이 해야 할 동작입니다. | 입력·출력·상태·지원 명령을 정합니다. |
| 제약 | 동작을 만족해야 하는 범위입니다. | 시간·전력·메모리·온도·오차·인터페이스 조건입니다. |
| 구현 | 기능을 회로·코드·공정·설정으로 만드는 작업입니다. | 설계 선택과 그 선택이 적용되는 범위입니다. |
| 평가 | 구현한 결과가 요구와 조건에 맞는지 판단하는 작업입니다. | 시험 입력·기대값·관측·판정·남은 한계입니다. |
| 설명용 사례 | 입력·측정·판정의 관계를 이해하기 위한 예입니다. | 가정한 조건과 실제 측정·실행한 범위를 구분합니다. |

프로그래밍 언어는 코드가 실행되는 위치와 역할로 설명합니다. C가 임베디드 펌웨어·알고리즘 기준 모델·테스터 프로그램 중 어디에 쓰이는지, Python이 계측·분석·모델 실행 중 무엇을 연결하는지 살펴봅니다. 이 학습 경로에서 다루는 기술이 모든 조직의 채용 필수 조건이라는 뜻은 아닙니다.

## 3. 검사·검증·평가를 대상별로 나눕니다

회사마다 용어를 쓰는 범위가 달라 단어 하나만으로 담당 부서를 결정하기 어렵습니다. 여기서는 다음 대상과 결과로 구분합니다.

| 구분 | 넣는 것 | 얻는 것 | 대표적인 판단 |
| --- | --- | --- | --- |
| 설계 기능 검증 | RTL·모델과 입력 시나리오입니다. | 기대 동작과 다른 출력·상태·커버리지입니다. | 사양대로 동작하는지 판단합니다. |
| 전기 특성 평가 | 실제 칩·보드에 인가한 전압·주파수·부하·온도입니다. | 지연·전류·파형·오류 분포입니다. | 어떤 조건에서 여유가 줄어드는지 판단합니다. |
| 공정·재료 계측 | 웨이퍼의 특정 위치와 가공 단계입니다. | 두께·선폭·조성·형상·결함입니다. | 공정 변화와 전기적 이상을 연결합니다. |
| 양산 선별 | 정해진 시험 프로그램과 제품입니다. | 개별 제품의 판정·등급·실패 항목입니다. | 출하·후속 조립에 보낼 대상을 정합니다. |
| 신뢰성 평가 | 정해진 스트레스와 전후 측정입니다. | 시간·온도·반복에 따른 열화·고장입니다. | 사용 중 발생할 고장 기구와 규격 충족을 평가합니다. |
| 소프트웨어 시험 | 코드·설정·데이터와 실행 환경입니다. | 기능·성능·복구·보안 관련 결과입니다. | 요구 기능과 운영 조건을 만족하는지 판단합니다. |
| AI·데이터 평가 | 고정한 데이터·모델·검색·도구 구성입니다. | 오류율·지연·추적 정보·운영 변화입니다. | 모델 점수와 실제 서비스의 성공을 따로 봅니다. |

설계 검증과 실물 평가의 연결은 [칩 설계·평가](06-칩설계와평가분석_chip-design-characterization.md), 제품과 보드의 검사는 [제품 회로·시스템 검사](04-제품회로와시스템검사_product-circuit-system-tests.md), 양산 테스트는 [메모리 제품·테스트 개발](08-메모리제품과테스트개발_memory-product-test-engineering.md)에서 이어집니다.

## 4. 하나의 실패가 여러 직무를 거치는 모습

```mermaid
flowchart LR
    A["요구 기능·사용 조건"] --> B["회로·RTL·알고리즘 설계"]
    B --> C["모델·시뮬레이션 검증"]
    C --> D["칩·보드·펌웨어 평가"]
    D --> E["공정·조립·양산 시험"]
    E --> F["현장·고객 사용 데이터"]
    F --> G["원인 가설과 수정안"]
    G --> B
    G --> E
```

이 그림은 모든 직무가 같은 순서로 일한다는 조직도가 아니라, 문제와 근거가 이동하는 경로입니다. 다음은 설명용 사례입니다.

### 예: 고온에서만 메모리 읽기가 실패합니다

1. 제품 담당자는 온도·전압·클록·시험 패턴과 실패 주소를 고정합니다. ‘뜨거우면 안 됩니다’보다 재현 조건이 먼저 필요합니다.
2. 펌웨어 담당자는 초기화·타이밍 설정·캐시·DMA 버퍼 소유권을 확인합니다. 잘못된 데이터가 메모리 셀에서 생겼는지 소프트웨어 경로에서 생겼는지 나눕니다.
3. 회로·평가 담당자는 전원 강하와 인터페이스 파형, 주파수·전압 조건별 실패 영역을 확인합니다.
4. 공정·분석 담당자는 필요한 시편의 구조·재료·접촉을 살펴 전기적 증상과 맞는 결함 기구를 좁힙니다.
5. 양산·품질 담당자는 로트·장비·사이트·시간별 분포와 재검사 이력을 연결합니다. 시험 조건을 바꿔 통과시킨 결과와 원인을 제거한 결과를 구분합니다.

여기서 C는 제품 안의 접근·초기화·검사 패턴을, Python은 조건 반복·장비 조회·로그 연결을 담당할 수 있습니다. 파형을 계측하는 장비, 원시 데이터를 분석하는 코드, 출하를 판정하는 규칙은 서로 다른 역할입니다.

## 5. 읽고 난 뒤 남길 작은 결과물

| 공부한 업무 | 직접 설명할 결과물 |
| --- | --- |
| 회로·펌웨어 | 블록도 한 장, 신호·전원 경로, 예상 파형과 실패 후보입니다. |
| 반도체 평가 | 시험 대상·인가 조건·관측량·합격 기준·불확도가 들어간 시험표입니다. |
| 공정·설비 | 가공 전후 단면, 조절 변수, 계측 위치, 원인 분리 계획입니다. |
| AI·IT | 데이터 흐름, 입력 계약, 실패 처리와 독립 평가 항목입니다. |
| 구매·생산관리·영업 | 수요·납기·재고·품질·비용의 연결과 숫자의 분모입니다. |
| 환경안전·인프라 | 설비 계통도, 감시 변수, 이상 검출과 운영 기록의 관계입니다. |

실제 수행한 범위와 아직 문헌으로만 공부한 범위를 나누어 기록합니다. 읽은 기술을 모두 자신의 실물 측정 경험으로 적는 것보다, 무엇을 어떤 근거로 판단했는지 보여 주는 편이 자료의 신뢰성을 높입니다.

## English

Read technical work through its product, object, action, constraints, execution environment and evidence. The role guides connect product development, semiconductor design and manufacturing, memory engineering, tests and operations. Published technical sources and illustrative investigations remain distinct from undisclosed implementations and measured results.
