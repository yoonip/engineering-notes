기준 자료는 「2026 상 삼성전자 DS부문 직무기술서」입니다. 아래 쪽수는 표지를 포함한 PDF 순서이며, 모집표는 2–3쪽입니다. 직무 이름이 같아도 사업부와 대상 제품이 다르면 업무가 달라집니다. 특히 S.LSI의 신호및시스템설계는 통신·영상 알고리즘을, AI센터의 같은 직무명은 이 판본에서 IT 보안 아키텍처를 다룹니다.

이 글의 업무 요약과 언어 표시는 해당 JD를 근거로 합니다. 연결한 실무 예제·검사 원리·도구 설명은 별도 학습 내용입니다. 요구 역량, 우대 사항, 권장 과목을 서로 바꾸어 읽지 않습니다.

## 2. 언어가 적혀 있는 위치와 강도를 확인합니다

아래는 JD에 직접 나온 표기를 요약한 것입니다. 여러 언어가 ‘등’과 함께 나열된 문장을 모든 언어의 동시 숙련이 필수라는 뜻으로 바꾸지 않습니다. 분석 도구·시뮬레이터·운영체제는 언어와 별도입니다.

| 직무·쪽 | 원문 구분 | 명시한 언어·도구 범위 | 읽을 때의 의미 |
| --- | --- | --- | --- |
| 메모리 공정기술 7, Foundry 공정기술 32 | Pluses | R·Python 등의 통계 도구입니다. | 공정 결과를 해석하는 데이터 역량의 우대입니다. |

## 3. 검사 이름보다 관측 대상이 먼저입니다

S.LSI 평가및분석 15쪽의 PVT·EFA/PFA·ATE, Foundry 회로설계 22쪽의 silicon validation·물리검증, TSP 49쪽의 패키지·테스트는 모두 ‘검사’와 관련되지만 산출물은 다릅니다.

| 업무 | 실제로 얻는 증거 | 다음 판단 |
| --- | --- | --- |
| RTL 기능 검증 | 주어진 자극에서의 신호·트랜잭션·assertion·coverage입니다. | 설계가 기능 요구를 만족하는지 판단합니다. |
| PDK·물리검증 | 규칙 위반 위치, 회로 연결 대응, 추출한 기생 성분입니다. | 레이아웃·모델·설계 조건을 수정합니다. |
| 실리콘 특성 평가 | 시료와 전압·온도·주파수·패턴에 묶인 측정값입니다. | 모델과 실측의 차이, 동작 여유를 분석합니다. |
| 양산 ATE 검사 | 정해진 한계·패턴에 따른 다이·제품별 결과와 bin입니다. | 출하 선별과 불량 분포를 판단합니다. |
| 고장 분석 | 재현 조건·전기적 위치 후보·물리적 관찰의 연결입니다. | 설계·공정·접속·시험계 중 원인을 좁힙니다. |
| 공정 계측 | 막 두께·CD·overlay·입자·조성 등의 측정 결과입니다. | 공정과 계측 자체의 변화를 구분합니다. |
| 신뢰성 평가 | 스트레스 조건·시간과 전후 특성·고장 자료입니다. | 고장 기구와 제품 사용 조건의 관계를 평가합니다. |

이 표는 JD의 업무를 공부하기 위한 기술 구분입니다. 각 회사 내부의 승인 조직·고객 계약·판정 한계는 이 표에서 추정하지 않습니다. 상세 원리와 출처는 [칩 평가](06-칩설계와평가분석_chip-design-characterization.md), [제조·패키지 검사](07-공정설비와패키지의검사_process-equipment-package-tests.md)에 연결했습니다.

## 4. 이름이 비슷해도 다른 업무

### 공정설계와 공정기술

공정설계는 필요한 소자·통합 구조와 공정 사이의 연결을 정하는 문제를 포함합니다. 공정기술은 단위 공정의 조건·소재·계측·결함과 생산성을 다루는 문제를 포함합니다. 둘은 협업하지만 같은 업무의 다른 번역은 아닙니다. Foundry 공정설계 27–30쪽에는 소자·SRAM·TCAD와 패키지 설계·시뮬레이션까지 들어 있습니다.

### TSP의 공정기술과 전공정의 공정기술

같은 반도체공정기술이라는 이름이라도 TSP 49–51쪽의 대상은 조립·테스트입니다. 연삭·절단·접합·몰딩·솔더볼·SMT·테스트를 다룹니다. 메모리/Foundry의 포토·식각·증착 등만 준비하면 이 차이를 놓치게 됩니다.

### S.LSI와 AI센터의 신호및시스템설계

S.LSI 13쪽은 통신과 영상 알고리즘을 설명합니다. AI센터 55쪽의 Role은 IT 보안 아키텍처·취약점 대응·보안 운영·오픈소스 거버넌스입니다. 이름이나 권장 과목에 AI가 등장한다는 이유로 둘 다 동일한 딥러닝 모델 개발 직무로 묶지 않습니다.

### 평가·분석과 설비기술

칩의 누설 전류가 높다는 측정과 진공 펌프의 상태가 나쁘다는 관측은 다릅니다. 평가·분석은 제품 특성·고장 증거를 다루고, 설비기술은 공정을 수행하는 장치의 상태·성능을 다룹니다. 제품 이상과 장비 로그가 같은 시점에 나타났다면 조건·로트·챔버·계측 이력을 연결해 검증해야 원인 후보가 됩니다.

## 5. 생산·인프라·환경·재무도 다른 기준으로 검사합니다

다음은 JD가 적은 업무를 실제로 이해하기 위한 학습 예입니다. 해당 회사의 내부 지표 정의나 승인 절차를 재현한 것은 아닙니다.

| 대상 | 먼저 익힐 개념 | 대조할 자료의 예 |
| --- | --- | --- |
| 생산관리·SCM | WIP는 공정 안의 재공, cycle time은 들어간 뒤 완료될 때까지의 시간, bottleneck은 전체 처리량을 제한하는 자원입니다. | 제품·route·재작업·설비 가용성·자재 도착과 납기입니다. 모든 설비의 가동률 최대가 전체 납기 최적이라는 뜻은 아닙니다. |
| 건설 | BIM은 건물·설비 정보를 연결하는 모델이며, 공정 관리는 시공 순서·의존 관계·자원·완료 증거를 관리합니다. | 설계 판본·현장 검측·변경 승인·공사 일정입니다. |
| Facility·전기 | 공급 품질과 연속성을 함께 봅니다. 압력·유량·수질·온습도·전원 이상은 서로 다른 계측 대상입니다. | 설비 수요·공급 여유·경보·고장 시각과 공정 영향입니다. [상세 검사](07-공정설비와패키지의검사_process-equipment-package-tests.md#7-fab-인프라는-공급-품질과-연속성을-봅니다)로 이어집니다. |
| 환경 | 측정값, 시설 변경점, 인허가와 기록 보존의 대응을 봅니다. | 배출·폐기물·자원순환 자료의 단위·기간·시설 식별자·원증빙입니다. 개별 법규의 현행 수치·판정은 해당 법령·허가 조건에서 확인해야 합니다. |
| 재무 | 재무회계는 외부 보고 기준, 관리회계는 내부 원가·손익 판단, 자금은 조달·운영·위험 관리와 연결됩니다. | 전표·자산·재고·원가 배부·예산/실적·투자 가정의 일치와 추적성입니다. |

이 업무에 SQL·Python을 적용하는 학습 예를 만들 수는 있지만, 이 JD의 건설·환경·재무 직무가 특정 언어를 필수로 요구한다고 쓰지는 않습니다. 계산의 목적과 원자료를 설명할 수 있어야 도구 사용도 업무 역량으로 연결됩니다.

## 6. 학습 결과를 업무의 증거로 연결합니다

다음 순서로 한 주제를 설명하시면 과목명과 실무가 이어집니다.

1. 대상과 요구를 정합니다. 예를 들어 ‘IP가 특정 전압·온도·주파수에서 읽기·쓰기를 수행해야 한다’고 적습니다.
2. 자극과 관측을 나눕니다. 펌웨어의 패턴·설정, 장비의 전원·파형, 호스트의 수집·분석을 구분합니다.
3. 고장 후보를 나눕니다. 설계·공정·패키지·보드·시험 프로그램이 같은 실패를 만들 수 있습니다.
4. 정상 대조와 조건별 결과를 보존합니다. 성공한 재시험만 남기면 간헐 실패의 정보를 잃습니다.
5. 조치 뒤 같은 기준으로 재평가하고 남은 범위를 적습니다.

[실무 계측 자료](../현장계측과검증_measurement-validation/README.md), [반도체 제조 공정](../반도체제조공정_semiconductor-fabrication/README.md), [설계·검증 사례](../설계와검증사례_engineering-cases/README.md)를 이 순서로 연결해 읽으실 수 있습니다. 코드 저장소에 공부한 내용을 적을 때에도 실제 수행한 측정·호스트 모델·문헌 조사를 구분합니다.
