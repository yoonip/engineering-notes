# 메모리 제품과 테스트 개발 | Memory product and test engineering

[직무·실무 목차](README.md) · [메모리 제품·양산 직무](03-메모리제품과양산의직무_memory-product-production-roles.md) · [칩 설계·평가](06-칩설계와평가분석_chip-design-characterization.md) · [C·Python의 위치](10-C와Python이쓰이는위치_languages-in-the-workflow.md) · [공개 메모리 검사 코드 사례](사례_cases/03-칩과메모리의공개검사코드_chip-memory-test.md)

메모리 테스트는 값을 쓰고 다시 읽는 한 동작보다 넓습니다. 무엇을 검사하는지, 어떤 조건으로 자극하는지, 기대값을 누가 만드는지, 실패를 어느 물리 구조와 연결하는지에 따라 직무와 프로그램의 역할이 달라집니다.

메모리 제품의 검사는 소자·회로의 특성, 웨이퍼·패키지의 선별, 컨트롤러·펌웨어와 호스트의 동작, 고객 사용 조건까지 이어집니다. 검사 위치마다 자극·관측값·시간·판정 범위가 다릅니다. 아래 원리와 사례는 공개 기술 자료를 연결한 학습 설명이며 특정 제품의 비공개 프로그램·장비 조건을 재현한 것이 아닙니다.

## 1. 비슷해 보이는 직무가 다른 결과물을 만듭니다

| 직무 | 중심 질문 | 대표 산출물의 학습 예 |
| --- | --- | --- |
| 회로 설계·검증 | 설계가 요구한 계산·시간·초기화 동작을 만드는지 확인합니다. | 참조 모델, RTL 시나리오, 파형과 coverage입니다. |
| 소자·특성 분석 | 전압·온도·공정 변화가 소자·셀의 전기적 특성에 미치는 영향을 확인합니다. | 전류·누설·문턱전압·감지 여유의 분포와 모델입니다. |
| Product Engineering | 제품 사양과 개발·양산 조건을 만족하는 시험 방법을 만듭니다. | 테스트 항목·프로그램·판정 한계·특성 평가·불량 분석입니다. |
| 양산기술(P&T) | 많은 제품을 일정한 품질·수율·처리량으로 검사·조립합니다. | 조건·장비·재료·시험 시간·수율의 관리 기록입니다. |
| Solution SW/HW | SSD 등의 완제품이 호스트·보드·펌웨어·열 조건에서 동작하는지 확인합니다. | 프로토콜·데이터 무결성·성능·전원·인터페이스 검증입니다. |
| 품질보증 | 제품 인증부터 양산·출하·고객 사용까지 필요한 품질 근거를 확인합니다. | 인증·변경 관리, 출하 검사와 고객 불량 조사입니다. |

예를 들어 ‘고온에서 특정 주소를 읽으면 틀립니다’라는 증상은 셀의 저장 특성, 접촉 문제, 주소 변환, 펌웨어, 타이밍 중 여러 곳에서 생길 수 있습니다. 테스트 담당자가 오류를 발견하고, 제품·소자·설계·패키지 담당자가 각각의 증거를 연결하는 구조로 이해하시면 좋습니다.

## 2. 웨이퍼·패키지·모듈·보드는 서로 다른 시험 대상입니다

| 대상·시험 위치 | 자극·관측의 예 | 이 단계에서 새로 보이는 문제 |
| --- | --- | --- |
| 웨이퍼 다이 | 프로브를 통해 전원·패턴을 인가하고 셀·소자·연결을 검사합니다. | 제조된 다이의 특성과 접촉 상태입니다. |
| 패키지 메모리 | 외부 단자로 접근하여 셀 동작·속도·온도 조건을 검사합니다. | 조립 이후의 접속·기생 성분·열 영향입니다. |
| HBM 적층체 | 다이 사이 경로와 스택 상태에서 기능·속도 등을 검사합니다. | TSV 노출·접합·적층 뒤의 변화입니다. |
| 메모리 모듈 | 여러 패키지와 보드·전원·인터페이스의 조합을 봅니다. | 실장·배선·부품 조합·설정 차이입니다. |
| 호스트·완제품 시스템 | CPU/컨트롤러·펌웨어·드라이버·OS·부하를 함께 봅니다. | 상호운용·부팅·리셋·장시간 부하·고객 조건입니다. |

Advantest는 웨이퍼 시험과 패키지 이후 최종 시험을 구분하고, 2023년 메모리 기술 발표에서는 HBM 적층 후 추가 시험 위치를 설명합니다. 이 발표의 당시 속도·병렬 검사 개수를 모든 현재 제품의 사양으로 옮기지는 않습니다. [공식 시험 개요](https://www.advantest.com/en/about/business/), [Memory Semiconductor Test Flow, PDF 12·16쪽](https://www.advantest.com/document/en/investors/ir-library/briefing/E_IR_technical_briefing_231129.pdf#page=12)

ATE는 자동 시험 장비, prober는 웨이퍼 위치·접촉·온도 등을 관리하는 장비입니다. 검사 프로그램은 장비의 자극·계측 자원을 설정하지만 빠른 신호의 각 에지를 일반 PC의 Python 반복문으로 직접 만드는 것은 아닙니다. 신호 생성·샘플링은 지원되는 테스터·계측 하드웨어가 맡고, PC 프로그램은 조건 설정·실행·데이터 수집·분석을 맡을 수 있습니다. [웨이퍼 검사 본문](../반도체제조공정_semiconductor-fabrication/07-웨이퍼검사와수율_eds-yield.md)에서 장비 역할을 이어서 설명합니다.

## 3. DRAM에서는 어떤 오류를 검사하나요

DRAM의 셀은 접근 트랜지스터와 저장 커패시터로 설명할 수 있습니다. 실제 제조 단면은 [DRAM·3D NAND](../반도체제조공정_semiconductor-fabrication/13-DRAM과3DNAND의공정단면_dram-3d-nand-integration.md)를 먼저 보시면 좋습니다.

| 검사 관점 | 입력·조건 | 관측과 구분할 오류 |
| --- | --- | --- |
| 저장·읽기 기본 동작 | 주소별 데이터와 읽기·쓰기 순서를 바꿉니다. | 기대한 값과 실제 값의 차이, 오류 주소·비트·순서입니다. |
| 주소 구별 | 서로 다른 주소에 다른 자료를 씁니다. | 주소 디코드·별칭·연결 문제로 서로 다른 위치가 같은 것처럼 동작하는 경우입니다. |
| 자료 패턴의 영향 | 0/1, 번갈아 나타나는 비트, 주소에 따른 값 등 패턴을 바꿉니다. | 자료 의존성·이웃 상태·변경 방향에 따라 달라지는 실패입니다. |
| 명령 타이밍 | 행 열기·읽기·쓰기·닫기·refresh의 간격을 바꿉니다. | 결과가 맞는 경우에도 허용 명령 간격을 어긴 것은 아닌지 별도로 봅니다. |
| 유지 특성 | 관리된 refresh·온도·대기 조건에서 저장 상태를 평가합니다. | 특정 셀·영역에서 저장 상태가 더 빨리 달라지는지입니다. |
| 속도·전압 여유 | 주파수·타이밍·전압 등의 조건을 바꿉니다. | 통과 영역과 실패 영역의 경계, 조건별 분포입니다. |

PassMark의 MemTest86 문서는 주소 패턴·moving inversions·bit-fade 등 호스트 메모리 시험의 목적과 cache·버퍼 영향의 한계를 설명합니다. moving inversions는 한 패턴을 기록한 뒤 순서대로 확인·반전하고 반대 방향으로 반복하는 방식입니다. 이 원리는 패턴을 바꾸는 이유를 이해하는 데 도움이 되지만, 상용 테스터의 셀별 생산 시험과 동일한 coverage를 뜻하지는 않습니다. [공식 알고리즘 설명](https://www.memtest86.com/tech_memtest-algoritm.html), [개별 시험 설명](https://www.memtest86.com/tech_individual-test-descr.html)

호스트 프로그램에서 잠시 기다렸다는 사실만으로 DRAM refresh를 멈췄다고 할 수는 없습니다. CPU cache·메모리 컨트롤러·백그라운드 접근도 경로에 들어갑니다. 어떤 계층을 실제로 제어했는지 확인해야 유지 시험을 해석할 수 있습니다. 값 비교와 명령 간격의 차이는 [기존 DDR 검사 사례](../설계와검증사례_engineering-cases/DDR명령간격과메모리패턴_ddr-command-pattern-checks.md)에서 학습 모형으로 다룹니다.

### 자료 한 비트가 틀렸을 때 바로 원인을 정하지 않습니다

설명용 가정으로 기대값이 `0x5A`, 관측값이 `0x5B`라고 하겠습니다. 둘을 XOR하면 `0x01`이므로 이 관측에서는 최하위 비트 하나가 다릅니다. 그러나 이것만으로 ‘해당 DRAM 셀 하나가 고장 났습니다’라고 확정할 수는 없습니다.

오류가 같은 주소나 자료선·접촉 site에서 반복되는지 확인합니다. 주파수·전압·온도를 바꾸었을 때와 다른 프로그램·보드에서도 같은 현상이 나타나는지 비교합니다. 원인 후보를 좁히는 관측과 고장을 확정하는 증거를 구분해야 합니다.

## 4. NAND 셀 검사와 SSD 검사는 다릅니다

NAND 셀은 전하 저장에 따라 달라지는 문턱전압을 이용합니다. 셀을 지우고 프로그램하고 읽는 특성과, SSD가 호스트의 논리 주소로 데이터를 보관하는 특성은 다른 계층입니다.

| 계층 | 검사하는 것 | 프로그램이 처리하는 자료 |
| --- | --- | --- |
| NAND 소자·배열 | 프로그램/소거·읽기 분포, 유지·반복 사용·disturb와 불량 위치입니다. | 셀·블록·페이지·조건별 오류와 분포입니다. |
| 컨트롤러·펌웨어 | 주소 변환·불량 관리·오류 처리·복구·동시성입니다. | 명령·상태·매핑·세대·복구 로그입니다. |
| NVMe 인터페이스 | 호스트 명령·응답·상태·리셋·기능 지원의 계약입니다. | 명령 ID·큐·응답·상태 값과 이벤트 순서입니다. |
| SSD 완제품 | 데이터 무결성·지연·처리량·전원·열·호스트 조합입니다. | 읽은 내용·검사값, I/O 분포, 온도·전원·실행 이력입니다. |

NVM Express는 기본 규격, 명령 집합, 전송 규격을 별도 문서로 나눕니다. 따라서 ‘NVMe 시험’에서도 어떤 판본·명령 집합·전송·선택 기능을 시험하는지 적어야 합니다. [공식 규격 구성](https://nvmexpress.org/specifications/)을 확인한 범위이며 이 글이 전체 규격의 모든 적합성 항목을 대신하지는 않습니다.

UNH-IOL은 NVMe 적합성 시험 계획을 공개합니다. 적합성은 규격에 따른 동작을, 상호운용은 다른 제품과의 조합을 평가합니다. 처리량 그래프만으로 둘을 확인했다고 할 수 없습니다. [대학 연구소의 NVMe 시험 계획](https://www.iol.unh.edu/testing/storage/nvme/test-plans)

### 전원·리셋 뒤에는 ‘다시 켜진다’와 ‘내용이 맞다’를 나눕니다

가상의 SSD 쓰기 시험을 생각해 보겠습니다. 기록할 내용, 완료 응답을 받은 명령, 영속성에 관한 조건을 먼저 정합니다. 이후 리셋·오류 주입 뒤에 장치를 다시 발견하는 것과 저장 내용을 확인하는 것을 별도 항목으로 둡니다. 응답을 받기 전의 쓰기까지 무조건 남아 있어야 한다고 정하거나, 응답을 받았다는 이유만으로 모든 조건의 영속성을 보장한다고 정하면 시험 계약이 잘못될 수 있습니다.

FTL은 호스트의 논리 주소와 내부 저장 위치를 연결하는 계층입니다. 기존 [FTL 매핑·중단 사례](../설계와검증사례_engineering-cases/FTL의매핑게시와전원중단_ftl-map-publication.md)는 데이터와 주소표의 갱신 순서를 파일 모형으로 비교합니다. 실제 SSD에 전원을 끊어 얻은 결과와 구분하여 읽으셔야 합니다.

## 5. 성능 시험에서는 부하 조건을 함께 저장합니다

IOPS는 초당 I/O 수, bandwidth는 초당 전송한 자료량, latency는 요청부터 정한 완료 지점까지의 시간입니다. 평균 지연이 같아도 드물게 오래 걸리는 요청의 비율은 다를 수 있습니다. p99는 관측 지연의 99%가 그 값 이하에 놓이는 지점이며 ‘모든 요청의 최대 지연’은 아닙니다.

| 기록할 조건 | 필요한 이유 |
| --- | --- |
| 읽기·쓰기 비율과 순차·임의 접근 | 서로 다른 내부 작업·cache·주소 분포를 만듭니다. |
| I/O 크기·큐 깊이·작업 수 | 병렬 요청 수와 명령 처리 비용을 바꿉니다. |
| 호스트·인터페이스·드라이버·펌웨어 판본 | 같은 장치라도 전체 경로의 병목이 바뀝니다. |
| cache·direct I/O·동기화·시험 영역 | 어디까지의 데이터 경로를 측정하는지 바꿉니다. |
| 초기 상태·예열·시험 시간·온도 | 일시적인 상태와 지속 동작을 구분합니다. |
| 오류·누락·재시도·관측 요청 수 | 빠른 실패를 빠른 정상 응답으로 잘못 집계하는 일을 막습니다. |

fio는 workload를 정의하고 I/O와 지연 분포를 측정하는 공개 도구입니다. 부하 정의·오류 처리·백분위수의 구체적인 항목은 [fio 3.42 공식 문서](https://fio.readthedocs.io/en/latest/fio_doc.html)에서 확인할 수 있습니다.

설명용으로 I/O 크기 4 KiB, 초당 완료한 정상 I/O 100,000개를 가정하면 자료량은 `4,096 × 100,000 = 409,600,000 B/s`입니다. 이는 409.6 MB/s 또는 390.625 MiB/s입니다. 이 단순 계산은 메타데이터·전송 오버헤드·실제 측정 결과를 포함하지 않습니다. 단위를 바꾸지 않고 서로 다른 그래프를 비교하면 같은 결과도 다르게 보일 수 있습니다.

| 위치 | 사용할 수 있는 언어·도구 | 구체적으로 하는 일 | 확인해야 할 경계 |
| --- | --- | --- | --- |
| SSD·컨트롤러 내부 펌웨어 | C/C++·필요한 Assembly 등 타깃 환경의 언어를 사용합니다. | 명령·메모리·버퍼·인터럽트·상태 전이를 구현하고 오류를 처리합니다. | 타깃 자원·동시성·시간 제한과 하드웨어 계약을 맞춰야 합니다. |
| 칩 설계의 기대값 모델 | C/C++ 등으로 모델을 만들고 시뮬레이터와 연결할 수 있습니다. | 연산·패킷·주소 변환의 기대 결과를 계산하여 RTL 결과와 대조합니다. | 계산의 일치와 사이클·리셋·프로토콜의 적합성은 다릅니다. |
| 시험 장비 프로그램 | 장비가 제공하는 SDK·언어·편집 환경을 따릅니다. | 핀·전원·패턴·계측·bin 판정을 구성합니다. | 테스터가 모두 같은 C++ API를 제공한다고 가정하지 않습니다. |
| 호스트 시험 러너 | Python·shell·지원 SDK 등의 교육용 예입니다. | 조건 목록을 반복하고 장비·타깃을 실행하며 로그를 수집합니다. | 실제 고속 에지를 Python 반복문의 속도로 제어하는 것은 아닙니다. |
| 대량 결과 분석 | Python·SQL 등을 쓸 수 있습니다. | 제품·시험·조건 ID로 자료를 묶고 분포·오류·상관관계를 비교합니다. | 데이터 단위·재시험·누락과 분모를 먼저 맞춰야 합니다. |

언어·라이브러리는 타깃 자원, 시험 장비의 API, 실행 시간과 기존 도구에 맞추어 선택합니다. Python이 유용한 이유는 ‘쉽기 때문’만이 아니라 많은 조건의 실행과 구조화된 로그 처리를 연결하기 편하기 때문입니다. 반대로 타깃의 메모리 접근·인터럽트·제어 경로는 타깃 언어와 하드웨어 계약의 이해가 필요합니다.

공개 [nvme-cli](https://github.com/linux-nvme/nvme-cli)는 호스트에서 NVMe 장치를 관리하는 명령행 도구의 예입니다. 이런 호스트 도구를 호출하는 스크립트, 도구 자체의 구현, SSD 안의 펌웨어는 서로 다른 프로그램입니다. 회사가 이 도구를 실제로 채택했다는 뜻으로 연결하지 않습니다.

## 7. 불량 분석은 전기적 증거와 물리적 증거를 잇습니다

| 관측 | 처음 할 비교 | 다음 조사로 넘길 근거 |
| --- | --- | --- |
| 특정 주소·비트 오류 | 패턴·시간·온도·전압·보드·site를 분리합니다. | 반복되는 논리 위치와 조건, 정상 대조 자료입니다. |
| 높은 접촉 저항 | probe·pad·위치·청소 전후를 비교합니다. | 접촉 문제와 실제 die 고장을 나눈 결과입니다. |
| 특정 다이 경계 오류 | 적층 전/후의 결과와 정렬·접합 관측을 비교합니다. | TSV 내부와 다이 사이 접합을 구분할 위치 정보입니다. |
| 리셋 후 잘못된 자료 | 완료 응답·저장 계약·주소 변환·복구 로그를 맞춥니다. | 소자 불량인지 펌웨어/메타데이터 순서 문제인지 나눌 기록입니다. |

전기적 분석은 실패 조건·경로를 좁히고, 물리적 분석은 해당 위치의 형상·재료·계면을 살핍니다. FIB는 국소 가공·시료 준비 등에, SEM/TEM은 서로 다른 해상도·시료 조건의 관찰에 사용됩니다. 관찰된 결함이 실제 전기적 실패와 연결되는지도 따로 확인해야 합니다. [Thermo Fisher의 전기·물리 불량 분석과 방법 분류](https://www.thermofisher.com/us/en/home/semiconductors/defect-localization.html)

불량 비율 하나만 줄었다고 개선을 확정하지 않습니다. 같은 제품 집합인지, 최초 시험과 재시험을 섞지 않았는지, 검사에서 놓친 불량이나 정상품 오판이 늘지 않았는지를 확인합니다. 예제는 [시험 ID·오판율](../설계와검증사례_engineering-cases/시험데이터의식별자와오판율_test-data-identity-metrics.md), 기록 항목은 [검사결과 판정과 기록](11-검사결과의판정과기록_test-decisions-evidence.md)에 연결했습니다.

## English

Memory testing spans design models, device characterization, production ATE and complete storage systems. This chapter separates wafer, package, stack, module and host-level evidence, then connects data patterns, timing, retention, protocols, persistence and workload-dependent performance to their software roles. C/C++ target firmware, reference models, equipment programs and Python/SQL analysis serve different layers. All numerical examples are stated assumptions rather than measured product results.
