# 반도체 설계·제조의 업무와 검증 | Semiconductor design and manufacturing roles

[직무 목차](README.md) · [전자제품·시스템](01-전자제품과시스템개발의직무_product-system-roles.md) · [메모리 제품·양산](03-메모리제품과양산의직무_memory-product-production-roles.md) · [칩 설계·평가](06-칩설계와평가분석_chip-design-characterization.md) · [공정·설비·패키지 검사](07-공정설비와패키지의검사_process-equipment-package-tests.md)

반도체 산업에는 회로와 시스템을 설계하는 업무, 소자·공정을 개발하는 업무, 장비·제조·검사·고객 적용을 다루는 업무가 연결됩니다. 같은 직무 이름도 제품·공정·개발 단계에 따라 뜻이 달라집니다. 아래에서는 회사의 조직명 대신 무엇을 설계하고 어떤 증거로 결과를 판단하는지 구분합니다.

## 1. 설계에서 제품으로 이어지는 인계

| 단계 | 입력 | 만드는 결과 | 다음 단계에서 확인할 내용 |
| --- | --- | --- | --- |
| 제품·아키텍처 | 기능·성능·전력·가격·사용 환경과 인터페이스 요구입니다. | 기능 분할·데이터 경로·메모리·입출력·목표 조건입니다. | 하위 설계의 역할·예산·호환·검증 가능성입니다. |
| 회로·RTL | 블록 요구·모델·라이브러리·설계 규칙입니다. | 회로·RTL·제약·기준 모델·시험입니다. | 기능·타이밍·전력과 인터페이스의 일치입니다. |
| 물리 구현 | 논리 설계·셀/배선 정보·클록·전원·제약입니다. | 배치·배선·추출·물리/타이밍 보고서입니다. | 제조 규칙·연결·타이밍·전원/신호 조건입니다. |
| 소자·공정·제조 | 소자 목표·공정 통합·단위 공정·장비 조건입니다. | 웨이퍼·소자 모델·계측·공정/설비 이력입니다. | 실제 분포와 모델, 결함·수율·공정 간 상호작용입니다. |
| 패키지·테스트 | 웨이퍼·다이·기판·접속·검사 요구입니다. | 조립 제품·시험 프로그램·결과·이력입니다. | 접속·열·기계·제품 동작·시험계 조건입니다. |
| 제품 적용·품질 | 사용 조건·고객 시스템·생산·반환품의 정보입니다. | 인증/특성 근거·고장 조사·변경·지원 자료입니다. | 재현 조건·원인·제품 사용 범위·조치 후 결과입니다. |

한 조직이 여러 단계를 맡을 수도 있고 공급사와 고객이 나누어 맡을 수도 있습니다. IDM·팹리스·파운드리·패키지/테스트 전문 업체의 관계는 [반도체 산업과 직무](13-반도체산업과직무의연결_semiconductor-value-chain.md)에서 이어집니다.

## 2. 회로·시스템·알고리즘 설계

| 세부 업무 | 설계 대상 | 구현·검증에서 다룰 내용 | 대표 결과물 |
| --- | --- | --- | --- |
| 디지털 IP·SoC | 프로세서 주변 블록·버스·메모리·데이터 경로·제어입니다. | 자료 폭·부호·클록·리셋·핸드셰이크·지연·처리량입니다. | RTL·명세·assertion·testbench·coverage입니다. |
| 아날로그·혼성신호 | 증폭·전원·클록·ADC/DAC·센서 인터페이스입니다. | 동작점·잡음·대역·선형성·오프셋·PVT·레이아웃 영향입니다. | 회로·시뮬레이션·특성표·레이아웃과 측정 대조입니다. |
| RF·통신 | RFIC·동기·변복조·채널 추정·부호화 등의 기능입니다. | 파형·SNR·주파수/시간 오차·수치 정밀도·관련 규격입니다. | 기준 모델·벡터·성능 곡선·구현과의 오차입니다. |
| 영상·센서 처리 | 이미지 센서·ISP·영상 전처리·인식 관련 기능입니다. | 입력 패턴·좌표·bit 깊이·색/채널·처리 지연입니다. | 알고리즘·입출력 형식·기준 영상·화질/오차 평가입니다. |
| 라이브러리·메모리·인터페이스 IP | 셀·SRAM 등 매크로·I/O·연결 블록입니다. | PVT·타이밍·전력·접속·모델·사용 제약입니다. | 특성화 자료·모델·설계/검증 뷰·실리콘 비교입니다. |
| 보안 IP | 난수원·암호 계산·키/접근 관리·메모리 보호입니다. | 기능·기준 벡터·권한·오류와 별도의 구현 공격 내성입니다. | 요구·벡터 결과·접근 차단·평가 범위입니다. |

PVT는 process·voltage·temperature, 공정 편차·전압·온도의 조건입니다. 같은 설계라도 동작 속도·전력·누설 등이 조건에 따라 달라지므로 하나의 대표 결과만 보지 않습니다. 디지털 기능, 아날로그 특성, 실리콘 측정은 [칩 설계와 평가](06-칩설계와평가분석_chip-design-characterization.md)에서 각각 구분합니다.

시스템 설계도 대상에 따라 제품 아키텍처·통신 및 영상 처리·IT 서비스 구조로 나뉩니다. 각 업무의 입력·출력·제약과 결과물을 먼저 확인합니다.

## 3. RTL·물리 구현·설계 지원

| 업무 | 무엇을 바꾸는지 | 확인할 결과 |
| --- | --- | --- |
| 기능 검증 | 입력 자극·시나리오·monitor·scoreboard·assertion을 만듭니다. | 요구와 구현의 일치, 예상한/예상하지 못한 상태와 coverage입니다. |
| 합성·배치·배선 | 논리와 물리 자원을 제약 아래 연결합니다. | 면적·전력·클록·혼잡·배선·타이밍과 구현 판본입니다. |
| 정적 타이밍 분석 STA | 클록·입출력·경로·예외와 지연 모델을 설정합니다. | setup·hold와 경로별 여유, 제약의 타당성입니다. |
| DRC·LVS·추출 | 제조 규칙·회로 연결·레이아웃의 기생 성분을 검사합니다. | 규칙 위반 위치·연결 불일치·추출 모델과 설계 영향입니다. |
| PDK·CAD 방법론 | 설계 규칙·소자/배선 모델·검증 도구·자동화 흐름을 연결합니다. | 판본·호환성·기준 설계·회귀 시험·재현 가능한 실행입니다. |
| DFT·양산 검사 준비 | 내부 상태의 제어·관측을 위한 구조와 패턴을 설계합니다. | scan·ATPG·BIST의 대상·패턴·고장 모델·검출 범위입니다. |

PDK는 process design kit, 특정 제조 공정에 맞춰 설계하는 데 필요한 모델·규칙·관련 자료의 묶음입니다. DRC는 layout이 제조 규칙을 지키는지, LVS는 추출한 연결이 회로도와 맞는지 확인합니다. 이 둘의 통과가 모든 기능·성능·수율을 보장하는 것은 아닙니다. [SkyWater SKY130 PDK 공식 문서](https://skywater-pdk.readthedocs.io/en/main/)의 모델·레이어·규칙·LVS 자료가 공개된 예입니다.

[OpenROAD Flow 공식 개요](https://openroad-flow-scripts.readthedocs.io/en/latest/mainREADME.html)는 RTL·제약·라이브러리 입력에서 합성·floorplan·배치·클록·배선·마무리 검사로 이어지는 흐름을 보여 줍니다. 공개 흐름의 단계 관계를 읽는 근거이며, 특정 제조사의 내부 sign-off 흐름과 동일하다는 뜻은 아닙니다.

STA의 setup은 캡처 에지 전에 데이터가 충분히 일찍 도착해야 하는 조건이고, hold는 그 에지 뒤 필요한 시간 동안 유지되어야 하는 조건입니다. 느린 경로뿐 아니라 너무 빠른 경로도 문제가 됩니다. [STA 기초](../전자컴퓨터공학_ece/15-FPGA-ASIC설계_fpga-asic/해설_notes/너무늦어도너무빨라도문제다_setup-hold-static-timing.md)와 [하드웨어 검증](../전자컴퓨터공학_ece/14-하드웨어검증_hardware-verification/README.md)이 이 차이를 설명합니다.

## 4. 소자·공정설계·단위 공정·설비

| 업무군 | 직접 다루는 대상 | 관측과 결과물 |
| --- | --- | --- |
| 소자·모델 | 트랜지스터·센서·메모리 셀 등의 구조·재료·전기 특성입니다. | I–V/C–V·변동·신뢰성·모델과 측정의 차이입니다. |
| 공정 통합·설계 | 필요한 소자를 구현하는 공정 순서와 구조·조건의 연결입니다. | 단면·설계 규칙·소자/배선 특성·공정 간 영향입니다. |
| 단위 공정 | 포토·식각·증착·이온주입·세정·CMP 등입니다. | CD·overlay·막 두께·균일도·선택비·입자·결함과 생산성입니다. |
| 계측·분석 | 공정 결과의 형상·조성·표면·결함을 측정합니다. | 측정계의 반복성·시료 준비·위치·불확도·분석 근거입니다. |
| 설비·장치 | 진공·가스·열·플라즈마·센서·로봇·제어와 부품입니다. | 상태·교정·정비·경보·공정 결과와 연결한 이력입니다. |
| 패키지 통합 | 다이·기판·접속·소재·열·기계 구조와 조립입니다. | 연삭·절단·접합·몰딩·실장·적층의 품질과 제품 특성입니다. |

TCAD는 소자·공정의 물리적 거동을 수치 모델로 해석하는 도구군입니다. 측정과 모델의 관계를 맞추는 교정도 필요합니다. [Synopsys TCAD의 공식 설명](https://www.synopsys.com/manufacturing/tcad.html)은 공정·소자 시뮬레이션과 모델 교정의 범위를 구분합니다. 모델 해가 있다는 사실과 실제 공정에서 그 분포가 만들어졌다는 사실은 다릅니다.

공정설계와 공정기술은 협업하지만 같은 업무의 다른 번역으로 고정할 수는 없습니다. 앞의 분류에서는 소자·통합 구조를 정하는 일과 단위 공정의 조건·재료·계측을 다루는 일을 구분했습니다. 제품·기업의 실제 분업에 따라 업무가 겹칠 수 있습니다. [제조 공정](../반도체제조공정_semiconductor-fabrication/README.md)과 [공정·설비 검사](07-공정설비와패키지의검사_process-equipment-package-tests.md)에서 세부 기술로 이어집니다.

## 5. 특성 평가·양산 선별·고장 분석

| 업무 | 얻는 증거 | 다른 업무와 구분할 점 |
| --- | --- | --- |
| 실리콘 특성 평가 | 시료·전압·온도·주파수·패턴에 연결된 값과 분포입니다. | 모델과 실측의 차이·동작 여유를 조사합니다. |
| ATE 제품 검사 | 패턴·판정 한계·측정 조건에 따른 제품별 결과와 bin입니다. | 반복 선별의 시험 시간·검출 범위·오판정도 고려합니다. |
| EFA·PFA | 전기적 위치 후보와 물리적 관찰을 연결합니다. | 증상·위치 후보·손상 현상·근본 원인을 같은 말로 쓰지 않습니다. |
| 신뢰성 평가 | 스트레스·시간·시료의 전후 특성과 고장 자료입니다. | 가속 시험의 조건·고장 기구와 실제 사용 조건을 연결합니다. |
| 고객·시스템 검증 | 보드·전원·인터페이스·펌웨어·환경에서의 제품 동작입니다. | 부품 단독 시험과 고객 시스템의 조건은 다를 수 있습니다. |

ATE는 automatic test equipment, 자동 시험 장비입니다. EFA는 electrical failure analysis, 전기적 고장 분석이며 PFA는 physical failure analysis, 물리적 고장 분석입니다. 예를 들어 부하에서만 동작이 실패하면 칩뿐 아니라 전원 강하·접속·온도·시험 패턴·판정 시점을 원인 후보로 나눕니다. 이는 고장 조사의 학습 예이며 특정 제품의 불량 기록은 아닙니다.

요구·자극·관측·판정·원인 후보를 실제 코드와 연결하는 읽기는 [칩·메모리 공개 검사 사례](사례_cases/03-칩과메모리의공개검사코드_chip-memory-test.md)로 이어집니다. 실리콘 측정·호스트 계산·RTL 시뮬레이션의 결과는 각각 구분합니다.

## 6. 언어가 필요한 위치

| 위치·업무 | 언어·도구의 역할 | 확인할 결과 |
| --- | --- | --- |
| RTL·testbench | Verilog·SystemVerilog 등으로 하드웨어 동작과 시험을 표현합니다. | 클록·리셋·병렬 동작·폭/부호·자극·기대값입니다. |
| 기준 모델·구동 | C/C++ 등이 계산 모델·펌웨어·시스템 시험에 쓰일 수 있습니다. | 참조 결과·대상 장치 상태·메모리·시간 경계입니다. |
| EDA 흐름 | Tcl·Python 등으로 도구 실행·설정·보고서 처리를 연결합니다. | 제약·도구/라이브러리 판본·실행·오류/경고·결과입니다. |
| 계측·데이터 | Python·통계 도구·SQL 등이 장비 제어·분석·질의를 맡습니다. | 원시값·단위·조건·분모·판정·추적 가능한 변환입니다. |
| 모델·해석 | 회로·전자기·열·구조·소자 시뮬레이터를 사용합니다. | 경계·재료/소자 모델·수렴·실측과의 오차입니다. |

C 기준 모델이 계산의 기대값을 만들고 RTL 시뮬레이션이 클록별 신호를 다룰 수 있습니다. 알고리즘 결과가 같다는 것과 리셋·버스·지연 규칙이 맞는 것은 서로 다른 검사입니다. 언어·시뮬레이터·분석 도구를 채용 요건 하나로 합치지 않고 [실행 위치와 데이터 흐름](10-C와Python이쓰이는위치_languages-in-the-workflow.md)으로 읽습니다.

## 7. 생산·시설·IT·사업의 연결

| 업무군 | 다루는 대상 | 기술 조직과 공유할 결과 |
| --- | --- | --- |
| 생산관리·SCM | 재공 WIP·진도·생산능력·자재·샘플·납기입니다. | 제품·route·재작업·설비 가용성·공급 조건입니다. |
| 공장 인프라 | 전력·공조·초순수·가스·배기·시설입니다. | 수요·공급 품질·고장 시각·계측·정비·공정 영향입니다. |
| 건설·설계 데이터 | 공간·설비·배관·시공 순서·변경입니다. | BIM 판본·실제 설치·설비 ID·공사/검측·인계 자료입니다. |
| 제조 IT·AI | 공정·설비·시험 자료와 업무 시스템·분석 모델입니다. | 키·시간·자료 품질·평가 분리·서비스/설비 연계입니다. |
| 보안·SW 품질 | 자산·권한·네트워크·서버·코드와 배포입니다. | 접근·취약점·구성·오픈소스 조건·변경/복구입니다. |
| 환경·안전·보건 | 배출·자원·화학물질·작업 위험과 노출입니다. | 대상·단위·기간·시설 식별·기준·변경·측정 이력입니다. |
| 원가·재무·제품 기획 | 재고·원가·투자·제품 목표와 사업성입니다. | 원증빙·배부 기준·기간·가정·목표/실제·고객 요구입니다. |

Cycle time은 투입부터 완료까지의 시간이고 bottleneck은 전체 처리량을 제한하는 자원입니다. 모든 설비의 가동률을 각각 최대화한다고 제품의 전체 납기가 최적이 되는 것은 아닙니다. 자료의 단위·기간·제품 경로가 맞아야 생산·비용·품질을 같은 기준으로 비교할 수 있습니다.

## 8. 한 업무를 기록하는 순서

1. 제품·블록·공정·설비 중 직접 바꿀 대상을 정합니다.
2. 입력·환경·기대한 결과·허용 범위를 적습니다.
3. 자극을 만드는 코드, 관측 장비, 데이터를 수집·분석하는 프로그램을 나눕니다.
4. 설계·공정·패키지·보드·시험계의 원인 후보를 대조합니다.
5. 정상 대조·실패·경계·변경 판본을 남기고 같은 기준으로 재평가합니다.

기록은 [검사 판정과 근거](11-검사결과의판정과기록_test-decisions-evidence.md), 장비는 [현장 계측](../현장계측과검증_measurement-validation/README.md), 실제 실행 범위가 있는 예제는 [설계·검증 사례](../설계와검증사례_engineering-cases/README.md)에 연결합니다.
