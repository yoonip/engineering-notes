# AI 추론 평가의 범위 | AI inference evaluation in October 2026

기준일은 2026-10-19입니다. AI 추론 시스템을 비교할 때에는 모델이 토큰을 생성하는 속도와 서비스가 요청 전체를 처리하는 능력을 함께 살펴봐야 합니다. 검색과 도구 호출이 포함되면 생성기 하나의 처리량만으로 전체 응답을 설명하기 어렵습니다.

## 공식 발표에서 확인한 변화

MLCommons는 2026-09-17의 [MLPerf Inference v6.1 분석](https://mlcommons.org/2026/09/chairs-mlperf-inference-v6-1/)에서 End-to-End RAG와 Agentic Edge Inference를 새로운 평가 대상으로 소개했습니다. 기존 모델의 Interactive 시나리오에도 변경이 있습니다. 이는 모든 모델에 같은 작업을 추가했다는 뜻이 아니므로, 모델별 지원 시나리오와 해당 회차의 규칙을 확인해야 합니다.

[Datacenter 결과 안내](https://mlcommons.org/benchmarks/inference-datacenter/)와 [공식 규칙](https://github.com/mlcommons/inference_policies/blob/master/inference_rules.adoc)은 시나리오, 품질 조건, 성능 지표를 함께 정의합니다. 전력을 비교할 때에도 칩의 TDP 표기와 실제 시스템의 전력 측정을 구분해야 합니다.

## 이 변화의 의미

다음은 위 발표를 바탕으로 한 해석입니다. 평가 단위가 요청 전체로 넓어지면 검색·전송·모델 실행·도구 재시도 중 어느 단계가 응답 시간을 지배하는지 분해할 필요가 커집니다. 모델 생성이 빨라졌어도 검색 시간이 그대로라면 전체 지연시간의 감소에는 한계가 있습니다.

직접 만든 예로 전체 시간이 검색 120ms, 프롬프트 처리 80ms, 생성 300ms, 기타 50ms라면 합계는 550ms입니다. 생성만 두 배 빨라지면 400ms가 되어 전체 속도 향상은 `550/400=1.375배`입니다. 모델 내부의 2배와 서비스 전체의 1.375배는 같은 지표가 아닙니다. 이 숫자는 설명용 가정이며 MLPerf 측정값이 아닙니다.

| 비교 대상 | 함께 맞출 조건 | 놓치기 쉬운 부분 |
| --- | --- | --- |
| 가속기 처리량 | 모델·정밀도·배치·장치 수 | 시스템 수치를 장치 한 개 수치로 읽는 오류 |
| 대화 지연시간 | 입력·출력 길이, 동시 요청, 지연 제한 | 평균만 보고 긴 대기 요청을 놓치는 오류 |
| RAG 요청 | 검색 자료·인덱스·검색 수·정답 판정 | 검색 실패를 생성 모델의 오류로만 보는 해석 |
| 에이전트 | 도구·호출 횟수·종료 조건·성공 기준 | 토큰 수가 많을수록 더 잘했다고 보는 해석 |
| 전력 효율 | 측정 위치·시간·시스템 범위·처리량 | TDP를 실제 소비전력으로 대입하는 계산 |

## 모델 크기와 메모리

가중치가 작아지는 것과 실행 메모리가 작아지는 것은 같은 변화가 아닙니다. 가중치 저장의 단순 하한은 `매개변수 수 × 비트 수 / 8`로 계산할 수 있지만, 실제로는 scale·zero-point·배치·KV cache·임시 버퍼가 추가됩니다. 긴 문맥을 사용하는 서비스에서는 가중치만 보고 실행 가능성을 판단하지 않습니다.

따라서 먼저 저장 공간과 실행 중 최대 메모리를 나누고, 메모리를 실제로 측정했는지 이론식으로 계산했는지도 구분합니다. [모델 실험](../AI모델실험_model-lab/README.md)의 CPU 계산과 [캐시 예산 해설](../분야_topics/26-AI모델-API_open-model-lab/해설_notes/빔탐색과캐시예산_beam-cache-budget.md)이 이 차이를 다룹니다.
