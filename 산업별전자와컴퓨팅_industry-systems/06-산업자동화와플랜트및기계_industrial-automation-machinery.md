# 산업 자동화·플랜트·기계의 전자와 컴퓨팅 | Industrial automation, plants and machinery

[산업별 목차](README.md) · [발전·전력망](05-원자력과발전및전력망_nuclear-generation-grid.md) · [제어 기초](../전자컴퓨터공학_ece/21-신호처리제어_signals-control/README.md)

산업 현장에서는 센서를 연결하고 프로그램을 실행하는 일만으로 작업이 끝나지 않습니다. 어떤 설비·제품의 값인지, 언제 취득한 값인지, 계산 결과가 실제 장치에 언제 반영됐는지, 기록과 현장 상태가 일치하는지를 함께 확인합니다. 전자공학은 신호·전력·장치의 물리 조건을, 컴퓨터공학은 시간·상태·통신·자료 구조와 소프트웨어의 동작을 연결합니다.

이 글은 철강·제조·플랜트·사출·농기계·엘리베이터·건축 설비의 기술을 시스템별로 나눕니다. 공개 사업 자료는 회사가 제공하는 업무 범위를 확인하는 근거로 사용했고, 아래의 고장 조사 상황은 원리를 설명하기 위한 자체 학습 사례로 구성했습니다.

## 2. PLC·DCS·SCADA·MES·ERP의 역할

약어를 설비의 한 칸에 고정하기보다 어떤 결정을 맡고 어떤 정보를 주고받는지 읽는 편이 정확합니다. 한 제품이나 시스템이 여러 기능을 포함하기도 합니다.

| 이름 | 기초 정의 | 주로 다루는 정보·결정 |
| --- | --- | --- |
| PLC | programmable logic controller, 기계·설비의 입출력과 논리·순서를 실행하는 제어기입니다. | 센서 입력·작동 상태·작업 순서·실행 주기·장치 출력입니다. |
| DCS | distributed control system, 여러 제어 부분과 운전·엔지니어링 기능을 분산해 구성하는 제어 시스템입니다. | 공정의 연속적인 값·제어·경보·운전 정보와 통합 관리입니다. |
| HMI | human-machine interface, 사람이 상태를 보고 필요한 조작·확인을 하는 접점입니다. | 화면·단위·명령·경보·상태·사용자 권한입니다. |
| SCADA | supervisory control and data acquisition, 여러 장치의 자료 취득과 상위 감시·관리를 연결합니다. | 원격 상태·이벤트·경보·이력·상위 명령의 전달입니다. |
| Historian | 시간에 따른 공정·설비 값을 축적하는 기록 체계입니다. | 태그·시간·품질 상태·압축·보존·조회 조건입니다. |
| MES·MOM | 제조 실행·제조 운영을 관리하는 시스템 또는 활동 범위입니다. | 작업·제품·자재·설비·품질·생산 실적과 진행 상태입니다. |
| ERP | enterprise resource planning, 기업의 자원·사업 계획을 연결하는 정보 시스템입니다. | 수요·구매·재고·회계·생산 계획 등입니다. |

ISA-95/IEC 62264의 계층은 기능과 정보 교환의 경계를 이해하는 모델입니다. 기업의 그림에 붙은 L0·L1 번호를 다른 표준의 같은 번호와 곧바로 동일시하면 혼동이 생깁니다. 예를 들어 포스코DX의 공개 EIC 그림은 Sensor·Motor, PLC·DCS, 공정 컴퓨터, MES, ERP의 관계를 자체 계층 표시로 설명합니다. 이 자료의 번호를 모든 공장의 보편적인 제품 배치로 확장하지 않습니다. [IEC 62264-1:2013의 공개 범위](https://webstore.iec.ch/en/publication/6675)는 제조 운영과 기업 기능 사이의 모델·용어·정보 교환을 다룹니다.

```mermaid
flowchart LR
    A["센서·모터·밸브·현장 설비"] --> B["제어기·입출력·통신"]
    B --> A
    B --> C["HMI·감시·경보·이력"]
    B --> D["작업·제품·품질·생산 운영"]
    C --> D
    D --> E["구매·재고·사업 계획"]
    E --> D
    F["도면·설계·구성·변경 정보"] --> B
    F --> D
```

그림은 기능 사이의 일반적인 인계 관계를 단순화한 자체 설명입니다. 클라우드가 연결되거나 데이터가 여러 방향으로 흐르더라도 제어·감시·생산 관리·기업 계획의 책임은 구분해서 설계해야 합니다.

## 3. 센서의 값이 제어기의 숫자가 되기까지

### 신호 조절·절연·단위

온도 센서의 저항이나 작은 전압, 압력 센서의 출력, 전류 루프의 값은 그대로 같은 숫자 형식으로 들어오지 않습니다. 센서·신호 조절·ADC·소프트웨어 환산을 지나면서 물리량의 의미가 붙습니다.

| 세부 기술 | 필요한 기초 | 확인할 오류 |
| --- | --- | --- |
| RTD·열전대 등 온도 계측 | RTD는 온도에 따른 저항 변화를, 열전대는 접점과 온도 차이의 전압을 이용합니다. | 결선·기준 접점·단선·감도·단위·채널 설정입니다. |
| 전류·전압 입력 | 전기 신호를 정한 물리 범위로 대응합니다. | 범위·극성·환산 계수·부하·접지와 오버레인지입니다. |
| 증폭·필터·절연 | 작은 신호를 읽고 필요한 대역을 선택하며 전기적 경계를 나눕니다. | 포화·오프셋·대역폭·지연·공통 전원·접지의 영향입니다. |
| 디지털 센서·분산 I/O | 장치 프로토콜·상태·시각을 함께 다룹니다. | CRC·상태 코드·갱신 주기·캐시·누락과 주소 대응입니다. |
| 소프트웨어 환산 | 원시 정수·실수에 단위와 물리 범위를 적용합니다. | 정수 폭·부호·byte 순서·scale·결측값을 0으로 바꾸는 처리입니다. |

4–20 mA 전류 루프는 산업용 신호 전달의 한 방식입니다. TI는 [전류 루프 송신기 개요](https://www.ti.com/product-category/amplifiers/special-function/4-20ma-signal-conditioners/overview.html)와 [공식 참조 설계](https://www.ti.com/tool/TIPD158)를 제공합니다. 이 신호를 받는 소프트웨어도 장치가 정한 측정 범위·유효 상태를 알아야 합니다.

예를 들어 4 mA를 물리량 0, 20 mA를 100에 대응한다고 가정하면 12 mA는 중간값 50입니다. 이는 선형 환산의 자체 계산입니다. 같은 12 mA라도 센서의 실제 범위가 다르면 나타내는 온도·압력·유량은 달라집니다. 단선·범위 초과·장치 진단의 구체적인 전류와 처리 방식은 실제 장치의 명세에서 확인합니다.

### 시간과 값의 유효성

화면의 숫자가 범위 안에 있어도 오래된 값일 수 있습니다. 장치 취득 시각, 제어기 처리 시각, 서버가 받은 시각, 화면을 그린 시각은 서로 다를 수 있습니다. 따라서 값에는 시각뿐 아니라 그 시각의 출처와 품질 상태를 연결해야 합니다.

[공정·설비의 공개 코드 사례](../직무와실무기술_job-practice/사례_cases/04-공정설비와패키지의검사사례_process-equipment-package.md)는 PyEpics의 실제 모니터 예제로 값·접속·갱신·시각을 나눕니다. 이 공개 시스템을 특정 제조사가 사용한다고 추정하는 자료는 아니며, 현장의 관측 경계를 익히는 연결 자료입니다.

## 4. PLC·임베디드 제어의 시간과 상태

PLC의 전형적인 설명에는 입력을 읽고 프로그램을 실행한 뒤 출력을 반영하는 흐름이 나옵니다. 실제 시스템에서는 여러 태스크, 네트워크 I/O와 드라이브의 내부 제어가 서로 다른 시점에 동작할 수 있습니다. 프로그램 한 번의 계산 시간과 센서 입력부터 실제 장치 응답까지의 시간은 구분해야 합니다.

[CODESYS의 Task Configuration](https://content.helpme-codesys.com/en/CODESYS%20Development%20System/_cds_f_task_configuration.html)은 태스크의 종류·우선순위·호출 순서를 설명합니다. 같은 환경에서도 주기 태스크와 사건 기반 태스크의 실행 조건이 다를 수 있으며, 대상 장치가 지원하는 설정을 확인해야 합니다.

| 개념 | 뜻 | 실무에서 남길 근거 |
| --- | --- | --- |
| 주기·deadline | 반복해서 실행하는 간격과 결과가 필요하기 전까지의 기한입니다. | 실행 주기·최악 지연·기한의 정의와 관측 위치입니다. |
| jitter | 반복 시각이나 지연의 흔들림입니다. | 평균뿐 아니라 분포·최대값·부하 조건입니다. |
| 상태 기계 | 현재 상태와 입력에 따라 다음 상태·출력을 정하는 표현입니다. | 정상·대기·완료·오류·재시작 전이와 원인 기록입니다. |
| 인터록·기능 분리 | 동작 조건·허용 관계와 안전 관련 기능의 책임을 구분합니다. | 적용 요구사항·상태·시험 범위·독립 검토의 근거입니다. |
| 재시작·복구 | 전원·통신·프로그램이 중단된 뒤 상태를 다시 맞춥니다. | 이전 작업의 완료 여부, 물리 상태, 기록과 재처리 정책입니다. |

가정한 입력→출력 기한이 10 ms이고, 서로 겹치지 않는 취득·전달·계산·반영 지연이 각각 3·4·2·3 ms라면 합계는 12 ms입니다. 계산 자체가 2 ms라는 이유로 전체 기한을 만족하지는 않습니다. 이 수치는 시간 예산을 설명하는 자체 계산이며 특정 설비의 권장 주기나 제어 설정값이 아닙니다.

전원이 돌아온 뒤 모든 출력과 이전 작업을 곧바로 복원하는 것이 항상 올바른 복구는 아닙니다. 시료·작업물·기계 위치·완료 기록을 어떤 방법으로 확인할지 요구사항에서 정해야 합니다. [RTOS·동시성의 기초](../전자컴퓨터공학_ece/17-펌웨어-RTOS_firmware-rtos/README.md), [펌웨어·통신의 원문 코드 사례](../직무와실무기술_job-practice/사례_cases/02-펌웨어와통신의공개코드_firmware-communication.md)가 시간·큐·상태의 구체적 예입니다.

## 5. 산업 통신과 데이터 계약

같은 Ethernet 케이블을 쓴다고 모든 통신의 주기·상태·자료 뜻이 같지는 않습니다. 장치 제어, 정보 교환, 대량 영상 전송과 상위 실적 보고는 필요한 지연·처리량·복구 방식이 다릅니다.

| 연결 | 필요한 구분 | 확인할 항목 |
| --- | --- | --- |
| PLC·분산 I/O·드라이브 | 주기 데이터와 비주기 설정·진단을 나눕니다. | 주기·지연·동기·통신 상태·실제 I/O 대응입니다. |
| Modbus 같은 레지스터 기반 연결 | 주소와 자료형·단위·순서를 함께 해석합니다. | register map·폭·부호·word 순서·상태와 재시도입니다. |
| OPC UA 같은 정보 모델 연결 | 값뿐 아니라 대상·관계·타입·상태를 다룹니다. | 장치 ID·데이터 모델·품질·시각·권한·인증서입니다. |
| 카메라·비전 PC | 취득 trigger·프레임·작업물 ID를 연결합니다. | 노출·취득 시각·프레임 누락·대역폭·판정 지연입니다. |
| MES·설비·물류 | 작업 지시와 실제 완료·이송을 일치시킵니다. | 작업·제품·설비·수량의 키, 중복·순서·재처리입니다. |

[OPC Foundation의 OPC UA 개요](https://opcfoundation.org/about/opc-technologies/opc-ua/)는 산업별 정보 모델과 상호운용의 범위를 보여 줍니다. 연결 성공과 의미의 일치는 별개입니다. 서로 같은 온도라고 부르더라도 섭씨·화씨, 보정 전·후, 순간값·평균값이 다르면 같은 지표가 아닙니다.

실제 프로토콜 오류와 값 해석의 차이는 [CAN·EtherCAT·Modbus 고장 분리](../현장계측과검증_measurement-validation/칩과시스템시험_chip-system-testing/차량과설비통신의고장분리_can-ethercat-modbus.md), 실적 재수신·중복 저장은 [공식 DB 예제](../직무와실무기술_job-practice/사례_cases/05-AI와제조IT의평가사례_ai-manufacturing-it.md)에서 이어집니다.

## 6. 철강·로봇·머신비전·사출의 세부 기술

### 연속 공정과 단위 설비

철강 같은 연속 공정에서는 속도·장력·온도·형상·전력의 관계를 시간과 위치에 맞춥니다. 한 지점에서 측정한 소재가 다음 계측기에 도달할 때에는 시간이 지납니다. 같은 시각에 기록된 두 센서가 반드시 같은 소재 위치를 본 것은 아닙니다. 소재 ID·이동·측정 지점과 시각의 대응이 중요합니다.

단위 설비는 제품 투입·고정·처리·검사·배출 같은 순서를 가질 수 있습니다. 전체 라인이 빠르더라도 특정 작업의 대기·교체·재작업이 병목을 만들 수 있습니다. 장비의 순간 속도와 양품의 출하 속도를 구분해야 합니다. [포스코DX의 공개 EIC 설명](https://www.poscodx.com/kor/business/eicEngineering)은 연속 공정, 크레인·창고·원료 이송 등의 단위 설비를 나누어 보여 줍니다.

### 로봇·서보·머신비전

머신비전은 카메라 영상에서 필요한 정보를 얻는 기술입니다. AI를 붙이기 전에 광학·조명·취득 조건이 달라졌는지 확인해야 합니다. 조명 변화로 영상이 달라진 문제를 모델 재학습 하나로 설명하면 원인을 놓칠 수 있습니다. [카메라 모델·필터·검증](../전자컴퓨터공학_ece/43-컴퓨터비전_computer-vision/해설_notes/카메라모델영상필터CV검증_camera-filtering-and-validation.md), [로봇·제어](../전자컴퓨터공학_ece/22-로봇제어_robotics-boards/README.md)에 공통 수학과 신호 원리를 연결했습니다.

### 사출·유압·농기계

사출시스템은 재료·열·기계·전기 제어가 결합됩니다. 위치·압력·온도·시간이 다른 단계에서 다른 의미를 가지므로 사이클의 어느 단계에서 얻은 자료인지 맞춰야 합니다. 전동식과 유압식에서는 구동·에너지 전달 경로가 달라져 모터·인버터·펌프·밸브·센서의 관측 대상도 달라집니다.

농기계는 이동체의 전자·통신과 작업기의 기계·유압 부하가 함께 움직입니다. 위치 정보와 실제 작업 품질, 센서·통신 상태, 작업기 부하를 나누어 봅니다. [LS엠트론 공식 사업 소개](https://www.lsmtron.com/)는 트랙터·사출시스템을 구분합니다. 구체적 모델의 자동화 수준·제어 기능은 해당 모델의 공개 사양으로 확인하며 모든 기계에 같은 기능이 있다고 가정하지 않습니다.

## 8. EPC·BIM·설계 해석과 현장 인계

EPC는 engineering, procurement and construction, 설계·조달·시공을 연결하는 사업 수행 범위입니다. FEED는 front-end engineering design, 본격적인 상세 설계·사업 수행 전에 기본적인 설계 조건과 범위를 구체화하는 단계입니다. [현대자동차그룹의 현대엔지니어링 소개](https://www.hyundaimotorgroup.com/ko/group/hyundai-engineering)는 이 역할과 플랜트·건축·자산관리의 사업 범위를 구분합니다.

BIM은 건물·시설의 형상뿐 아니라 부재·설비·관계·속성 정보를 연결하는 모델링·정보 관리의 관점입니다. CAD 형상, 구조·열·유동·전기 해석, 공정·물량·자산 정보는 입력과 판단 대상이 다릅니다. 같은 파일에 함께 보이더라도 한 결과가 다른 분야의 적합성을 자동으로 보증하지는 않습니다.

| 연결 단계 | 전자·컴퓨터 업무 | 자주 생기는 불일치 |
| --- | --- | --- |
| 설계 요구·도면 | 계측·전기·통신·I/O·네트워크·전원 요구를 모델·문서에 연결합니다. | 태그·단위·정격·도면 개정이 맞지 않는 문제입니다. |
| 모델 교환 | 형상·설비 속성·좌표·ID를 다른 도구로 전달합니다. | 원점·단위·좌표계·속성 누락·서로 다른 식별자입니다. |
| 설계 해석 | 물리·전기·운용 조건에 맞는 모델과 경계를 정합니다. | 형상 판본·경계 조건·부하·모델 가정이 다른 문제입니다. |
| 조달·제작 | 실제 공급품의 자료를 승인된 설계와 맞춥니다. | 대체품·firmware·부품 개정이 시험 자료와 다른 문제입니다. |
| 설치·시운전 | 실제 결선·장치·제어 구성과 설계·시험을 대조합니다. | 채널·네트워크·표시·물리 위치가 다른 문제입니다. |
| 운영·자산 관리 | 설치된 설비와 정비·교체·상태 자료를 연결합니다. | 교체 후 ID·모델·정비 이력이 갱신되지 않는 문제입니다. |

[buildingSMART의 IFC 공식 설명](https://technical.buildingsmart.org/standards/IFC/)은 시설 정보를 교환하는 개방형 표준의 범위를 다룹니다. IFC 형식이 유효하다는 결과는 실제 시공의 위치·하중·성능까지 맞다는 뜻이 아닙니다. 설계 모델과 as-built, 실제 설치 상태를 반영한 정보의 대응을 따로 확인합니다. [HL디앤아이한라의 사업 소개](https://www.hldni.com/mobile/sub/company/company.asp)는 건축·토목·플랜트·환경의 사업 범위를 확인하는 근거이며 특정 BIM 제품의 채택 근거로 사용하지 않았습니다.

### FAT·SAT·통합 시험

공급사에서 확인한 제어 구성과 현장에 설치된 구성은 결선·장치·네트워크·상위 인터페이스가 다를 수 있습니다. FAT는 공장 인수 시험, SAT는 현장 인수 시험이며, 통합 시험은 여러 부분 사이의 계약·상태·동작이 맞는지 확인합니다. [IEC 62381:2024 공개 소개](https://webstore.iec.ch/en/publication/67572)는 FAT·FIT·SAT·SIT의 범위와 책임·시험 계획을 다룹니다.

시험 결과에는 명령을 보냈다는 사실뿐 아니라 어떤 장치·태그·판본에서 무엇을 관측했고 어떤 요구로 판정했는지 남깁니다. 공장 시험의 통과를 현장의 모든 결선·운용 조건이 통과했다는 의미로 바꾸지 않습니다.

## 9. OT 보안·기록·정비의 연결

OT, operational technology는 물리적 장치·공정을 감시하거나 제어하는 기술을 가리킵니다. 서버의 자료뿐 아니라 현장의 가용성·시간·물리적 영향과 정비 가능성도 고려해야 합니다. 일반 업무 PC의 업데이트·재시작 방법을 운전 중 제어기에 그대로 적용하는 것은 다른 문제입니다.

[NIST SP 800-82 Rev. 3, 2023년 최종본](https://csrc.nist.gov/pubs/sp/800/82/r3/final)은 OT의 특성과 보안을 다룹니다. 확인 시점에는 Rev. 4가 공개 초안으로 안내되므로 이 글의 기준은 최종본 Rev. 3입니다. 여기서는 보호 원리와 운영 기록을 읽으며 실제 제어망에 접근·시험한 결과를 제시하지 않습니다.

| 검토 항목 | 실제 업무에서 확인할 내용 |
| --- | --- |
| 자산·구성 기준선 | 장치·역할·소프트웨어·firmware·네트워크·설정과 책임자를 식별합니다. |
| 접근·분리 | 어떤 계정·시스템이 어떤 기능에 접근해야 하는지와 경계를 검토합니다. |
| 변경·업데이트 | 적용 조건·검증·변경 영향·되돌릴 방법과 기록을 맞춥니다. |
| 백업·복원 | 파일 보유와 실제 복구 가능성, 필요한 판본·키·설정의 완전성을 구분합니다. |
| 원격 정비·로그 | 승인된 작업·사용자·시간·대상·변경·종료 상태를 추적합니다. |
| 사건 조사 | 장치 상태·통신·계정·설비 사건을 같은 시간 기준으로 대조합니다. |

AI 기반 이상 탐지가 있어도 기록의 장치 ID·시각·단위가 틀리면 조사 방향이 달라집니다. 관련 원리는 [AI·제조 IT의 공식 예제](../직무와실무기술_job-practice/사례_cases/05-AI와제조IT의평가사례_ai-manufacturing-it.md)에서 학습 자료·중복 기록·판정의 경계를 나누어 설명합니다.

## 10. 한 가지 현상을 끝까지 조사합니다

### 검사 로봇을 교체한 뒤 불량률이 달라 보입니다

이것은 학습용으로 구성한 상황입니다. 새로운 로봇 자체가 원인일 수도 있지만, 카메라·조명·trigger·작업물 위치·제품 구성·자료 결합이 함께 바뀌었을 수 있습니다.

| 관측 | 확인할 대조 | 남길 결과 |
| --- | --- | --- |
| 영상이 흐려졌습니다. | 같은 작업물·노출·이동 조건과 정지 영상을 비교합니다. | 원시 영상·노출·trigger·동작 조건입니다. |
| 판정은 맞는데 배출 대상이 다릅니다. | 제품 ID·프레임 ID·판정 시각·실제 이송 순서를 맞춥니다. | 지시와 실제 처리의 대응 기록입니다. |
| 일부 제품군에서만 차이가 큽니다. | 제품·위치·재질·크기별로 분리해 비교합니다. | 집단별 표본·누락·오검출·판정 불가 기록입니다. |
| 서버의 불량 수만 증가했습니다. | 최초·재시험·재수신의 실행 키를 비교합니다. | 원시 시험과 집계 행의 대응입니다. |
| 새 모델에서만 점수가 높습니다. | 평가 자료와 전처리·모델 판본을 확인합니다. | 독립 평가와 학습·전처리 이력입니다. |

수정은 카메라 보정·취득 조건·자료 계약·알고리즘 중 확인된 원인에 맞춥니다. 수정 후에는 원래 실패 조건과 별도의 정상·경계 조건을 같은 기준으로 다시 검사합니다. 이 글은 실제 로봇·제조 라인을 운전하거나 불량률을 측정한 기록이 아닙니다.
