# 정렬과 비교 함수

[학습목차](README.md) · [연습문제](연습문제_problem-index.md)

## 값을 바꾸지 않고 순서를 정하는 연산

정렬은 입력 원소를 보존하면서 지정한 비교 관계에 맞게 순서를 바꾸는 작업입니다.
숫자 크기, 종료 시각, 여러 필드의 우선순위처럼 무엇을 앞에 둘지 먼저 정해야 합니다.
정렬이 중요한 이유는 순서가 생기면 인접한 원소만 비교하거나 후보를 한 방향으로 제외할 수 있기 때문입니다.
정렬된 배열에서의 이진 탐색과 최솟값·최댓값 접근은 이런 이점을 보여 줍니다. [MIT 강의 3, Sorted Array](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/6d1ae5278d02bbecb5c4428928b24194_MIT6_006S20_lec3.pdf)

하지만 정렬로 원래 시간 순서나 인접 관계가 없어지면 다른 문제가 될 수 있습니다.
원래 위치를 출력해야 한다면 원소와 함께 원래 인덱스를 저장합니다.

## 인식 단서와 비교 규칙

“순위”, “가장 먼저 끝나는”, “같은 값끼리 묶기”, “가까운 두 값”은 정렬을 검토할 단서입니다.
여러 기준이 있으면 주 기준, 동률 기준, 완전 동률의 처리 순서를 적습니다.
독립된 각 기준을 따로 정렬하는 것과 하나의 사전식 키로 정렬하는 것은 같지 않을 수 있습니다.
안정 정렬을 이용해 여러 번 정렬할 때는 덜 중요한 기준부터 적용해야 합니다.
Python 정렬은 안정성을 보장하며 `key`는 각 입력 원소에 대해 한 번 계산합니다. [Python Sorting HOWTO, Key Functions·Sort Stability](https://docs.python.org/3/howto/sorting.html)

정렬 기준을 실행 중에 바꾸거나 외부의 변하는 상태에 의존시키면 일관된 순서를 정의하지 못할 수 있습니다.
허용되는 순서 관계가 있는지부터 확인한 뒤 정렬 함수를 선택합니다.

## 직접 구성한 예제: 점수와 제출 순위

기록은 이름, 점수, 제출 순위로 이루어집니다.
점수는 높은 순서, 같은 점수는 제출 순위가 작은 순서로 정하며 완전 동률은 입력 순서를 유지합니다.

| 입력 순서 | 이름 | 점수 | 제출 순위 | 정렬 키 |
|---:|---|---:|---:|---|
| 0 | A | 90 | 2 | (-90,2) |
| 1 | B | 80 | 1 | (-80,1) |
| 2 | C | 90 | 1 | (-90,1) |
| 3 | D | 90 | 1 | (-90,1) |

키를 오름차순으로 비교하면 결과는 C, D, A, B입니다.
C와 D의 키가 같으므로 안정성 조건에 따라 입력에서 앞선 C가 먼저입니다.
반대로 모든 키에 단순히 역순 옵션을 적용하면 제출 순위까지 큰 값이 먼저 되어 요구와 달라집니다.

```python
records = [("A", 90, 2), ("B", 80, 1), ("C", 90, 1), ("D", 90, 1)]  # 튜플 리스트에 원래 기록 저장
ordered = sorted(records, key=lambda record: (-record[1], record[2]))  # 람다 키로 점수 내림차순·순위 오름차순 지정
names = [record[0] for record in ordered]  # 리스트 내포로 정렬된 이름만 추출
```

## 비교 함수의 계약

C의 비교 함수는 첫 값이 앞이면 음수, 동등하면 0, 뒤이면 양수를 반환하는 형태입니다. [GNU C Library, Comparison Functions](https://sourceware.org/glibc/manual/latest/html_node/Comparison-Functions.html)
C++ 정렬의 비교자는 첫 값이 둘째보다 앞서야 하는지를 불리언으로 반환합니다.
C++의 엄격 약순서 조건에는 자기 자신보다 앞서지 않는 성질과 관계의 추이성이 포함됩니다. [C++ 작업 초안, alg.sorting.general](https://eel.is/c++draft/alg.sorting.general)

따라서 C++ 비교자에서 `a <= b`를 반환하면 같은 원소끼리도 참이 되어 계약을 어깁니다.
C에서 `a-b`를 그대로 반환하면 자료형 범위를 벗어나는 뺄셈이 문제가 될 수 있습니다.
관계 비교 결과를 조합하거나 각 필드를 차례로 비교하는 형태가 안전한 선택입니다.

## 정당성의 확인

예제의 키 첫 항은 점수의 부호를 뒤집으므로 높은 점수가 작은 키가 됩니다.
첫 항이 같을 때 둘째 항을 비교하므로 제출 순위의 요구도 그대로 반영됩니다.
키가 완전히 같은 경우에는 안정 정렬의 계약으로 입력 순서가 보존됩니다.
또한 출력이 입력 원소의 순열인지 확인해야 누락·복제 없는 정렬이라고 할 수 있습니다.

정렬 뒤 탐욕 선택을 하는 풀이에서는 이 설명만으로 최적성이 증명되지는 않습니다.
왜 그 순서의 선택을 최적해의 앞부분과 교환해도 손해가 없는지 별도의 교환 논증이 필요합니다.

## 시간·공간과 입력 규모

병합 정렬처럼 균형 분할과 선형 병합을 사용하는 비교 정렬은 O(N log N) 시간을 얻습니다.
반면 단순 선택 정렬은 남은 전체를 반복 검색하므로 O(N²)입니다.
키 비교에 길이 L인 문자열의 긴 공통 접두부 검사가 필요하면 비교 한 번을 O(1)로 세면 안 됩니다.
정수 키 범위가 작으면 계수 정렬처럼 비교 기반 정렬과 다른 설계도 가능합니다.

Python `sorted`는 새 리스트를 만들고 `list.sort`는 원래 리스트를 정렬합니다. [Python Sorting HOWTO, Sorting Basics](https://docs.python.org/3/howto/sorting.html)
C와 C++에서도 제자리 정렬이라는 표현만 보고 보조 공간이 반드시 O(1)이라고 추정하지 않습니다.
사용하는 함수의 시간·공간·안정성 보장은 각각 확인해야 합니다.

## 실전의 적용 조건

보고서의 여러 열을 우선순위로 정렬할 때는 빈 값, 대소문자, 동률의 순서를 명확히 합니다.
서로 다른 데이터 공급처의 문자열을 정렬하려면 인코딩과 정규화, 원하는 언어별 정렬 규칙도 검토합니다.
모든 작업이 미리 주어졌다면 일괄 정렬이 적절하지만, 작업이 계속 들어오며 다음 하나만 필요하면 힙이 적절할 수 있습니다.
이 사례는 선택 조건을 설명하며 특정 검색 서비스의 순위 산식을 재현하는 것은 아닙니다.

## 실수와 반례

- 문자열 `"10"`과 `"2"`의 사전식 순서는 숫자 크기 순서와 다릅니다.
- 부동소수점 NaN을 일반적인 수처럼 비교하면 순서 관계의 가정이 깨질 수 있습니다.
- 원소의 일부 필드만 복사해 정렬하면 답에 필요한 식별 정보를 잃을 수 있습니다.
- 안정성에 의존하면서 불안정 정렬로 바꾸면 완전 동률에서 결과가 달라집니다.

## 복습 질문과 답

질문 1. 점수 내림차순·이름 오름차순은 어떻게 구별해 표현합니까?

답. 각 기준의 방향을 따로 정한 키나 비교자를 사용하며 전체 역순으로 두 기준을 함께 뒤집지 않습니다.

질문 2. 정렬했으니 탐욕 선택도 최적입니까?

답. 아닙니다. 정렬 기준에 따른 선택이 최적해를 훼손하지 않는 별도의 근거가 필요합니다.
