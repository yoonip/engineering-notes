# 반례 설계와 독립 검증, 성능 측정

[학습 목차](README.md) · [유형별 연습문제](연습문제_problem-index.md)

## 테스트가 필요한 이유

증명이 맞아도 구현이 그 증명대로 동작하지 않을 수 있습니다. 반대로 예제가 모두 맞아도 알고리즘의 가정이 틀릴 수 있습니다. 정당성 논리, 구현 검사, 성능 측정, 사이트 채점 결과를 각각 다른 근거로 관리합니다.

새 알고리즘을 검사할 때 최적화한 코드와 거의 같은 코드로 정답 비교기를 만들면 같은 실수를 공유하기 쉽습니다. 작은 입력에서 정의를 그대로 계산하는 완전 탐색, 직접 경로 열거, 모든 부분집합 검사가 느리지만 독립적인 기준이 될 수 있습니다.

## 자체 예제: 부분합 최댓값 검증

길이가 작은 배열에서 가능한 모든 [l,r) 구간을 나열하고 합을 직접 구하는 O(n³) 비교기를 둘 수 있습니다. 실제 풀이가 O(n) DP라면 두 구현의 구조가 다릅니다. 공집합을 허용하는지에 따라 전부 음수인 배열의 정답이 0 또는 가장 큰 음수가 되므로 명세를 먼저 맞춥니다.

검증 순서는 명세→수작업 예제→작은 전수·무작위 비교→큰 경계 입력→실제 채점으로 이어집니다. 모든 단계가 모든 문제에 필요한 것은 아니지만 실패가 어디서 발생했는지 구분할 수 있어야 합니다.

## 반례를 만드는 축

| 축 | 입력 | 잡을 수 있는 문제 |
| --- | --- | --- |
| 크기 | 빈 입력·최소·최대 | 초기값, 길이 0/1, 자원 한계입니다. |
| 값 | 0·음수·최대·모든 값 같음 | 나눗셈, INF, 오버플로, 중복 처리입니다. |
| 순서 | 정렬·역순·교대 | 단조성 가정과 최악 반복입니다. |
| 그래프 구조 | 사슬·별·고립·사이클·평행 간선 | 재귀 깊이, 연결 가정, 간선 ID입니다. |
| 경계 | 정확히 임계값·임계값 ±1 | 포함 여부와 이진 탐색 종료입니다. |
| 중복 상태 | 다른 경로로 같은 상태 도착 | 방문 처리와 최선 값 갱신입니다. |

무작위 입력은 항상 정답이 존재하도록 생성할지, 불가능한 입력도 포함할지 명세에 맞춥니다. 특정 구조만 생성하면 테스트 수가 많아도 그 구조 밖의 반례를 보지 못합니다.

## 관계를 이용하는 검사

정답을 모르는 큰 입력에도 예상되는 관계를 검사할 수 있습니다. 무방향 그래프의 정점 번호를 일대일로 바꾸어도 연결 요소 수는 같아야 합니다. 원소 순서가 무관한 문제에서는 셔플 전후 결과가 같아야 합니다. 모든 간선 비용을 양수 c배 하면 합 기반 최단 거리도 c배입니다. 조건이 다른 문제에 이런 변환을 그대로 적용하지 않습니다.

정렬 결과는 값이 정렬되어 있는지와 원래 원소의 다중집합이 같은지를 함께 검사합니다. 합계만 같다는 검사는 원소가 달라진 버그를 놓칩니다. 구성적 풀이는 출력 형식만 보지 말고 모든 제약을 별도 검사기로 확인합니다.

## 실패 입력 줄이기

큰 무작위 반례가 나오면 원소·간선·질의를 줄여도 실패가 남는지 확인합니다. 값의 절댓값과 상태 수를 줄이면 잘못된 가정이 보입니다. 시드, 실패 입력, 기대값과 실제값, 실행 버전을 함께 보관하면 다시 재현할 수 있습니다.

메모리 오류는 C/C++의 경고와 AddressSanitizer·UndefinedBehaviorSanitizer 등 도구로 확인할 수 있습니다. 도구가 탐지하지 못했다고 정의되지 않은 동작이 없다는 증명은 아닙니다. Python도 aliasing과 가변 상태 공유처럼 언어 규칙상 정상 실행되는 논리 오류를 별도로 검사합니다.

## 성능을 비교하는 방법

같은 입력·런타임·컴파일 옵션·측정 범위를 맞춥니다. 알고리즘만 비교하면 입력 생성·읽기·정렬·전처리·출력을 어디에 포함했는지 밝힙니다. 반복 측정의 분포와 최대 메모리를 보고 평균 하나만으로 시간 제한 통과를 단정하지 않습니다.

[Python timeit 문서](https://docs.python.org/3/library/timeit.html)는 반복 측정과 기본 GC 비활성화를 설명합니다. 짧은 코드의 하한 비용을 보는 측정과 긴 서비스의 GC·입출력 포함 지연은 목적이 다릅니다. 로컬 1초가 사이트 1초라는 보장도 없습니다.

격자 1000×1000에서 정점당 작은 객체 여러 개를 만들면 점근 공간 O(V)라도 수백만 객체의 비용이 생길 수 있습니다. 시간 초과는 차수, 상수, 입력 변환, 메모리 접근을 나누어 분석합니다. 같은 실패 코드를 이유 없이 반복 제출하는 대신 새 가설과 변경을 대응시킵니다.

## 판정 기록과 실제 적용

| 기록 | 확인한 내용 | 확인하지 못한 내용 |
| --- | --- | --- |
| 수작업 예제 | 지정 예제의 계산입니다. | 다른 모든 입력의 정답입니다. |
| 로컬 차등 검사 | 생성·열거한 범위의 일치입니다. | 제한 전체의 증명과 사이트 성능입니다. |
| 사이트 정답 | 해당 언어 제출에 대한 사이트 테스트 결과입니다. | 다른 언어·수정된 코드의 자동 통과입니다. |
| 벤치마크 | 명시한 환경·입력의 비용입니다. | 임의 환경에서 같은 배수의 속도입니다. |

현업에서는 같은 원리가 회귀 테스트, 속성 검사, 퍼징과 장애 재현으로 이어집니다. 실패를 숨기는 예외 처리보다 잘못된 가정이 드러나는 작은 재현 예제가 다음 수정을 빠르게 만듭니다. 이 문서의 예제는 검증 방법 설명용이며 기존 제출을 다시 채점한 기록이 아닙니다.

복습: 최적화 전후 결과가 1만 건 같으면 정답이 증명되는지 설명합니다. 답은 검사 범위의 근거가 쌓인 것이며, 보편적 정당성은 여전히 상태와 전이의 논리로 설명해야 한다는 점입니다.
