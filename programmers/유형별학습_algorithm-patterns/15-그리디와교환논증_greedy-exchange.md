# 그리디 선택과 교환 논증

[학습목차](README.md) · [연습문제](연습문제_problem-index.md)

## 핵심 원리와 중요성

그리디는 현재 정한 선택을 되돌리지 않고 답을 늘려 가는 방법입니다.
빠른 선택 규칙과 그 규칙이 최적해를 남긴다는 증명이 함께 있어야 합니다.
정렬 한 번과 선형 순회로 끝나는 경우가 많아, 모든 조합을 비교하기 어려운 입력에서 유용합니다.
예를 들어 회의의 개수를 최대화할 때에는 가장 빨리 끝나는 회의를 선택합니다.
이 규칙은 회의의 중요도 합을 최대화하는 문제와는 조건이 다릅니다. [MIT 구간 스케줄링 강의](https://ocw.mit.edu/courses/6-046j-design-and-analysis-of-algorithms-spring-2015/ff2a7015ff913fc01f0381d8f5126a9a_MIT6_046JS15_lec01.pdf)

## 알아보는 단서와 적용 조건

- 같은 수의 선택을 했을 때 종료 시각·사용 자원이 작을수록 남은 선택이 많아지는 구조를 찾습니다.
- 인접한 두 작업의 순서를 바꿨을 때 비용 차이를 식으로 계산할 수 있는지 확인합니다.
- 최소 신장 트리처럼 안전한 선택을 보장하는 별도 구조가 있는지도 확인합니다.
- 입력이 크다는 사실만으로 그리디가 정답이라는 결론을 내리지 않습니다.

선택한 회의들이 같은 방 하나를 사용하고, 끝나는 시각에 다음 회의를 시작할 수 있다고 가정합니다.
각 회의는 시작보다 종료가 늦으며, 모든 회의의 가치는 개수 1로 같습니다.
여러 방, 준비 시간, 가중치가 추가되면 선택 규칙이나 상태 자체를 다시 검토합니다.

## 풀이 절차

1. 최대화·최소화하려는 양과 선택의 허용 조건을 문장으로 정합니다.
2. 후보 규칙을 정하고 작은 입력에서 반례를 먼저 찾습니다.
3. 임의의 최적해를 그리디 선택과 같게 바꿀 수 있는지 증명합니다.
4. 선택 뒤에 남는 문제도 같은 형태인지 확인합니다.
5. 정렬 기준, 동률 처리, 경계의 포함 여부를 코드로 옮깁니다.

## 직접 구성한 회의 예제와 추적

회의는 A=[0,3), B=[1,2), C=[2,4), D=[3,5), E=[4,6)입니다.
반열린 구간 [s,f)는 시각 f에 방을 비운다는 뜻입니다.
종료 시각순은 B, A, C, D, E입니다.

| 확인한 회의 | 직전 종료 | 판단 | 선택 결과 |
| --- | ---: | --- | --- |
| B=[1,2) | 없음 | 첫 회의 선택 | B |
| A=[0,3) | 2 | 시작 0이 2보다 작아 제외 | B |
| C=[2,4) | 2 | 시작과 직전 종료가 같아 선택 | B,C |
| D=[3,5) | 4 | 겹치므로 제외 | B,C |
| E=[4,6) | 4 | 이어서 선택 | B,C,E |

선택한 회의는 3개입니다. 가장 일찍 시작하는 A부터 고르면 이 입력에서는 2개만 선택합니다.

## 왜 맞는지: 첫 선택의 교환

최적해의 첫 회의를 O, 가장 빨리 끝나는 회의를 G라고 정합니다.
G의 종료 시각은 O보다 늦지 않습니다.
최적해에서 O를 G로 바꾸어도 뒤의 회의는 여전히 G 종료 뒤에 시작합니다.
따라서 회의 수를 줄이지 않으면서 G를 포함하는 최적해를 얻습니다.
G와 겹치는 회의를 지우고 남은 입력에 같은 논증을 반복합니다.
이 과정은 선택 개수를 보존하며 최적해를 그리디 결과로 바꾸므로 최적성을 보장합니다. [Washington 대학 교환 논증 강의](https://courses.cs.washington.edu/courses/cse421/25wi/files/slides/lecture7_greedy2_ink.pdf)

교환 논증에서 바꾸는 대상은 반드시 가능한 해여야 합니다.
“더 좋아 보입니다”라는 말만으로 뒤의 제약이 유지된다고 가정하면 증명에 빈틈이 생깁니다.

## 짧은 구현과 복잡도

```python
def select_meetings(meetings):  # (시작, 종료) 목록에서 겹치지 않는 회의 선택
    ordered = sorted(meetings, key=lambda item: item[1])  # 종료가 빠른 후보부터 비교
    chosen = []  # 실제 선택한 회의를 복원할 목록
    finish = None  # 아직 회의를 고르지 않은 상태
    for start, end in ordered:  # 각 회의를 한 번씩 확인
        if finish is None or start >= finish:  # 직전 선택과 양립하는지 검사
            chosen.append((start, end))  # 안전한 선택을 결과에 추가
            finish = end  # 다음 회의가 시작할 수 있는 경계 갱신
    return chosen  # 최대 개수의 회의 목록 반환
```

회의 수 n에 대해 정렬 O(n log n), 순회 O(n) 시간입니다.
위 구현은 정렬한 복사본과 결과에 O(n) 공간을 사용합니다.
입력이 이미 종료순이면 선택 자체는 O(n) 시간입니다.

## 실수와 반례

가중 회의 A=[0,2), 가치 2와 B=[0,3), 가치 100에서는 빨리 끝나는 A가 최적이 아닙니다.
동전 {1,3,4}로 6을 만들 때 큰 동전부터 고르면 4+1+1이지만 최적은 3+3입니다.
이 반례는 회의 개수 문제의 증명을 부정하지 않으며, 서로 다른 문제의 조건을 구분하는 용도입니다.
C·C++ 정렬 비교 함수에서 종료 시각을 빼서 반환하면 큰 정수의 뺄셈이 넘칠 수 있습니다.
직접 대소를 비교하고, 결과의 합이 필요한 다른 그리디 문제에서는 누적 자료형도 따로 정합니다.

## 실전 연결과 연계 유형

예약 선택과 작업 순서 문제에서 교환 논증은 간단한 정책의 적용 범위를 설명합니다.
실제 예약 시스템의 취소·우선순위·여러 자원 제약까지 이 단순 모델이 해결한다고 가정하지 않습니다.
가중 회의 선택은 [동적 계획법](16-동적계획법의상태와전이_dynamic-programming.md), 선택지 수가 작은 경우는 완전 탐색과 연결합니다.
최적해를 구하는 그리디와 성능 비율만 보장하는 [근사 알고리즘](36-무작위화와근사최적화_randomized-approximation.md)을 구분합니다.

## 복습 질문과 답

- 질문: 가장 짧은 회의를 고르는 규칙도 같은 증명으로 성립합니까? 답: 짧아도 가운데에 걸쳐 양쪽 회의를 막을 수 있어, 종료 시각 비교에 사용한 교환 논증이 성립하지 않습니다.
- 질문: 회의 시작과 직전 종료가 같으면 어떻게 처리합니까? 답: 여기서는 [s,f) 모델이므로 허용하며, 문제의 경계 규칙이 바뀌면 비교도 바꿉니다.
- 질문: 예제에서 맞는 규칙이면 충분합니까? 답: 예제는 반례 탐색에 유용하지만 모든 입력을 다루는 교환 논증이나 다른 정당성 증명이 필요합니다.
