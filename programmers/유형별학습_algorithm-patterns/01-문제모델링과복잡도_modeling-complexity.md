# 문제 모델링과 복잡도

[학습목차](README.md) · [연습문제](연습문제_problem-index.md)

## 문제를 계산 가능한 형태로 바꾸는 과정

모델링은 이야기에서 입력, 상태, 허용 연산, 원하는 출력을 분리하는 과정입니다.
같은 배송 이야기라도 가장 짧은 거리, 처리 가능한 주문 수, 모든 경로의 개수는 서로 다른 문제입니다.
먼저 “올바른 출력이 만족해야 하는 조건”을 문장이나 식으로 적습니다.
MIT 6.006 첫 강의도 문제의 입력·출력 조건과 모든 유효 입력에 대한 정답성을 알고리즘의 출발점으로 다룹니다. [MIT 강의 1, Problem·Algorithm·Correctness](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/477c78e0af2df61fa205bcc6cb613ceb_MIT6_006S20_lec1.pdf)

자료구조부터 정하면 필요한 정보보다 구현하기 쉬운 정보를 저장하기 쉽습니다.
반대로 상태와 연산을 먼저 정하면 배열, 해시, 그래프 중 무엇이 필요한지 비교할 수 있습니다.

## 인식 단서와 전제 확인

입력 크기는 원소 수 하나로 끝나지 않을 수 있습니다.
문자열이라면 총 문자 수, 그래프라면 정점 수와 간선 수, 질의라면 원소 수와 질의 수를 따로 셉니다.
숫자가 매우 크면 그 숫자에 비례하는 반복과 입력의 비트 길이에 비례하는 반복을 구별합니다.
“최댓값을 최소화”라는 표현은 매개변수 탐색의 단서이지만, 판정 함수의 단조성을 먼저 확인해야 합니다.
“순서와 무관”은 정렬이나 빈도 집계의 단서이며, 원래 위치가 답에 필요하면 위치 정보도 보존합니다.

아직 입력 조건이 불명확하면 음수 허용, 중복 허용, 빈 입력, 오버플로, 동시 발생 사건을 먼저 확인합니다.
정렬로 입력 순서를 바꿔도 되는지와 같은 전제는 구현 선택보다 앞서는 문제 조건입니다.

## 직접 구성한 예제: 주문 구간 합

하루 주문량이 `[3, 1, 4, 2, 5]`이고 여러 날짜 구간의 총량을 묻는다고 가정합니다.
원소 수를 N, 질의 수를 Q로 두고, 질의 구간은 시작을 포함하고 끝을 제외하는 `[l,r)`로 정합니다.
출력 조건은 각 질의에 대해 `a[l] + ... + a[r-1]`을 반환하는 것입니다.

| 선택 | 준비 비용 | 질의 하나 | 전체 비용 |
|---|---:|---:|---:|
| 매번 직접 합산 | O(1) | O(N) 최악 | O(NQ) |
| 누적합 저장 | O(N) | O(1) | O(N+Q) |
| 모든 구간 답 저장 | O(N²) | O(1) | O(N²+Q) |

누적합은 `[0,3,4,8,10,15]`입니다.
`[1,4)`의 답은 `10-3=7`이며 실제 값 `1+4+2`와 같습니다.
질의가 하나뿐이면 준비 비용을 포함한 두 방법이 모두 O(N)입니다.
따라서 누적합이 언제나 더 낫다는 결론이 아니라, 반복 질의라는 조건에서 이득이 있다는 결론입니다.

## 비용을 세는 절차

1. 반복 횟수를 입력 변수로 표현합니다.
2. 반복 내부 연산의 비용을 별도로 확인합니다.
3. 중첩 반복이 실제로 독립적으로 N번씩 도는지 확인합니다.
4. 정렬, 복사, 해시 계산, 큰 정수 계산, 출력 저장도 포함합니다.
5. 여러 테스트의 입력 크기 합에 제한이 있으면 그 합을 기준으로 계산합니다.

길이 N인 문자열을 반복해서 복사하면 겉으로 한 반복문이어도 O(N²)이 될 수 있습니다.
반대로 두 포인터가 각각 앞으로 N번만 움직이면 중첩된 `while`이 있어도 O(N)일 수 있습니다.
점근적 비용은 증가 경향을 비교하는 도구이며, 특정 컴퓨터에서 몇 초인지 보장하는 공식은 아닙니다. [MIT 강의 1, Efficiency·Model of Computation](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/477c78e0af2df61fa205bcc6cb613ceb_MIT6_006S20_lec1.pdf)

## 정답성과 모델의 대응

먼저 모델의 모든 허용 해가 실제 문제의 허용 해인지 확인합니다.
다음으로 실제 문제의 모든 허용 해가 모델에서도 표현되는지 확인합니다.
한쪽만 보이면 금지된 해를 허용하거나 정답 후보를 누락할 수 있습니다.
예를 들어 주문이 “연속 날짜”여야 한다면 임의 부분집합을 고르는 모델은 다른 문제입니다.

누적합 모델에서는 `P[i]`가 처음 i개 값의 합이라는 불변식을 사용합니다.
`P[0]=0`으로 시작하고 다음 원소를 더하면 이 의미가 유지됩니다.
두 접두 구간의 공통 부분을 빼면 정확히 `[l,r)`만 남으므로 출력 조건을 만족합니다.

## 입력 규모와 자원 판단

N=100000일 때 N²개의 항목은 100억 개입니다.
항목당 8바이트라는 단순한 배열 가정만으로도 800억 바이트이므로 저장 자체가 부담입니다.
이 값은 메모리 계산 예제이며 실제 언어 객체의 크기를 측정한 결과는 아닙니다.
Python 객체 배열, C++ 컨테이너, C의 연속 배열은 같은 항목 수라도 부가 비용이 다릅니다.

시간 복잡도와 함께 입력, 보조 공간, 반환 결과 공간을 나누어 적습니다.
모든 조합을 출력해야 한다면 출력 수 자체가 지수적일 수 있으며 계산만 줄여 해결할 수 없습니다.

## 언어에 따른 구현 판단

C에서는 배열 길이, 할당 실패 처리, 정수 범위, 소유권을 직접 확인합니다.
C++에서는 컨테이너의 재할당과 반복자 무효화 여부를 함께 봅니다.
Python 정수는 임의 정밀도이므로 값이 커질수록 정수 연산 비용도 증가할 수 있습니다. [Python 숫자형 문서](https://docs.python.org/3/library/stdtypes.html#numeric-types-int-float-complex)
세 언어 모두 같은 O(N log N)이어도 비교 함수 호출, 객체 생성, 입출력 비용은 다릅니다.
작은 입력의 정답 비교와 대표 큰 입력의 시간 확인은 서로 다른 검증입니다.

## 실전과 현업의 적용 조건

반복 보고서 생성에서는 같은 데이터로 질의가 반복되는지 먼저 확인합니다.
데이터가 매 질의마다 바뀌면 정적 누적합 대신 갱신을 지원하는 구조가 필요할 수 있습니다.
경로 계획에서는 도로 방향, 이동 시간의 음수 여부, 시간대별 변화가 모델을 바꿉니다.
이 사례들은 설계 상황을 설명하며 특정 서비스의 실제 내부 구현을 주장하지 않습니다.

## 실수와 반례

- 평균 입력만 생각하면 모든 값이 같은 경우나 한쪽으로 치우친 경우의 최악 비용을 놓칩니다.
- N만 세고 문자열 길이를 무시하면 긴 키를 비교하거나 해시하는 비용이 사라집니다.
- “항상 된다”는 직관은 작은 반례 하나로 깨질 수 있으므로 적용 조건을 명시합니다.
- 정답인 느린 기준 풀이를 버리면 빠른 풀이를 작은 입력에서 비교할 도구도 잃습니다.

## 복습 질문과 답

질문 1. O(N) 풀이가 O(N log N) 풀이보다 항상 빠릅니까?

답. 증가 경향은 더 작지만 상수, 입력 규모, 연산 종류에 따라 실제 시간은 달라집니다.

질문 2. 모델이 실제 문제와 같다는 것은 어떻게 확인합니까?

답. 실제 해와 모델의 해가 양방향으로 대응하며 비용도 보존되는지 확인합니다.

질문 3. 느린 풀이를 먼저 쓰는 이유는 무엇입니까?

답. 작은 입력에서 정답 기준을 만들고 빠른 풀이가 버린 후보가 없는지 비교하기 위해서입니다.

## C·C++·Python으로 같은 예제 실행

같은 반열린 구간 질의를 직접 순회와 누적합으로 각각 계산해 결과와 계산 구조를 비교합니다.

이 예제에서 직접 구현하는 기법은 문제 모델링 · 비용 비교 · 직접 순회 · 누적합입니다. 같은 표준 입력에서 세 언어가 같은 결과를 출력합니다.

### 입력과 출력

첫 줄 N Q(1≤N,Q≤50), 다음 N개 정수(−1000~1000), 이후 Q줄에 0≤l≤r≤N입니다.

```text
5 2
3 1 4 2 5
1 4
0 5
```

첫 줄은 직접 합산한 Q개 결과, 둘째 줄은 누적합으로 구한 같은 결과입니다.

```text
7 15
7 15
```

### 입력부터 결과까지

| 단계 | 중간 상태 | 수행 이유 |
| --- | --- | --- |
| 1 | a=[3,1,4,2,5], 질의=[(1,4),(0,5)] | 입력과 출력 조건을 같은 반열린 구간으로 모델링합니다. |
| 2 | 직접 첫 질의: 1+4+2=7 | 질의 구간의 세 원소를 읽습니다. |
| 3 | prefix=[0,3,4,8,10,15] | 앞의 i개 합을 한 번 구축합니다. |
| 4 | prefix[4]−prefix[1]=10−3=7, prefix[5]−prefix[0]=15 | 같은 답을 경계 두 개의 차이로 계산합니다. |

### C 예제

[실행 가능한 C 파일](<예제_examples/01-문제모델링과복잡도_modeling-complexity/example.c>)

```c
#include <stdio.h> // 정수 입력과 결과 출력에 쓸 표준 함수
int main(void) { // 실행 시작점
    int n, q, a[50], l[50], r[50]; // 최대 50개 값과 질의의 반열린 경계
    long long prefix[51] = {0}, direct[50]; // 빈 접두 합과 직접 계산 결과
    scanf("%d %d", &n, &q); // 값 개수와 질의 개수 읽기
    for (int i = 0; i < n; ++i) scanf("%d", &a[i]); // 원래 배열 입력
    for (int i = 0; i < q; ++i) scanf("%d %d", &l[i], &r[i]); // 모든 질의의 시작과 끝 저장
    for (int i = 0; i < q; ++i) { // 직접 합산 방식으로 각 질의 처리
        direct[i] = 0; // 이번 질의의 합 초기화
        for (int j = l[i]; j < r[i]; ++j) direct[i] += a[j]; // 대상 구간의 원소를 하나씩 더하기
        printf("%s%lld", i ? " " : "", direct[i]); // 직접 구한 합을 질의 순서대로 출력
    } // 직접 합산 결과 한 줄 완성
    printf("\n"); // 첫 결과 줄 끝내기
    for (int i = 0; i < n; ++i) prefix[i + 1] = prefix[i] + a[i]; // 배열을 한 번 읽어 접두 합 구축
    for (int i = 0; i < q; ++i) printf("%s%lld", i ? " " : "", prefix[r[i]] - prefix[l[i]]); // 두 접두 합 차이로 같은 질의 출력
    printf("\n"); // 누적합 결과 줄 끝내기
    return 0; // 정상 종료
} // 두 방식의 비교 끝
```

### C++ 예제

[실행 가능한 C++ 파일](<예제_examples/01-문제모델링과복잡도_modeling-complexity/example.cpp>)

```cpp
#include <iostream> // 표준 입력과 출력 스트림
#include <vector> // 입력 크기에 맞춘 값과 질의 배열
using namespace std; // 표준 이름의 접두사 생략
int main() { // 실행 시작점
    int n, q; cin >> n >> q; // 원소 수와 질의 수 읽기
    vector<int> a(n), l(q), r(q); // 값과 반열린 질의 경계 저장
    vector<long long> prefix(n + 1, 0); // 빈 구간을 포함한 접두 합
    for (int& value : a) cin >> value; // 원래 배열 입력
    for (int i = 0; i < q; ++i) cin >> l[i] >> r[i]; // 질의 경계 입력
    for (int i = 0; i < q; ++i) { // 직접 합산으로 질의 처리
        long long total = 0; // 이번 구간 합 초기화
        for (int j = l[i]; j < r[i]; ++j) total += a[j]; // 구간 원소를 하나씩 더하기
        cout << (i ? " " : "") << total; // 직접 계산 결과 출력
    } // 직접 합산 종료
    cout << '\n'; // 첫 결과 줄 끝내기
    for (int i = 0; i < n; ++i) prefix[i + 1] = prefix[i] + a[i]; // 한 번의 순회로 접두 합 구축
    for (int i = 0; i < q; ++i) cout << (i ? " " : "") << prefix[r[i]] - prefix[l[i]]; // 공통 앞부분을 빼 같은 질의 처리
    cout << '\n'; // 둘째 결과 줄 끝내기
    return 0; // 정상 종료
} // 두 방식의 비교 끝
```

### Python 예제

[실행 가능한 Python 파일](<예제_examples/01-문제모델링과복잡도_modeling-complexity/example.py>)

```python
import sys # 전체 정수 입력을 읽을 표준 모듈
data = list(map(int, sys.stdin.buffer.read().split())) # 공백 토큰을 정수로 변환
n, q = data[:2] # 원소 수와 질의 수 해체
values = data[2:2 + n] # 원래 값 배열 분리
queries = [tuple(data[2 + n + 2 * i:4 + n + 2 * i]) for i in range(q)] # 질의의 반열린 경계 묶기
direct = [] # 직접 합산 결과 목록
for left, right in queries: # 각 질의를 입력 순서대로 확인
    total = 0 # 이번 구간 합 초기화
    for index in range(left, right): # 대상 구간 인덱스 순회
        total += values[index] # 원소 하나씩 합산
    direct.append(total) # 직접 구한 합 저장
prefix = [0] # 빈 접두 구간의 합
for value in values: # 원소를 한 번씩만 읽기
    prefix.append(prefix[-1] + value) # 다음 접두 합 생성
fast = [prefix[right] - prefix[left] for left, right in queries] # 같은 질의를 두 접두 합 차이로 계산
print(*direct) # 직접 합산 결과를 첫 줄에 출력
print(*fast) # 누적합 결과를 둘째 줄에 출력
```

- 시간: 직접 방식 O(NQ), 누적합 방식 O(N+Q), 둘 다 실행하는 이 프로그램은 O(NQ+N+Q)입니다.
