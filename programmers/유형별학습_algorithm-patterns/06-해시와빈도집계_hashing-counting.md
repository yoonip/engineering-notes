# 해시와 빈도 집계

[학습목차](README.md) · [연습문제](연습문제_problem-index.md)

## 값으로 위치를 찾는 방법

해시 테이블은 키를 해시값으로 바꾸어 저장 위치를 정하고 같은 키의 값을 빠르게 찾는 구조입니다.
빈도 집계는 각 키에 등장 횟수를 연결하는 활용입니다.
이름에서 정보 찾기, 중복 검사, 두 집합의 일치 여부처럼 원래 입력 순서보다 같은 값의 식별이 중요할 때 유용합니다.
단순 배열 인덱스로 표현하기 어려운 큰 수나 문자열 키도 다룰 수 있습니다.

서로 다른 키가 같은 위치로 가는 충돌은 정상적으로 처리해야 하는 상황입니다.
해시값이 같다는 사실만으로 키 자체가 같다고 판단하면 안 됩니다.
적절한 해시와 부하율 조절 같은 가정 아래에서 기대·분할 상환 상수 시간이 나오는 것이지 모든 입력에 대한 무조건 상수 시간은 아닙니다. [MIT 강의 4, Chaining·Universal Hashing·Dynamic](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/ce9e94705b914598ce78a00a70a1f734_MIT6_006S20_lec4.pdf)

## 인식 단서와 다른 선택

“같은 값이 몇 번”, “이전에 등장했는지”, “이름으로 조회”, “순서와 무관한 동일 구성”은 해시의 단서입니다.
키가 0부터 K-1까지 작은 정수라면 길이 K의 빈도 배열이 더 단순할 수 있습니다.
키의 범위가 너무 크면 실제 등장한 키만 저장하는 해시나 좌표 압축을 검토합니다.
최솟값, 이웃 키, 구간 안의 키 개수가 필요하다면 해시만으로 순서 질의를 해결할 수 없습니다.

키가 변경 가능한 객체라면 저장 후 동등성이나 해시가 바뀌지 않는지도 확인해야 합니다.
“객체가 같은가”와 “업무상 같은 항목인가”는 다를 수 있으므로 식별 키를 먼저 정의합니다.

## 직접 구성한 예제: 재고와 요청

재고가 `A,A,B,C`이고 요청이 `A,C,C`라고 가정합니다.
같은 이름의 물건은 서로 대체 가능하며 각 요청은 물건 하나를 사용합니다.

| 요청 처리 | 처리 전 관련 재고 | 판정 | 처리 후 |
|---|---:|---|---:|
| A | A:2 | 공급 가능 | A:1 |
| C | C:1 | 공급 가능 | C:0 |
| C | C:0 | 공급 불가능 | 전체 요청 실패 |

이때 재고에 C가 존재한다는 집합 정보만으로는 두 번째 C 요청을 거부할 수 없습니다.
중복을 구별해야 하므로 존재 여부가 아니라 개수를 저장해야 합니다.

```python
stock = {}  # 딕셔너리로 물건 이름별 남은 개수 저장
for item in ["A", "A", "B", "C"]:  # for문으로 재고를 한 번씩 읽기
    stock[item] = stock.get(item, 0) + 1  # 없는 키는 0으로 보고 해당 재고 개수 증가
possible = True  # 모든 요청을 처리할 수 있다는 초기 가정
for item in ["A", "C", "C"]:  # 요청을 순서대로 확인
    if stock.get(item, 0) == 0:  # 필요한 물건이 남아 있는지 검사
        possible = False  # 공급 불가능한 요청을 발견한 상태 기록
        break  # 이후 요청을 더 확인하지 않고 실패 확정
    stock[item] -= 1  # 처리한 요청 하나만큼 남은 재고 차감
```

## 정답성의 불변식

재고를 세는 반복에서 `stock[k]`는 지금까지 읽은 재고 중 키 k의 등장 횟수입니다.
초기 빈 딕셔너리와 키 하나의 증가로 이 의미가 유지됩니다.
요청 처리에서는 `stock[k]`가 초기 재고에서 이미 공급한 요청 수를 뺀 값입니다.
값이 0일 때 추가 요청을 거부하므로 같은 물건을 중복으로 공급하지 않습니다.
모든 요청을 끝냈다면 각 요청에 재고 하나를 대응시켰으므로 충분성이 성립합니다.

## 기대 시간과 문자열 키 비용

재고 N개와 요청 Q개를 읽는 예제는 키 처리 비용을 상수로 가정하면 기대 O(N+Q) 시간입니다.
공간은 실제 서로 다른 키 수 K에 대해 O(K)입니다.
길이가 긴 문자열 키는 내용을 읽는 해시 계산과 충돌 시 동등성 비교 비용도 포함해야 합니다.
모든 키를 한꺼번에 저장하는 대신 필요한 통계만 유지할 수 있는지 검토합니다.

최악 시간 보장이 중요하거나 입력을 외부에서 적대적으로 선택할 수 있다면 해시의 가정을 별도로 확인합니다.
정렬 후 같은 키를 연속 집계하는 방식은 O(N log N) 비교 비용을 지불하는 대안입니다.

## 언어별 자료구조

C에서는 버킷 배열, 충돌 처리, 삭제 표시, 재해시와 메모리 소유권을 직접 설계하거나 검증된 구현을 사용합니다.
C++의 `unordered_map`은 해시 기반 조회, `map`은 순서 있는 조회라는 서로 다른 연산 요구에 대응합니다.
Python에서는 `dict`, `set`, `collections.Counter`의 목적을 구별합니다.
`Counter`는 없는 키의 개수를 0으로 읽지만, 개수를 0으로 만든 키를 자동 삭제하지는 않습니다. [Python collections.Counter](https://docs.python.org/3/library/collections.html#collections.Counter)
따라서 “저장된 키 수”와 “현재 양수 개수인 항목 수”를 혼동하면 안 됩니다.

## 실전의 적용 조건

로그에서 오류 코드별 건수를 세는 작업은 코드의 종류가 제한되면 빈도 배열로도 처리할 수 있습니다.
텍스트 토큰 빈도에서는 대소문자 통합과 구두점 제거 여부에 따라 서로 같은 키의 정의가 달라집니다.
서로 다른 사용자 수를 정확히 세려면 중복 제거용 키의 범위와 보관 기간도 정해야 합니다.
이 예시는 정확 집계의 조건이며 근사 집계나 특정 분석 제품의 구현을 설명하지 않습니다.

## 실수와 반례

- 재고 `A,A`와 `A`는 집합으로 바꾸면 모두 `{A}`가 되어 개수 차이를 잃습니다.
- 해시값만 저장하면 충돌한 다른 문자열을 같은 값으로 셀 수 있습니다.
- 딕셔너리의 순회 순서를 숫자나 사전식 정렬 순서라고 가정하면 안 됩니다.
- 빈도 감소 뒤 0인 키를 남겼다면 서로 다른 활성 값의 개수를 `len`으로 바로 구할 수 없습니다.

## 복습 질문과 답

질문 1. 같은 해시값이면 같은 원소입니까?

답. 아닙니다. 충돌이 가능하므로 실제 키의 동등성 확인이 필요합니다.

질문 2. `Counter`의 키가 존재하면 남은 개수가 양수입니까?

답. 아닙니다. 0이나 음수도 저장할 수 있으므로 값의 의미를 직접 검사해야 합니다.

질문 3. 해시 대신 빈도 배열을 고를 조건은 무엇입니까?

답. 키를 작은 정수 구간의 인덱스로 직접 표현할 수 있고 그 범위를 할당할 수 있을 때입니다.

## C·C++·Python으로 같은 예제 실행

각 값을 한 번 집계한 뒤 질의 키의 등장 횟수를 조회합니다. C 예제는 충돌을 선형 탐사로 직접 처리합니다.

이 예제에서 직접 구현하는 기법은 해시 · 충돌 처리 · 빈도 집계입니다. 같은 표준 입력에서 세 언어가 같은 결과를 출력합니다.

### 입력과 출력

N Q(0≤N≤20,1≤Q≤20), N개 값, Q개 질의 키입니다. 키는 −1000~1000입니다.

```text
6 3
10 20 10 -5 20 10
10 -5 7
```

각 질의 키의 빈도를 한 줄에 출력합니다.

```text
3 1 0
```

### 입력부터 결과까지

| 단계 | 중간 상태 | 수행 이유 |
| --- | --- | --- |
| 1 | 빈 테이블 | 집계 전에는 모든 키의 개수가 0입니다. |
| 2 | 10을 세 번 읽어 counts[10]=3 | 같은 키는 같은 빈도에 합칩니다. |
| 3 | counts[20]=2,counts[−5]=1 | 다른 키는 독립된 개수를 보관합니다. |
| 4 | 질의10,−5,7의 답=3,1,0 | 등장하지 않은 키를 0으로 처리합니다. |

### C 예제

[실행 가능한 C 파일](<예제_examples/06-해시와빈도집계_hashing-counting/example.c>)

```c
#include <stdio.h> // 빈도 입력과 출력
enum { CAPACITY = 53 }; // 서로 다른 키 최대 20개보다 넉넉한 해시 칸 수
static int used[CAPACITY], keys[CAPACITY], counts[CAPACITY]; // 빈 칸 표시·키·빈도 배열
static int locate(int key) { // 키가 있거나 처음 빈 칸인 위치 찾기
    int slot = (key % CAPACITY + CAPACITY) % CAPACITY; // 음수 키도 0~52의 시작 위치로 변환
    while (used[slot] && keys[slot] != key) slot = (slot + 1) % CAPACITY; // 충돌한 다른 키 뒤를 선형 탐사
    return slot; // 같은 키 또는 삽입 가능한 빈 칸 반환
} // 해시 위치 탐색 끝
int main(void) { // 실행 시작점
    int n, q; scanf("%d %d", &n, &q); // 값 수와 질의 수 읽기
    for (int i = 0; i < n; ++i) { // 값을 한 번씩 집계
        int key; scanf("%d", &key); int slot = locate(key); // 값과 해시 칸 찾기
        used[slot] = 1; keys[slot] = key; ++counts[slot]; // 키를 보관하고 빈도 증가
    } // 전체 빈도 구축 끝
    for (int i = 0; i < q; ++i) { // 질의 키를 차례로 조회
        int key; scanf("%d", &key); int slot = locate(key); // 찾는 키의 칸 확인
        printf("%s%d", i ? " " : "", used[slot] ? counts[slot] : 0); // 없는 키는 0으로 출력
    } // 모든 질의 처리 끝
    printf("\n"); // 출력 줄 끝내기
    return 0; // 정상 종료
} // 해시 빈도 집계 끝
```

### C++ 예제

[실행 가능한 C++ 파일](<예제_examples/06-해시와빈도집계_hashing-counting/example.cpp>)

```cpp
#include <iostream> // 정수 입력과 결과 출력
#include <unordered_map> // 키에서 빈도를 찾을 해시 테이블
using namespace std; // 표준 이름 접두사 생략
int main() { // 실행 시작점
    int n, q; cin >> n >> q; unordered_map<int, int> counts; // 개수와 빈도 테이블 준비
    for (int i = 0; i < n; ++i) { // 모든 입력 값을 집계
        int key; cin >> key; ++counts[key]; // 없는 키는 0에서 시작해 빈도 증가
    } // 빈도 구축 끝
    for (int i = 0; i < q; ++i) { // 질의 키를 순서대로 조회
        int key; cin >> key; auto found = counts.find(key); // 조회만 하고 없는 키를 새로 넣지 않기
        int answer = found == counts.end() ? 0 : found->second; // 찾지 못하면 빈도 0
        cout << (i ? " " : "") << answer; // 질의 순서대로 빈도 출력
    } // 질의 처리 끝
    cout << '\n'; // 출력 줄 끝내기
    return 0; // 정상 종료
} // 해시 빈도 집계 끝
```

### Python 예제

[실행 가능한 Python 파일](<예제_examples/06-해시와빈도집계_hashing-counting/example.py>)

```python
import sys # 정수 토큰 입력
data = list(map(int, sys.stdin.buffer.read().split())) # 공백 입력을 정수로 변환
n, q = data[:2] # 값 수와 질의 수
counts = {} # 키별 빈도를 저장할 해시 딕셔너리
for key in data[2:2 + n]: # 입력 값 한 번씩 순회
    counts[key] = counts.get(key, 0) + 1 # 없는 키의 기본 빈도 0에서 증가
queries = data[2 + n:2 + n + q] # 조회할 키 목록 분리
print(*(counts.get(key, 0) for key in queries)) # 없는 키는 0으로 답하고 원래 질의 순서 유지
```

### 언어별 차이

| 비교할 점 | C | C++ | Python |
| --- | --- | --- | --- |
| 입력 | scanf로 공백으로 구분된 정수를 읽습니다. | cin으로 공백으로 구분된 정수를 읽습니다. | buffer.read().split()으로 입력 토큰을 한 번에 읽고 정수로 해석합니다. |
| 저장과 연산 | 53칸 배열과 선형 탐사를 직접 사용합니다. | unordered_map이 해시 저장과 충돌 처리를 담당합니다. | dict의 get으로 없는 키를 0으로 읽습니다. |
| 자료형과 범위 | 키와 최대 빈도 20은 int 범위 안입니다. | 키와 최대 빈도 20은 int 범위 안입니다. | int로 정수를 저장합니다. 허용 입력 범위는 C·C++ 예제와 같습니다. |

### 예제의 비용과 실행 파일

- 시간: 키 처리의 평균 비용을 일정하게 보는 해시 모형에서 O(N+Q)입니다. 충돌이 몰리면 키 탐색이 길어질 수 있습니다.
- 보조 공간: 해시 자체는 C에서 고정53칸, C++·Python에서 서로 다른 키 수 D에 대해 O(D)입니다. Python의 입력·질의 목록에는 O(N+Q)가 추가됩니다.

원래 값을 질의마다 다시 세지 않고 키의 집계 결과를 재사용합니다.
