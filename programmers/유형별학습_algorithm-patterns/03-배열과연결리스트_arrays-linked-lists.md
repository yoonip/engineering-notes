# 배열과 연결 리스트

[학습목차](README.md) · [연습문제](연습문제_problem-index.md)

## 같은 순서와 다른 저장 방식

배열과 연결 리스트는 모두 원소의 순서를 표현하지만 위치를 찾는 방식이 다릅니다.
배열은 연속한 저장 공간과 인덱스를 이용하고, 연결 리스트는 다음 원소로 가는 연결을 이용합니다.
따라서 “순서가 있는 자료”라는 말만으로 어느 구조가 적절한지 결정할 수 없습니다.
인덱스 조회, 끝 추가, 중간 삽입처럼 자주 수행할 연산을 먼저 나누어야 합니다.
MIT 6.006은 순서에 대한 인터페이스와 그 연산을 지원하는 실제 표현을 구별합니다. [MIT 강의 2, Sequence Interface·Array Sequence·Linked List](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/79a07dc1cb47d76dae2ffedc701e3d2b_MIT6_006S20_lec2.pdf)

## 인식 단서와 부적합한 선택

“i번째 원소를 자주 읽는다”면 배열 계열의 임의 접근이 유리합니다.
“이미 가리키는 노드 뒤에 끼워 넣는다”면 연결 변경의 이점이 있습니다.
그러나 “값 x를 찾아 그 뒤에 삽입”은 찾는 비용까지 포함하므로 연결 리스트라고 O(1)이 되지 않습니다.
원소 수가 고정되고 순회가 많다면 포인터를 따라가는 구조보다 배열이 단순할 수 있습니다.

연결 리스트의 장점은 삽입 위치의 노드나 필요한 앞 노드를 이미 알고 있다는 조건에서 나옵니다.
배열도 사용하지 않는 여유 공간이 있다고 해서 중간 삽입의 이동 비용까지 없어지지는 않습니다.

## 연산별 비교

| 연산 | 연속 배열 | 단일 연결 리스트 |
|---|---|---|
| i번째 조회 | O(1) | O(N) 최악 |
| 맨 앞 추가 | O(N) 이동 | O(1) 연결 변경 |
| 알려진 노드 뒤 추가 | O(N) 이동 최악 | O(1) 연결 변경 |
| 마지막 원소 추가 | 용량 내 O(1) | 꼬리 포인터가 있으면 O(1) |
| 알려진 값 검색 | O(N) | O(N) |

동적 배열은 용량을 기하급수적으로 늘리는 설계에서 끝 추가의 분할 상환 O(1)을 얻습니다.
이것은 모든 추가가 O(1)이라는 뜻이 아니라 여러 추가의 총비용을 나누어 본 결과입니다. [MIT 강의 2, Dynamic Arrays·Amortized Analysis](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/79a07dc1cb47d76dae2ffedc701e3d2b_MIT6_006S20_lec2.pdf)

## 직접 구성한 예제: 순서 중간에 항목 추가

순서 `[A,C,D]`에서 A 뒤에 B를 넣는다고 가정합니다.
배열은 뒤 원소를 먼저 한 칸씩 이동해야 기존 값을 덮어쓰지 않습니다.
연결 리스트는 A 노드의 위치를 이미 알고 있다고 가정합니다.

| 단계 | 배열의 유효 구간 | 연결 리스트의 연결 |
|---|---|---|
| 시작 | A,C,D | A→C→D |
| 공간 확보 | A,C,D,빈칸 | 새 B 노드 확보 |
| 첫 변경 | A,C,D,D | B의 next를 C로 지정 |
| 둘째 변경 | A,C,C,D | A의 next를 B로 지정 |
| 마무리 | A,B,C,D | A→B→C→D |

연결 리스트에서 A의 next부터 B로 바꾸고 옛 C의 위치를 보관하지 않으면 나머지 연결을 잃을 수 있습니다.
배열에서 앞에서부터 이동하면 C를 복사한 값으로 D를 덮어쓸 수 있습니다.

## 구현 절차와 불변식

배열에서는 할당한 용량과 실제 원소 수를 구별합니다.
삽입 전 용량을 확인하고 뒤에서 앞으로 이동한 뒤 새 값을 넣고 길이를 늘립니다.
반복 중에는 “아직 옮기지 않은 앞부분과 이미 옮긴 뒷부분이 각각 보존된다”는 의미를 유지합니다.

연결 리스트에서는 머리, 꼬리, 다음 연결이 서로 일치해야 합니다.
삽입 전 모든 기존 원소로 이어지는 경로를 보존한 채 새 노드를 그 경로 사이에 넣습니다.
삭제에서는 연결에서 먼저 분리한 뒤 더 이상 쓰이지 않는 노드의 수명을 끝냅니다.
빈 리스트와 원소 하나인 리스트는 머리·꼬리가 함께 바뀌는 특별한 경계입니다.

## 인덱스 기반 연결의 작은 코드

다음은 노드 번호로 연결을 표현한 직접 구성 예제입니다.
0번이 A, 1번이 C, 2번이 D이며 새 B는 3번입니다.

```python
labels = ["A", "C", "D", "B"]  # 리스트에 노드별 값 저장
next_node = [1, 2, -1, -1]  # -1을 끝 표시로 사용하는 다음 노드 번호 배열
after = 0  # 이미 알고 있는 삽입 위치 A의 노드 번호
new_node = 3  # 새로 연결할 B의 노드 번호
next_node[new_node] = next_node[after]  # 새 노드가 기존 뒷부분 C를 먼저 가리키게 설정
next_node[after] = new_node  # A의 다음 연결을 B로 바꾸어 순서에 끼워 넣기
```

이 코드는 노드 번호를 아는 상황의 O(1) 연결 변경만 보여 줍니다.
값 B를 검색하거나 메모리를 새로 확보하는 비용까지 모두 O(1)이라고 주장하는 코드는 아닙니다.

## 시간·공간과 언어 차이

연결 리스트는 값 외에도 연결 정보를 저장하며 노드별 할당 비용이 생길 수 있습니다.
연속 배열은 순차 접근에서 지역성을 활용하기 좋지만 실제 성능은 자료 크기와 실행 환경에 따라 달라집니다.
C 배열은 길이를 자동으로 알 수 없으므로 길이와 용량을 별도로 전달해야 합니다.
C에서 `realloc` 뒤의 저장 위치가 바뀔 수 있으므로 옛 주소를 계속 쓰지 않도록 설계합니다.
C++의 `vector`와 `list`는 이름에 대응하는 연산 특성을 이해한 뒤 선택합니다.
Python `list`는 단일 연결 리스트가 아니라 동적 배열 계열이므로 앞 원소 삭제를 반복하는 큐 구현에 주의합니다.

## 실전의 선택 조건

최근 항목을 순서대로 읽는 작업은 배열로 저장하고 일괄 순회하는 설계가 자연스럽습니다.
캐시의 사용 순서를 고치며 특정 항목을 즉시 옮겨야 한다면 해시와 이중 연결 구조를 결합할 수 있습니다.
이 경우 해시는 노드 위치를 찾고 연결 구조는 앞뒤 순서를 바꾸는 서로 다른 역할을 맡습니다.
예시는 구조 선택의 조건이며 모든 캐시가 같은 구현을 쓴다는 뜻은 아닙니다.

## 실수와 반례

- 단일 연결 리스트에서 현재 노드만 알면 그 노드의 임의 삭제가 항상 O(1)이라는 설명은 부정확합니다. 앞 노드가 필요할 수 있습니다.
- 꼬리 포인터가 없는 리스트에서 끝 추가를 N번 하면 반복 검색으로 O(N²)이 될 수 있습니다.
- 삭제한 노드의 주소나 무효화된 참조를 보관하면 논리적 순서가 맞아도 수명 오류가 생깁니다.
- 배열의 빈 용량을 원소로 취급하면 초기화하지 않은 값을 결과에 섞을 수 있습니다.
