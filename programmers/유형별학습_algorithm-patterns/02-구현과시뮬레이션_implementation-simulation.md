# 구현과 시뮬레이션

[학습목차](README.md) · [연습문제](연습문제_problem-index.md)

## 규칙과 상태 전이

구현 문제의 핵심은 긴 설명을 정확한 상태 전이로 바꾸는 것입니다.
시뮬레이션은 현재 상태에 규칙을 적용해 다음 상태를 만드는 계산입니다.
여기서 상태는 다음 행동과 결과를 결정하는 데 필요한 정보의 묶음입니다.
위치만으로 부족하면 방향, 남은 자원, 방문 기록, 현재 단계도 포함합니다.

중요한 이유는 규칙 하나의 해석 차이가 전체 과정의 결과를 바꾸기 때문입니다.
알고리즘이 단순해도 경계, 갱신 순서, 종료 시점이 맞지 않으면 다른 시스템을 계산하게 됩니다.
반복 과정은 초기화·유지·종료 조건을 따로 보며 검토할 수 있습니다. [Cornell CS2112, Loop Invariants](https://www.cs.cornell.edu/courses/cs2112/2021fa/lectures/lecture.html?id=loopinv)

## 인식 단서와 적용 한계

“명령을 차례로 수행”, “한 턴마다 이동”, “동시에 변화” 같은 표현은 상태 전이의 단서입니다.
작업 수 T가 작으면 설명 그대로 T번 실행하는 방법이 적절할 수 있습니다.
T가 10억처럼 크면 주기 탐지, 수식, 사건 단위 건너뛰기 등 반복 횟수를 줄일 방법이 필요합니다.
한 사건마다 모든 물체를 검사한다면 물체 수 N과 사건 수 T의 곱도 확인합니다.

상태에서 과거 정보를 지워도 되는지는 규칙에 달려 있습니다.
방문한 칸에서는 보상이 다시 생기지 않는다면 현재 위치만 같은 두 상황은 같은 상태가 아닙니다.
반대로 미래에 영향을 주지 않는 로그 전체를 상태에 넣으면 메모리만 늘어납니다.

## 직접 구성한 예제: 작은 로봇

가로·세로 크기가 3인 격자에서 행과 열은 0부터 2까지입니다.
로봇은 `(1,1)`에서 동쪽을 보고 시작하며 `(1,2)`는 벽이라고 가정합니다.
명령 `F`는 앞 칸이 비어 있을 때 한 칸 이동하고, `R`은 제자리에서 오른쪽으로 회전합니다.
명령열은 `F,R,F,F`입니다.

| 처리 명령 | 처리 전 위치·방향 | 검사 또는 변화 | 처리 후 위치·방향 |
|---|---|---|---|
| F | (1,1), 동 | (1,2)는 벽 | (1,1), 동 |
| R | (1,1), 동 | 남쪽으로 회전 | (1,1), 남 |
| F | (1,1), 남 | (2,1)은 빈칸 | (2,1), 남 |
| F | (2,1), 남 | (3,1)은 범위 밖 | (2,1), 남 |

막힌 이동을 “명령 자체를 취소”하는지 “위치만 유지”하는지부터 명확히 해야 합니다.
이 예제에서는 명령은 처리된 것으로 세고 위치만 유지합니다.

## 상태 전이의 작성 순서

1. 상태 변수와 각 변수의 의미를 적습니다.
2. 모든 명령에 대해 읽는 값과 바꾸는 값을 구분합니다.
3. 다음 위치나 변화량을 먼저 계산합니다.
4. 범위와 충돌을 검사한 뒤 허용된 변화만 확정합니다.
5. 결과 기록과 종료 검사를 규칙에서 정한 시점에 수행합니다.

행 증가가 남쪽이라는 좌표 약속을 처음부터 유지합니다.
방향 배열을 북·동·남·서로 두면 오른쪽 회전은 방향 번호에 1을 더한 뒤 4로 나눈 나머지입니다.
중간에 화면 좌표와 수학 좌표를 섞으면 위·아래가 뒤집힙니다.

## 짧은 구현과 줄별 역할

다음은 위 예제를 직접 구현한 Python 코드이며, 실제 로봇 제어 코드가 아닙니다.

```python
position = (1, 1)  # 튜플 대입으로 현재 행·열 저장
direction = 1  # 정수 1을 동쪽 방향 번호로 지정
steps = [(-1, 0), (0, 1), (1, 0), (0, -1)]  # 리스트로 북·동·남·서 이동량 정의
walls = {(1, 2)}  # 집합에 벽 좌표 저장
for command in "FRFF":  # for문으로 명령을 입력 순서대로 처리
    if command == "R":  # 비교식으로 회전 명령 분기
        direction = (direction + 1) % 4  # 나머지 연산으로 방향 번호를 0~3 안에 유지
    else:  # 이 예제의 나머지 명령인 전진 처리
        dr, dc = steps[direction]  # 튜플 해체로 현재 방향 이동량 읽기
        nr, nc = position[0] + dr, position[1] + dc  # 다음 칸을 임시 변수로 계산
        if 0 <= nr < 3 and 0 <= nc < 3 and (nr, nc) not in walls:  # 범위와 벽을 모두 검사
            position = (nr, nc)  # 허용된 이동만 현재 상태에 확정
```

## 정당성의 기준

각 반복 직전에 저장한 상태가 앞선 명령들을 규칙대로 수행한 상태와 같다는 불변식을 둡니다.
초기 상태는 문제에서 지정한 상태이므로 불변식이 성립합니다.
회전은 방향만 바꾸고 전진은 허용 조건을 만족한 위치만 바꾸므로 다음 명령 직전에도 의미가 유지됩니다.
모든 명령이 끝나면 불변식이 최종 상태의 정답성을 설명합니다.
명령 하나마다 처리 위치가 증가하므로 유한한 명령열에서 종료도 보장됩니다.

## 동시 갱신과 시간 복잡도

동시에 번지는 상태를 한 배열에서 즉시 바꾸면 앞에서 갱신한 값이 같은 턴에 다시 사용될 수 있습니다.
예를 들어 `[1,0,0]`에서 인접 칸으로 한 턴에 한 칸만 번져야 할 때, 왼쪽부터 즉시 갱신하면 `[1,1,1]`이 될 수 있습니다.
이 규칙의 올바른 한 턴 결과는 `[1,1,0]`이므로 이전 상태와 다음 상태를 분리해야 합니다.

로봇 예제의 명령 수를 T라고 하면 벽 집합 조회를 평균 상수 시간으로 가정할 때 기대 시간은 O(T)입니다.
격자 전체를 매 턴 검사하는 방식은 높이 H, 너비 W에서 O(THW)입니다.
배열 두 장을 사용하면 공간은 O(HW)이지만 같은 배열을 복사하는 비용도 턴마다 포함합니다.

## 언어와 실전 조건

C에서는 격자 경계 검사 전에 배열을 읽지 않도록 조건 순서를 확인합니다.
C++에서 좌표를 참조로 보관한 채 컨테이너를 재할당하면 참조의 유효성을 확인해야 합니다.
Python에서 `[[0]*W]*H`는 행 객체를 공유하므로 독립된 행을 만드는 표현과 구별합니다.
교통 모형이나 재고 흐름 모형에서는 사건 시각이 드물면 매 시각 반복보다 다음 사건으로 건너뛰는 편이 적절합니다.
이때 같은 시각의 사건 처리 순서가 결과를 바꾸는지 업무 규칙으로 먼저 정해야 합니다.

## 실수와 연계 유형

- 방향 전환 뒤 이동하는지 이동 뒤 전환하는지 섞으면 한 명령부터 결과가 달라집니다.
- 반복 상태를 찾을 때 위치만 비교하면 자원이나 방문 기록이 다른 상태를 잘못 합칠 수 있습니다.
- 디버깅 출력으로 입력 전체를 매번 복사하면 관찰 코드가 성능 병목이 될 수 있습니다.
