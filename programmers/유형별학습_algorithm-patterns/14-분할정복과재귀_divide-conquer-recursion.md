# 분할 정복과 재귀

[학습목차](README.md) · [연습문제](연습문제_problem-index.md)

## 작은 문제의 계약과 결과 결합

재귀는 함수가 같은 종류의 더 작은 문제를 호출하는 표현 방식입니다.
분할 정복은 문제를 여러 부분으로 나누고 각 부분의 해를 구한 뒤 원래 문제의 해로 결합하는 설계입니다.
모든 재귀가 분할 정복인 것은 아니며, 모든 분할 정복을 반드시 재귀 문법으로 작성해야 하는 것도 아닙니다.
병합 정렬의 반복적 아래쪽 결합도 같은 분할 구조를 계산하는 방법입니다.

중요한 이유는 전체 입력을 한 번에 다루는 대신 부분 문제의 정답 계약을 사용해 큰 문제를 설명할 수 있기 때문입니다.
계약에는 입력 범위, 반환 결과의 의미, 원본을 바꾸는지 여부가 포함됩니다.

## 인식 단서와 적용 조건

큰 문제를 작은 동종 문제로 나눌 수 있고 부분 결과를 충분한 정보로 결합할 수 있으면 분할 정복을 검토합니다.
문제를 나눈 뒤 남는 경계 상호작용이 무엇인지 먼저 적습니다.
각 절반의 답만 알면 되는지, 접두·접미·최댓값 같은 추가 요약이 필요한지가 결합 설계를 결정합니다.
예를 들어 최대 부분배열은 왼쪽 내부, 오른쪽 내부, 경계를 가로지르는 경우를 모두 고려해야 합니다.

크기가 줄지 않는 호출은 종료를 보장하지 못합니다.
거의 같은 부분 문제를 반복해 푸는 구조라면 메모이제이션이나 동적 계획법을 검토합니다.

## 직접 구성한 예제: 네 값의 병합 정렬

배열 `[6,1,4,2]`를 오름차순으로 정렬한다고 가정합니다.
각 절반을 정렬하면 `[1,6]`과 `[2,4]`이며 두 정렬 결과를 병합합니다.

| 병합 단계 | 왼쪽 남은 값 | 오른쪽 남은 값 | 이번 선택 | 누적 결과 |
|---:|---|---|---:|---|
| 1 | 1,6 | 2,4 | 1 | 1 |
| 2 | 6 | 2,4 | 2 | 1,2 |
| 3 | 6 | 4 | 4 | 1,2,4 |
| 4 | 6 | 없음 | 6 | 1,2,4,6 |

분할은 원소 수를 줄이고, 결합은 정렬된 두 열의 맨 앞 중 작은 값을 선택합니다.
MIT 6.006도 이 구조와 `2T(N/2)+Θ(N)` 점화식을 함께 설명합니다. [MIT 강의 3, Merge Sort](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/6d1ae5278d02bbecb5c4428928b24194_MIT6_006S20_lec3.pdf)

## 짧은 코드와 호출 계약

다음 함수는 입력 리스트를 직접 바꾸지 않고 정렬된 새 리스트를 반환합니다.

```python
def merge_sort(values):  # 리스트를 정렬한 새 리스트를 돌려주는 재귀 함수
    if len(values) <= 1:  # 더 나눌 필요가 없는 빈 리스트·원소 하나의 기저 사례 검사
        return values.copy()  # 입력을 공유하지 않는 정렬 결과 복사본 반환
    middle = len(values) // 2  # 두 부분의 크기를 비슷하게 나눌 경계
    left = merge_sort(values[:middle])  # 더 작은 왼쪽 부분을 재귀적으로 정렬
    right = merge_sort(values[middle:])  # 더 작은 오른쪽 부분을 재귀적으로 정렬
    merged, i, j = [], 0, 0  # 병합 결과와 두 부분의 다음 읽기 위치 초기화
    while i < len(left) and j < len(right):  # 양쪽에 비교할 값이 남아 있는 동안 반복
        if left[i] <= right[j]:  # 같을 때는 왼쪽 값을 먼저 두는 비교 규칙
            merged.append(left[i]); i += 1  # 왼쪽의 다음 작은 값을 결과에 넣고 위치 전진
        else:  # 오른쪽의 다음 값이 더 작은 경우
            merged.append(right[j]); j += 1  # 오른쪽 값을 넣고 위치 전진
    merged.extend(left[i:])  # 오른쪽이 끝났다면 남은 왼쪽 값들을 순서대로 추가
    merged.extend(right[j:])  # 왼쪽이 끝났다면 남은 오른쪽 값들을 순서대로 추가
    return merged  # 두 정렬 결과를 합친 새 정렬 리스트 반환
```

각 재귀 호출의 결과가 정렬되어 있다는 계약을 사용하되, 그 계약은 더 작은 입력에 대한 귀납으로 뒷받침해야 합니다.
“재귀가 알아서 해 준다”는 말만으로 계약과 종료의 설명을 대신하지 않습니다.

## 정당성의 귀납과 병합 불변식

원소가 0개나 1개인 리스트는 이미 정렬되어 있으므로 기저 사례가 맞습니다.
더 작은 모든 입력의 결과가 맞다고 가정하면 두 재귀 결과는 정렬되어 있고 원래 원소들을 보존합니다.
병합 반복에서는 결과가 지금까지 소비한 원소들을 정렬한 목록이라는 불변식을 유지합니다.
양쪽의 남은 맨 앞보다 더 작은 미소비 원소는 없으므로 두 앞값 중 작은 값을 다음에 놓는 것이 맞습니다.
한쪽이 끝나면 다른 쪽의 남은 순서도 이미 정렬되어 있으므로 그대로 붙일 수 있습니다.
따라서 전체 결과도 정렬된 입력의 순열이며 귀납 단계가 성립합니다.

종료는 정답성과 별개로 확인합니다.
길이가 2 이상이면 두 호출 모두 원래 길이보다 작고, 반복 병합에서도 i 또는 j가 늘어나므로 유한 시간에 끝납니다.

## 재귀 트리와 비용

균형 분할에서는 깊이가 O(log N)이고 각 깊이의 전체 병합량이 O(N)입니다.
따라서 시간은 O(N log N)입니다.
호출이 두 번이라는 이유만으로 O(2^N)이라고 계산하면 부분 문제 크기가 줄어드는 효과를 놓칩니다.
반대로 `T(N)=T(N-1)+O(N)`처럼 한 개씩만 줄어들면 총합은 O(N²)일 수 있습니다.

위 리스트 코드의 슬라이스·복사 비용도 깊이별 O(N) 작업에 포함됩니다.
동시에 살아 있는 부분 리스트·결과의 총크기는 O(N), 호출 경로 자체는 O(log N)입니다.
실행 전체에서 누적해서 할당한 양과 한 시점의 최대 보조 공간은 서로 다른 값입니다.

## 언어와 구현 선택

C에서는 보조 배열을 한 번 할당하고 인덱스 범위를 전달하여 반복 할당을 줄일 수 있습니다.
C++에서도 부분 컨테이너 복사 대신 반복자나 인덱스 구간을 전달하는 방식을 검토합니다.
Python에서 슬라이스는 새 리스트를 만들므로 범위 인덱스 방식과 비용을 비교합니다.
균형 분할의 깊이는 로그이지만 연결 경로를 한 정점씩 방문하는 재귀는 깊이가 N이 될 수 있습니다.
후자의 경우 언어의 호출 스택을 확인하고 명시적 스택으로 바꾸는 방법을 검토합니다.

## 실전의 적용 조건

큰 파일들을 부분 정렬한 뒤 합치는 모형에서는 결합 단계가 순차 읽기로 가능하다는 점이 중요합니다.
메모리 밖의 자료를 처리한다면 디스크 읽기·쓰기 횟수와 버퍼 크기를 별도 비용으로 계산해야 합니다.
병렬 처리도 부분 작업이 독립적으로 실행될 수 있을 때 가능하며, 결합·통신 비용이 사라지는 것은 아닙니다.
이는 분할 구조의 활용 조건이며 특정 데이터 처리 제품의 실제 파이프라인을 단정하지 않습니다.

## 실수와 반례

- 길이 2에서 같은 길이의 하위 구간을 다시 넘기면 기저 사례에 도달하지 못합니다.
- 양쪽 절반의 최대 부분배열 답만 취하면 `[2,-1,2]`처럼 경계를 가로지르는 정답을 놓칠 수 있습니다.
- 정렬 결과를 원본에 쓸지 새로 반환할지 섞으면 호출자는 바뀌지 않은 배열을 답으로 읽을 수 있습니다.
- 두 부분의 크기가 항상 균형이라고 가정하면 편향된 분할의 최악 비용을 놓칩니다.

## 복습 질문과 답

질문 1. 재귀 호출이 두 개면 지수 시간입니까?

답. 호출 수뿐 아니라 크기 감소와 결합 비용을 함께 보아야 하며 병합 정렬은 O(N log N)입니다.

질문 2. 결합 단계에서 더 큰 앞값을 먼저 고르면 무엇이 깨집니까?

답. 나중에 더 작은 값을 뒤에 둘 수밖에 없어 병합 결과가 정렬되어 있다는 불변식이 깨집니다.
