# 무엇을 설계하고 무엇을 넘기는가 | Design objects and handoffs

[설계 목차](README.md) · [Linux 환경](01-Linux설치와라이선스_linux-eda-setup.md) · [PDK와 공정 노드](02-공정노드와PDK및라이브러리_process-pdk-libraries.md)

## 칩을 만든다는 말의 범위

전자회로는 소자와 배선의 연결입니다. 집적회로, 즉 IC는 그 회로를 반도체 위에 집적한 것입니다. 웨이퍼는 여러 설계의 다이를 만들 수 있는 원판이고, die는 웨이퍼에서 분리하는 개별 칩 조각입니다. package는 다이의 외부 연결·보호·기계적 지지·열 전달을 맡습니다. SoC는 프로세서·메모리·주변 장치 등의 기능을 하나의 시스템으로 집적한 설계를 뜻하며, package와 같은 기준의 분류가 아닙니다.

회로 설계자는 전류·전압·소자 크기를 결정합니다. 디지털 설계자는 데이터와 상태가 클록에 따라 움직이는 규칙을 표현합니다. 물리 설계자는 실제 셀의 위치와 금속 연결을 결정합니다. 패키지 설계자는 다이 밖의 연결과 열·기계 구조를 결정합니다. 한 사람이 작은 실습의 여러 역할을 맡을 수도 있지만, 서로 다른 결과물을 확인하는 업무라는 점은 같습니다.

공개 구현 흐름의 구체적인 예는 [OpenROAD Flow Scripts 튜토리얼](https://openroad-flow-scripts.readthedocs.io/en/latest/tutorials/FlowTutorial.html)의 floorplan·placement·CTS·routing 단계에서 확인할 수 있습니다. 각 단계가 배치·배선 데이터와 보고서를 남기는지 살펴보시면 추상적인 설계 설명을 실제 파일에 연결할 수 있습니다.

## 요구사항을 먼저 적는 이유

아래는 설명을 위해 직접 구성한 SRAM 블록의 요구사항 예입니다. 특정 제품 사양이나 제조 결과는 아닙니다.

| 요구사항 | 예시 | 뒤에서 확인할 내용 |
| --- | --- | --- |
| 용량과 조직 | 256 words × 32 bits | 주소 8비트, 저장 데이터 총 8,192비트입니다. |
| 포트 | 단일 포트, 한 클록에 한 명령 | 동시에 읽고 쓰는 동작을 허용할지 정합니다. |
| 읽기 | 요청 다음 클록에 결과 유효 | 테스트벤치와 타이밍 모델이 같은 의미여야 합니다. |
| 쓰기 | 4개의 byte enable | 부분 쓰기가 보존해야 할 바이트를 검사합니다. |
| 전원·주파수 | 선택한 공정의 사용 조건에서 결정 | 소자 한계·PVT·전력·STA와 연결합니다. |
| 검사 | 저장 셀과 주소 선택의 결함 검사 | 기능 시뮬레이션에 더해 MBIST·수리 정책을 정합니다. |

`256 × 32 ÷ 8 = 1,024 bytes`이므로 이 조직은 데이터만 세면 1 KiB입니다. ECC·예비 행·주변회로·배선의 면적은 여기에 포함하지 않습니다. 단순 비트 수가 같아도 포트 수와 입출력 조직이 다르면 셀·디코더·센스 앰프·배선이 달라집니다.

메모리 매크로를 가져올 때에는 실제 매크로의 읽기 지연·쓰기 마스크·극성·전원 모드에 요구사항을 맞춥니다. 기존 RTL 배열이 자동으로 그 매크로로 바뀌는지는 합성 도구의 추론·매핑 설정과 라이브러리에 달려 있습니다. 이 연결은 [SRAM](05-SRAM셀과메모리매크로_sram-design.md)과 [RTL 모델](07-Verilog와SystemVerilog의연결_rtl-verification-ams.md)에서 설명합니다.

## 두 설계 흐름이 만나는 지점

트랜지스터 수준에서는 같은 인버터라도 크기·배치·배선에 따라 지연과 전류가 달라집니다. SPICE 계열 시뮬레이터는 소자 모델과 연결을 받아 전기적 동작을 계산합니다. RTL에서는 그 인버터 하나하나 대신 비트 연산과 상태 전이를 표현하고, 합성 도구가 라이브러리의 셀로 구현합니다.

셀과 메모리 설계자는 다음 설계자가 내부 트랜지스터를 모두 다시 계산하지 않아도 사용할 수 있도록 여러 표현을 제공합니다. 동작 모델은 기능, 타이밍 라이브러리는 지연·제약·전력, 물리 추상은 크기·핀·막힘 영역, GDS는 도형을 표현합니다. IHP 공개 PDK의 [PDK Contents](https://github.com/IHP-GmbH/IHP-Open-PDK#pdk-contents)에서는 표준셀·입출력·SRAM에 CDL·GDSII·LEF·Liberty·Verilog가 함께 제공되는 실제 구성을 확인할 수 있습니다.

예를 들어 SRAM 모델의 주소는 8비트인데 LEF·GDS가 9비트 주소용 다른 매크로의 것이면, 각 도구가 개별 파일을 읽는 데 성공해도 설계 전체의 의미는 맞지 않습니다. 같은 매크로 이름뿐 아니라 용량·포트·판본·핀·전원·코너를 함께 묶어 관리합니다.

## 같은 흐름으로 무엇을 만들 수 있는가

| 대상 | 주로 사용하는 설계 | 추가로 필요한 조건 |
| --- | --- | --- |
| CPU·MCU·가속기·통신 제어기 | RTL·표준셀·SRAM·입출력 IP | ISA·버스·검증·메모리·타이밍·테스트 구조가 필요합니다. |
| SRAM 매크로·캐시 | 비트셀·배열·주변회로와 디지털 제어 | 셀 안정성·저전압 동작·특성화·수율을 확인합니다. |
| DRAM·HBM | 메모리 셀·센스 앰프·제어·인터페이스·적층 | DRAM 전용 소자·공정과 적층·검사 자료가 필요합니다. |
| ADC·DAC·PLL·센서 인터페이스 | 아날로그·혼합신호와 디지털 보정 | 잡음·선형성·안정성·정합·지터를 확인합니다. |
| RF 송수신기 | RF 소자·수동소자·고주파 전자기 분석 | 소자의 주파수 모델과 패키지·기판의 영향을 포함합니다. |
| 전력관리 IC | 아날로그 제어·전력 소자·보호 회로 | 허용 전압·전류·열·격리 구조를 지원하는 공정이 필요합니다. |
| 포토닉스·MEMS | 광·기계 소자와 전용 레이아웃·해석 | 해당 제조 방식의 PDK와 전용 모델이 필요합니다. |

이 표는 설계 업무를 분류한 설명입니다. 모든 공개 PDK가 이 소자를 전부 제공한다는 뜻은 아닙니다. 예를 들어 [IHP의 공개 설계 지원](https://www.ihp-microelectronics.com/services/research-and-prototyping-service/open-source-design-enablement)은 analog·digital·mixed-signal·RF를 다루며, [gdsfactory 프로젝트](https://github.com/gdsfactory/gdsfactory)는 photonics·analog·quantum·MEMS 등의 레이아웃을 다룹니다. 지원하는 설계 대상은 프로젝트의 기능과 선택한 공정 자료를 함께 확인합니다.

## 설계 완료를 판단하는 순서

1. 요구한 기능을 검증합니다. 오류 입력·리셋·경계 동작도 명세에 포함합니다.
2. 선택한 공정·전원·온도·부하에서 성능과 소비 전력을 확인합니다.
3. 레이아웃에서 연결과 공정 규칙을 검사하고 기생 성분을 추출합니다.
4. 추출 후 다시 성능·타이밍·전력·신뢰성 조건을 확인합니다.
5. 제조·패키지·검사 담당자에게 넘기는 데이터와 보고서가 동일한 판본을 가리키는지 확인합니다.

파형이 맞는다는 것, DRC가 통과했다는 것, GDS 파일이 생겼다는 것은 각각 확인한 대상이 다릅니다. 어느 하나만으로 설계 전체가 제조·동작 가능한 상태라고 결론짓지 않습니다. [최종 파일과 제조 인계](13-최종파일과제조인계_tapeout-deliverables.md)에서 마지막 결과물을 정리합니다.
