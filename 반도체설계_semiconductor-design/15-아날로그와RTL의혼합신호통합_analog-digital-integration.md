# 아날로그 레이아웃과 RTL의 혼합신호 통합 / Integrating analog macros and RTL

ADC의 트랜지스터 회로와 레이아웃을 완성해도 CPU가 그 값을 읽는 칩이 바로 만들어지지는 않습니다. 아날로그 입력·전원·기준 전압을 연결하고, 변환 완료를 기다리며, 결과를 디지털 클록에서 안전하게 받아 레지스터와 메모리에 전달해야 합니다. 이 글은 full-custom 아날로그 블록과 RTL 블록이 만나는 경계를 설계·검증·물리 구현의 세 관점에서 설명합니다.

공식 문서 확인일은 2026-10-26입니다. 아래의 12비트 ADC→레지스터→DMA 예제는 연결 조건을 설명하기 위한 자체 설계 가정입니다. 실제 제품, OpenTitan의 구현, 실행한 시뮬레이션이나 제작 성과를 뜻하지 않습니다. RTL 문법과 모델 종류의 기초는 [Verilog·SystemVerilog·아날로그 모델의 연결](07-Verilog와SystemVerilog의연결_rtl-verification-ams.md)을 먼저 읽을 수 있습니다.

## 1. 두 설계 경로가 만나는 곳

Full-custom 설계는 회로의 소자·크기·연결과 레이아웃을 직접 다루는 방식입니다. 디지털 RTL 설계에서는 합성기가 논리를 셀로 바꾸고 배치배선 도구가 셀과 배선을 배치합니다. 칩에는 두 방식으로 만든 블록이 함께 들어갈 수 있습니다.

```text
아날로그 경로: 사양 → 회로도·SPICE → 레이아웃 → DRC·LVS → 추출 후 해석
                                                        ↓
                                               ADC hard macro의 여러 뷰
                                                        ↓
디지털 경로: 제어·레지스터 RTL → 검증·합성 → 칩 배치배선 → 상위 연결·물리 검사
                                                        ↓
                                       칩 동작 시험과 제조 인계 자료
```

Hard macro는 내부 배치와 도형이 정해진 블록입니다. 상위 배치배선 도구는 그 내부 트랜지스터를 RTL에서 다시 합성하지 않고 블록의 경계·핀·배선 금지 영역을 사용합니다. [LibreLane의 Using Macros](https://librelane.readthedocs.io/en/stable/usage/using_macros.html)의 Macro Files 절은 LEF를 배치배선용 인터페이스, GDS를 최종 도형 전달용 뷰로 구분합니다. 이는 공개 흐름의 파일 역할을 설명하는 근거이며, 그 흐름만으로 임의의 아날로그 IP를 제조할 수 있다는 뜻은 아닙니다.

아날로그 팀이 ‘ADC 출력은 12비트입니다’라고 알리고 디지털 팀이 12개의 선을 연결하는 것만으로는 부족합니다. 그 값이 언제 유효한지, 어느 클록에서 받는지, 전원이 꺼질 때 무엇을 관측하는지까지 같은 규약으로 정해야 합니다.

## 2. 같은 매크로를 설명하는 파일 묶음

뷰(view)는 같은 블록을 특정 작업에 필요한 형태로 표현한 자료입니다. `adc12`라는 이름이 여러 파일에 나타나더라도 파일 내용과 목적은 다릅니다.

| 전달 자료 | 상위 설계에서 사용하는 내용 | 함께 맞출 조건 |
|---|---|---|
| 포트·동작 규약 | 입력 범위, 극성, 비트 폭, 클록, 지연, ready·valid·오류의 의미 | 기준 전압, 전원 순서, 보정 완료, 허용되는 요청 순서입니다. |
| LEF 추상 뷰 | 블록 크기, 신호·전원 핀의 위치와 층, 배선 장애물 | 매크로 이름, 방향·원점, 허용 회전·반전과 실제 GDS가 맞아야 합니다. |
| GDS/OASIS | 내부 소자와 배선을 포함한 레이아웃 도형 | 공정·층 번호·단위, 하위 셀과 사용 판본이 맞아야 합니다. |
| CDL/SPICE 기준 netlist | 소자와 핀 연결, LVS 기준 또는 회로 해석의 입력 | 서브회로 핀 순서·소자 모델·전원과 bulk 연결을 확인합니다. CDL 파일의 직접 시뮬레이션 가능 여부는 별도입니다. |
| Liberty 등 타이밍 모델 | 제공된 디지털 핀의 지연·부하·setup/hold 등 | 실제로 특성화된 아크와 코너를 확인합니다. 아날로그 전달 특성 전체가 `.lib`에 담기지는 않습니다. |
| 기능 모델·RNM·AMS 모델 | 시스템 동작 시험에 필요한 변환·지연·전원·상태 | 어느 비이상성과 고장 조건을 포함하고 생략했는지 명시합니다. |
| 추출 netlist와 사용 조건 | 레이아웃 기생 성분을 포함한 회로 해석 | schematic 버전, RC 코너, 포함한 기생 성분과 상위 추출의 경계를 맞춥니다. |

파일마다 포트를 적는 방식이 같을 필요는 없습니다. 디지털 버스 `data_o[11:0]`가 LEF에는 비트별 핀으로, SPICE에는 순서가 있는 서브회로 단자로 나타날 수 있습니다. 필요한 것은 이름을 대충 비슷하게 맞추는 일이 아니라 비트별 대응표입니다. 대소문자, 버스 구분 문자, 접지의 전역 이름, 생략된 전원 핀을 변환 규칙과 함께 확인합니다.

타이밍 모델이 없는 매크로의 출력에 임의의 지연 숫자를 넣어 분석을 통과시키지 않습니다. 매크로 내부의 아날로그 검증, 디지털 경계의 특성화, 상위 연결 경로의 분석을 누가 어떤 조건으로 책임지는지 정합니다. Cadence의 [2011년 혼합신호 정적 분석 설명](https://community.cadence.com/cadence_blogs_8/b/cic/posts/bringing-static-analysis-methods-to-mixed-signal-designs)은 여러 뷰의 불일치와 복잡한 아날로그 블록의 `.lib` 모델 작성 한계를 설명합니다. 여기서는 그 문제 구분만 참고하며 구판 제품의 기능·명령을 현재 설치 절차로 사용하지 않습니다.

## 3. 전압, 논리, 실수값 사이의 경계

| 표현 | 값이 나타내는 것 | 경계에서 필요한 판단 |
|---|---|---|
| `electrical` 전압·전류 | 아날로그 해석기가 회로 방정식으로 계산하는 양입니다. | 기준 노드, 부하, 전원과 연속시간 동작입니다. |
| 4상태 디지털 논리 | `0`, `1`, `X`, `Z`의 사건 기반 표현입니다. | 임계값, 미정 상태, 구동 여부와 관측 에지입니다. |
| RNM의 실수값 | 아날로그 의도를 이산 사건으로 갱신한 수치입니다. | 갱신 시점, 단위, 미연결·미정·전원 차단을 표현하는 별도 규약입니다. |

`real` 값 0.8을 전달했다고 해서 전류가 흐르거나 입력 커패시터가 충전되는 것은 아닙니다. 반대로 전압 0.8 V를 논리 1로 읽을 수 있는지는 수신기의 전원과 임계값에 달려 있습니다. 실수형 숫자 하나에는 논리형의 `X`·`Z` 규약이 자동으로 생기지 않으므로, 유효성·전원 상태를 별도 신호나 합의된 net type으로 표현해야 할 수 있습니다. [UVM-MS 1.0의 3.1절](https://www.accellera.org/images/downloads/standards/uvm-ms/UVM-MS_1.0.pdf)은 사건 기반 DMS/RNM과 아날로그·디지털 해석기를 함께 쓰는 AMS를 구분합니다.

Verilog-AMS의 connect module은 서로 다른 영역의 신호를 바꾸는 시뮬레이션 모델입니다. Connect rule은 어떤 discipline·방향의 경계에 어떤 변환 모델을 넣는지 정합니다. Discipline은 전기적 양의 성격과 해석 영역을 선언하는 언어 구성입니다. [VAMS-2023 LRM의 7.5–7.8절](https://www.accellera.org/images/downloads/standards/v-ams/VAMS-LRM-2023.pdf)은 이러한 연결 모듈과 계층별 자동 삽입을 정의합니다. 이 표준은 2024-02-14 판본이며, 실제 도구의 지원 범위와 설정 문법도 확인해야 합니다.

이 연결 모듈은 칩 안에 새 ADC나 레벨 시프터를 제조해 넣는 명령이 아닙니다. 실제 회로에 필요한 레벨 시프터·절연 셀·입력 버퍼와 시뮬레이션 경계 모델은 따로 대응시킵니다. ADC의 12비트 양자화 기능도 단일 전압을 1비트 논리로 바꾸는 E2L 변환과 구별합니다.

### 3.1 임계값과 전원·히스테리시스

아래는 특정 CMOS 입력의 규격이 아닌 자체 히스테리시스 수신기 가정입니다. 히스테리시스는 입력이 같은 중간 전압에 있어도 직전 출력 상태에 따라 결과가 달라지는 성질입니다.

- 정상 동작 범위의 수신 전원이 1.8 V이면 하한을 전원의 30%인 0.54 V, 상한을 70%인 1.26 V로 가정합니다.
- 입력이 상한을 넘어 올라갈 때 1, 하한 아래로 내려갈 때 0이 되며 두 임계값 사이에서는 앞 상태를 유지합니다. 시작 시 앞 상태가 없다면 초기화 규칙도 필요합니다.
- 전원이 유효 범위를 벗어나면 정상 임계값 규칙을 적용하지 않습니다. 전원 차단 중의 매크로 핀, 시스템 쪽 절연 출력, RNM 유효성 표시는 각각 정의합니다.

고정된 0.9 V 임계값만 사용하면 전원 변화나 꺼진 도메인의 잘못된 구동을 놓칠 수 있습니다. [Cadence의 E2L 모델 설명](https://community.cadence.com/cadence_blogs_8/b/cic/posts/start-your-engines-best-practices-for-converting-an-electrical-signal-to-logic-value-with-mixed-signal-modelling)은 상·하한, 히스테리시스, 동적 전원과 변환 사건을 구분합니다. 그 글의 전압·시간 값은 해당 모델의 예시이며 위 자체 가정의 공정 근거가 아닙니다.

### 3.2 변환 시점도 모델의 일부입니다

일정 주기마다 전압을 읽는 모델과 임계값 통과 사건을 검출하는 모델은 짧은 펄스를 다르게 관측할 수 있습니다. `cross`는 지정한 방향의 임계 통과를 찾으며 시간·표현식 허용 오차가 있습니다. ADC에서는 그 사건과 별도로 실제 샘플링 시점을 정합니다. 디지털 값이 바뀐 시점, 아날로그 전압을 취득한 시점, 디지털 수신 레지스터가 코드를 저장한 시점을 같은 사건으로 취급하지 않습니다. 근거는 [VAMS-2023의 5.10.3.1절](https://www.accellera.org/images/downloads/standards/v-ams/VAMS-LRM-2023.pdf)과 [UVM-MS 1.0의 6.1절](https://www.accellera.org/images/downloads/standards/uvm-ms/UVM-MS_1.0.pdf)입니다.

## 4. 자체 예제: ADC에서 DMA의 메모리 쓰기까지

이후에는 다음 한 예제를 계속 사용합니다. DMA(direct memory access)는 CPU가 매번 값을 복사하는 대신 버스 거래로 주변장치의 값을 읽어 메모리에 쓰는 하드웨어입니다. 이 예제의 DMA는 메모리 매핑된 `DATA` 레지스터를 읽으며 ADC 핀을 직접 읽지 않습니다.

```text
외부 입력·기준 전압 → u_adc: 아날로그 hard macro
                               │ 12비트 코드·valid·ready
                        u_adc_wrap: ADC 클록의 보관 레지스터
                               │ 데이터 유지 + 요청/응답 CDC
                        u_regs: 시스템 클록의 DATA·STATUS
                               │ 메모리 매핑 버스 읽기
                            u_dma → 버스 쓰기 → u_sram
```

### 4.1 수치와 인터페이스 가정

| 항목 | 자체 예제의 조건 |
|---|---|
| 변환 | 단극성 12비트이며 입력 범위는 0–1.2 V입니다. |
| ADC 클록 | 10 MHz로 가정합니다. 실제 ADC의 최대 처리율을 뜻하지 않습니다. |
| 시스템 클록 | 50 MHz이며 ADC 클록과 위상 관계를 보장하지 않습니다. |
| 요청 | `ready_o=1`이고 결과 보관 슬롯이 비어 있을 때 한 번의 `start_i`를 받습니다. |
| 보정 | 전원·기준 전압이 준비된 뒤 `cal_req_i`로 보정을 요청하고 `cal_done_o`를 기다립니다. 구체적인 보정 알고리즘은 이 예제 밖입니다. |
| 결과 | 수신 상승 에지의 setup·hold 조건을 만족하는 `data_o[11:0]`와 한 ADC 클록 길이의 `valid_o`입니다. |
| 버퍼 | 읽지 않은 결과 하나를 보관하며 다음 변환을 막습니다. 연속 취득용 FIFO를 제공하는 예제가 아닙니다. |
| 비정상 상태 | 준비 시간·보정·변환에 각기 시간 제한을 두고 실패 시 오류를 남깁니다. 제한 수치는 실제 매크로 규격에서 정해야 합니다. |

여기의 포트 이름과 동작은 자체 규약입니다. 실제 사례인 [OpenTitan ADC controller의 인터페이스](https://opentitan.org/book/hw/ip/adc_ctrl/doc/theory_of_operation.html)는 전원 기동 대기, 채널 선택, `data_valid`와 데이터 수신을 구분합니다. 특히 이 문서의 실제 ADC 인터페이스에는 별도 sample request가 없고 채널 선택의 0→유효 채널 변화가 변환을 시작합니다. 그 규약을 위 `start_i` 규약과 섞어 연결하면 안 됩니다.

### 4.2 핀과 상위 net의 대응

아래 `soc_top.u_adc`는 아날로그 매크로 인스턴스이고 `soc_top.u_adc_wrap`은 합성할 디지털 제어·수신 RTL입니다. 예시 이름이며 저장소에 실행용 IP 소스가 제공된다는 뜻은 아닙니다.

| 매크로 포트 | 방향·표현 | 상위 연결·소유자 | 연결 시 확인할 조건 |
|---|---|---|---|
| `ain`, `vrefp`, `vrefn` | 아날로그 입력 | 입력 패드와 기준 전압 회로입니다. | 공통 모드·차동 여부, 허용 범위·입력 부하를 실제 규격과 맞춥니다. 이 예제는 `vrefn=0 V`입니다. |
| `avdd`, `avss` | 아날로그 전원·기준 | 아날로그 전원망입니다. | RNM의 숫자 전원과 물리 전원 핀을 구분합니다. |
| `dvdd`, `dvss` | 디지털 경계 전원·기준 | ADC 출력 인터페이스용 전원망입니다. | 수신 RTL의 전압 영역과 실제 레벨 변환·절연 경로를 맞춥니다. |
| `clk_i`, `rst_ni` | 1비트 입력 | ADC 도메인의 클록·리셋입니다. | 리셋 극성과 해제 조건, 클록 허용 조건을 맞춥니다. |
| `en_i`, `cal_req_i`, `start_i` | 각 1비트 입력 | `u_adc_wrap`의 ADC 도메인 제어입니다. | 시스템 버스의 한 사이클 펄스를 직접 연결하지 않습니다. |
| `cal_done_o`, `ready_o` | 각 1비트 출력 | `u_adc_wrap`의 상태 입력입니다. | 유지되는 상태인지 펄스인지와 유효 전원 조건을 맞춥니다. |
| `data_o` | 12비트 출력 | ADC 도메인 결과 보관 레지스터입니다. | `[11:0]`의 비트 순서와 부호 없는 코드를 맞춥니다. |
| `valid_o` | 1비트 출력 | 같은 도메인의 수신 허용 조건입니다. | 유효 에지에서 데이터와 함께 받습니다. |

이 표의 디지털 포트 이름·폭은 기능 모델, RTL 선언, 타이밍 뷰와 맞추고, 아날로그 단자·전원은 schematic·CDL/SPICE·LEF·GDS와 대응시킵니다. RNM에서 `ain`이 실수형 입력이고 AMS에서는 `electrical`일 수 있으므로 같은 파일을 이름만 바꾸어 컴파일하지 않습니다. 어댑터나 설정별 wrapper의 자료형 변환을 명시합니다. 전원 핀을 생략한 기능 모델이 필요하다면 전원 포함 물리 매크로로 연결되는 별도 규칙과 시험 항목을 남깁니다.

### 4.3 코드의 기대값을 계산합니다

설명용 이상적 양자화기는 다음과 같이 가정합니다. `clip(x,0,4095)`는 범위를 벗어난 정수를 양 끝으로 제한하는 연산이며, 아래 식은 실행 코드가 아닙니다.

\[
q=\operatorname{clip}\!\left(\left\lfloor 2^{12}\frac{V_{in}}{1.2\,\mathrm{V}}\right\rfloor,0,4095\right),\qquad
\Delta V=\frac{1.2\,\mathrm{V}}{4096}=292.96875\,\mu\mathrm{V}
\]

| 취득 시점의 입력 | 기대 코드 | 해석 |
|---|---|---|
| 0 V | 0 | 아래쪽 끝입니다. |
| 0.3 V | 1024 | 범위의 1/4입니다. |
| 0.6 V | 2048 | 범위의 1/2입니다. |
| 1.2 V | 4095 | 계산값 4096을 최댓값으로 포화시킵니다. |
| −0.01 V | 0 | 이 자체 모델은 아래쪽으로 포화시킵니다. 실제 핀의 허용 입력을 보장하지 않습니다. |

이 기대값은 offset·gain 오차, 잡음, 비선형성, 기준 전압 변화와 샘플링 지터를 생략합니다. 실제 매크로와 비교할 때는 그 규격에 맞는 오차 범위와 취득 시간을 사용합니다. 같은 순간의 파형 커서 값으로 이미 앞에서 취득한 ADC 코드를 판단하지 않습니다.

## 5. 전원 기동부터 읽기 완료까지의 상태 규약

| 단계 | 수행하는 일 | 다음 단계 조건·실패의 근거 |
|---|---|---|
| 1. 전원과 리셋 | 아날로그·디지털 전원, 기준 전압과 클록을 준비하고 리셋을 유지합니다. | 전원·기준의 유효 조건과 순서를 파형에서 확인합니다. RTL의 `en=1`만으로 준비 완료를 판단하지 않습니다. |
| 2. 리셋 해제·보정 | 도메인별 해제 조건을 만족한 뒤 `en_i`, `cal_req_i`를 설정합니다. | 보정 완료와 기동 대기를 구분합니다. 둘 중 하나가 시간 안에 끝나지 않으면 `ERROR`와 원인을 남깁니다. |
| 3. 변환 요청 | 소프트웨어가 `STATUS.READY=1`, `BUSY=0`, `VALID=0`을 확인한 뒤 `CONTROL.START`를 씁니다. | 명령을 ADC 도메인으로 전달하고 실제 수락 응답을 받습니다. 상태 읽기 뒤 조건이 바뀌었다면 재확인하여 거절·오류로 응답합니다. |
| 4. ADC 결과 수신 | `valid_o=1`인 수신 에지에서 코드 전체를 `sample_q`에 저장합니다. | 데이터의 setup·hold와 valid의 도메인을 확인합니다. 그 전의 임의 코드를 결과로 사용하지 않습니다. |
| 5. 시스템 영역 전달 | `sample_q`를 고정하고 CDC 요청을 보냅니다. 시스템 영역이 결과를 `DATA`에 받으면 `VALID=1`이 됩니다. | 데이터의 안정 기간과 요청·응답 상태를 확인합니다. 이때 소스 슬롯을 재사용하지 않습니다. |
| 6. DMA 읽기 | DMA가 유효한 `DATA`의 32비트 읽기 거래를 수행합니다. | 성공 응답의 하위 12비트만 코드이며 상위 비트는 0입니다. 버스 요청 발생과 거래 완료를 구분합니다. |
| 7. 소비와 메모리 쓰기 | 성공한 읽기에서만 `VALID`를 지우고 CDC 응답을 돌려보냅니다. DMA가 받은 값을 SRAM에 씁니다. | ADC 영역은 응답을 관측한 뒤 슬롯을 재사용합니다. DMA 완료는 목적지 쓰기의 성공 응답까지 확인한 뒤 알립니다. |

기동 시간이 짧은 기능 모델은 단계 2의 결함을 숨길 수 있습니다. 시험에서는 즉시 준비되는 경우와 지연·실패하는 경우를 나누고, 전원 차단·리셋·보정 실패가 거래 도중 발생했을 때도 검사합니다. 실제 전원 차단 핀이 미정이 될 수 있다면 전원이 유지되는 경계 회로가 시스템 쪽 `READY`·`VALID`를 무효화하도록 설계·모델을 대응시킵니다.

이 예제의 `CONTROL`, `STATUS`, `DATA`는 자체 레지스터 규약입니다. 예를 들어 블록 내부 offset을 각각 `0x00`, `0x04`, `0x08`로 정할 수 있습니다. 실제 SoC 주소는 주소 할당 자료에서 정하며 OpenTitan 주소를 뜻하지 않습니다. `DATA`를 비어 있을 때 읽으면 버스 오류를 반환하고, 실패한 읽기는 보관 값을 소비하지 않는 것으로 정합니다. DMA와 디버거·CPU가 동시에 `DATA`를 읽으면 누가 결과를 소비하는지도 정해야 합니다. 여기서는 DMA 동작 중 CPU의 소비 읽기를 금지합니다.

## 6. 여러 비트의 결과를 CDC로 넘기는 방법

CDC(clock-domain crossing)는 서로 다른 클록 영역 사이의 전달입니다. 12비트 각각에 2단 플립플롭을 달아도 비트들이 같은 변환 결과에 속한다는 것은 보장되지 않습니다. 예를 들어 코드가 `0x7FF`에서 `0x800`으로 바뀌면 여러 비트가 동시에 바뀌므로 목적지에 섞인 단어가 보일 수 있습니다. 시뮬레이션의 이상적인 0지연 신호만으로는 이 물리적 위험을 충분히 보이지 못합니다.

이 예제는 한 결과만 보관하므로 데이터 유지와 요청/응답 handshake를 사용합니다. 소스는 결과 전체를 고정한 뒤 요청을 보내고, 목적지는 동기화한 요청을 보고 안정된 단어를 받습니다. 목적지가 결과를 소비한 뒤 응답을 돌려보내며, 소스는 응답을 확인하기 전까지 데이터와 요청 상태를 임의로 바꾸지 않습니다. 데이터 경로가 제어 경로보다 충분히 먼저 안정되는지에 대한 구현 제약도 필요합니다. ‘데이터를 유지합니다’라는 설명만으로 실제 배치배선 지연 검토가 끝나지는 않습니다.

[OpenTitan의 `prim_sync_reqack_data.sv`](https://github.com/lowRISC/opentitan/blob/master/hw/ip/prim/rtl/prim_sync_reqack_data.sv)는 데이터가 딸린 요청/응답 CDC와 데이터 유지 assertion의 실제 공개 예입니다. 그 소스는 기본적으로 데이터 자체를 레지스터에 저장하지 않는다고 명시하며, 방향·옵션·리셋 조건에 따른 계약이 있습니다. 이름만 가져다 인스턴스화하면 안전해지는 범용 버퍼로 취급하지 않습니다. 여기의 전체 ADC·DMA 설계가 그 소스를 사용하거나 검증했다는 뜻도 아닙니다.

동기화 지연은 클록 위상에 따라 달라집니다. 따라서 CPU가 START를 쓴 뒤 고정된 시스템 클록 몇 번만 기다리고 DATA를 읽는 방법 대신 명령 수락·상태·시간 제한을 사용합니다. 처리량이 필요한 연속 ADC라면 비동기 FIFO와 overflow·backpressure 정책을 따로 설계해야 합니다.

리셋도 양쪽 계약에 포함합니다. 이 예제에서는 한쪽 리셋이나 전원 재시작이 생기면 진행 중 명령·결과를 폐기하고 오류를 알린 뒤 양쪽 handshake 상태를 다시 맞춥니다. 이전 요청의 응답을 새 변환의 응답으로 받아들이지 않아야 합니다. 부분 리셋을 허용하는 구체적인 CDC 구조와 실제 리셋 순서는 따로 검증합니다.

## 7. 상위 계층에서 모델을 선택하는 방법

같은 `soc_top.u_adc`라도 시험 목적에 따라 바인딩(binding)을 바꿀 수 있습니다. 바인딩은 인스턴스를 어느 셀·모듈·서브회로·뷰의 정의로 해석할지 정하는 일입니다. 라이브러리에 파일이 존재한다는 사실과 이번 실행에서 그 파일을 선택했다는 사실은 다릅니다.

| 구성 | `u_adc`에 선택할 표현 | 상위에 함께 두는 것 | 답하려는 질문 |
|---|---|---|---|
| 디지털 동작 시험 | 코드·준비·지연·오류를 만드는 기능 모델입니다. | 제어·CDC·레지스터·DMA RTL과 버스 모델입니다. | 요청 누락, 읽기 순서, 오류 처리와 데이터 보존입니다. |
| RNM 시스템 시험 | 입력·기준·전원 의도를 실수값과 상태로 표현한 모델입니다. | 같은 디지털 RTL과 RNM 자극·관찰 어댑터입니다. | 입력 변화와 시스템 상태·결과의 관계입니다. |
| AMS 경계 시험 | 선택한 블록의 Verilog-A/AMS 또는 SPICE 표현입니다. | 필요한 디지털 RTL, 실제 경계 변환·부하 모델입니다. | 전원·정착·임계 통과와 디지털 수신의 상호작용입니다. |
| 추출 후 시험 | 해당 레이아웃의 추출된 아날로그 회로입니다. | 필요한 상위 배선 기생 성분과 디지털 표현입니다. | 배선·부하·전원 조건을 반영한 경계 동작입니다. |
| 합성·배치배선 | 매크로 인터페이스와 제공된 타이밍·물리 뷰입니다. | 합성할 wrapper RTL, LEF와 최종 병합할 GDS입니다. | 매크로를 보존한 상위 연결·배치·배선입니다. |
| 상위 LVS | 승인된 기준 서브회로와 물리 추출 결과입니다. | 디지털 셀의 기준 회로·전원 연결·상위 연결입니다. | 최종 도형의 연결이 기준과 같은지입니다. |

설정에는 top, 인스턴스 경로, 라이브러리·셀·뷰 또는 정의 파일, 파라미터, 전원·포트 매핑, 연결 모듈 규칙을 함께 남깁니다. Config view나 흐름별 바인딩 파일을 사용하는 경우 셀 전체에 적용한 선택과 특정 인스턴스의 선택을 구분합니다. 실행 후 생성된 netlist·elaboration 보고서에서 실제 선택 결과를 확인합니다. 같은 모듈명의 기능 모델과 SPICE 변환 wrapper를 파일 순서에 맡겨 중복 정의하지 않습니다.

[Synopsys VCS AMS 데이터시트의 Flexibility·Increased Productivity 절](https://www.synopsys.com/content/dam/synopsys/verification/datasheets/vcs-ams-ds.pdf)은 여러 모델 수준과 상위 계층 구성, 포트 매핑·연결 진단을 설명합니다. [Cadence Circuit Simulation의 Mixed-Signal Simulation 설명](https://www.cadence.com/en_US/home/tools/custom-ic-analog-rf-design/circuit-simulation.html)은 Xcelium과 Spectre를 결합하는 Spectre AMS Designer의 역할을 설명합니다. 두 자료는 지원 방식의 예이며, 특정 판본·라이선스가 모든 구성을 실행한다는 보증으로 사용하지 않습니다.

RNM에서 AMS로 바꾸는 경우 포트 이름 외에 자료형·discipline·방향·전압 기준·샘플링·지연 규약을 다시 확인합니다. 전기적 양방향 단자를 한 방향의 실수 입력으로 단순화한 모델은 역방향 부하나 구동 충돌을 표현하지 못할 수 있습니다. 이 차이를 감춘 채 동일한 모델이라고 부르지 않습니다.

## 8. PLL이 만든 클록도 별도 인터페이스입니다

PLL(phase-locked loop)은 기준 신호와 출력의 위상 관계를 제어하는 회로입니다. 디지털 상위 설계는 아날로그 내부 대신 기준 클록, enable·power-down·bypass, 출력 클록, lock 등 제공된 경계를 연결할 수 있습니다. 이 신호가 실제 IP에 모두 존재한다고 가정하지 않고 제공된 인터페이스에서 확인합니다.

| 모델·검사 | 다룰 수 있는 항목의 예 | 별도로 남는 항목 |
|---|---|---|
| 기능 클록 모델 | 설정에 따른 출력 주기, bypass, lock 지연·상실의 지정 시나리오입니다. | 실제 lock 범위·위상 잡음·지터·전원 민감도입니다. |
| STA 클록 정의 | 동작 모드에서의 주기·에지 관계와 제약·불확실성입니다. | 기동 중의 파형과 아날로그 lock 과정입니다. |
| PLL 아날로그·추출 후 시험 | 모델에 포함된 루프 동작·부하·전원·기생 영향입니다. | 모델에 없는 제조 편차나 관측하지 않은 모든 동작 조건입니다. |

`lock=1`을 클록 품질 전체의 증명으로 사용하지 않습니다. Lock 상태의 동기화·안정 확인, 클록 전환·게이팅, 리셋 해제를 해당 설계 규약에 맞게 연결합니다. 아직 움직이지 않는 PLL 출력 클록으로만 기동 상태를 관찰하려 하면 제어가 진행되지 않을 수 있으므로, 어떤 제어가 항상 동작하는 클록에 있어야 하는지도 정합니다.

[OpenSTA의 `create_generated_clock` 설명](https://opensta.readthedocs.io/en/latest/Commands/#create-generated-clock)은 분주기와 PLL처럼 기존 클록에서 생긴 클록을 모델링하는 기능을 설명합니다. 관계가 알려진 정상 동작 모드와 독립·비동기 모드는 실제 회로에 맞춰 나눕니다. PLL을 black box로 두었다는 이유로 그 출력 클록 정의와 수신 경로까지 없애거나, ADC·PLL에 닿는 경로 전체를 false path로 지정하지 않습니다. 제외한 내부 아날로그 검사의 범위, 남겨서 검사할 디지털 경계, 별도 검증 근거를 함께 기록합니다.

## 9. 모델 수준을 나누어 같은 계약을 검사합니다

모델을 자세하게 만들수록 모든 시스템 시험이 자동으로 더 유용해지는 것은 아닙니다. 필요한 현상을 포함한 모델로 그 현상과 맞는 시험을 수행해야 합니다. 다음은 이 자체 ADC 예제의 검증 계획이며 실행 결과가 아닙니다.

| 시험 수준 | 실행할 시험 | 비교·관찰 근거 |
|---|---|---|
| ADC 블록 | 입력 범위·경계 코드·기동·보정·부하·전원 변화를 봅니다. | 실제 취득 시점의 입력, 출력 코드·지연과 해당 사양의 허용 오차입니다. |
| 디지털 wrapper | valid 없는 데이터, 준비 전 START, 보관 중 START, timeout·리셋을 시험합니다. | 수락된 명령 수, 유효 결과 수, 소비된 결과 수와 상태 전이입니다. |
| CDC·레지스터 | 클록 위상·주기를 바꾸고 한쪽 정지·리셋과 느린 소비를 시험합니다. | 데이터 유지 조건, 요청·응답의 일대일 대응, 미정·미제약 경로와 정적 CDC/RDC 보고서입니다. |
| DMA 연결 | 읽기·쓰기 대기, 버스 오류, 목적지 범위, 소프트웨어 재설정을 시험합니다. | 완료한 읽기 값과 SRAM 쓰기 값·주소·횟수, 성공 응답과 완료 알림입니다. |
| AMS 경계 | 느린 전원 램프, 기준 전압 정착, 임계 근처 입력과 디지털 수신을 시험합니다. | 실제 전압·변환 모듈 상태·샘플링 사건·RTL 관측을 같은 시간축에서 비교합니다. |
| 추출 후 | 선택한 코너·입력·부하에서 ADC 경계와 상위 연결을 다시 시험합니다. | 추출 전후 차이, 기생 성분 범위, 포트·전원 연결과 지연·오차 기준입니다. |

RNM은 디지털 사건 기반 시스템 시험을 구성하기에 적합하지만, 생략한 회로 현상은 그 시험에서 발견할 수 없습니다. SPICE·AMS의 비용도 회로 규모·시험 길이·모델·해석 설정에 따라 달라지므로 고정된 속도 배수로 일반화하지 않습니다. 빠른 모델과 상세 모델의 공통 자극·관찰 지점을 정하고, 정상 범위뿐 아니라 포화·준비 전·전원 저하 등 모델 경계에서도 결과가 왜 달라지는지 확인합니다. 한쪽의 지연과 오차를 다른 쪽에서 검사 가능한 허용 범위로 연결합니다.

UVM-MS를 사용하는 시험에서는 UVM 클래스가 자극·기대값·시험 순서를 다루고 MS bridge의 core가 DUT 쪽 전압·부하 등을 다룰 수 있습니다. Proxy는 두 부분의 제어·관찰 API를 연결합니다. 디지털 scoreboard는 DMA의 읽기·메모리 쓰기를, 아날로그 관찰은 실제 취득 입력·준비 시간을 확인하도록 역할을 정합니다. [UVM-MS 1.0의 4.2–4.4절](https://www.accellera.org/images/downloads/standards/uvm-ms/UVM-MS_1.0.pdf)을 참고한 구성 원리이며, 여기서 완성된 UVM-MS 실행 환경을 제공하거나 실행한 것은 아닙니다.

## 10. LEF로 배치하고 GDS를 합친 뒤에도 연결을 확인합니다

1. ADC 레이아웃의 핀·전원·배선 장애물과 일치하는 LEF를 만듭니다. 허용 방향, 매크로 주변 여유와 민감한 입력·기준 배선 조건도 전달합니다.
2. 디지털 합성에서는 매크로를 내부 RTL로 치환하지 않고 보존하며 wrapper와 레지스터·DMA를 합성합니다. 매크로를 미연결 또는 출력 상수로 잘못 해석해 제거하지 않았는지 결과 netlist를 확인합니다.
3. 칩 floorplan에서 ADC와 입력 패드·기준 전압·전원망의 관계를 정합니다. 디지털 배선이 LEF 핀에 닿았다는 사실 외에 아날로그 배선의 층·차폐·간격·부하와 PDK 규칙도 확인합니다.
4. 디지털 상위 도형에 승인된 ADC GDS와 필요한 하위 셀을 병합합니다. LEF만 읽고 화면에 직사각형이 보이는 상태를 ADC 내부 도형이 포함된 최종 레이아웃으로 판단하지 않습니다.
5. 최종 상위 도형에서 추출한 연결을 전원 핀까지 연결한 상위 기준 회로와 비교합니다. 기준 회로에는 디지털 셀 뷰와 ADC의 대응 CDL/SPICE 또는 승인된 계층 검증 정책이 필요합니다.
6. 칩 배선의 기생 성분과 ADC 내부 추출 성분의 경계를 정해 필요한 후속 해석을 합니다. 같은 배선 RC를 양쪽에 중복 포함하거나 경계의 연결 RC를 빠뜨리지 않습니다.

이 절차는 특정 상용 도구의 명령 목록이 아닙니다. 아날로그 전원·접지 분리, guard ring·well·substrate 연결, ESD·패드와 디지털 전원망의 연결은 공정과 IP의 규칙에 따라 정합니다. `avss`, `dvss`라는 이름이 다르다고 물리적으로 항상 절연되어야 한다거나, 이름만 같게 바꾸면 전원 잡음 문제가 해결된다고 가정하지 않습니다.

상위 LVS에서 ADC 내부를 black box로 제외했다면 내부 트랜지스터 연결은 그 검사에서 확인하지 않습니다. 별도 매크로 LVS 결과와 사용한 도형의 판본을 연결하고 상위 경계의 핀 대응은 검사해야 합니다. [KLayout LVS Overview의 abstract circuits](https://www.klayout.de/doc/manual/lvs_overview.html)는 이 내부 제외 범위를 설명합니다. 또한 [KLayout LVS Compare의 Checking pin labels](https://www.klayout.de/doc/manual/lvs_compare.html)는 기본 연결 비교와 외부 핀 이름 검사를 구분합니다. 따라서 도구·deck의 실제 핀 정책을 확인하며 ‘LVS 일치’ 한 줄만으로 패드·채널·기준 전압의 의도된 이름 대응까지 확정하지 않습니다.

## 11. 실패를 찾는 증거와 순서

| 관측한 문제 | 먼저 대조할 근거 | 잘못된 결론을 피할 점 |
|---|---|---|
| RNM은 동작하지만 AMS elaboration이 실패합니다. | 바인딩 결과·중복 정의·포트 자료형·discipline·연결 규칙입니다. | RTL 기능 오류와 모델 연결 오류를 구분합니다. |
| 항상 0 또는 최댓값만 읽힙니다. | 입력·기준 전압·단위·극성·포화식·전원 상태입니다. | DMA가 값을 읽는다는 사실만으로 ADC 입력이 올바르다고 판단하지 않습니다. |
| 변환은 되지만 데이터가 간헐적으로 섞입니다. | valid의 수신 에지, 전체 단어 유지 기간, CDC 요청·응답과 실제 제약입니다. | 비트별 동기화나 이상적인 RTL 파형만으로 원인을 지우지 않습니다. |
| 준비 전 결과가 유효해집니다. | 보정·전원·기준 전압 파형, 선택한 모델의 기동 규약입니다. | 기능 모델의 즉시 ready를 실제 회로의 기동 성능으로 옮기지 않습니다. |
| DATA 읽기 값과 SRAM 값이 다릅니다. | 완료된 버스 응답·주소·폭·byte enable·DMA 오류입니다. | ADC의 아날로그 정확도와 디지털 복사 오류를 분리합니다. |
| 배치 화면은 정상인데 stream-out에 셀이 없습니다. | LEF/GDS 셀 이름·병합 목록·계층·단위입니다. | 추상 경계가 보이는 상태와 내부 도형 포함을 구분합니다. |
| 상위 LVS가 맞지만 채널·패드 기능이 다릅니다. | 포트 순서·이름 대응, black box·핀 동등화·label 검사 정책입니다. | 내부 제외와 연결 대칭성 때문에 무엇이 비교되지 않았는지 확인합니다. |
| 추출 후에만 코드·준비 시간이 달라집니다. | 선택한 회로 뷰·RC 코너·부하·전원·기준 배선과 중복 추출입니다. | 허용 오차·시간 기준을 바꾸기 전에 원인을 확인합니다. |

기록에는 모델·매크로 판본, top과 인스턴스 바인딩, 입력·전원·클록 조건, 시험명·seed, 기대 기준과 첫 실패 시점을 연결합니다. 디지털 회귀 통과, AMS 경계 시험 통과, 매크로·상위 물리 검사 통과와 실제 제조·실측은 각기 다른 기록입니다.
