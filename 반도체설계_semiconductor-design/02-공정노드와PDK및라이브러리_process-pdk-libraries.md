# 공정 노드, PDK와 셀 라이브러리

같은 회로도나 RTL이라도 공정과 라이브러리가 달라지면 사용할 소자, 면적, 지연, 전력과 배선 규칙이 달라집니다. 공정 설계 키트인 PDK(Process Design Kit)는 특정 제조 공정으로 설계하기 위한 규칙·모델·도구 설정의 묶음입니다. 단순한 트랜지스터 그림 모음이나 범용 시뮬레이터가 아닙니다.

이 글은 공정 이름의 의미, PDK 파일의 역할, 코너와 판본을 맞추는 방법을 설명합니다. 기준일은 2026년 10월 26일이며, 공개 문서에서 확인한 구성과 설명용 예를 다룹니다. 비공개 파운드리 PDK의 내용이나 제조 성능을 직접 확인한 기록은 아닙니다.

## 1. nm 이름과 실제 치수

공정 노드는 한 세대의 제조 기술을 구분하는 이름입니다. 현대의 노드 이름을 모든 트랜지스터의 게이트 길이, 금속 선폭 또는 특정 피치와 같은 수치로 읽으면 안 됩니다. Intel도 [공정 명명 설명](https://www.intel.com/content/www/us/en/support/articles/000097598/processors.html)에서 노드 이름과 실제 물리 치수의 관계가 과거와 달라졌음을 설명합니다.

| 구분 | 뜻 | 비교할 때의 주의점 |
|---|---|---|
| 게이트 길이 | 소자의 게이트 아래 채널 길이와 관련된 치수 | 그려진 길이와 전기적으로 추출한 유효 길이를 구분합니다. |
| 게이트 피치 | 이웃한 게이트 패턴 사이의 반복 간격 | 선폭만이 아니라 간격과 접촉 구조의 영향을 받습니다. |
| 금속 피치 | 이웃한 배선의 반복 간격 | 금속층과 설계 규칙에 따라 달라집니다. |
| 표준 셀 높이·밀도 | 셀 배치 구조와 구현 가능한 논리 집적도 | 셀 종류, 트랙 높이, 배선 가능성과 측정 회로를 함께 봅니다. |
| 공정 노드 이름 | 공급사가 구분한 공정 세대·제품군 | 서로 다른 공급사의 같은 숫자가 같은 구조나 성능을 뜻하지 않습니다. |

Intel의 [2017년 노드 명명 논평](https://download.intel.com/newsroom/2021/archive/2017-03-28-editorials-lets-clear-up-node-naming-mess.pdf)은 게이트 피치와 최소 금속 피치의 곱만으로는 논리 셀 구조에 따른 밀도 차이를 모두 반영하지 못한다고 설명합니다. 이는 공급사가 제안한 비교 방식에 관한 자료이며, 모든 공정의 단일한 공인 순위표로 사용하지 않습니다.

구조도 따로 확인해야 합니다. 평면 MOSFET, FinFET, GAA(Gate-All-Around)는 게이트가 채널을 제어하는 형상이 다릅니다. GAA 나노시트는 얇은 채널의 둘레를 게이트가 감싸는 구조입니다. TSMC의 [2024년 N2 논문 소개](https://research.tsmc.com/page/logic/97.html)는 N2를 GAA 나노시트 논리 공정으로 설명합니다. 이 사실을 모든 `2 nm`라는 이름이나 모든 메모리 공정에 그대로 적용할 수는 없습니다.

## 2. 로직·SRAM·DRAM 공정의 차이

디지털 로직 공정의 PDK에 SRAM 매크로가 있다고 해서 범용 DRAM 공정까지 포함된 것은 아닙니다. SRAM은 전원이 있는 동안 상태를 유지하는 래치형 셀을 사용하고, 일반적인 DRAM 셀은 접근 트랜지스터와 전하를 저장하는 커패시터를 사용합니다. DRAM은 전하 손실을 보충하는 리프레시가 필요합니다. [Samsung의 DRAM 설명](https://semiconductor.samsung.com/dram/)에서 셀 구조와 리프레시를 확인할 수 있습니다.

전용 DRAM 제조 공정에서는 조밀한 셀 배열과 저장 커패시터, 누설과 보존 시간, 주변 회로를 함께 고려합니다. 따라서 로직 공정의 노드 숫자를 DRAM 세대 이름과 직접 비교할 수 없습니다. 예를 들어 SK hynix의 [1c DDR5 개발 설명](https://news.skhynix.com/en/roundtable-on-world-first-1c-ddr5/)은 `1c`를 10 nm급의 여섯 번째 세대로 설명하고, 커패시터 모듈과 셀 저항 등의 개발 과제를 따로 다룹니다. `1c`를 게이트 길이가 1 nm라는 뜻으로 읽지 않습니다.

## 3. PDK 안의 자료와 별도 라이브러리

PDK는 공정의 바탕을 제공하고, 표준 셀 라이브러리는 인버터·논리 게이트·플립플롭처럼 반복해서 사용할 회로를 제공합니다. I/O 셀과 SRAM·PLL 등의 매크로는 별도 라이브러리로 제공되기도 합니다. 모든 PDK에 모든 IP가 포함되어 있다고 가정하지 않습니다.

```text
제조 공정과 공정 옵션
        ↓
PDK: 규칙·소자 모델·층 정의·검사 및 추출 설정
        ↓
표준 셀 / I/O / 메모리·아날로그 IP의 여러 뷰
        ↓
회로 시뮬레이션·합성·배치배선·검증·제작 데이터
```

| 자료 | 담긴 내용 | 주로 읽는 단계 | 혼동하기 쉬운 점 |
|---|---|---|---|
| DRM, 설계 규칙 문서 | 층의 의미, 최소 폭·간격, 소자·신뢰성·제작 조건 | 회로·레이아웃 설계와 최종 확인 | 문서의 모든 지침이 자동 DRC에 구현되어 있지는 않습니다. |
| 소자 모델 | 전압·온도·공정 조건에 따른 전류·전하 등의 수학적 모델과 파라미터 | SPICE 계열 회로 시뮬레이션 | 모델 파일만으로 배치배선용 셀 정보가 생기지 않습니다. |
| technology LEF | 배선층·비아·사이트와 배선에 필요한 기술 정보 | 디지털 물리 구현 | 특정 셀 내부의 전체 도형을 담는 파일이 아닙니다. |
| cell LEF | 셀의 크기·핀·장애물 등 배치배선용 추상 정보 | 배치·배선 | GDS의 모든 트랜지스터와 도형을 대신하지 않습니다. |
| Liberty, `.lib` | 셀 논리 기능, 지연·전이·타이밍 제약, 전력 등의 특성 | 합성과 정적 타이밍 분석 | 공정·전압·온도와 모델 종류를 맞춰야 합니다. |
| GDSII·OASIS | 계층과 레이어별 레이아웃 도형 | 레이아웃 조립·물리 검증·제작 데이터 전달 | 도형 자체가 회로 기능의 완전한 설명은 아닙니다. |
| CDL·SPICE netlist | 소자와 연결, 소자 파라미터 | LVS의 기준 회로, 회로 시뮬레이션 | CDL 방언과 모델 호환성을 확인해야 하며, 모든 파일이 곧바로 모든 시뮬레이터에서 동작하지 않습니다. |
| DRC·LVS deck | 규칙 검사와 소자 인식·연결 비교를 실행하는 도구별 규칙 | 물리 검증 | 공정과 검사 도구 판본에 맞는 deck이 필요합니다. |
| RC 추출 deck·기술 파일 | 배선 저항·정전용량을 계산할 공정·코너 정보 | 기생 성분 추출 | SPICE의 트랜지스터 모델이나 셀 Liberty와 역할이 다릅니다. |
| Verilog 모델 | 셀·매크로의 논리 동작이나 타이밍 모형 | RTL·게이트 수준 시뮬레이션 | 추상화 수준에 따라 아날로그 동작은 표현하지 않습니다. |

위 파일 종류는 [IHP Open PDK의 PDK Contents](https://github.com/IHP-GmbH/IHP-Open-PDK/blob/main/README.md)와 [open_pdks의 GF180 구성 설명](https://github.com/fossi-foundation/open-pdks/blob/main/gf180mcu/README)에서 실제 사례를 확인할 수 있습니다. 파일명의 확장자가 같아도 공정·셀·도구용 변환 판본이 다르면 호환된다고 보장할 수 없습니다.

GF180의 [Design Manual](https://gf180mcu-pdk.readthedocs.io/en/latest/physical_verification/design_manual/Design_Manual.html)은 DFM 지침, 안테나 규칙, 신뢰성 규칙과 `Rules not coded` 부록을 구분합니다. 따라서 DRC 보고서의 오류가 0개라는 사실과 제조사가 요구하는 모든 검토를 마쳤다는 주장은 구별해야 합니다.

## 4. 같은 셀의 여러 뷰를 맞추는 이유

합성에서는 Liberty의 논리와 지연을 보고 셀을 선택합니다. 배치배선에서는 그 셀의 LEF 크기와 핀을 사용합니다. 최종 레이아웃에는 대응하는 GDS 도형이 들어갑니다. LVS는 레이아웃에서 추출한 소자·연결을 기준 netlist와 비교합니다.

예를 들어 같은 이름의 셀을 서로 다른 라이브러리 판본에서 가져오면 `.lib`의 핀과 LEF의 핀이 어긋나거나, 셀 크기·전원 핀·레이아웃 내용이 맞지 않을 수 있습니다. 이때 `.lib` 파일 하나를 바꾸어 합성 경고만 없애는 방식으로는 해결되지 않습니다. 라이브러리의 판본 묶음과 핀 규약을 함께 맞춥니다.

정적 타이밍 분석에서 설계의 배선 기생 성분을 전달하는 SPEF는 PDK 그 자체와 구분합니다. PDK의 RC 기술 정보와 실제 배선 형상을 이용해 설계별 SPEF를 만들 수 있습니다. [OpenRCX 문서](https://openroad.readthedocs.io/en/latest/main/src/rcx/README.html)는 공정·코너별 추출 규칙과 배선에서 R·C를 추출하여 SPEF로 저장하는 과정을 설명합니다.

## 5. 코너와 동작 조건

코너(corner)는 제조 편차와 동작 조건을 대표하도록 정한 분석 조건입니다. `TT`, `SS`, `FF`는 흔히 typical·slow·fast 트랜지스터 조합을 나타내지만, 정확한 이름과 의미는 해당 PDK를 확인합니다. 온도와 전압도 함께 지정해야 합니다.

| 조건 | 확인할 내용 | 예시 판단 |
|---|---|---|
| 트랜지스터 공정 코너 | NMOS·PMOS 조합과 모델 절 | `FS`와 `SF`의 뜻을 파일 이름만 보고 뒤바꾸지 않습니다. |
| 전압·온도 | 셀 특성화의 공급 전압과 온도 | 전압만 같은 다른 온도의 `.lib`를 임의로 대체하지 않습니다. |
| 배선 RC 코너 | 금속·비아와 유전체 변동을 반영한 추출 조건 | 트랜지스터가 빠른 조건과 배선 지연이 작은 조건은 별개입니다. |
| 셀 내부 변동·타이밍 모델 | 지연 표, 제약 표, OCV 관련 자료 | 코너 하나만으로 모든 칩 내부 변동을 다룬다고 가정하지 않습니다. |

[LibreLane Timing Corners](https://librelane.readthedocs.io/en/stable/usage/timing_corners.html)는 PVT와 배선 코너를 구분합니다. 공식 예시 `sky130_fd_sc_hd__tt_025C_1v80.lib`는 typical 공정, 25 °C, 1.8 V의 셀 특성 파일입니다. 이 이름을 다른 공정의 전압 규칙으로 일반화하지 않습니다. 또한 setup과 hold의 가장 나쁜 조건이 항상 같은 코너이거나, 온도가 높을수록 모든 경로가 무조건 느려진다고 가정하지 않습니다. 실제 라이브러리와 분석 시나리오에서 판단합니다.

## 6. PDK를 얻는 두 경로

비공개 PDK를 사용하는 경우에는 소속 기관의 CAD 담당자나 파운드리·공인 서비스 창구를 통해 공정과 프로젝트 조건을 확인합니다. 계약에 따라 NDA, 사용자 계정, 프로젝트 승인과 자료 접근 권한이 필요할 수 있습니다. 실제 사례로 IHP의 [SG13G3Cu PDK 교육 안내](https://www.ihp-microelectronics.com/events-1/detail/tutorial-on-ihps-130-nm-bicmos-pdk-including-cu-backend-and-next-generation-technology-using-cadence-and-ads)는 NDA를 요구합니다. 이 비공개 교육용 공정과 공개 SG13G2 PDK를 같은 배포물로 취급하지 않습니다.

| 공개 PDK | 공식 공개 자료의 대상 | 공개 상태를 읽는 방법 |
|---|---|---|
| SKY130 | SkyWater 130 nm 계열 | [공식 상태 문서](https://skywater-pdk.readthedocs.io/en/main/status.html)는 공개 배포물을 experimental preview로 설명합니다. |
| GF180MCU | GlobalFoundries 0.18 μm 3.3 V/6 V MCU 공정 | [공식 저장소](https://github.com/google/gf180mcu-pdk)는 공개판의 experimental preview 상태를 설명합니다. |
| IHP SG13G2 | 130 nm SiGe BiCMOS, 아날로그·디지털·RF | [IHP 공식 저장소](https://github.com/IHP-GmbH/IHP-Open-PDK/blob/main/README.md)는 공개판을 preview로 설명합니다. |

기반 제조 공정에 제작 실적이 있다는 사실과 공개 배포판의 검증 상태는 다릅니다. 공개 라이선스도 제작 서비스·마스크·웨이퍼·패키징의 무료 제공을 뜻하지 않습니다. 실제 제작에서는 제공자의 제출 규칙과 사용할 PDK·IP 판본을 따로 확인합니다.

LibreLane 등 공개 흐름은 원자료를 그대로 읽기보다 도구에 맞게 구성·변환한 PDK를 사용할 수 있습니다. [LibreLane PDK 안내](https://librelane.readthedocs.io/en/stable/usage/about_pdks.html)는 Open PDKs와 Ciel을 통한 구성 및 특정 판본 사용을 설명합니다. 공개 PDK를 내려받았다는 이유만으로 모든 상용 도구용 설정이 완성되었다고 보지 않습니다.

## 7. 자주 생기는 오류

| 증상 | 확인 순서 |
|---|---|
| `unknown model`·소자 모델 누락 | 소자 이름 → 모델 파일 포함 경로 → 코너 절 → 시뮬레이터용 모델 형식 |
| 합성한 셀을 배치할 수 없습니다. | 합성 라이브러리 이름 → LEF 셀 이름과 핀 → 동일 판본의 셀 뷰 |
| GDS에 하위 셀이 비어 있습니다. | 참조한 셀 이름 → GDS 병합 목록 → 누락된 매크로 뷰 |
| LVS의 전원·접지 연결이 다릅니다. | 핀 순서·전원 연결 규약 → netlist 형식 → LVS 설정과 추출 결과 |
| 배선 후 지연이 예상과 크게 다릅니다. | RC 코너 → 배선 형상과 SPEF → 단위·핀·타이밍 제약 → 셀 코너 |
| DRC는 통과했지만 제출 조건이 남았습니다. | 검사 범위 → 문서에만 있는 규칙 → 안테나·밀도·신뢰성·제출 체크리스트 |
