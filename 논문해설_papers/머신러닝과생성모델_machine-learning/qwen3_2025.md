# Qwen3: 생각하는 모드와 짧게 답하는 모드를 한 모델에 담기

An Yang, Anfeng Li, Baosong Yang, Beichen Zhang, Binyuan Hui 등 Qwen Team의 「Qwen3 Technical Report」는 Alibaba Qwen 연구진의 2025년 기술 보고서입니다. [arXiv 제출 기록](https://arxiv.org/abs/2505.09388)은 2025년 5월 14일, PDF 표지는 5월 15일입니다. [공식 저장소](https://github.com/QwenLM/Qwen3)와 함께 읽습니다. 나중의 Qwen3-2507이나 Qwen3.5를 이 첫 Qwen3 보고서의 동일 모델로 합치지 않습니다.

## 원문 구조와 질문

1절은 개요, 2절은 dense·MoE 구조, 3절은 사전학습 자료와 단계·평가, 4절은 추론 학습·모드 결합·일반 강화학습·증류·평가, 5절은 결론입니다. 6절은 저자, 부록은 긴 문맥과 다국어 추가 평가입니다. 같은 모델에 thinking과 non-thinking 모드를 결합하고, 추론 예산을 조절하며, 큰 교사에서 작은 모델로 행동을 전달하는 흐름입니다. [원문 2–4절](https://arxiv.org/pdf/2505.09388)

‘생각하는 모드’는 모델의 생성 절차와 출력 형식에 관한 용어입니다. 사람이 의식적으로 생각한다는 심리학적 능력을 그대로 측정했다는 뜻은 아닙니다. 길게 생성하면 반드시 정답이 된다는 보장도 아닙니다.

## dense, MoE, 증류

dense 모델은 해당 층의 정해진 가중치를 넓게 사용하는 구조입니다. MoE는 여러 전문가 부분 중 일부를 항목마다 선택해 계산합니다. 총 매개변수는 저장한 전체 용량, 활성 매개변수는 해당 입력 처리에 쓰이는 일부 용량을 뜻합니다. 두 숫자는 역할이 다릅니다.

증류는 강한 교사의 출력이나 확률 정보를 이용해 학생 모델을 학습시키는 방법입니다. 교사의 모든 지식이 손실 없이 작은 모델로 옮겨진다는 뜻은 아닙니다. 학생이 직접 만든 열에서 교사 분포를 참조하는지, 교사가 미리 만든 답만 사용하는지도 다른 조건입니다.

## 직접 계산하는 전문가 선택

설명용 층에 전문가 8개가 있고 입력마다 2개를 선택한다고 하겠습니다. 한 항목에서 전문가 수 기준 활성 비율은 2/8=25%입니다. 그러나 공유 부분이나 어텐션 계산까지 25%가 되는 것은 아닙니다. 모든 전문가 가중치를 저장할 메모리도 필요할 수 있습니다.

| 구분 | 예제의 수 | 놓치기 쉬운 조건 |
| --- | --- | --- |
| 전체 전문가 | 8 | 저장해야 할 전체와 관련됩니다 |
| 선택 전문가 | 2 | 항목별 계산과 관련됩니다 |
| 전체 전문가 활성 비율 | 25% | 전체 모델 비용 비율은 아닙니다 |

두 입력이 서로 다른 전문가를 선택하면 묶음 전체에서는 더 많은 전문가를 사용할 수 있습니다. 따라서 “항상 모델의 25%만 메모리에 올리면 된다”는 결론도 나오지 않습니다. 통신과 병렬화 조건을 함께 봐야 합니다.

## 추론 예산을 비용으로 읽기

직접 만든 단순 모델에서 출력 처리 속도가 초당 100토큰으로 일정하다고 가정하겠습니다. 추가 추론 1000토큰은 10초, 4000토큰은 40초입니다. 이는 실제 Qwen3의 측정 속도가 아닙니다. 품질 비교에 쓰는 출력 예산이 사용자 지연과 비용에도 관련된다는 산술입니다.

```math
t=\frac{\text{생성 토큰 수}}{\text{초당 토큰 수}}
```

출력 예산을 늘렸을 때 벤치마크 평균이 높아져도 모든 개별 문제에서 정답으로 바뀌는 것은 아닙니다. 어떤 문제에서는 잘못된 방향을 오래 이어 갈 수도 있습니다. 정확도와 토큰 수·시간을 따로 보고, 정답 하나당 비용이나 제한 시간 안의 성공률 같은 목표도 정해야 합니다.

## 모드와 출력 형식을 확인하는 자체 입력

요청 A를 “12×13의 답 숫자만 적어 주세요”, 요청 B를 “조건이 서로 충돌하는지 짧은 근거와 함께 판단해 주세요”로 만들겠습니다. 첫 요청의 기대 판정은 숫자 156과 형식 준수입니다. 두 번째는 결론과 조건의 일치 여부를 별도로 확인합니다.

non-thinking을 쓴다고 모든 어려운 요청에 바로 틀리는 것은 아니며, thinking을 쓴다고 모든 쉬운 요청에 유리한 것도 아닙니다. 적용 모드, 채팅 템플릿, 생성 예산을 함께 기록해야 비교가 됩니다. 숨은 추론 구간과 최종 답을 섞어 ‘숫자만’ 조건을 판정하면 형식 평가도 달라질 수 있습니다.

이 예에서는 모델을 실행하지 않았습니다. 모드별 성공이나 실패를 가정한 결과 표를 만들지 않고, 어떤 조건을 판정할지를 직접 제시합니다. 논문의 성능 표와 자체 평가 설계의 증거 수준을 구분합니다.

## 결과와 해석의 한계

원문은 추론·코딩·지시 따르기·다국어 등의 결과와 thinking budget, 증류의 비교를 보고합니다. 지원 언어 수는 모든 언어에서 같은 품질이라는 뜻이 아닙니다. 평가 언어·문제 수·번역과 판정 방식을 확인해야 한국어에 대한 범위를 판단할 수 있습니다. [원문 4.6–4.7절과 부록 A](https://arxiv.org/pdf/2505.09388)

on-policy 증류의 일부 계산 절감 결과도 해당 교사·학생·자료와 비교 기준의 결과입니다. 모든 작은 모델 학습이 정해진 배수로 싸진다는 보장이 아닙니다. 전체 매개변수와 활성 매개변수만으로도 장치별 실제 속도를 확정할 수 없습니다.

후속 [Qwen3.5-Omni 보고서](qwen35-omni_2026.md)는 다른 기반 구조에서 음성·영상 이해와 생성을 통합합니다. 이는 같은 조직의 후속 연구 연결이며 Qwen3 텍스트 모델이 이미 그 음성 생성 능력을 갖췄다는 의미는 아닙니다.

## 모델 이름과 비교 조건을 남기기

같은 Qwen3 계열이라도 작은 dense 모델과 큰 MoE 모델의 결과를 하나의 ‘Qwen3 점수’로 합치면 무엇을 비교했는지 알기 어렵습니다. 모델 식별자, 기반 또는 지시 학습 여부, thinking 설정과 출력 예산을 한 줄씩 기록하면 비교 대상을 분명하게 남길 수 있습니다.

한 입력에서 최선 답을 여러 번 뽑아 그중 정답이 있는지를 보는 평가와, 한 번 뽑은 답을 그대로 쓰는 평가는 다릅니다. 예를 들어 10문제에서 각 8개 답을 생성한 경우와 각 1개 답을 생성한 경우는 총 생성량도 다릅니다. 높은 성공률의 배경에 어떤 샘플 예산이 있었는지 확인해야 합니다.

이 사례는 특정 모델의 pass@k를 새로 측정한 것이 아닙니다. 보고서의 한 행을 실제 사용 조건으로 옮길 때 필요한 구분입니다. 공개 가중치를 사용할 수 있다는 사실도 자신이 가진 장치에서 같은 속도와 품질을 얻었다는 실행 근거를 대신하지 않습니다.

## 스스로 확인하기

1. 전문가 25%를 선택하면 전체 모델 메모리도 25%인가요?
2. thinking의 출력 길이가 길면 정답은 항상 더 정확한가요?
3. 지원 언어 수가 한국어 품질을 직접 나타내나요?

<details>
<summary>답과 이유</summary>

1. 아닙니다. 전체 저장 가중치와 공유 계산이 남습니다.
2. 아닙니다. 예산과 성공은 개별 입력·모델 조건에 따라 다릅니다.
3. 아닙니다. 해당 언어의 별도 평가가 필요합니다.
