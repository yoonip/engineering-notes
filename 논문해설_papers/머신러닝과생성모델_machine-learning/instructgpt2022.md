# InstructGPT: 사람의 시범과 선호로 지시 따르기를 학습하기

Long Ouyang, Jeff Wu, Xu Jiang, Diogo Almeida, Carroll L. Wainwright 등의 「Training language models to follow instructions with human feedback」는 OpenAI 연구진의 NeurIPS 2022 논문입니다. [원문](https://arxiv.org/abs/2203.02155)을 기준으로 읽습니다. 사전학습한 GPT-3에 사람의 시범과 비교 평가를 더하는 연구이며, 이후 ChatGPT 제품의 모든 구성을 설명하는 문서는 아닙니다.

## 원문의 흐름과 질문

1–2절은 배경, 3절은 방법과 자료·평가자·학습·평가 설정, 4절은 API 분포와 공개 과제 결과, 5절은 논의·한계·사회적 영향입니다. 부록은 프롬프트 자료, 사람 평가 지침, 학습 설정과 추가 결과를 제공합니다. 시범으로 지도 미세조정 SFT를 하고, 답변 비교로 보상 모델을 학습한 뒤, 그 보상을 사용하는 강화학습을 수행합니다. [원문 3절, 그림 2](https://arxiv.org/pdf/2203.02155)

논문의 사람 선호 결과는 해당 프롬프트 분포와 평가 지침에서 얻었습니다. 작은 모델의 답변이 더 선호되었다는 사실을 모든 분야의 지식·추론 능력이 더 높다는 결론으로 바꾸지 않습니다.

## 지도학습, 보상 모델, 정책

지도학습은 입력과 목표 답의 쌍으로 학습하는 방식입니다. 선호 데이터는 같은 질문의 여러 답 중 어느 쪽이 더 나은지 비교한 자료입니다. 보상 모델은 질문과 답변에 점수를 매기는 모델입니다. 정책은 실제로 다음 토큰을 선택해 답변을 만드는 언어 모델입니다.

보상 점수는 사람의 만족도를 직접 측정한 물리량이 아닙니다. 비교 자료의 순서를 잘 설명하도록 학습한 값입니다. 평가자들이 서로 다른 판단을 내릴 수도 있고, 같은 사람도 주어진 지침에 따라 다른 기준을 사용할 수 있습니다. ‘인간과 정렬했다’는 말 뒤에는 누구의 어떤 선호인지가 필요합니다.

## 직접 만드는 세 단계의 자료

설명용 요청을 “회의가 오후 3시로 바뀌었다는 문자를 두 문장 안으로 써 주세요”라고 정하겠습니다. 실제 서비스나 논문의 사용자 프롬프트를 복사한 예가 아닙니다.

| 단계 | 자체 예제 자료 | 학습할 관계 |
| --- | --- | --- |
| SFT | 요청과 간결한 시범 답 | 요청에 맞는 답을 생성합니다 |
| 선호 비교 | 간결한 답 A와 장황한 답 B | 같은 요청에서 A를 더 선호합니다 |
| 강화학습 | 정책이 새로 만든 여러 답 | 높은 점수를 받는 방향을 찾습니다 |

시범 답에는 회의 시각이 정확해야 하고, 길이 제한도 지켜야 합니다. “오전 3시”라고 잘못 적은 짧은 답은 형식은 맞아도 내용은 실패입니다. 정확성과 형식을 한 개의 모호한 ‘좋음’으로 합치면 어떤 행동이 보상받는지 알기 어려워집니다.

## 비교 점수의 확률을 손으로 보기

답 A와 B의 보상 점수를 2와 0으로 직접 부여하겠습니다. 차이에 시그모이드를 적용하는 비교 모델에서는 A를 선호할 확률을 다음처럼 계산할 수 있습니다.

```math
P(A\succ B)=\frac{1}{1+e^{-(2-0)}}\approx0.880797
```

둘에 모두 100을 더해도 차이는 2이므로 확률은 같습니다. 따라서 점수 102가 행복도 102점이라는 식의 절대 해석은 근거가 없습니다. 이 숫자는 구조를 이해하기 위한 계산이며 실제 평가자나 보상 모델의 출력이 아닙니다.

선호가 바뀌는 질문도 있습니다. 어떤 사용자는 자세한 설명을 원하고 다른 사용자는 한 줄만 원합니다. 질문의 조건을 빼고 답변 길이만 보상하면 원하는 행동을 배우지 못할 수 있습니다. 비교 데이터에는 같은 입력 조건이 왜 중요한지 보여 줍니다.

## 왜 원래 모델에서 너무 멀어지지 않게 하나요

학습된 보상 모델에는 오류와 빈틈이 있을 수 있습니다. 정책이 점수만 극단적으로 최적화하면 사람이 실제로 원하는 답보다 보상 모델을 속이는 표현을 찾을 수 있습니다. 기준 정책과의 차이를 제한하는 항은 이런 변화를 조절하는 장치입니다. 다만 제한 항 하나로 사실성이나 안전성이 완전히 보장되지는 않습니다.

직접 만든 예로 보상 모델이 답변 끝의 “도움이 되셨기를 바랍니다”를 과도하게 좋아한다고 하겠습니다. 내용이 틀려도 그 문구만 반복해서 점수를 얻는다면 보상 해킹입니다. 사람의 평가 점수와 자동 보상 점수를 별도로 확인해야 하는 이유입니다.

또한 선호 학습으로 답변이 공손해졌다고 외부 사실을 자동으로 새로 알게 되는 것은 아닙니다. 사실 확인이 필요한 요청에는 근거 자료와 평가가 따로 필요합니다. 정렬 목표, 지식의 범위, 도구 사용 여부를 같은 개념으로 묶지 않습니다.

## 원문의 결과와 남은 한계

논문은 지시 따르기와 선호 외에 진실성·유해한 출력·공개 과제의 변화도 따로 평가합니다. 학습 평가자의 가치 판단, 제한된 언어·사용자 분포, 잘못된 생성과 유해 출력의 잔존을 한계로 다룹니다. 모델이 항상 올바른 지시를 따르거나 모든 사용자의 가치에 일치한다는 결론은 아닙니다. [원문 4–5절](https://arxiv.org/pdf/2203.02155)

후속 [DPO](dpo2023.md)는 별도 보상 모델과 PPO를 사용하는 절차의 일부를 다른 손실로 바꿉니다. 두 방법을 비교할 때 선호 자료의 품질과 모델·계산 예산도 맞춰야 합니다. 이 글의 회의 문자와 점수 예는 직접 만든 교육 자료이며 API 호출·사람 선호 실험·보상 모델 실행을 하지 않았습니다.

## 평가자 간 차이를 남기는 연습

자체 요청을 “어려운 내용을 짧게 설명해 주세요”라고 정하겠습니다. 평가자 A는 예시가 있는 답을, B는 한 문장짜리 정의를 더 좋아할 수 있습니다. 둘 중 한 답만 절대적인 정답으로 표시하면 실제 선호의 차이가 자료에서 사라집니다. 길이 제한과 독자 수준을 먼저 구체적으로 주면 비교의 해석이 더 분명해집니다.

또한 같은 사람이 두 답을 비교할 때 순서나 문체의 영향을 받을 수 있습니다. 평가 지침과 답의 배치를 기록해야 하고, 평가자 간 합의 정도도 확인할 수 있습니다. 다수의 선호가 모였다는 사실과 모든 소수 의견이 틀렸다는 결론은 다릅니다.

이 연습은 선호 자료의 주관성을 이유로 모든 평가가 무의미하다는 뜻은 아닙니다. 무엇을 누구의 판단으로 평가했는지 명확하게 남기자는 뜻입니다. 논문의 사람 선호 결과도 그 조건 안에서의 근거로 읽으며, 이 글은 새 평가자를 모집하거나 합의율을 측정하지 않았습니다.
