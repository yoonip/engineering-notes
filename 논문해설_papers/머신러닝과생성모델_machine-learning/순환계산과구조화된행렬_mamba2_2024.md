# Mamba-2: 순환 계산과 구조화된 행렬 계산을 같은 식으로 보기

Tri Dao와 Albert Gu의 「Transformers are SSMs: Generalized Models and Efficient Algorithms Through Structured State Space Duality」는 ICML 2024 논문입니다. 소속은 Princeton University와 Carnegie Mellon University입니다. [원문](https://arxiv.org/abs/2405.21060), [학회 서지](https://proceedings.mlr.press/v235/dao24a.html), [공식 구현](https://github.com/state-spaces/mamba)을 기준으로 읽습니다. 제목을 모든 softmax Transformer가 아무 조건 없이 유한 상태 모델과 같다는 주장으로 읽지 않습니다.

## 원문 구조와 논리적 연결

1–2절은 배경, 3절은 상태공간 모델과 반분리 행렬, 4절은 구조적 마스크 어텐션, 5절은 SSD, 6절은 효율적인 알고리즘, 7절은 구조, 8절은 시스템 최적화, 9절은 실험, 10–11절은 논의와 결론입니다. 부록은 표기와 상세 유도를 제공합니다. 재귀식을 펼친 행렬의 구조를 이용해, 순환 방식과 블록 행렬 방식으로 같은 계산을 표현하는 것이 핵심입니다. [원문 3–6절](https://arxiv.org/pdf/2405.21060)

언어 모델링 결과와 핵심 층의 속도 결과는 서로 다른 측정입니다. 어떤 커널이 빠르다는 사실을 모든 길이·장치에서 전체 모델이 같은 배수로 빠르다는 뜻으로 바꾸지 않습니다.

## 이중성, 구조 행렬, 랭크

이중성은 같은 대상을 서로 다른 표현으로 다루는 관계입니다. 여기서는 모든 성질이 같은 두 물리 이론이라는 뜻보다, 계산의 두 형식을 연결하는 대수적 관점입니다. 구조 행렬은 모든 원소를 제각각 저장하지 않아도 일정한 규칙으로 나타낼 수 있는 행렬입니다.

랭크는 행렬이 표현하는 독립 방향의 수입니다. 반분리 행렬은 특정한 대각선 바깥 부분들이 낮은 랭크 구조를 갖는 행렬 계열입니다. “행렬 전체의 랭크가 무조건 1”이라는 뜻은 아닙니다. 어떤 부분에 어떤 제약이 있는지 봐야 합니다.

## 직접 펼치는 세 단계의 재귀식

단순한 상태를 h_t=a_t h_(t−1)+b_t x_t, 출력은 y_t=c_t h_t, 초기 상태는 0이라고 정하겠습니다. 이는 SSD 전체를 그대로 재현하는 모델이 아닌 관계 설명용 예제입니다.

```math
h_1=b_1x_1
```

```math
h_2=a_2b_1x_1+b_2x_2
```

```math
h_3=a_3a_2b_1x_1+a_3b_2x_2+b_3x_3
```

앞 입력의 영향은 중간 단계의 a들을 곱하며 전달됩니다. y에 c를 곱하는 항까지 포함하면 입력 벡터에 곱하는 하삼각 행렬로 쓸 수 있습니다. 하삼각은 미래 입력이 과거 출력에 영향을 주지 않는 인과적 순서와 연결됩니다.

## 숫자로 두 표현 맞추기

a2=a3=0.5, 모든 b와 c를 1, 입력을 (2,4,8)로 정하면 순환 계산의 출력은 (2,5,10.5)입니다. 행렬로도 다음과 같습니다.

```math
\begin{bmatrix}1&0&0\\0.5&1&0\\0.25&0.5&1\end{bmatrix}
\begin{bmatrix}2\\4\\8\end{bmatrix}
=\begin{bmatrix}2\\5\\10.5\end{bmatrix}
```

행렬의 모든 칸을 저장하면 쌍의 개수만큼 비용이 들지만, 계수의 곱 구조를 이용하면 더 작은 상태로 계산할 수 있습니다. 반대로 GPU의 빠른 행렬 곱을 활용하려면 여러 항목을 블록으로 묶는 방식이 유리할 수 있습니다. 같은 답을 내는 수식이라도 장치에서의 시간은 다를 수 있습니다.

이 수치는 직접 만든 산술이며 Mamba-2 가중치나 논문 실험 결과가 아닙니다. 실제 모델에서는 상태와 채널, 학습 가능한 투영 등이 추가됩니다. 한 숫자의 예제를 그대로 모델 전체의 구조라고 생각하지 않아야 합니다.

## 블록 안과 블록 사이의 계산

긴 열을 여러 묶음으로 나누면 묶음 안의 입력 관계와, 이전 묶음에서 넘어오는 상태를 나누어 다룰 수 있습니다. 하나의 큰 행렬을 모두 계산하는 방식과 모든 위치를 단순 순회하는 방식 사이에서, 구조를 활용하는 계산 경로를 설계합니다.

설명용으로 입력 여덟 개를 네 개씩 두 블록으로 묶어 보겠습니다. 첫 블록의 마지막 상태는 두 번째 블록에 전달됩니다. 두 번째 블록이 첫 블록의 원문 항목 전체를 다시 읽는 것과, 요약 상태를 받는 것은 다릅니다. 블록 경계를 잘못 초기화하면 같은 긴 열이 두 개의 독립된 열처럼 처리될 수 있습니다.

서로 다른 사용자의 열을 한 묶음에 넣을 때도 마찬가지입니다. 길이를 맞추기 위한 패딩과 실제 문장 경계를 구분해야 합니다. 앞 사용자의 상태를 다음 사용자에게 이어 주면 성능뿐 아니라 자료 분리의 의미도 바뀝니다. 가변 길이 처리의 구현 조건이 중요한 이유입니다.

## 결과, 한계, 후속 연결

원문은 연상 기억 과제, 언어 모델링, 속도, 구조 비교를 나누어 평가합니다. 고정된 상태 크기는 긴 문맥의 임의 세부를 모두 보존한다는 보장이 아닙니다. 어떤 어텐션 변형과 대수적으로 연결되는지와, 실제 언어 모델에서 같은 정확도를 갖는지는 서로 다른 종류의 주장입니다. [원문 9–10절](https://arxiv.org/pdf/2405.21060)

후속 [Titans](추론중갱신하는신경망기억_titans2025.md)는 Mamba-2 등을 비교 대상으로 삼고 기억의 갱신 방식을 달리합니다. 관계를 다룬 이론이 그 후속 모델의 모든 성공을 설명하거나, 모든 Transformer를 대체했음을 뜻하지는 않습니다. 이 글은 재귀식과 행렬식의 일치만 직접 검산했습니다.

## 같은 계산의 검산 순서

재귀식과 행렬식을 비교할 때 먼저 입력 길이를 아주 작게 정하고, 임의 계수를 사용해 두 출력을 모두 계산하는 방법이 유용합니다. 세 단계 예제에서 a3만 0으로 바꾸면 마지막 출력은 이전 입력과 무관하게 b3x3만 남아야 합니다. 이 경계 사례는 오래된 영향이 실제로 지워지는지 확인해 줍니다.

반대로 a2와 a3를 1로 두면 이전 상태가 감쇠 없이 더해집니다. 이 경우 마지막 출력은 b와 c를 1로 정했을 때 입력의 누적합입니다. 서로 다른 특수 사례에서 두 표현의 결과가 맞는지 확인하면 인덱스 하나가 어긋난 오류를 찾기 쉽습니다.

그러나 작은 예제의 일치만으로 큰 GPU 구현의 모든 정밀도와 성능이 검증된 것은 아닙니다. 수식의 대응, 수치 안정성, 메모리 경계, 병렬 실행은 검증 단계가 다릅니다. 여기서는 앞의 세 단계 산술을 확인했으며 공식 커널 전체를 재실행하지 않았습니다.
