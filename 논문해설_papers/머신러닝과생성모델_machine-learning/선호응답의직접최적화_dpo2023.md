# DPO: 선호하는 답의 상대 확률을 기준 모델과 비교하기

Rafael Rafailov, Archit Sharma, Eric Mitchell, Stefano Ermon, Christopher D. Manning, Chelsea Finn의 「Direct Preference Optimization: Your Language Model is Secretly a Reward Model」은 NeurIPS 2023 논문입니다. 소속은 Stanford University와 CZ Biohub입니다. [원문](https://arxiv.org/abs/2305.18290), [저자 구현](https://github.com/eric-mitchell/direct-preference-optimization)을 기준으로 읽습니다.

## 원문의 논리 순서

1–2절은 배경, 3절은 선호 모델과 KL 제약 목표, 4절은 DPO 유도, 5절은 이론 분석, 6절은 실험, 7절은 논의입니다. 부록 A는 최적 정책과 손실의 유도, 나머지는 구현·평가·추가 결과를 다룹니다. 선호 자료로 보상 모델을 따로 학습하고 PPO를 수행하는 절차 대신, 특정 선호 모델과 정규화 목표의 관계를 이용해 직접 정책 손실을 만듭니다. [원문 3–5절](https://arxiv.org/pdf/2305.18290)

“강화학습이 전혀 필요 없다”는 구호보다, 어떤 목적과 가정을 다른 최적화 문제로 표현했는지 보는 편이 정확합니다. 임의의 사람 선호와 모든 모델 조건에서 자동으로 같은 해를 얻는다는 뜻은 아닙니다.

## 선호 쌍과 기준 정책

선호 쌍은 같은 요청에 대한 더 선호하는 답과 덜 선호하는 답입니다. 기준 정책은 학습이 너무 멀리 변하지 않도록 비교하는 고정 모델입니다. 로그 확률비는 현재 모델이 어떤 답을 기준 모델보다 얼마나 더 그럴듯하게 보는지 나타냅니다.

시그모이드는 실수를 0과 1 사이의 값으로 바꾸는 함수입니다. β는 기준과의 관계를 조절하는 계수로 손실에 들어갑니다. 확률을 단순히 높이는 학습이 아니라, 선택된 답과 거절된 답 사이의 상대적 변화가 중요합니다. 전체 응답의 로그 확률은 토큰별 로그 확률을 정해진 마스크와 함께 더해 계산합니다.

## 직접 계산하는 상대 변화

설명용으로 현재 정책이 선호 답 A와 비선호 답 B에 부여한 전체 응답 확률을 0.3과 0.1로 정하겠습니다. 기준 정책에서는 각각 0.2와 0.2라고 둡니다. 이 수치는 실제 모델 응답이 아닌 계산 예제입니다.

```math
\Delta=\log\frac{0.3}{0.2}-\log\frac{0.1}{0.2}
=\log3\approx1.098612
```

β=1이면 손실은 −log σ(Δ)입니다. σ(log 3)=3/4이므로 손실은 약 0.287682입니다. 두 답 모두 기준보다 확률이 높아졌는지를 묻는 계산이 아닙니다. A와 B의 상대 비율이 얼마나 선호 방향으로 바뀌었는지 봅니다.

| 모델 | A 확률 | B 확률 | A/B |
| --- | --- | --- | --- |
| 기준 | 0.2 | 0.2 | 1 |
| 현재 | 0.3 | 0.1 | 3 |

현재 모델이 (0.15, 0.05)를 부여해도 A/B는 3이므로 이 예의 쌍별 차이는 같습니다. 이는 다른 응답들에 배정한 확률까지 같다는 뜻은 아닙니다. 한 선호 쌍의 손실은 전체 분포의 모든 성질을 직접 측정하지 않습니다.

## 정답 길이가 다른 경우

짧은 답과 긴 답의 확률을 비교할 때는 토큰이 몇 개 포함되었는지 중요합니다. 토큰별 확률이 0.5라면 두 토큰의 곱은 0.25, 네 토큰의 곱은 0.0625입니다. 길이 차이 때문에 전체 확률의 규모가 달라질 수 있습니다.

그래서 임의로 토큰 평균을 취해도 같은 DPO라고 말할 수는 없습니다. 논문의 목적식과 구현이 어떤 구간을 합산하는지, 프롬프트와 패딩을 제외하는지, EOS를 어떻게 처리하는지 확인해야 합니다. 서로 다른 마스킹은 서로 다른 학습 목표를 만들 수 있습니다.

직접 만든 요청을 “정답 숫자만 쓰세요: 7+8”이라고 하겠습니다. 선호 답을 ‘15’, 비선호 답을 ‘답은 15입니다’로 정하면 주로 형식 선호를 학습합니다. ‘15’와 ‘16’을 비교하면 사실 정확성의 차이가 큽니다. 어떤 종류의 선호 쌍을 모았는지에 따라 학습할 행동도 달라집니다.

## 이론적 관계와 실제 자료의 차이

선호가 보상 차이로 설명된다는 가정은 유도에서 중요한 역할을 합니다. 실제 평가는 평가자마다 기준이 달라질 수 있고, 특정 답 A를 B보다, B를 C보다, C를 A보다 선호하는 순환도 생길 수 있습니다. 제한된 비교 자료에서 목적을 최적화했다고 모든 사용자 요구를 일관되게 만족한다는 뜻은 아닙니다.

또한 데이터 밖 요청에서의 동작과 보상 과최적화는 별도 문제입니다. 보상 모델을 명시적으로 만들지 않는다고 선호 자료의 편향이나 분포 이동이 없어지지는 않습니다. 답변 길이나 자신감 있는 말투를 과도하게 선호하는 자료라면 그런 경향도 학습될 수 있습니다.

## 결과와 후속 연결

원문은 감정 조절, 요약, 대화 등의 과제에서 비교하고 자동 평가와 사람 판단의 관계도 확인합니다. 연구에서 다룬 모델 규모와 과제를 넘어 모든 환경에서 PPO보다 우월하다고 일반화하지 않습니다. [원문 6–7절](https://arxiv.org/pdf/2305.18290)

후속 [IPO를 제안한 선호 학습 논문](https://arxiv.org/abs/2310.12036)은 선호를 확률적으로 학습할 때의 다른 목적과 과최적화를 논의합니다. 같은 선호 데이터에서 다른 목적을 선택할 수 있다는 연결입니다. 이 글은 자체 확률 계산만 수행했으며 실제 정책을 미세조정하거나 선호 승률을 측정하지 않았습니다.

## 선호 라벨의 방향을 확인하기

같은 요청에 대한 두 답을 파일에 저장할 때 선택된 답과 거절된 답의 열을 바꾸면 손실이 밀어 주는 방향도 반대가 됩니다. 두 답 모두 문법적으로 자연스럽다고 해도 라벨 방향은 학습 목표의 핵심입니다. 점수가 내려간다는 사실만으로 올바른 선호를 배웠다고 결론 내릴 수 없습니다.

직접 만든 검사로 요청의 정답 숫자가 15인 사례에서 선택 열에는 ‘15’, 거절 열에는 ‘16’을 두고, 열 이름과 손실의 부호를 먼저 손으로 확인할 수 있습니다. 요청 토큰을 답의 확률에 잘못 포함하지 않았는지도 함께 확인합니다. 작은 자료 구조 오류가 전체 학습의 의미를 바꾸는 사례입니다.

이 확인은 DPO에 특유한 새 성능 주장이 아니라 목적식을 코드와 연결하는 원리입니다. 실제 미세조정을 실행하지 않았더라도 입력 쌍과 확률비의 방향은 산술로 점검할 수 있습니다. 이후 성능을 보고할 때는 이런 정적 검토와 실제 사람 선호 평가를 구분해야 합니다.
