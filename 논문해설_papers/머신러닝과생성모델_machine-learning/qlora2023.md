# QLoRA: 고정한 저정밀 가중치 위에서 작은 어댑터 학습하기

Tim Dettmers, Artidoro Pagnoni, Ari Holtzman, Luke Zettlemoyer의 「QLoRA: Efficient Finetuning of Quantized LLMs」는 University of Washington 연구진의 NeurIPS 2023 논문입니다. [원문](https://arxiv.org/abs/2305.14314), [저자 코드](https://github.com/artidoro/qlora), [저자 양자화 라이브러리](https://github.com/bitsandbytes-foundation/bitsandbytes)를 기준으로 설명합니다. 기존 LoRA 해설과 달리 여기서는 양자화된 고정 기반 모델과 학습 메모리의 관계를 중심으로 읽습니다.

## 원문 구조와 핵심

1–2절은 배경, 3절은 NF4·이중 양자화·페이지 최적화, 4절은 일반 미세조정과 비교, 5절은 대화 모델 평가, 6절은 정성 분석, 7–9절은 관련 연구·한계·영향입니다. 부록에는 설정, 평가, 자료와 NF4를 다룹니다. 기반 가중치는 4비트로 보관하고 고정하며, 연산에 필요한 표현으로 풀어 계산하면서 저랭크 어댑터를 학습합니다. 모든 연산과 기울기를 4비트로 계산한다는 뜻은 아닙니다. [원문 3절](https://arxiv.org/pdf/2305.14314)

65B 모델을 48GB 장치에서 미세조정한 보고와, 그 규모에서 완전한 16비트 전체 미세조정과 동등함을 직접 입증했다는 주장은 다릅니다. 원문의 8절도 큰 규모의 전체 미세조정 비교가 제한됨을 밝힙니다.

## 양자화와 저랭크의 뜻

양자화는 많은 가능한 숫자값을 더 적은 대표값으로 표현하는 방법입니다. 비트 수가 작으면 저장할 수 있는 코드의 수가 줄어듭니다. NF4는 정규분포 형태의 가중치에 맞춘 대표값 배치를 사용하는 데이터 형식입니다. 정확히 등간격인 정수 코드와 같은 뜻은 아닙니다.

저랭크 어댑터는 큰 행렬을 직접 모두 바꾸는 대신 작은 두 행렬의 곱으로 변화를 표현합니다. 랭크는 독립적으로 표현할 수 있는 방향의 수와 관련된 개념입니다. 어댑터를 학습한다고 기반 가중치의 양자화 오차가 완전히 사라진다는 수학적 보장은 아닙니다.

## 직접 계산하는 저장량

설명용으로 매개변수 10억 개를 생각하겠습니다. 원소마다 16비트라면 순수 가중치에 20억 바이트가 필요합니다. 4비트라면 5억 바이트입니다. 바이트를 GiB로 바꾸면 각각 약 1.863과 0.466입니다.

```math
10^9\times\frac{16}{8}=2\times10^9\ \mathrm{bytes},
\qquad10^9\times\frac{4}{8}=5\times10^8\ \mathrm{bytes}
```

이 계산에는 블록별 스케일, 양자화 메타데이터, 어댑터, 기울기, 최적화 상태, 활성값과 작업 공간이 없습니다. 따라서 4비트 가중치의 단순 저장량을 GPU 전체 메모리 요구량으로 적으면 부족하게 계산됩니다. 큰 문맥 길이와 배치도 활성값의 비용을 늘릴 수 있습니다.

## 어댑터의 숫자를 손으로 세기

기반 행렬이 4096×4096이면 원소 수는 16777216개입니다. 변화량을 랭크 8의 두 행렬 4096×8과 8×4096으로 표현하면 합계는 65536개입니다. 단순히 한 행렬의 변화량만 비교하면 1/256입니다.

| 부분 | 원소 수 | 학습 여부의 예 |
| --- | --- | --- |
| 기반 행렬 | 16777216 | 고정합니다 |
| 첫 어댑터 | 32768 | 학습합니다 |
| 둘째 어댑터 | 32768 | 학습합니다 |

이 표는 선택한 행렬 한 개의 계산입니다. 실제 모델은 여러 층과 여러 투영 행렬을 포함하므로 전체 어댑터 수는 어디에 적용했는지에 따라 달라집니다. 랭크를 두 배로 하면 이 예의 학습 원소 수도 두 배지만, 품질이 두 배가 된다는 뜻은 아닙니다.

## 이중 양자화와 순간 메모리

가중치 블록을 양자화할 때는 각 블록의 범위를 나타내는 스케일 숫자도 필요합니다. 이중 양자화는 그 스케일 자체의 저장량을 줄이는 접근입니다. 가중치만 세고 스케일을 빼면 실제 저장 비용을 놓칠 수 있습니다.

페이지 최적화는 순간적인 메모리 요구를 다루기 위한 장치입니다. 사용한 전체 계산이 사라지거나 모든 장치에서 전송 비용이 0이 되는 것은 아닙니다. 자료 이동과 페이지 처리 때문에 실제 시간은 달라질 수 있으므로, 메모리 적합 여부와 속도는 따로 측정해야 합니다.

직접 평가 입력으로 짧은 문서의 날짜·금액·예외를 추출하는 요청을 만들 수 있습니다. 완전한 정밀도 기반과 양자화 기반에서 같은 입력·템플릿·추론 설정을 쓰고, 사실 일치와 형식 일치를 나누면 어떤 오류가 늘었는지 보기가 쉽습니다. 이 글에서는 그런 모델 실행을 하지 않았으며, 가상의 성능 점수를 만들지 않습니다.

## 결과와 한계, 후속 연결

논문은 여러 모델과 자료에서 미세조정 및 대화 평가를 비교하고, 자동 심판과 사람 평가의 문제도 다룹니다. 특정 대화 벤치마크의 상대 점수를 ‘모든 능력에서 ChatGPT의 몇 %’로 옮기면 범위를 과장하게 됩니다. [원문 4–6절, 8절](https://arxiv.org/pdf/2305.14314)

후속 [LoftQ](https://arxiv.org/abs/2310.08659)는 양자화와 저랭크 초기화를 함께 다루는 연구입니다. QLoRA와 이름이 비슷하더라도 초기화 방법과 비교 조건은 별개입니다. 메모리를 줄인 방법이 어떤 가중치를 고정했고, 어떤 상태를 학습하며, 어디서 원래 정밀도를 사용하는지 추적하는 것이 핵심입니다.

## 저장 정밀도와 계산 정밀도

직접 작은 값 0.37을 대표값 0.3 또는 0.4 중 하나로 저장한다고 해 보겠습니다. 0.4를 선택하면 저장 오차는 0.03입니다. 연산할 때 0.4를 더 넓은 정밀도로 풀어 계산해도 원래 0.37이 자동으로 돌아오는 것은 아닙니다. 수치를 더 정밀한 형식에 옮기는 것과 잃은 정보를 복구하는 것은 다릅니다.

어댑터가 다른 가중치와 함께 그 영향을 일부 보상할 수는 있지만, 모든 입력에서 양자화 오차를 정확히 상쇄할 수 있다고 미리 보장하지 않습니다. 학습한 입력과 처음 보는 입력을 나누어 평가해야 합니다. 작은 저장 오차가 최종 출력에서 어떤 차이로 나타나는지도 모델의 다른 계산에 따라 달라집니다.

이 장난감 반올림은 NF4의 실제 코드북을 그대로 보여 주는 예는 아닙니다. 대표값을 줄이면 생기는 기본적인 정보 손실을 설명합니다. 실제 NF4의 품질이나 어댑터의 보상 정도는 논문의 비교 조건과 별도 실험을 통해 확인해야 합니다.
