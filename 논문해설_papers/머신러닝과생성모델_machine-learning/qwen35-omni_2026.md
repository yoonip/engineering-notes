# Qwen3.5-Omni: 이해한 문맥을 끊김 없는 음성으로 연결하기

Qwen Team의 「Qwen3.5-Omni Technical Report」를 읽습니다. 연구 조직은 Alibaba의 Qwen입니다. [arXiv 기록](https://arxiv.org/abs/2604.15804)의 v2는 2026년 4월 21일이며, 확인한 PDF 표지는 4월 22일입니다. 저자 목록은 원문 7절에 있으며 Jin Xu, Yunfei Chu 등 핵심 기여자와 전체 기여자를 구분합니다. 이 글은 [28쪽 원문 v2](https://arxiv.org/pdf/2604.15804v2)를 대상으로 하며 학회 발표를 임의로 붙이지 않습니다.

## 원문 구조와 문제

1절은 개요, 2절은 AuT·Thinker·Talker·ARIA와 스트리밍, 3절은 사전학습, 4절은 이해와 음성 생성의 후속 학습, 5절은 입력별 이해·음성 평가, 6절은 결론입니다. 7절은 저자, 8절은 언어별 추가 결과입니다. 이해와 텍스트 생성을 담당하는 Thinker와 음성 토큰을 생성하는 Talker를 연결하며, 텍스트와 음성의 서로 다른 처리 속도를 맞추기 위해 ARIA를 사용합니다. [원문 2–5절](https://arxiv.org/pdf/2604.15804v2)

이 모델은 텍스트·이미지·음성·영상 입력을 다루지만 각 입력과 출력의 평가 조건은 다릅니다. 음성을 이해하는 능력과 특정 언어로 자연스럽게 말하는 능력을 하나의 ‘언어 지원’ 숫자로 합치지 않습니다.

## 코덱, 코드북, 스트리밍

코덱은 음성을 계산에 사용할 표현으로 바꾸고 다시 파형으로 복원하는 방식입니다. 코드북은 대표적인 표현 조각을 모은 표이며, 여러 코드북을 사용하면 남은 세부를 단계적으로 표현할 수 있습니다. 코드북 토큰은 텍스트의 글자나 단어와 같은 단위가 아닙니다.

스트리밍은 전체 답을 완성한 뒤 보내는 대신 작은 조각을 순서대로 전달하는 방식입니다. 첫 패킷 지연은 처음 재생 가능한 조각이 나오기까지의 시간입니다. 전체 답변이 끝나는 시간, 초당 처리량, 동시에 처리하는 요청 수와는 다른 지표입니다.

## 직접 계산하는 음성 시간 해상도

원문 2.2–2.3절은 AuT 출력의 시간 단위를 6.25Hz, 약 160ms에 해당한다고 설명합니다. 설명용 10초 오디오에서 일정한 6.25Hz를 단순 적용하면 62.5개 시간 위치에 해당합니다. 실제 정수 토큰 수는 경계·패딩·블록 처리에 따라 달라질 수 있으므로 62.5개의 토큰이 실제 출력된다고 적지 않습니다.

```math
1/6.25=0.16\ \mathrm{s},\qquad
10/0.16=62.5
```

영상 프레임을 초당 1장 확인한다면 400초는 400장에 대응합니다. 720P는 프레임의 공간 해상도이고, 1FPS는 시간 방향의 샘플링 빈도입니다. 400초 동안 일어난 모든 30FPS 움직임을 동일한 세밀함으로 보존한다는 뜻은 아닙니다.

| 단위 | 묻는 질문 | 혼동하면 안 되는 값 |
| --- | --- | --- |
| Hz | 초당 시간 위치가 몇 개인가요 | 텍스트의 단어 수 |
| FPS | 초당 영상 표본이 몇 장인가요 | 영상의 가로·세로 크기 |
| ms | 처리에 얼마의 시간이 걸리나요 | 이해 정확도 |

이 계산은 원문 단위의 의미를 확인하는 산술이며 실제 파일을 입력해 측정하지 않았습니다.

## ARIA가 필요한 이유

같은 뜻도 언어마다 텍스트 토큰 수와 음성 길이의 비율이 다를 수 있습니다. 고정된 규칙으로 텍스트 두 토큰마다 음성 토큰 세 개를 내보내면 어떤 문장에서는 말할 내용과 소리의 진행이 어긋날 수 있습니다. ARIA는 접두사에서 음성과 텍스트 누적 비율을 제어하는 정렬 방식을 사용합니다. [원문 2.4절](https://arxiv.org/pdf/2604.15804v2)

직접 만든 단순 예로 텍스트 단위가 4개, 음성 단위가 12개인 한 항목을 생각하겠습니다. 전체 비율은 3입니다. 텍스트 2개가 준비된 시점에 음성 단위 10개를 이미 내보내면 누적 비율은 5로 전체 비율보다 큽니다. 이런 산술은 앞서 나간 흐름을 표현하는 데 도움이 되지만, 실제 ARIA의 모든 학습·디코딩을 재현하는 예는 아닙니다.

원문의 정렬 규칙을 외운다고 말 빠르기와 발음이 무조건 좋아지는 것은 아닙니다. 코드북 표현과 학습 자료, 문장과 언어별 토큰화도 관련됩니다. 텍스트를 정확히 생성했어도 소리에서 숫자를 빠뜨리거나 잘못 발음하는 경우는 별도 판정이 필요합니다.

## 지연 표를 읽는 방법

원문 표 1–2는 Plus와 Flash의 첫 패킷 지연과 동시 요청별 처리량을 보고합니다. 2.5절은 자원 배치와 병렬화가 다르므로 두 변형의 숫자를 엄격한 같은 자원 비교로 쓰지 말라고 설명합니다. 표의 여러 지연 행을 단순히 더하면 전체 지연이 되는 것도 아닙니다. 병렬 경로와 임계 경로가 있기 때문입니다.

직접 만든 예로 인코더 100ms 뒤에 텍스트와 음성 준비가 각각 80ms와 120ms로 겹쳐 진행된다고 가정하면, 단순 합 300ms가 아니라 해당 경로에서는 220ms가 될 수 있습니다. 실제 시스템은 더 복잡하므로 이 수치도 측정값이 아닌 병렬 처리의 예제입니다.

## 평가와 한계, 확인 가능한 연결

원문은 음성 인식의 WER, 화자 유사도, 여러 입력의 질의응답, 도구 사용 등을 나눕니다. WER가 낮아도 말투·감정·화자 특성이 모두 정확하다는 뜻은 아닙니다. 반대로 자연스러운 음성이라고 내용의 수치나 근거가 맞는 것도 아닙니다. 공개 및 내부 평가 자료와 자동 심판 조건을 함께 확인해야 합니다. [원문 5절과 표 7–10](https://arxiv.org/pdf/2604.15804v2)

자체 입력으로 “총액 12,300원, 할인 15%, 최종액을 말해 주세요”를 쓰면 계산 정답 10,455원과 실제 발음·숫자 누락을 따로 판정할 수 있습니다. 여기서는 음성 생성이나 API를 실행하지 않았습니다. 본문 속 저자 결과를 독립 재현했다고 적지 않습니다.

확인한 원문은 이전 Qwen-Omni 계열과 Qwen3.5 구조를 연결합니다. 이후 독립 후속 연구의 영향이나 현재 제품의 보편적 품질까지는 이 자료만으로 단정하지 않습니다. 긴 입력을 받을 수 있다는 설명도 모든 위치의 세부를 동일하게 회상한다는 보장이 아닙니다.

## 음성의 내용을 작은 단위로 판정하기

할인 예제에서 최종액 10,455원을 정확히 계산했어도 음성에서 ‘만 사천오백오십 원’처럼 읽으면 숫자가 달라집니다. 반대로 발음은 매끄럽지만 할인을 두 번 적용해 잘못 계산했을 수도 있습니다. 계산 내용, 텍스트 표기, 음성의 수치 실현을 각각 확인해야 합니다.

화자의 말투가 비슷하다는 유사도와 내용의 정확성도 다릅니다. 긴 음성을 평가할 때에는 일부 단어 누락, 반복, 중간 중단 뒤의 이어 말하기가 평균적인 음질 점수에 가려질 수 있습니다. 직접 만든 입력의 정답을 알고 있다면 숫자와 고유명사를 별도 항목으로 판정할 수 있습니다.

이것은 모델이 실제로 그런 오류를 냈다는 관찰 보고가 아닙니다. 음성 이해와 생성이 결합된 구조에서 성공을 어떻게 정의할지 보여 주는 자체 평가 사례입니다. 보고된 첫 패킷 지연을 내용 정확도의 근거로 사용하지 않는 이유와도 연결됩니다.
