# Telatar 1999: 안테나가 여러 개일 때 전송 용량은 어떻게 달라질까요?

## 원문과 읽은 범위

I. Emre Telatar, 「Capacity of Multi-antenna Gaussian Channels」, European Transactions on Telecommunications 10(6), 585–595, 1999년입니다. 당시 소속은 미국 Lucent Technologies의 Bell Laboratories입니다. [출판 서지와 DOI](https://doi.org/10.1002/ett.4460100604), [MIT가 공개한 저자 원고](https://web.mit.edu/6.454/www/www_fall_2004/alex_o/Telatar99.pdf)를 확인했습니다. 확인일은 2026년 10월 20일입니다.

읽은 전문은 28쪽짜리 공개 원고입니다. 서론 1–2쪽, 준비 개념 2–5쪽, 고정 채널 5–9쪽, Rayleigh 채널 9–19쪽, 비에르고딕 채널 19–24쪽, 다중접속과 결론 25쪽, 부록·참고문헌 26–28쪽을 읽었습니다. 이 원고는 1994–1995년에 작성되었다는 설명을 포함하며 최종 학술지의 11쪽 조판본과 같지 않습니다. 출판사 화면의 2008년 온라인 등록일을 연구 발표 연도로 사용하지 않습니다.

## 하나의 주파수에서 여러 길을 사용하는 문제

휴대전화와 기지국 사이에서는 전파가 벽과 바닥에 반사되어 여러 경로로 도착합니다. 안테나 하나에서는 반사파가 서로 지워지는 현상이 문제가 됩니다. 여러 안테나가 서로 다른 신호의 혼합을 관찰하면, 그 차이를 이용하여 여러 데이터를 구분할 수도 있습니다. MIMO는 multiple-input multiple-output의 약자로, 송신과 수신에 여러 안테나를 사용하는 통신 구조입니다.

논문의 질문은 특정 휴대전화의 다운로드 속도가 아닙니다. 잡음과 전력 제한이 주어졌을 때, 오류를 매우 작게 만들면서 보낼 수 있는 정보율의 상한을 묻습니다. 이 상한을 채널 용량이라고 합니다. 용량 이하라고 해서 임의의 짧은 코드가 바로 통과하는 것은 아닙니다. 부호 길이, 복호 지연, 채널 추정에 필요한 자원은 실제 구현에서 따로 고려합니다.

## 2–3절: 복소 행렬로 신호의 혼합을 적습니다

기본 모형을 다음과 같이 적을 수 있습니다.

```math
y=Hx+n,\qquad E[nn^{\dagger}]=I,\qquad \mathrm{tr}(Q)\leq P.
```

x는 송신 안테나별 신호를 모은 벡터이고 y는 수신 벡터입니다. H의 각 원소는 특정 송신 안테나에서 특정 수신 안테나로 가는 경로의 크기와 위상 변화를 담습니다. 복소수는 진폭뿐 아니라 파동의 위상도 표현하므로 사용합니다. †는 복소켤레를 취한 뒤 행과 열을 바꾸는 연산입니다. Q는 송신 신호의 공분산이며 대각선의 합인 trace가 총 평균 전력입니다. 잡음 공분산을 I로 둔 것은 단위를 잡음 기준으로 정규화한 모형입니다.

고정된 H에서 수신기가 채널을 알고 있고 입력이 공분산 Q의 적절한 복소 Gaussian 분포일 때, 정보율은 다음 행렬식으로 표현됩니다. 실제 QAM 입력의 정보율을 임의의 전력에서 그대로 나타내는 식은 아닙니다. 여기서는 독자의 계산 편의를 위해 밑이 2인 로그를 씁니다. 원문의 자연로그 값은 nat 단위이며 bit와 수치가 다릅니다.

```math
I(Q,H)=\log_2\det(I+HQH^{\dagger}).
```

행렬식 det는 행렬을 하나의 수로 요약하는 연산입니다. 독립적인 공간 경로로 좌표를 바꾸면 각 경로의 「1+신호 대 잡음비」가 곱해지고, 로그를 취하면 경로별 정보율의 합이 됩니다. 안테나 개수만 세기보다 H가 몇 개의 독립적인 방향을 구분하는지, 즉 rank를 살펴야 하는 이유입니다.

송신기도 현재 H를 알면 좋은 경로에 더 많은 전력을 주는 water filling을 사용할 수 있습니다. 바닥 높이가 서로 다른 그릇에 물을 붓는 것처럼, 잡음에 비해 불리한 경로에는 전력을 적게 주거나 주지 않습니다. 이 설명은 수학적 전력 배분의 비유이며 모든 상용 MIMO 장비가 같은 방식으로 작동한다는 뜻은 아닙니다.

## 직접 계산: 총 전력과 안테나별 전력을 구분합니다

다음은 원저의 실험 수치가 아니라, 잡음 분산이 1인 가상 채널의 계산입니다. H=I₂이고 총 전력 P=10을 두 송신 안테나에 5씩 나누면 다음과 같습니다.

```math
C_{2\times2}=2\log_2(1+5)=5.1699\ \text{bit/복소 채널 사용}.
C_{1\times1}=\log_2(1+10)=3.4594.
```

두 경우 모두 총 전력이 10입니다. 안테나 두 개에 각각 10을 주고 「안테나 때문에 빨라졌다」고 비교하면 전력도 두 배로 늘린 셈입니다. 또한 5.1699를 곧바로 Gb/s라고 읽으면 안 됩니다. 초당 채널 사용 횟수, 대역폭의 정의, 파일럿·부호화·프레임 오버헤드가 추가로 필요합니다.

이제 H=diag(1,0)으로 바꾸겠습니다. 두 번째 경로가 완전히 끊어진 모형입니다. 현재 H를 모른 채 전력을 5씩 주면 log₂6=2.5850만 얻습니다. 반면 송신기가 끊어진 경로를 알아서 첫 경로에 10을 모두 주면 log₂11=3.4594입니다. 같은 안테나 수라도 채널과 송신기의 정보가 다르면 결과가 달라집니다.

## 4–5절: 평균적으로 좋은 채널과 매번 보장되는 채널

Rayleigh 모형은 경로 계수가 확률적으로 변한다고 가정합니다. 수신기는 현재 채널을 알지만 송신기는 분포만 아는 경우, 대칭적인 독립 채널에서는 전력을 균등하게 배분한 평균 log-det 식이 등장합니다. 평균은 서로 다른 채널 상태를 충분히 겪는 부호화 조건과 연결됩니다. 평균 속도가 높다는 사실과 특정 순간의 연결이 끊기지 않는다는 사실은 다릅니다.

outage는 선택한 정보율을 현재 채널이 감당하지 못하는 사건입니다. 주사위를 한 번 던져 정한 H가 전송 내내 유지되는 모형과 매번 다른 H를 충분히 겪는 모형을 섞으면 안 됩니다. 논문에서 다루는 고정 전력·비에르고딕 Rayleigh 조건의 영 outage 용량 논의는 나쁜 채널의 확률을 완전히 제거할 수 없다는 뜻입니다. 모든 무선 통신의 실제 속도가 0이라는 결론이 아닙니다. 5절의 일부 outage 최적 공분산 논의는 추측으로 제시되므로 보편적으로 증명된 정리처럼 인용하지 않습니다.

## 근거와 실제 적용의 경계

이 연구의 중심 근거는 확률·행렬 해석입니다. 상용 기지국을 야외에서 측정한 논문이 아닙니다. 독립 경로, 채널 지식, Gaussian 잡음과 전력 제약이라는 전제를 먼저 확인해야 합니다. 현실의 안테나 상관, 인체 차폐, 증폭기 비선형성, 제한된 피드백은 단순 식에 자동으로 포함되지 않습니다.

공간 다중화와 송신 다이버시티도 구분해야 합니다. 전자는 서로 다른 데이터를 병렬로 보내는 방향이고 후자는 같은 정보를 다른 경로로 전달하여 오류를 줄이는 방향입니다. [Alamouti의 두 안테나 방식](alamouti1998-diversity.md)을 함께 읽으면 「안테나 두 개면 무조건 두 배」라는 오해를 피할 수 있습니다. 이 논문에서 사용한 행렬 계산은 실제 시스템의 가능 범위를 생각하는 도구이며 제품 성능표 자체가 아닙니다.

## 스스로 확인해 보세요

식을 읽을 때에는 y와 H의 크기부터 써 보시면 좋습니다. 송신 안테나가 t개, 수신 안테나가 r개이면 x는 t×1, H는 r×t, y는 r×1입니다. HQH†는 r×r이므로 더하는 I도 r×r이어야 합니다. 이런 차원 검사는 계산기를 사용하기 전에 잘못된 곱셈을 찾는 간단한 방법입니다. 물리 단위와 행렬의 크기는 서로 다른 검사이므로 둘 다 확인합니다.

1. H=I₂, 총 전력 10의 예에서 두 안테나에 10씩 주면 왜 공정한 비교가 아닐까요?
2. 안테나가 두 개이면 H의 rank도 반드시 2일까요?
3. 평균 정보율이 같은 두 시스템의 outage 확률도 같다고 할 수 있을까요?

1. 총 전력이 20으로 바뀝니다. 안테나 구조의 효과와 전력 증가의 효과를 분리할 수 없습니다.
2. 아닙니다. 두 열이 같은 방향이거나 한 열이 0이면 rank는 1 이하일 수 있습니다. 독립적인 혼합을 구분할 수 있어야 합니다.
3. 그렇지 않습니다. 같은 평균이라도 정보율의 분포가 다를 수 있습니다. 목표 정보율 R보다 작아지는 확률을 따로 비교해야 합니다.
