## 전체를 다시 저장해야 합니까?

큰 사전학습 모델을 과제마다 전부 fine-tuning하면 학습할 값과 과제별 저장량이 커집니다. LoRA는 원 가중치를 고정하고, 그 가중치에 더할 변화량을 두 작은 행렬의 곱으로 표현하여 학습합니다. 원문 §4가 방법을 정의합니다. Adaptation은 여기서 ‘새 과제에 맞춘 조정’이라는 뜻으로 읽으시면 됩니다.

‘고정한다’는 것은 해당 학습에서 가중치를 갱신하지 않는다는 뜻입니다. 원 모델을 메모리에서 없애도 된다는 뜻은 아닙니다. 출력 계산에는 원 가중치가 계속 필요합니다.

## Rank를 ‘작은 숫자’보다 정확하게 읽기

Rank, 즉 계수는 행렬의 열 또는 행이 제공하는 독립적인 방향의 수입니다. 0이 아닌 두 열이 서로 두 배 관계라면 두 열을 저장했더라도 독립적인 방향은 하나입니다. Low-rank는 변화가 적은 독립 방향의 조합으로 표현된다는 뜻이며, 원 가중치 전체가 작은 계수라고 가정하는 말과는 다릅니다.

입력 크기가 k, 출력 크기가 d일 때 원 가중치 `W₀`는 `d×k`입니다. 변화량을 `B(d×r) A(r×k)`로 나타내면 학습할 값은 `dk`개 대신 `r(d+k)`개가 됩니다. 보통 적용하는 배율까지 쓰면 다음과 같습니다.

$$y=W_0x+\frac{\alpha}{r}BAx$$

`r`은 선택한 내부 차원, `α`는 변화량의 배율을 정하는 설정입니다. 엄밀히는 `rank(BA)≤r`이며 언제나 r과 같은 것은 아닙니다. 이 식과 모양은 원문 §4.1을 기준으로 합니다.

## 직접 정한 작은 행렬의 출력

설명을 위해 배율 `α/r=1`, 원 가중치 `W₀`는 2×2 단위행렬로 정합니다. 입력은 `x=(2,1)`, `A=(1,−1)`, `B=(0.1,0.2)ᵀ`입니다.

| 순서 | 계산 | 결과 |
| --- | --- | --- |
| 원 경로 | `W₀x` | `(2,1)` |
| 작은 공간으로 | `Ax=1×2−1×1` | `1` |
| 출력 공간으로 | `B(Ax)` | `(0.1,0.2)` |
| 두 경로 합치기 | `(2,1)+(0.1,0.2)` | `(2.1,1.2)` |

변화 행렬은 `BA=[[0.1,−0.1],[0.2,−0.2]]`입니다. 이를 W₀에 미리 더해 만든 행렬 `[[1.1,−0.1],[0.2,0.8]]`에 x를 곱해도 `(2.1,1.2)`가 나옵니다. 두 계산이 같은 것은 분배법칙으로 확인할 수 있습니다. 학습된 모델의 정확도를 재현한 실험은 아닙니다.

이 2×2 예에서는 원 행렬도 4개, A와 B도 합쳐 4개 값이어서 학습할 값의 수가 줄지 않습니다. 큰 정사각 행렬에서 차이가 뚜렷해집니다. 직접 정한 `d=k=1000`, `r=4`라면 1,000,000개와 8,000개로 125배 차이가 납니다. 이것은 해당 행렬의 학습 변수 개수 비교이며 모델 전체 메모리나 실행시간 125배 절감을 뜻하지 않습니다.

## 초기값과 추론의 의미

원문의 구성은 A를 무작위로, B를 0으로 시작하여 처음 변화량을 0으로 만듭니다. 두 행렬을 모두 0으로 두면 일반적인 이 곱의 학습에서 서로를 통해 흐르는 gradient도 0이 되는 문제가 생길 수 있습니다. ‘출력이 처음에 같도록 한다’와 ‘모든 학습 변수를 같은 0으로 둔다’는 다른 선택입니다.

선형 경로의 변화량을 W₀에 합치면 추론 시 같은 크기의 행렬 곱으로 계산할 수 있습니다. 공식 `loralib` 구현은 설정에 따라 평가 모드에서 병합합니다. 다만 여러 adapter를 동적으로 바꾸는 시스템이나 양자화된 가중치의 병합에서는 구현 조건을 따로 확인해야 합니다. 병합 가능성만으로 모든 장치에서 latency가 반드시 같다고 측정한 것은 아닙니다. [공식 구현 설명](https://github.com/microsoft/LoRA)의 Additional Notes에서 병합 설정을 확인하실 수 있습니다.

## 결과에서 더 확인할 질문

원문의 비교 대상, 적용한 행렬, 선택한 r과 학습 설정을 함께 보아야 합니다. 작은 변화량으로 충분한 과제도 있지만 그 사실이 모든 과제의 좋은 해를 작은 계수로 표현할 수 있다는 증명은 아닙니다. 필요한 기반 모델 메모리, activation, optimizer 상태, 추가 가중치 저장량도 서로 다릅니다.

[GPT-3의 문맥 예시](문맥의예시로수행하는언어과제_gpt3.md)는 평가 중 가중치를 바꾸지 않습니다. LoRA는 추가 행렬의 값을 실제로 갱신합니다. ‘적은 예시로 적응한다’와 ‘적은 변수만 학습한다’는 비교 축이 다르다는 점을 남기시면 좋습니다.

## 자기 점검

1. `d=k=100`, `r=2`이면 원 행렬과 추가 행렬의 변수 수는 각각 얼마입니까?
2. rank가 r 이하인 대상은 W₀입니까, BA입니까?
3. 추가 가중치 파일이 작으면 기반 모델도 필요 없습니까?

<summary>답과 해설</summary>

1. 원 행렬은 10,000개, 추가 행렬은 `2×(100+100)=400`개입니다.

3. 필요합니다. 별도로 저장한 추가 가중치만으로 원 모델의 출력을 계산할 수는 없습니다. 병합해 저장한 전체 가중치와도 구분합니다.
