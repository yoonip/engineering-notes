## 무엇을 바꾸어 물었습니까?

새 과제를 풀 때마다 별도 정답 자료로 가중치를 다시 조정해야 한다면, 과제 수만큼 학습과 관리가 필요합니다. 이 논문은 큰 자기회귀 언어 모델에 과제 설명과 소수의 풀이 예시를 입력으로 주는 평가를 체계적으로 살폈습니다. 가장 큰 모델은 1,750억 parameter이며, 평가할 때의 zero-shot·one-shot·few-shot은 가중치를 갱신하지 않는 설정입니다. 근거는 원문 §2입니다.

‘Few-shot learner’를 ‘문제 몇 개만 배우고 완성된 모델’로 읽으면 사전학습을 놓칩니다. 이미 대규모 학습을 거친 모델이 새 과제의 예시를 문맥에서 참고한다는 뜻입니다. 여기서 shot은 입력에 제시하는 시범 사례 한 개를 가리킵니다.

## 가중치를 바꾸는 일과 입력을 바꾸는 일

| 방법 | 새 과제의 예시를 어디에 씁니까? | 그 단계에서 가중치를 갱신합니까? |
| --- | --- | --- |
| Fine-tuning | 학습용 입력·정답 쌍으로 씁니다. | 갱신합니다. |
| Zero-shot 평가 | 과제 설명을 주고 시범 정답은 주지 않습니다. | 갱신하지 않습니다. |
| One-shot 평가 | 설명과 시범 한 개를 문맥에 넣습니다. | 갱신하지 않습니다. |
| Few-shot 평가 | 설명과 여러 시범을 문맥에 넣습니다. | 갱신하지 않습니다. |

다음은 차이를 설명하기 위해 직접 만든 입력입니다. 실제 GPT-3를 실행해 얻은 출력은 아닙니다.

```text
영어 색 이름을 한국어로 옮겨 주세요.
red → 빨강
blue → 파랑
green →
```

이미 답이 있는 두 줄은 문맥에 포함된 시범입니다. 마지막 줄의 답을 생성한 뒤 이 대화를 저장한다고 해서 모델 가중치가 자동으로 바뀌지는 않습니다. 정답 문장을 손실함수에 넣고 미분하여 가중치를 조정하는 학습과 구분해야 합니다.

‘In-context’는 ‘지금 입력된 문맥 안에서’라는 느낌으로 읽으시면 됩니다. 예시의 순서나 표현, 출력 형식을 바꾸면 입력 자체가 달라집니다. 그러므로 모델 크기만 같다고 모든 prompt의 결과가 같은 것은 아닙니다.

## 다음 토큰 확률을 손으로 확인하기

Autoregressive는 앞의 내용을 조건으로 다음 내용을 모델링한다는 뜻입니다. 토큰은 모델이 다루는 텍스트 단위이며 언제나 단어 하나와 일치하지는 않습니다. 아래에서는 설명을 위해 두 토큰 A와 B만 생각합니다.

$$P(A,B)=P(A)P(B\mid A)$$

직접 정한 값이 `P(A)=0.8`, `P(B|A)=0.5`이면 두 토큰 열의 확률은 `0.8×0.5=0.4`입니다. 두 확률을 더한 1.3은 이 열의 확률이 될 수 없습니다. 평균 음의 로그확률은 자연로그 기준으로 `−(ln 0.8+ln 0.5)/2 ≈ 0.458145`입니다.

여기서 conditional의 ‘조건부’는 어떤 조건문이 참이라는 뜻이 아닙니다. 이미 A가 주어졌을 때 B에 부여한 확률이라는 뜻입니다. 이 작은 계산은 확률의 연결을 보여 줄 뿐 실제 모델의 번역 능력이나 논리적 정확도를 측정하지 않습니다.

```mermaid
flowchart LR
    A[과제 설명과 풀이 예시] --> B[입력 토큰 열]
    B --> C[학습된 가중치로 확률 계산]
    C --> D[다음 토큰 선택]
    D --> E[입력 뒤에 붙여 계속 생성]
```

## 결과 표를 어떻게 읽어야 합니까?

논문의 과제별 결과는 ‘언어 모델을 크게 하고 문맥으로 과제를 지정하는 접근’을 검토할 근거입니다. 그러나 과제마다 정답률과 예시의 효과가 달랐으며, 원문 §4는 학습 자료와 평가 자료가 겹칠 가능성을 점검합니다. §5의 한계를 함께 읽어야 합니다.

새 방법을 평가한다면 같은 문항으로 zero-shot·few-shot을 비교하되, 예시가 평가 정답을 누설하지 않도록 분리해야 합니다. 직접 만든 색 이름 세 개에 잘 답한 결과를 복잡한 추론 전체에 일반화할 수는 없습니다. 또한 정답률, F1, 번역 지표처럼 서로 다른 척도를 한 숫자처럼 비교하지 않습니다.

이 연구가 연 다음 질문은 ‘모든 가중치를 다시 학습하지 않고 어떻게 과제에 적응할 수 있습니까?’입니다. [LoRA](작은행렬의모델적응_lora.md)는 이 질문에 대해 입력 예시를 늘리는 대신 작은 추가 행렬을 학습하는 경로를 보여 줍니다. 두 논문의 적응 방식과 비용을 나란히 읽으시면 차이가 분명해집니다.

## 자기 점검

1. 시범 답 두 개를 prompt에 넣으면 두 번의 gradient update가 있었다고 말할 수 있습니까?
2. `P(A)=0.6`, `P(B|A)=0.5`일 때 `P(A,B)`는 얼마입니까?
3. 모델이 사전학습에서 본 평가 문항을 맞혔다면 새 과제 적응의 증거로 충분합니까?
