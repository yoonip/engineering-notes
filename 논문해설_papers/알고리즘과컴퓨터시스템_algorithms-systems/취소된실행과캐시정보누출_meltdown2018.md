# 취소된 실행이 남기는 캐시 흔적 / Meltdown and memory isolation

## 주소가 있고 권한이 없는 상황

원문은 영향을 받는 CPU에서 사용자에게 읽기 권한이 없는, 주소 공간에 매핑된 데이터를 일시적으로 사용하고 캐시 흔적으로 전달하는 공격을 설명합니다. 여러 기기에서 읽기와 대응책을 평가하며, 성공 여부·속도·오류율은 CPU·캐시·운영체제 설정 등에 의존합니다. 모든 CPU나 현재 패치된 장치가 같은 상태라는 뜻은 아닙니다. 다음 관측값과 계산은 자체 모형입니다.

가상 주소는 프로그램이 사용하는 주소, 물리 주소는 실제 메모리 위치를 나타내는 주소입니다. 페이지 테이블은 둘의 대응과 접근 권한을 기록합니다. 주소가 매핑되어 있다는 것은 변환할 대상이 있다는 뜻이고, 사용자에게 읽기 권한이 있다는 뜻은 아닙니다.

커널은 운영체제의 핵심 권한 영역입니다. 당시 여러 운영체제는 빠른 진입을 위해 사용자 프로세스 주소 공간에 커널 부분도 매핑하되, 권한 비트로 일반 프로그램의 접근을 막았습니다. 원문의 공격은 이 권한 검사와 하드웨어 실행 사이의 경계를 다룹니다. 주소 변환 자체가 없는 상황과 같은 것으로 생각하면 대응 원리를 놓칩니다.

## 아키텍처 상태와 내부 상태

아키텍처 상태는 명령어 집합이 프로그램에 약속한 레지스터·메모리 등의 관측 가능한 결과입니다. 마이크로아키텍처 상태는 캐시·예측기·버퍼처럼 그 명령을 빠르게 구현하는 내부 상태입니다. 구현을 숨긴다는 말이 실제로 아무 방법으로도 관측할 수 없다는 뜻은 아닙니다.

순서 밖 실행은 준비된 뒤쪽 명령을 먼저 처리해 실행 장치를 활용하는 방법입니다. 추측 실행은 아직 확정되지 않은 경로 등을 예측해 처리하는 방법입니다. 둘은 관련되지만 같은 범위의 용어는 아닙니다. 일시적 실행 transient execution은 최종 프로그램 결과로 채택되지 않았지만 내부 흔적을 남길 수 있는 실행을 설명할 때 사용합니다.

자체 추상 모형에서 숨긴 값이 3이고, 그 값에 따라 허용된 관측 버퍼의 네 구역 중 3번이 캐시에 들어갔다고 하겠습니다. 나중에 잘못된 읽기를 취소하여 프로그램 레지스터를 복원하더라도, 버퍼 3번의 빠른 접근이 그대로 남으면 정보가 이어집니다.

```mermaid
flowchart LR
    A[권한상 허용하지 않은 값의 일시적 사용] --> B[값에 의존하는 내부 캐시 변화]
    A --> C[오류 처리와 정상 결과 취소]
    B --> D[허용된 버퍼 접근 시간을 관측]
    D --> E[값에 관한 정보 추정]
```

취소가 완벽한지는 무엇을 되돌린다고 정의했는지에 달렸습니다. 레지스터가 원래 값으로 돌아왔다는 확인은 캐시 흔적이 사라졌다는 확인을 대신하지 않습니다. 반대로 캐시를 썼다는 사실만으로 모든 CPU에서 권한 없는 값이 그 단계까지 전달된다고 결론 내릴 수도 없습니다.

## 시간으로 전달된 정보를 읽기

다음 표는 실제 측정이 아닌 가상 관측값입니다. 접근 시간이 80사이클 미만이면 빠르다고 정한 단순 판정기를 가정합니다.

| 관측 구역 | 가정한 시간 | 단순 판정 |
| --- | --- | --- |
| 0 | 210사이클 | 느림 |
| 1 | 195사이클 | 느림 |
| 2 | 205사이클 | 느림 |
| 3 | 42사이클 | 빠름 |

이 결과는 3번이 캐시되었다는 가설을 지지합니다. 그러나 실제 시간에는 스케줄링·프리페치·다른 작업·캐시 충돌 등의 잡음이 섞입니다. 빠른 구역이 둘이면 어느 것을 선택할지, 모두 느리면 실패인지 값 0인지, 반복 간 결과를 어떻게 합칠지 정해야 합니다. 이 조건을 정하지 않은 채 항상 정답을 읽는 함수처럼 설명하면 오류율을 숨기게 됩니다.

원문도 특정 값으로 치우치는 오류와 반복·전달 비트 수의 절충을 다룹니다. 한 번 읽기가 틀릴 확률만 보지 말고 데이터 전체의 복원 정확성도 봐야 합니다. 자체 독립 오류 모형에서 각 바이트가 99% 정확하면 256바이트 전부가 맞을 확률은 0.99²⁵⁶≈7.63%입니다. 실제 오류가 독립이라는 뜻은 아니며, 작은 단위 정확도와 전체 성공이 다른 지표임을 보여 주는 계산입니다.

## 정보 누출과 권한 획득의 차이

기밀 정보를 읽는 일과 커널 권한으로 임의 코드를 실행하는 일은 다릅니다. 읽기만 가능해도 비밀번호·키·다른 작업의 내용을 노출할 수 있으므로 중요하지만, 이를 곧바로 모든 쓰기·실행 권한을 얻는 동일한 효과로 표현하지 않습니다.

컨테이너는 커널을 공유하는 경우가 많고, 완전 가상화된 VM은 다른 주소 변환·격리 계층을 사용할 수 있습니다. 따라서 “가상 환경에서 성공했다”라는 문장에는 당시 어떤 환경과 매핑을 시험했는지가 붙어야 합니다. 원문이 특정 환경에서 수행한 시험을 모든 하이퍼바이저와 모든 VM 간 읽기로 일반화하지 않습니다.

마찬가지로 한 CPU에서 장난감 캐시 흔적 실험이 성공했다는 관측과, 그 CPU에서 커널의 비밀 데이터를 읽는 전체 공격이 성공했다는 관측은 다릅니다. 접근 권한 우회와 정보 전달의 두 연결을 각각 확인해야 합니다.

## 페이지 테이블 격리가 줄이는 경로

사용자 실행 중에는 필요한 최소 부분 외에 커널 매핑을 두지 않고, 커널 진입 때 다른 페이지 테이블로 바꾸면 공격이 이용하는 주소 변환의 표면을 줄일 수 있습니다. [Linux의 PTI 공식 설명](https://docs.kernel.org/arch/x86/pti.html)은 이 구조와 커널 진입·이탈에 필요한 최소 매핑을 설명합니다. 원문에서 KAISER와 KPTI를 연결해 읽는 후속 구현 근거입니다.

이 방식은 모든 추측 실행 공격을 하나로 해결하는 만능 방어가 아닙니다. [Spectre](예측실행경로의정보누출_spectre2019.md)는 피해 프로그램이 자기 권한으로 읽을 수 있는 데이터를 잘못 예측한 경로에서 사용하게 하는 다른 상황을 포함합니다. 커널 매핑을 줄이는 조치와 피해 프로그램 내부의 경로·예측·데이터 의존성을 다루는 조치는 적용 지점이 다릅니다.

격리 전환의 비용도 시스템 호출 빈도, 주소 변환 캐시와 장치 기능 등에 따라 다릅니다. 원문 속도를 최신 장치의 성능 손실률로 바꾸지 않습니다. 여기서는 공격 코드를 실행하거나 현재 컴퓨터의 취약 여부를 검사하지 않았으며, 원문과 공식 설계 문서를 분석한 범위입니다.

## 자기 점검

1. 매핑된 주소라면 사용자 프로그램에 읽기 권한도 있나요?
2. 오류가 나서 레지스터 결과를 취소했다면 캐시 정보도 반드시 없어지나요?
3. 바이트마다 99% 정확하다는 것은 긴 데이터도 99% 확률로 전부 맞는다는 뜻인가요?
