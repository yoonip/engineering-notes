# 나머지 거듭제곱과 공개키 / RSA encryption and signatures

RSA를 이해하려면 계산이 되돌아온다는 사실과, 공격자가 정보를 얻기 어렵다는 주장을 나누어 읽어야 합니다. 전자는 수학적 등식으로 증명하지만 후자는 공격 모형과 계산 난도에 관한 가정을 필요로 합니다.

## 공개할 정보와 숨길 정보

원문은 두 소수의 곱 n과 공개 지수 e를 공개하고, 비밀 지수 d로 역변환하는 방법을 제안합니다. §IX는 소인수분해와 여러 공격의 관계를 논하며, 모든 역변환 공격과 소인수분해가 동등하다는 증명은 제시하지 않습니다. 다음의 작은 수는 원문 실험이나 실용 보안 설정이 아닌 자체 계산입니다.

소수는 1보다 크고 양의 약수가 1과 자신뿐인 정수입니다. 서로소인 두 정수는 최대공약수가 1입니다. `a mod n`은 a를 n으로 나눈 나머지이며, 합동식은 두 수의 차이가 n의 배수라는 뜻입니다. 곱셈 역원은 곱한 결과의 나머지가 1이 되게 하는 수입니다.

소수 p=5, q=11을 택하면 n=55입니다. 1부터 54까지 중 55와 서로소인 정수의 개수는 오일러 피 함수 phi(55)=4×10=40입니다. e=3에 대해 d=27을 택하면 3×27=81=1+2×40이므로 역원 관계가 성립합니다.

```math
C=M^e\bmod n,\qquad M=C^d\bmod n
```

M=7이면 C=343 mod 55=13입니다. 복호화는 13의 27제곱의 나머지를 구합니다. 거대한 정수를 먼저 전부 만들 필요는 없습니다.

| 거듭제곱 | 55로 나눈 나머지 |
| --- | --- |
| 13¹ | 13 |
| 13² | 4 |
| 13⁴ | 16 |
| 13⁸ | 36 |
| 13¹⁶ | 31 |

27=16+8+2+1이므로 필요한 나머지를 곱하면 31×36×4×13 mod 55=7입니다. 이것이 반복 제곱입니다. 지수의 이진 표현을 따라 제곱과 필요한 곱셈을 수행합니다. 지수 크기만큼 반복하는 방식과 달리 지수의 비트 수에 비례하는 단계로 계산할 수 있습니다. 각 큰 정수 곱셈 자체의 비용은 별도로 남습니다.

## 왜 원래 수로 돌아오는가

서로소인 M에는 오일러 정리를 적용할 수 있습니다. 다만 허용한 메시지 중에는 p나 q의 배수도 있으므로 그 경우를 빠뜨리면 정확성 증명이 끝나지 않습니다. 원문은 p와 q 각각에 대해 확인한 뒤 두 나머지를 합칩니다.

예를 들어 M=5이면 C=125 mod 55=15이며 복호화도 5입니다. 5는 55와 서로소가 아니므로 “모든 메시지가 서로소이기 때문”이라고 설명할 수 없습니다. p=5로 보았을 때 메시지가 0인 경우는 거듭제곱 뒤에도 0이고, q=11 쪽에서는 비영 값에 대한 정리를 적용할 수 있습니다. 서로 다른 두 소수에 대한 나머지가 원래 메시지와 같으면 그 곱을 법으로 해도 같습니다.

정확성은 키를 올바르게 생성하고 0 이상 n 미만의 정수를 다룬다는 조건을 포함합니다. 긴 문서를 숫자 하나로 바꿨더니 n보다 컸다면, 이미 표현 영역 밖입니다. 문자열과 정수 사이 인코딩, 블록 길이, 복호화 실패 처리까지 포함해야 실제 프로토콜이 됩니다.

```mermaid
flowchart LR
    A[수신자 공개키 n과 e 확인] --> B[메시지를 정해진 형식으로 표현]
    B --> C[공개 연산으로 암호문 생성]
    C --> D[수신자의 비밀 연산]
    D --> E[형식 검증과 메시지 해석]
```

## 역변환이 어렵다는 것만으로 충분한가

자체 반례로 메시지가 오직 숫자 0 또는 1인 경우를 보겠습니다. 이 작은 예의 공개 연산에서는 두 값이 각각 0과 1로 암호화됩니다. 공격자는 비밀키를 몰라도 둘을 구별합니다. 더 일반적으로 결정적인 공개 암호화에서 가능한 메시지가 두 개뿐이면, 공격자가 둘을 직접 암호화해 비교할 수 있습니다. 큰 수를 썼다는 사실만으로 메시지 분포에서 생기는 정보를 숨기지는 못합니다.

변조도 별도 문제입니다. 이 예에서 7의 암호문은 13, 2의 암호문은 8입니다. 두 암호문을 곱하면 104 mod 55=49이며 이를 복호화하면 14입니다. 공개 연산의 곱셈 구조가 평문 곱셈과 연결됩니다. 실제 공격 목표와 입력 검증을 정하지 않고 “암호문을 바꾸면 무조건 무의미해진다”고 생각할 수 없습니다.

서명과 비밀 통신의 목표도 다릅니다. 서명은 메시지와 서명자 사이의 관계를 확인하는 데 쓰며, 메시지를 숨기는 기능이 자동으로 생기지 않습니다. 작은 원시 연산을 “개인키로 암호화하면 안전한 서명”이라는 완성된 지침으로 바꾸면 인코딩과 공격 모델을 놓칩니다.

## 후속 규격과 논문의 한계

[RFC 8017](https://www.rfc-editor.org/rfc/rfc8017.html)은 RSA의 원시 연산과 RSAES-OAEP 같은 암호화 방식, RSASSA-PSS 같은 서명 방식을 구분합니다. §5의 정수 연산과 §7–8의 완성된 방식은 같은 층이 아닙니다. 이는 원문을 공부하면서 얻은 수학식과 실제 사용하는 암호 라이브러리의 인터페이스를 구분하는 데 도움이 됩니다.

1978년 논문의 키 길이 권고와 당시 소인수분해 시간 표는 그 시점의 추정입니다. 오늘의 안전 기준이나 실행 성능으로 옮기지 않습니다. 논문이 보여 준 구조적 발상은 공개 연산과 비밀 역연산을 분리하는 것이며, 모든 구현의 보안과 키 유출·시간 정보·오류 응답까지 증명한 결과는 아닙니다. 후속 [확률적 암호화](probabilistic-encryption1984.md)는 암호문에서 일부 정보가 새는 문제를 더욱 분명한 정의로 다룹니다.

## 자기 점검

1. p=5, q=11일 때 왜 e=3과 d=27이 짝을 이루나요?
2. 메시지가 두 개뿐인 결정적 공개 암호화가 왜 구별 공격에 약한가요?
3. 소인수분해가 어려우면 RSA를 이용한 모든 프로토콜이 자동으로 안전한가요?

<details>
<summary>해설 보기</summary>

1. phi(n)=40이고 3×27의 나머지가 40을 법으로 1이기 때문입니다.
2. 누구나 가능한 두 메시지를 공개키로 암호화하고 관측한 암호문과 비교할 수 있습니다.
3. 그렇지 않습니다. 메시지 인코딩, 변조, 인증, 키 취급과 구현에서 관측되는 정보까지 별도로 분석해야 합니다. 역변환 정확성 증명은 이 문제들을 모두 해결하지 않습니다.
