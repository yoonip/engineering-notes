# 알고리즘과 컴퓨터 시스템 / Algorithms and computer systems

문자열과 그래프의 계산 원리, 계산 난도와 암호, 분산 합의, 저장소, 운영체제와 하드웨어 보안을 다루는 논문 30편을 모았습니다. 1960년 전후의 고전부터 2024·2025년 시스템 연구까지 연결해 읽을 수 있습니다.

각 글에는 읽은 원고의 판과 위치, 문제와 핵심 발상, 용어, 직접 만든 예제, 결과의 적용 조건, 세 가지 자기 점검을 적었습니다. 원문의 전체 번역이나 실험 재현 보고가 아닙니다. 논문이 보고한 결과와 설명을 위해 만든 수·상황을 구분하며, 원문 링크에서 증명과 측정 조건을 함께 확인하실 수 있습니다.

## 연결해서 읽는 순서

처음에는 Dijkstra·Quicksort에서 확정 조건과 비용 분석을 읽고, KMP·Boyer–Moore·Karp–Rabin에서 후보를 줄이는 세 방법을 비교하시면 좋습니다. “일치한 길이”, “제외한 정렬”, “같은 지문값”은 각각 무엇을 확실히 알려 주는지 직접 적어 보세요.

Bloom→LSM-tree→Bigtable은 작은 메모리로 불필요한 저장소 작업을 줄이는 흐름입니다. 이후 Spanner에서는 저장 성능에 더해 여러 거래의 관측 순서를 요구하면 어떤 층이 추가되는지 볼 수 있습니다. 빠른 자료구조를 갖추었다는 사실만으로 여러 서버의 거래 의미가 정해지지는 않습니다.

FLP→Paxos→Raft는 불가능성의 조건과 조건부 진행을 함께 읽는 순서입니다. 비잔틴 장군은 장애 모형이 중단에서 임의 행동으로 바뀔 때 별도 조건이 필요함을 보여 줍니다. 종료·안전성·유효성과 메시지 전달 가정을 같은 표에 놓고 비교해 보세요.

RSA→확률적 암호화→Shor는 되돌릴 수 있는 수학식, 계산 제한 공격자의 정보, 계산 장치 모형의 변화가 서로 다른 논점임을 보여 줍니다. Grover의 제곱근 질의 가속을 Shor의 구조적인 주기 찾기와 같은 결과로 외우지 않는 것이 중요합니다.

seL4→Meltdown·Spectre→Rex는 어떤 명세와 실행 모형을 검증하는지 묻는 순서입니다. 기능적 정확성, 메모리 안전성, 시간 관측에 대한 비밀성, 신뢰해야 하는 런타임은 각각 확인해야 합니다. 최신 논문의 비교 표도 대상 버전·실험 장치·부하·오류 범위를 읽은 뒤 해석하시면 됩니다.
