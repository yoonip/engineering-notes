## 두 방향의 변화를 구분합니다

첫째는 공격자가 AI로 기존 작업의 비용·속도·규모를 바꾸는 경우입니다. 둘째는 조직이 AI에 자료와 도구를 연결하면서 새 접근 경계를 만드는 경우입니다. 전자는 피싱·취약점 연구·자료 분석 등의 변화이고, 후자는 프롬프트 주입·도구 권한·모델 및 데이터 공급망의 문제입니다. ‘AI 해킹’ 한 단어로 합치면 대응해야 할 지점이 흐려집니다.

영국 NCSC의 2027년까지의 전망은 AI가 침입 활동의 효율과 효과를 높이고, 패치하지 않은 시스템에 대한 위협을 키울 것으로 평가합니다. 동시에 문서는 전망의 불확실성과 사람의 전문성이 남는다는 조건을 둡니다. 이를 모든 모델이 스스로 어떤 시스템이든 침입한다는 실증 결과로 읽지 않습니다. [NCSC Key judgements·Assessment](https://www.ncsc.gov.uk/report/impact-ai-cyber-threat-now-2027)

## 각 변화에 대응할 공학적 경계

다음 표는 그 위협 범주를 서비스 설계에 연결한 자체 대응 예시이며 특정 공격 사건의 재현 기록은 아닙니다.

| 변화 | 비용이 낮아지는 부분 | 방어에서 바꿀 사항 |
| --- | --- | --- |
| 자연스러운 사칭 메시지 | 번역·문맥 맞춤·초안 작성입니다. | 문법·말투보다 발신 신뢰·독립 확인·피싱 저항성 인증을 봅니다. |
| 코드·설정 분석 보조 | 큰 코드에서 후보 경로를 찾는 작업입니다. | 외부 노출 자산·패치 지연·회귀 검사 시간을 줄입니다. |
| 대량 자료 분류 | 로그·문서·발견 항목을 요약하는 작업입니다. | 비밀 최소화·반출 통제·자료 접근 기록을 연결합니다. |
| 음성·영상 합성 | 목소리·외모에 기대는 신뢰를 흉내 냅니다. | 지급·권한 변경을 별도 등록 경로와 승인 절차로 확인합니다. |
| AI 코딩 도입 | 검토 없이 코드가 늘어나는 속도입니다. | 코드 출처·시험·권한·의존성 검사를 배포 조건으로 둡니다. |

## 방어 AI는 판단을 보조하고 권한은 제한합니다

보안 AI는 로그 묶기, 취약점 후보 설명, 수정안 제안, 문서 검색에 쓸 수 있습니다. 입력 로그나 소스 주석에도 공격자가 쓴 문장이 들어갈 수 있습니다. 분석 AI에 방화벽 변경·계정 삭제·배포 권한을 한꺼번에 주면 잘못된 해석이 실제 장애로 이어집니다. 관찰→제안→검사→승인의 단계별 권한과 실행 예산을 정합니다.

‘정답처럼 보이는 취약점 설명’은 재현 입력·영향 경로·수정 전후 검사로 확인합니다. 벤치마크 정답률과 특정 조직의 보안 사고 감소율도 다른 지표입니다. 평가에는 도구·네트워크·시간·시도 횟수·사용한 모델 판본·사람의 개입을 남겨야 합니다.

## 작은 계산으로 자동 차단의 부담을 봅니다

자체 가정으로 10,000건 중 악성100건, 탐지율90%, 정상 오탐률1%라면 참 경보90건·거짓 경보99건입니다. 경보 정밀도는 `90/(90+99) ≈ 47.6%`입니다. 탐지율만 보고 모두 자동 차단하면 정상 사건도 많이 차단할 수 있습니다. 이 수치는 실제 AI 제품의 측정값이 아닙니다. 영향이 작은 분류와 계정 폐기 같은 고영향 조치는 다른 승인 조건을 사용합니다.

AI 시스템 자체의 보호는 [프롬프트·RAG](12-프롬프트와검색자료_llm-rag-security.md), [도구 권한](13-AI에이전트와도구권한_agent-tool-security.md), [모델·데이터 생명주기](14-모델과데이터의보호_ml-lifecycle.md)로 이어집니다.

## AI로 가능한 일과 실제 피해를 구분합니다

생성형 도구는 문장 번역·개인화, 코드 설명, 공개 자료 분류, 초안 작성 같은 작업의 진입 비용을 낮출 수 있습니다. 그렇다고 모든 공격자가 취약점을 찾아 실제 침입에 성공하거나 사람이 하던 분석을 완전히 대체한다는 뜻은 아닙니다. NCSC의 2027년까지 전망은 AI의 효율과 효과가 커질 가능성을 평가한 전망 자료입니다. 제품별 성능 측정이나 모든 위협 행위자의 현재 능력으로 인용하지 않습니다.

| AI 사용 영역 | 기대 가능한 보조 | 검증이 필요한 위험 |
| --- | --- | --- |
| 사회공학 메시지 | 문맥을 맞춘 초안·번역·요약을 빠르게 만들 수 있습니다. | 발신자 확인과 금융·권한 변경의 별도 승인입니다. |
| 코드 분석 | 취약 후보와 수정 아이디어를 찾는 데 도움을 줄 수 있습니다. | 오탐·누락·잘못된 수정이므로 재현과 독립 검토가 필요합니다. |
| 로그 분류 | 대량 기록에서 조사 후보를 정리할 수 있습니다. | 입력 오염·민감정보·기저율에 따른 오탐입니다. |
| 보안 자동화 | 반복적인 분류나 제한된 읽기 작업을 수행할 수 있습니다. | 실제 시스템을 변경하는 권한은 별도 정책과 승인으로 제한합니다. |
| 합성 미디어 | 음성·영상 모방으로 신뢰 확인을 어렵게 할 수 있습니다. | 단일 통화·영상 확인 대신 사전 등록된 확인 절차를 둡니다. |

방어 AI의 출력은 증거가 아니라 조사 후보로 다룹니다. 원문 로그·소스·실행 경로에서 재현되는지 확인하고, 평가에는 모델명·버전·도구·입력 데이터·사람 개입·오류 비용을 기록합니다. 작은 오탐률도 정상 사건이 매우 많은 환경에서는 다수의 거짓 경보를 만들 수 있으므로, 자동 차단은 오판 영향과 되돌리기 가능성에 따라 제한합니다.
