## 자료와 수식 확인

정의와 기본 법칙은 대학의 공개 강의·교재, 국가기관의 기술 문서, 표준 문서와 제조사의 공식 자료를 기준으로 정리했습니다. MIT·Stanford·Berkeley 등의 강의, BIPM·NIST·LLNL, Arm·ST·Espressif·TI·Analog Devices·AMD·NVIDIA 등의 자료를 사용했습니다. 구체적인 근거는 각 글의 식과 설명 옆에 연결했습니다.

각 글에서는 두 개 이상의 관련 자료를 대조했습니다. 서로 다른 자료가 같은 기호를 다른 의미로 쓰면 이 문서의 정의로 다시 정리했습니다. 이와 별도로 수식의 차원, 부호, 초기·경계조건과 극한값을 확인하고 계산 모델을 검사했습니다. 예를 들어 다음 구분을 본문에 반영했습니다.

| 항목 | 적용한 구분 |
| --- | --- |
| 불확도 전파 | 독립은 공분산 0의 충분조건이며, 무상관과 독립은 같은 말이 아닙니다 |
| RLC 에너지 | 일반식은 입력 전력에서 저항 손실을 뺀 값이며 무입력일 때 감소식으로 줄어듭니다 |
| Euler 안정성 | 평형값에 대한 차이의 감소와 해석해에 대한 수치오차를 구분합니다 |
| ADC | 코드 분해능·양자화 잡음·실제 정확도, 주파수 대역과 입력 조건을 구분합니다 |
| DMA | 컴파일러 접근·순서 보장·캐시 관리·버퍼 소유권을 구분합니다 |
| GPU | 메모리 계층·연산 정밀도·일량과 처리량·이론 상한과 측정값을 구분합니다 |

본문은 원자료의 문장을 옮긴 번역문이 아니라 정의와 유도를 연결한 설명입니다. Mermaid 그림과 수치 예제는 이 문서에 맞게 구성했고, PNG·SVG 그래프는 [생성 코드](../예제_examples/공학기초_foundations/make_figures.py)로 그렸습니다. 외부 그림 파일은 포함하지 않았습니다. 참고 문서와 그 문서의 그림·원문에 대한 권리는 각 원저작자에게 있습니다.

[기초 출처](../참고자료_references/기초출처_FOUNDATIONS_SOURCES.md)은 글마다 사용한 직접 링크를 모은 색인입니다. 전체 교재가 모든 문장을 보증한다는 뜻은 아니며, 각 글에서 연결한 절과 페이지의 정의·조건이 대조 범위입니다. 검토 기준일은 2026-10-19입니다.

실행 명령은 `python 예제_examples/공학기초_foundations/run_checks.py`입니다. [검사 요약](../예제_examples/공학기초_foundations/VERIFICATION.json)과 그룹별 README에 범위와 기준을 기록했습니다. 여러 경우를 반복하는 하나의 테스트도 있으므로 표의 개수는 테스트 메서드 수이지 입력 수가 아닙니다.

이 검사에서 확인한 것은 명시한 수학 모델과 상태 규약입니다. Python FIFO의 통과는 별도로 포함한 SystemVerilog의 실행 결과가 아닙니다. 이번 환경에서는 RTL simulator를 실행하지 않았으며 [해당 기록](../예제_examples/공학기초_foundations/circuits_hardware/VALIDATION.json)에 구분했습니다. C 컴파일·ABI 적합성, 실제 보드 부팅과 DMA, 실제 회로·계측, GPU benchmark도 이 테스트 결과에 포함하지 않습니다.

계산 검증은 구현이 식·명세를 따르는지 확인하는 일입니다. 물리 모델의 타당성 확인은 의도한 환경에서 실측과 비교해 충분히 맞는지 살피는 일입니다. 해석해와의 일치나 격자 수렴만으로 실제 장치의 정확도가 정해지지는 않습니다.

## English

### Sources and equations

Definitions and laws are based on university teaching material, national-agency technical documents, standards and official manufacturer references. Sources include MIT, Stanford and Berkeley; BIPM, NIST and LLNL; and Arm, ST, Espressif, TI, Analog Devices, AMD and NVIDIA. Exact supporting links appear beside the relevant equations and explanations.

Each article cross-checks at least two relevant sources. Different symbol conventions are restated using the article's own definitions. Additional checks examine dimensions, signs, initial/boundary conditions and limiting cases, alongside executable models. The distinctions above cover zero covariance versus independence; input power versus unforced RLC energy loss; Euler equilibrium deviations versus trajectory error; ADC resolution versus accuracy; compiler ordering, cache maintenance and DMA ownership; and consistent GPU memory levels, precision, work, rates and measured scope.

The articles connect definitions and derivations rather than reproducing translated source passages. Mermaid diagrams and numerical examples were constructed for these explanations. PNG/SVG plots are generated by the [included script](../예제_examples/공학기초_foundations/make_figures.py). No third-party image files are included. Rights to reference documents, their text and figures remain with their owners.

[기초 출처](../참고자료_references/기초출처_FOUNDATIONS_SOURCES.md) indexes the direct references for each article. Citing a textbook does not imply that it certifies every statement here: the linked sections and pages define the cross-check scope. The review date is October 19, 2026.

### Executed checks

| Group | Tests | Independent references |
| --- | ---: | --- |
| Mathematics and physics | 24 | Hand calculations, residual orthogonality, standard statistics, exact solutions, grid/time convergence |
| Circuits and hardware | 15 | Exact solutions versus RK4, charge integration, deque FIFO oracle, line power/DC limits, uncertainty samples |

| Signals, control, AI and performance | 18 | Identical samples, error integration, geometric sequences, centered differences, attention invariants, performance bounds |

Run `python 예제_examples/공학기초_foundations/run_checks.py`. The [verification summary](../예제_examples/공학기초_foundations/VERIFICATION.json) and group README files record scope and criteria. Counts refer to test methods, not individual inputs; some methods evaluate many cases.

The tests verify the specified mathematical and state models. Passing the Python FIFO does not establish execution of the separately included SystemVerilog design. RTL simulation was not run in this environment, as recorded in [its validation metadata](../예제_examples/공학기초_foundations/circuits_hardware/VALIDATION.json). C compilation/ABI conformance, physical board startup/DMA, circuit measurements, and GPU benchmarks are outside these results.

Computational verification checks agreement with equations and specifications. Physical-model validation checks whether the model is adequate against measurements for an intended use. Agreement with an exact solution or grid convergence alone does not establish real-device accuracy.
