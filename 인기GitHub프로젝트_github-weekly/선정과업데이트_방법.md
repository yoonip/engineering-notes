# 주간 프로젝트 선정과 업데이트 | Weekly selection and updates

## 목록의 기준

[GitHub Trending](https://github.com/trending?since=weekly)의 언어 제한 없는 `This week` 화면에서 앞에 표시된 저장소를 순서대로 읽습니다. GitHub가 제공하는 주간 관심 목록이며, 전 세계 모든 저장소의 품질이나 사용 가치를 비교한 순위는 아닙니다. 화면 순서는 주간 별 증가량 순서와 다를 수 있으므로 프로그램이 별 수로 다시 정렬하지 않습니다.

각 항목에는 Trending의 `stars this week`, GitHub REST API의 누적 별·포크·언어·라이선스 표시, 원문 소개를 기록합니다. 이 수치는 수집 시점마다 달라지며 주간 별 수와 누적 별 수는 조회 시점과 집계 방식도 다릅니다. 라이선스가 특정되지 않으면 공식 파일을 확인하도록 표시합니다. 공개 저장소라는 이유만으로 모든 코드·모델·자산을 자유롭게 이용할 수 있는 것은 아닙니다.

기능 설명은 공식 README를 바탕으로 작성한 한국어 해설을 우선 사용하며 확인 날짜를 표시합니다. 저장소 ID·원문 소개·README가 바뀌면 기존 설명을 자동 재사용하지 않습니다. 새 영어 설명에는 Argos Translate의 영어→한국어 공개 모델을 적용하고 기계번역이라고 표시합니다. 한국어 원문은 그대로 사용합니다. 다른 언어만 있는 설명이나 소개가 없는 저장소에는 확인 가능한 언어 정보와 원문 링크를 남깁니다. 자동 실행이 저장소의 코드를 설치하거나 실행해 제품 성능을 시험하는 것은 아닙니다.

상세 안내도 모든 주간 글에서 기능·대상 사용자·설치·사용 예시 순서로 구성합니다. 공식 문서의 확인 판본을 커밋 링크로 고정하며, README에 연결된 같은 저장소의 설치·사용 문서도 필요한 범위에서 읽습니다. 명령의 운영체제·에이전트·실행 환경과 준비 사항을 함께 표시합니다. 기존 한국어 해설은 저장소 ID와 README가 일치할 때 사용하고, 문서가 바뀌면 현재 판본의 구간을 추출해 CPU로 번역합니다. 설치 명령·API 예시는 원문을 유지하며, 원문에 없는 명령과 실행 결과는 만들지 않습니다.

자동 게시 전에는 고정판 GitHub 문서의 파일 해시와 제목 링크를 대조하고, 명령과 발췌 문장이 해당 원문에 있는지 확인합니다. 명령 앞의 조건과 상위 절 제목도 함께 남깁니다. 필요한 준비 코드나 긴 첫 단계를 건너뛰어 다음 명령만 싣지 않으며, 원문 확인에 실패한 글은 게시하지 않습니다.

장점·제약·대안과의 차이·선택 상황도 같은 글에 이어집니다. 기존 비교는 양쪽 공식 문서의 기능과 조건을 대조한 해설이며, 특정 상황에서의 선택 기준은 그에 근거한 판단입니다. 직접 측정한 성능 결과와 구분합니다. 자동 글에는 제작자의 장단점·선택 설명·비교표를 발췌하고 그 출처를 표시합니다. 비교 절에서 구체적인 대안으로 연결한 GitHub 저장소가 있으면 상대의 공식 README도 확인해 기능과 실행 조건을 함께 보여줍니다. 근거가 없는 우열이나 추천 이유는 생성하지 않습니다.

프로젝트 소개 목록에는 처음 살펴볼 저장소를 별도로 모았습니다. 해당 목록을 과거의 월간 순위로 환산하지 않았으며, 수집을 시작하기 전의 10월 주차별 수치는 만들지 않습니다.

## 월과 주차

월요일을 발행 주의 시작으로 사용하고, 그 월요일이 속한 월의 첫 번째·두 번째·세 번째·네 번째·다섯 번째 월요일을 각각 1·2·3·4·5주차로 표시합니다. 예를 들어 2026년 11월 2일은 11월 1주차, 11월 9일은 2주차입니다. 다섯 번째 월요일이 있으면 5주차도 생성합니다. 연도와 월은 실행 날짜로 계산하므로 2027년 이후에도 설정을 매번 바꿀 필요가 없습니다.

Trending의 주간 값은 조회 당시 GitHub가 보여주는 값입니다. 글 제목의 발행 주차와 달력상의 월요일~일요일 별 개수를 동일한 통계로 해석하지 않습니다. 글과 JSON 기록에 실제 수집 시각과 원본 주소를 남깁니다. 같은 주에 다시 실행하면 기존 기록을 덮지 않고, 수집이 실패한 주를 나중의 현재 목록으로 채우지도 않습니다.

## 실행 자원과 일정

[GitHub Actions 설정](../.github/workflows/github-weekly.yml)의 `23 0 * * 1`은 UTC 월요일 00:23, 한국 표준시 월요일 09:23입니다. GitHub가 Ubuntu runner를 할당해 Python 수집·번역 코드를 실행하고, 저장소 전용 `GITHUB_TOKEN`으로 새 기록을 커밋합니다. 컴퓨터나 이 채팅을 켜둘 필요가 없습니다. `GITHUB_TOKEN`은 GitHub 접근 인증이며 GPT의 처리 토큰과는 다릅니다.

외부 LLM API를 호출하지 않습니다. 필요한 기계번역은 공개 번역 모델을 내려받아 runner CPU에서 처리하고, 같은 원문은 해시로 찾아 번역 결과를 재사용합니다. GitHub 서버의 컴퓨터·네트워크 자원은 사용하며, 표준 공개 저장소 runner는 [GitHub 정책상 무료](https://docs.github.com/en/billing/concepts/product-billing/github-actions)입니다. 프로젝트 소개에 등장하는 다른 AI 도구의 사용 비용까지 무료라는 뜻은 아닙니다.

GitHub 예약 실행은 지연되거나 누락될 수 있고, 공개 저장소에 60일간 활동이 없으면 중지될 수 있습니다. 정기 게시가 정상적으로 이어지면 저장소 활동도 계속 남습니다. 필요할 때 [실행 화면](https://github.com/yoonip/engineering-notes/actions/workflows/github-weekly.yml)에서 수동 실행·오류 확인·중지를 할 수 있습니다. 근거는 [GitHub의 schedule 안내](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)입니다.

## 보관과 출처

주차별 Markdown 옆의 JSON에는 선택 순서, 원본 URL, 수집 시각, 저장소 메타데이터와 한국어 소개 방식을 보관합니다. 원본 Trending 응답의 SHA-256도 남깁니다. 이 해시는 저장해 둔 관측값을 원본 페이지의 현재 내용과 동일하게 만들거나 GitHub의 집계를 독립 검증해 주는 값은 아닙니다.

- [GitHub Trending](https://github.com/trending?since=weekly): 주간 표시 순서와 `stars this week`의 직접 출처입니다.
- [GitHub REST: Get a repository](https://docs.github.com/en/rest/repos/repos#get-a-repository): 저장소 ID·주소·설명·언어·별·포크·라이선스 메타데이터의 출처입니다.
- [Argos Translate 공식 문서](https://argos-translate.readthedocs.io/en/latest/): 공개 패키지를 설치해 로컬 번역을 수행하는 방식을 설명합니다.
- [Argos 공식 모델 목록](https://github.com/argosopentech/argospm-index): 사용하는 영어→한국어 모델의 배포 목록입니다.
- [수집 코드와 운영 안내](../.github/github-weekly/README.md): 중복 판별, 오류 처리와 재실행 방법입니다.
