# ChatGPT와 Claude: 모델의 답변이 실제 작업으로 이어지는 과정 / From model answers to completed work

기준일: 2026년 10월 20일. 공식 문서와 외부 평가의 원자료를 읽은 문헌 리뷰입니다. Argo-Bench의 판본과 점수는 10월 21일에 다시 확인했습니다. 유료 계정이나 API를 새로 구매해 두 서비스를 직접 비교한 결과는 아닙니다.

## 현재 비교하는 대상

ChatGPT와 Claude는 서비스 이름이고 GPT-6.1 Sol과 Claude Opus 5.5는 그 안에서 선택하거나 API로 호출하는 모델 이름입니다. 같은 모델이라도 검색, 파일 처리, 코드 실행, 권한 설정이 달라지면 끝낼 수 있는 작업이 달라집니다. 모델 점수를 앱 전체의 성능으로 옮기면 안 됩니다.

[ChatGPT Learn의 모델 안내](https://learn.chatgpt.com/docs/models?surface=web)는 GPT-6.1 Sol의 출시 배포에 Plus·Pro·Business·Enterprise·Edu를 포함하며, Enterprise와 Edu는 관리자가 활성화해야 한다고 설명합니다. 해당 제공 화면은 Work와 Codex이며 일반 Chat과 구분합니다. Free와 Go는 출시 대상에 포함되지 않습니다. 지원 클라이언트와 작업 공간 설정에 따라서도 선택지가 달라집니다. 이 문서는 GPT-6 Astra와 Luna도 구분합니다. 따라서 ‘모든 ChatGPT 이용자가 항상 같은 최신 모델을 사용합니다’라고 적을 수 없습니다.

[Anthropic의 Opus 5.5 발표](https://www.anthropic.com/claude-opus-5-5)는 공개일을 2026년 9월 22일로 밝힙니다. [모델 문서](https://platform.claude.com/docs/en/models/opus-5-5/overview)의 API 식별자는 `claude-opus-5-5`이며, 문맥 창은 100만 토큰, 일반 최대 출력은 12만 8천 토큰입니다. 앱 요금제의 이용량을 API의 토큰 한도와 혼동하지 않아야 합니다. 지원 국가·계정·배포 경로도 확인 대상입니다.

## 왜 긴 문서와 도구를 함께 다룰 수 있습니까?

언어 모델은 문장을 토큰이라는 작은 단위로 바꾸어 처리합니다. 토큰은 단어와 항상 일치하지 않습니다. 특히 한국어 글자 수에 일정한 수를 곱해서 정확한 요금을 계산할 수는 없습니다. 문맥 창은 한 번의 처리에 참고할 수 있는 입력과 출력 등의 범위이며, 장기 기억의 크기나 사실을 틀리지 않는 정도를 뜻하지 않습니다.

일반적인 생성 모델은 앞선 문맥을 바탕으로 다음 토큰을 고르는 과정을 반복합니다. 학습에서 익힌 패턴, 현재 입력, 도구에서 얻은 결과가 다음 답변의 재료가 됩니다. 검색을 했다는 사실과 검색 결과가 주장을 뒷받침한다는 사실도 서로 다릅니다. 출처에 ‘가능성이 있습니다’라고 되어 있는데 답변이 ‘입증되었습니다’로 바뀌면, 링크가 있어도 근거를 보존하지 못한 것입니다.

에이전트는 모델이 도구 호출과 중간 결과 확인을 이어서 수행하도록 만든 시스템입니다. 예를 들어 표를 읽고, 계산 코드를 실행하고, 결과 파일을 만드는 과정입니다. 모델이 함수 이름과 인수를 제안하더라도 실제 접근 권한과 실행 환경은 서비스가 제공합니다. 모델을 더 크게 만들기만 해서는 파일 손상 방지, 취소, 재시도, 사용자 확인 문제까지 자동으로 해결되지 않습니다.

추론 노력 설정은 답하기 전에 사용하는 계산량을 조절하는 수단입니다. 같은 ‘높음’이라는 표시가 회사 사이에서 같은 연산량을 뜻하지는 않습니다. 길게 생각한 답변도 틀릴 수 있고, 간단한 분류에서는 추가 계산이 시간과 비용만 늘릴 수 있습니다. 공개되지 않은 매개변수 수나 내부 구조를 제품명으로 추정해 비교하지 않습니다.

## 외부 평가가 보여 주는 범위

[TextQL의 Argo-Bench v1.2](https://argo-bench.com/)는 기업 데이터 업무를 모사한 210개 과제를 평가합니다. 10월 21일 확인 표에서 Opus 5.5의 평균 점수는 59.1, GPT-6.1 Sol은 49.1이며, 과제당 API 비용은 각각 4.71달러와 0.49달러입니다. 두 모델 모두 Extra high 설정입니다. 평균은 부분 점수를 포함하며, 완전 해결 비율은 95점 이상 과제의 비율을 따로 셉니다. 채점 오류를 수정한 판본이므로 다른 판본의 수치와 섞지 않습니다. 데이터 질의 비용은 제외되어 있습니다.

이 자료는 두 모델 제조사와 다른 주체가 수행한 원평가이지만, 평가자는 데이터 에이전트 사업자 TextQL입니다. 모사된 업무, 해당 도구 구성, 채점 규칙에서 나온 결과입니다. 모든 회사의 비공개 데이터나 한국어 글쓰기까지 대표하지 않습니다. 채점 규칙이 바뀌면 순위와 수치도 다시 확인해야 합니다.

비교 조건을 더 잘 이해하려면 실패한 과제를 보셔야 합니다. SQL 문법이 맞아도 잘못된 고객에게 조치를 적용할 수 있습니다. 테스트를 통과한 코드라도 문제 정의를 잘못 읽었을 수 있습니다. 실제 작업에서는 정답률 외에 잘못 실행한 변경, 사람이 다시 확인한 시간, 복구 가능성까지 함께 살펴야 합니다. 제조사의 출시 표에서 다른 회사 점수를 옮겨 온 항목은 동일한 도구와 계산 예산으로 재시험한 결과인지 확인해야 합니다.

## 비용을 직접 계산해 봅니다

아래는 Opus 문서의 일반 API 단가를 적용한 자체 계산입니다. 입력 1만 토큰, 청구 대상 출력 2천 토큰, 캐시·배치·빠른 모드·도구 요금이 없는 가정을 사용합니다. 실제 이용 기록은 아닙니다.

```math
C=\frac{10{,}000}{1{,}000{,}000}\times4
 +\frac{2{,}000}{1{,}000{,}000}\times20
 =0.08\ \text{달러}
```

같은 요청을 다섯 번 다시 실행하면 이 가정에서는 0.40달러입니다. 답변 토큰의 단가만 낮은 모델보다 한 번에 과제를 끝내는 모델이 최종적으로 저렴할 수도 있습니다. 반대로 이 계산을 월 구독료와 직접 비교할 수는 없습니다. 구독은 이용량 제한과 기능 제공 방식이 다르며, API 청구 토큰에는 화면에 그대로 나타나지 않는 추론 토큰이 포함될 수 있습니다.

## 실제로 고를 때 남길 기록

같은 원본 문서와 요구사항을 사용하고 모델명·추론 설정·검색 허용 여부를 기록합니다. 문서에 없는 숫자를 추가했는지, 인용한 절에 해당 근거가 있는지, 계산을 재현할 수 있는지를 각각 확인합니다. 코드 과제라면 숨은 테스트와 실패 로그를 남기는 편이 답변의 자신감이나 문장 길이를 세는 것보다 유용합니다.

검색 자료나 저장소 파일에 적힌 문장이 도구 사용 지시로 섞이는 문제도 있습니다. 이를 프롬프트 주입이라고 합니다. 파일에 접근할 수 있다는 기능과 그 안의 모든 지시를 따르는 권한은 구별해야 합니다. 길게 자율 실행하는 기능에서는 허용 범위, 변경 기록, 복구 수단이 제품 성능의 일부입니다.

서비스가 기억해 둔 선호, 대화에 들어간 예시, 모델의 학습 결과도 구별해야 합니다. 사용자가 예시 세 개를 보여 준 뒤 형식을 잘 따른다고 해서 그 자리에서 기본 가중치가 다시 학습된 것은 아닙니다. 문맥에서 예시를 이용한 결과일 수 있습니다. 이 구분은 개인정보가 어디에 남는지와 다른 대화에서도 같은 행동이 유지되는지를 판단할 때 중요합니다.

작업 품질을 비교할 작은 예를 들어 보겠습니다. 원본 표에서 매출은 120, 비용은 90인데, 첨부 메모에는 비용이 잠정치라고 적혀 있습니다. 좋은 답변은 이익을 30으로 계산하는 데서 끝나지 않고 잠정치라는 조건도 보존해야 합니다. 계산기가 맞는 답을 냈더라도 모델이 메모를 누락하면 최종 보고서는 부정확합니다. ‘계산 성공’과 ‘요구사항 충족’을 다른 항목으로 채점하는 이유입니다. 이런 확인 항목을 먼저 정해 두면 특정 서비스의 말투나 친숙함에 점수가 끌려가는 일을 줄일 수 있습니다.
