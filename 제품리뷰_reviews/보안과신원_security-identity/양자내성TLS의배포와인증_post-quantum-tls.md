# 양자내성 TLS: Cloudflare의 혼합 키 합의와 남은 인증 / Hybrid post-quantum TLS deployment

기준일: 2026년 10월 20일. Cloudflare의 현재 TLS 문서, NIST 최종 표준, 대학 연구진의 연합 인증 연구를 읽은 문헌 리뷰입니다. 브라우저 패킷 수집이나 서버 벤치마크를 새로 실행하지 않았습니다. 제공 기능과 원리, 연구자가 계산한 전환 비용을 구별합니다.

## 통신 내용을 잠그는 열쇠와 상대 신원은 다릅니다

TLS는 브라우저와 서버가 통신을 보호하는 절차입니다. 세 역할을 나누면 이해하기 쉽습니다. 키 합의는 양쪽이 같은 비밀을 얻는 일이고, 전자서명은 상대가 주장하는 신원과 자료의 진위를 확인하는 데 쓰이며, 대칭 암호는 합의한 키로 실제 자료를 보호합니다. 봉투를 잠그는 방법을 바꾸었다고 보낸 사람을 확인하는 절차까지 자동으로 바뀌지는 않습니다.

충분한 능력의 양자컴퓨터는 현재 널리 쓰는 일부 공개키 알고리즘을 위협합니다. 아직 그런 공격을 이 글에서 실행하거나 관찰했다는 뜻은 아닙니다. 지금 암호문을 저장했다가 나중에 풀려는 위협 때문에 장기 비밀의 키 합의를 미리 바꾸는 이유가 생깁니다. 양자내성은 양자 장비로 통신한다는 뜻이 아니라, 알려진 양자 공격을 견디도록 고안한 고전 컴퓨터용 암호를 가리킵니다.

[NIST FIPS 203 최종본](https://nvlpubs.nist.gov/nistpubs/fips/nist.fips.203.pdf)은 2024년 8월 13일 발표되었으며 ML-KEM을 규정합니다. KEM은 수신자가 공개한 키로 송신자가 공유 비밀과 캡슐화 암호문을 만들고, 수신자가 자신의 비밀키로 같은 공유 비밀을 얻는 구조입니다. 웹페이지 본문 전체를 ML-KEM으로 직접 암호화하는 방식은 아닙니다. 표준 적합성과 구현·시스템 전체의 안전성도 별개입니다.

## 실제 배포 대상은 무엇인가요?

[Cloudflare의 현재 문서](https://developers.cloudflare.com/ssl/post-quantum-cryptography/)는 TLS 1.3 기반 연결에서 `X25519MLKEM768`을 권장하고 예전 `X25519Kyber768Draft00`을 폐기된 방식으로 구분합니다. 이름이 비슷해도 최종 ML-KEM과 과거 초안 구현의 협상 식별자를 섞어서는 안 됩니다. 고객 웹사이트의 지원과 실제 방문자의 사용도 다릅니다. 클라이언트까지 같은 방식에 동의해야 해당 연결에 적용됩니다.

혼합 방식은 기존 X25519와 ML-KEM에서 얻은 재료를 정해진 키 도출 절차로 결합합니다. 둘을 두 번 실행했다는 말만으로 안전성이 따라오는 것은 아닙니다. 협상·검증·비밀 결합 방식이 제대로 구현되었다는 조건에서 서로 다른 수학적 가정에 의존하는 보호를 함께 남기려는 설계입니다. 취약한 난수나 메모리 유출까지 수학적 가정 하나로 막지는 못합니다.

현재 문서의 ML-DSA 서명 지원은 Cloudflare와 원본 서버 사이의 인증을 대상으로 합니다. 방문자에서 Cloudflare까지의 양자내성 인증은 개발 중인 범위로 구분합니다. 따라서 방문자 연결에 혼합 키 합의가 잡혔다고 인증서 체계와 모든 내부·원본 연결이 전부 양자내성이라고 쓰지 않습니다. 2029년 전체 제품군 전환은 회사의 목표이며 현재 완료 상태가 아닙니다.

## 원리만 보면 놓치는 바이트 수

FIPS 203의 Table 3, 인쇄 39쪽/PDF 48쪽에서 ML-KEM-768의 캡슐화 키는 1184바이트, 캡슐화 암호문은 1088바이트입니다. 768은 인터넷 전송 속도나 키의 바이트 수를 그대로 뜻하지 않습니다. 실제 TLS 메시지에는 X25519 자료와 길이 필드, 확장, 서명과 인증서 등이 더해집니다.

다음은 표준의 두 자료만 합친 자체 전송 계산입니다.

```math
B=1184+1088=2272\ \mathrm{bytes}
```

가상의 10 Mbit/s 링크에서 이 자료의 직렬화 시간만 계산하면 `2272×8/10,000,000=0.0018176초`, 약 1.82 ms입니다. 1 Mbit/s이면 약 18.18 ms입니다. 이는 TLS 전체 지연도, 두 방향에 걸친 실제 완료 시간도 아닙니다. 왕복 지연, 패킷 분할과 손실, 혼잡, 인증서와 CPU 시간을 생략했습니다. 바이트 증가가 작아 보여도 경계 크기를 넘겨 패킷이 더 생기면 지연 변화는 선형이 아닐 수 있습니다.

같은 자료가 1만 번의 새 연결에 들어간다는 단순 합계는 22.72 MB입니다. 실제 서비스에서는 연결 재사용·재개·캐시 여부가 달라집니다. 그래서 초당 요청 수와 초당 새 핸드셰이크 수를 같은 값으로 두고 비용을 추정하면 큰 오차가 날 수 있습니다.

## 독립 연구는 실제 서비스를 전환했나요?

[Fabrizio·Sperotto·van Rijswijk-Deij의 TMA 2025 논문](https://tma.ifip.org/2025/wp-content/uploads/sites/14/2025/06/tma2025_paper20.pdf)은 SURFCONEXT 운영 로그와 암호 벤치마크를 결합했습니다. §III–V에서 2024년의 25일 로그, 단일 CPU 코어의 알고리즘 시험, 서명·검증·TLS 연산 수를 이용한 부하 추정을 구분합니다. 실제 연합 인증 서비스를 모두 양자내성으로 바꾸고 이용자가 체감한 시간을 측정한 보고는 아닙니다.

연구의 유용한 발견은 전환 비용이 선택한 서명과 키 합의의 조합에 따라 크게 달라진다는 점입니다. 격자 기반 조합과 다른 수학적 계열의 대안은 같은 비용이 아니었습니다. 모든 요청을 새 TLS 연결로 보는 상한 쪽 가정이 있으며 자료 인코딩 등 일부 작업도 제외합니다. 이 연구의 OpenSSL/OQS 시험을 Cloudflare 전체 서버의 속도로 대체하지 않습니다.

한 대학 로그인은 브라우저와 서버의 암호화 외에도 기관이 만든 토큰의 서명, 중앙 허브의 검증과 재서명, 다른 서비스의 검증을 거칩니다. TLS만 바꾸면 응용 계층의 오래된 서명이 그대로 남을 수 있습니다. 이 연결 구조가 논문을 읽을 이유이며, 단일 암호 함수의 초당 처리량만 비교해서는 전환 작업을 설명하기 어렵습니다.

## 기업이 지금 바꾸고도 기존 방식 일부를 남기는 이유

경쟁 대안은 혼합 키 합의, 양자내성 알고리즘만 쓰는 방식, 기존 방식 유지입니다. 혼합은 호환성과 새로운 알고리즘의 불확실성을 함께 고려하지만 자료와 구현 경로가 늘어납니다. 단독 양자내성은 기존 재료를 빼지만 상대 지원과 결합 안전성의 평가 조건이 달라집니다. 기존 방식은 배포가 쉽더라도 장기 보관 자료의 위협을 남깁니다.

표준화된 알고리즘이 나와도 모든 장비와 인증서가 같은 날 바뀌지는 않습니다. 브라우저·운영체제·보안 장비·인증기관·원본 서버가 협조해야 합니다. 인증을 검사하는 중간 장비가 새로운 메시지를 거부하면 암호 계산이 빨라도 연결은 실패합니다. 규제 기관의 검증 대상과 자체 서버 라이브러리의 버전도 맞춰야 합니다.

Cloudflare 같은 중개 서비스는 여러 사이트에 같은 기능을 배포할 수 있습니다. 반대로 사업자는 방문자 연결에서 제공자가 선택한 정책에 의존합니다. 종속을 줄이려면 협상 결과를 관찰하고, 원본 서버와 다른 CDN에서도 지원되는 표준 식별자·라이브러리를 사용하며, 설정을 바꿀 수 있는 경로를 남겨야 합니다. 이를 crypto-agility, 암호 민첩성이라고 부릅니다. 아무 알고리즘이나 자주 바꾸는 것이 아니라, 목록·의존성·관측·검증을 갖추어 교체할 수 있다는 뜻입니다.
