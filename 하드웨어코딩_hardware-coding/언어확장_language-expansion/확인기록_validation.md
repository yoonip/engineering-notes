## 오류 조건을 나누는 이유

RISC-V와 cocotb의 결함 대조는 정상 소스 대신 의도적으로 잘못 동작하는 작업 복사본·매개변수를 실행한 결과입니다. 컴파일 오류나 프로세스 시작 실패를 기능 결함 검출로 세지 않았습니다.

SystemC의 bad-expectation은 DUT에 결함을 주입한 경우가 아닙니다. 정상 모형의 결과와 다른 기대값을 검사기에 주었을 때 실행이 실패하는지 확인한 대조입니다. Tcl의 일곱 오류 조건은 잘못된 입력 설정의 거절이며 회로 결함의 검출과 구분합니다.

## 아날로그 수치 비교

RC 모형은 R=1kΩ·C=1µF, 시정수1ms입니다. 과도 응답은 유한 상승 시간1µs의 입력에 대한 정확해와 비교했습니다. 최대 전압 절대 오차는 약2.998×10⁻⁸V이며 한도10⁻⁵V보다 작았습니다. AC는 1V 입력에서 복소 전달함수와 비교했고 최대 복소 오차는 약2.289×10⁻¹⁶으로 한도10⁻¹⁰보다 작았습니다. 이상 소자·해석 설정에서의 수치 비교이며 실물 측정 오차가 아닙니다.

## 도구와 소스의 범위

Rust 라이브러리는 no_std로 컴파일했지만 테스트 바이너리는 호스트 Windows에서 실행했습니다. MCU의 시작 코드·인터럽트·MMIO를 Rust로 실행한 기록은 아닙니다. RISC-V는 QEMU virt에서 실행했으며 실물 칩의 명령 지연을 측정하지 않았습니다.

Tcl은 Yosys의 일반 회로 구조 변환과 SDC 생성까지 실행했습니다. 생성한 SDC는 그 흐름의 최적화에 입력되지 않았고 STA에서도 읽지 않았습니다. 셀 라이브러리 매핑·배치 배선·실제 setup/hold 충족을 확인한 기록은 아닙니다. SystemC에서 지정한 ns 지연은 설명용 모형의 가정이며 실제 소자 지연과 구분합니다.

SystemC 의존 라이브러리 빌드는 날짜 매크로에 대한 경고2개를 기록하고 해당 의존성에만 경고 완화 옵션을 사용했습니다. 직접 작성한 SystemC 예제는 -Wall -Wextra -Werror로 컴파일했습니다. QEMU의 bare 모드 선택 경고와 HDL의 시간 단위 경고도 원로그에 남겼습니다.

기존 Python 문제 풀이와 이전 HDLBits 채점 기록은 이번 확장 예제의 실행 대상으로 수정하지 않았습니다. cocotb에서 사용한 전송 버퍼는 기존 원본과 같은 바이트의 복사본이며, Tcl도 작업 폴더에만 원본 RTL을 복사합니다.

## 게시 소스와 저장된 실행 기록

22개 소스·제약 예시 파일의 SHA-256과 README에 실은 전체 코드를 대조합니다. SDC 예시는 생성한 텍스트이고, 나머지 파일도 각 예제에서 맡은 실행·설정·검사 역할을 구분합니다. [목록 JSON](catalog.json)은 경로·언어·해시를 담은 기계 판독용 목록입니다.

[check_sources.py](check_sources.py)는 현재 파일과 기록이 같은지 확인하는 정적 검사입니다. 컴파일러·시뮬레이터를 다시 실행하지 않습니다. 실행을 재현하려면 각 README의 도구 설치 조건과 실행 명령을 사용합니다. Chisel·SystemRDL·HLS는 학습 경로를 조사해 연결했으며 이번에 실행한 예제로 표시하지 않습니다.

[현재 소스·문서 대조 결과](source-check.json)에 검사 시각과 자료별 일치 결과가 있습니다.
