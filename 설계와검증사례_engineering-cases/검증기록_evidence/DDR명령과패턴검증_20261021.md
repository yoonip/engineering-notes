# DDR 명령과 패턴 실행 기록 | DDR command and pattern execution record

2026-10-21에 [공개 SV fixture·Python 감시기·설정](../../예제_examples/실무검증_practical-validation/ddr_validation/README.md)을 실행했습니다. 대상은 파일 구동 명령·배열 fixture이며 실제 DDR 소자나 PHY는 없습니다. [사례 본문](../DDR명령간격과메모리패턴_ddr-command-pattern-checks.md)에 오류의 원인과 검출 한계를 설명합니다.

## 고정 조건과 실행

| 항목 | 조건 |
| --- | --- |
| 환경 | Windows 11 `10.0.26200`, Python 3.12.14·MSC v.1944 64비트입니다. |
| 도구 | Icarus Verilog compiler/runtime 12.0 devel, `s20150603-1539-g2693dd32b`입니다. |
| fixture | 비합성 SystemVerilog, 2bank·4row·4column·16bit, 32워드·64byte입니다. |
| 시간 | SV 클록 10ns, AL=0, RD 응답 2cycle, WR 배열 갱신 즉시입니다. |
| 자체 제한 | tRCD3·tRAS6·tRP2·tRFC8·tWR2·tRTP2, REF 발행 간격 최대40cycle입니다. |
| 초기 상태 | 두 bank가 닫혀 있고 배열은 미초기화입니다. DRAM 전원 인가·mode register·training은 구현하지 않습니다. |
| build | 새 ASCII 폴더, 상대 입력 파일명, 순차 컴파일, 자식 `TEMP/TMP` 지정입니다. |

최종 동일 소스의 일반 실행은 private `tmp/usb-update-ddr-20261021/ddr/run-2`, 최적화 실행은 `run-3-O`에 남겼습니다. 초기 실행 `run-1`도 보존하며 최종 표는 metadata에 AL·refresh 정책을 명시한 소스를 기준으로 합니다. 공개 재현 명령은 [README](../../예제_examples/실무검증_practical-validation/ddr_validation/README.md#실행)에 있습니다. 일반 명령 앞에 `python -O`를 사용하고 새 `--out`을 주면 최적화 조건을 재현할 수 있습니다.

정상 주소 설정의 실제 compile/sim 명령 형태는 다음과 같습니다.

```text
C:/iverilog/bin/iverilog.exe -g2012 -gstrict-expr-width -Wall -s ddr_command_fixture -Pddr_command_fixture.FAULT=0 -Pddr_command_fixture.CYCLES=256 -o sim.vvp ddr_command_fixture.sv
C:/iverilog/bin/vvp.exe sim.vvp
```

나머지 설정은 FAULT와 프로그램 길이를 바꾸고 별도 `program.hex`를 사용합니다. 두 최종 실행에서 컴파일 30회·시뮬레이션 30회는 모두 종료 0이었습니다. 전체 회귀는 각각 종료 0·PASS였고 15개 trace의 해시가 일치했습니다. `-O`에서 없어질 수 있는 `assert`로 기능 판정을 구현하지 않았습니다.

## 정상·결함·검출 한계의 구분

| 설정 | 판정 | 오류 기록 수 | 실제 관측 |
| --- | --- | --- | --- |
| correct_address | PASS | 0 | 256행, WR/RD/응답 각32, REF8, 기준 초기화 주소32입니다. |
| correct_checkerboard_inverse | PASS | 0 | 512행, WR/RD/응답 각64, REF16입니다. |
| early_rcd | FUNCTIONAL_FAIL | 1 | cycle10, ACT 이후 2<3입니다. |
| early_ras | FUNCTIONAL_FAIL | 17 | cycle9의 PRE가 ACT 이후 1<6이며 이후 닫힌 행 접근 등이 이어집니다. |
| early_rp | FUNCTIONAL_FAIL | 2 | cycle27의 ACT가 PRE 이후 1<2이며 cycle32에 열린 bank의 REF도 기록합니다. |
| early_rfc | FUNCTIONAL_FAIL | 1 | cycle7의 ACT가 REF 이후 최소8보다 빠릅니다. |
| missing_refresh | FUNCTIONAL_FAIL | 1 | cycle40 경계까지 허용하고 cycle41에 엄격한 자체 deadline을 위반합니다. |
| stuck_address / alias_address | FUNCTIONAL_FAIL | 각각16 | 주소 패턴이 bit0 고정·column bit1 alias를 구별합니다. |
| stuck_zero_blind_spot / alias_zero_blind_spot | PASS | 각각0 | 같은 결함이 있어도 전체0 자료로는 구별하지 못합니다. |
| read_unwritten | FUNCTIONAL_FAIL | 2 | cycle18에 미초기화 주소와 유효 X 자료를 구분해 기록합니다. |
| drop_read_responses | FUNCTIONAL_FAIL | 32 | RD32건에 응답0건입니다. 관측값 불일치0건을 통과로 해석하지 않습니다. |
| unknown_read_data | FUNCTIONAL_FAIL | 32 | 예정 응답마다 유효 자료가 X입니다. |
| incomplete_trace | INFRA_ERROR | 계산하지 않습니다. | sim은 종료0이지만 trace는 예정256행 중128행입니다. |

개별 판정은 PASS4·FUNCTIONAL_FAIL10·INFRA_ERROR1이며, PASS4에는 패턴의 검출 한계 대조2개가 포함됩니다. 이는 무결함 장치 수나 제조 수율이 아닙니다. 회귀의 PASS는 각 대조의 예상 결과가 일치했다는 뜻입니다. 의도한 미완성 trace조차 실제 compile/sim이 성공해야 해당 대조의 성공으로 셉니다.

정상 첫 행의 명령은 REF0, ACT8, WR11/12/13/14, RD16/18/20/22, PRE26, REF32입니다. 최초 네 응답은 `(cycle,tag,data)`로 `(18,4,A500)`, `(20,6,A401)`, `(22,8,A702)`, `(24,10,A603)`입니다. stuck 변이는 cycle20에 A401 대신 A400, alias 변이는 cycle18에 A500 대신 A702를 돌려줍니다. 이 리터럴과 timing 경계, 응답 개수를 별도 확인했습니다.

## 수집·비교 오류를 통과시키지 않는지 확인했습니다

정상 trace를 복사한 파일 없음·마지막 행 누락·cycle 중복·CSV 열 초과·X command/control·다른 입력 echo의 여섯 대조는 `INFRA_ERROR`였습니다. 첫 두 응답의 tag만 교환한 대조는 `FUNCTIONAL_FAIL`였습니다. 이 7개 파일 대조는 명령/자료 결함을 실제 SV에서 실행한 15설정과 구분했습니다.

존재하지 않는 Icarus 경로를 지정한 별도 CLI는 종료2·`INFRA_ERROR`였습니다. 기존 최종 출력 폴더를 다시 사용한 CLI도 종료2였고 기존 report SHA256은 유지됐습니다. 원시 명령·환경·표준 출력/오류·종료 상태와 source/input/artifact 해시는 각 report에 남겼습니다. 일반·`-O` 일치, 리터럴, 경계, 검출 한계, CLI 거절을 대조한 private `final-checks.json`의 22항목이 모두 일치했습니다.

## 출처 열람과 시험 범위

AMD PG150 v1.4, 문서 표시일2025-12-03의 [PHY Only Interface](https://docs.amd.com/r/en-US/pg150-ultrascale-memory-ip/PHY-Only-Interface), [DDR4 non-custom timing 설정](https://docs.amd.com/r/en-US/pg150-ultrascale-memory-ip/Setting-Timing-Parameters-for-DDR4-Non-Custom-Memory-Parts), [Isolating the Data Error](https://docs.amd.com/r/en-US/pg150-ultrascale-memory-ip/Isolating-the-Data-Error)의 실제 본문을 읽었습니다. 각각 controller/PHY 책임, tREFI/tRFC 입력 단위·확인 책임, bit·주소·패턴·read/write별 오류 분리를 대조했습니다.

[Micron DDR4 공식 페이지](https://www.micron.com/products/memory/dram-components/ddr4-sdram)의 자료 목록은 확인했지만 연결된 TN-40-40 PDF는 접근 페이지로 이동해 읽지 못했습니다. SPD 페이지의 실제 표 값도 추출되지 않아 수치를 사용하지 않았습니다. 실제 읽은 구간과 접근 제한을 private `source-review.md`에 구분했습니다.

timing 숫자와 refresh deadline은 자체 계약입니다. DRAM 전원 인가·mode register·burst·CL/CWL·DDR 양 edge 전송·PHY calibration·retention·ECC·cache·보드 신호·JEDEC 적합성은 검증하지 않았습니다. timing 위반 뒤 배열이 반환한 값을 실제 DRAM의 결과로 예측하지 않습니다. checkerboard 역패턴을 썼다는 사실로 모든 주소 alias를 검출한다고 주장하지 않습니다.

## English

The final ordinary and optimized Python runs execute fifteen real Icarus compilations and simulations each. All processes exit zero, while the checker distinguishes four PASS outcomes, ten controlled functional failures and one intentionally incomplete trace. Two PASS outcomes expose all-zero pattern blind spots and are not fault-free-device claims.

The correct address-pattern trace has 256 records, thirty-two writes, reads and responses, and eight refresh commands. The first read returns A500 at cycle18; a column alias instead returns A702. Suppressing every response yields zero observed value mismatches but thirty-two missing-response failures. Seven altered-trace controls and twenty-two final record/literal/CLI checks match their expectations.

Source, input and all fifteen trace hashes agree between ordinary and `-O` execution. The scope is a fixed nonsynthesizable command/array fixture, with self-defined cycle timing and a strict refresh issue deadline. It does not establish DDR PHY behavior, cell retention, device timing compliance, cache correctness or measured board operation.
