## 우선순위 모델

L은 시각 0에 뮤텍스를 보유하고 H/M은 시각 1에 준비됩니다. 자체 입력 L=3·M=8·H=1에서 다음 값을 얻었습니다.

| 경로 | 실행 순서 | H 완료 | H 응답시간 | 절대 마감 5 |
| --- | --- | --- | --- | --- |
| 상속 없음 | `LMMMMMMMMLLH` | 12 | 11 | false |
| 상속 적용 | `LLLHMMMMMMMM` | 4 | 3 | true |

이 단위는 실제 tick·ms가 아닙니다. 총 CPU 일은 두 경로 모두 12입니다. 시간별 Ready 선택과 별도로 작업 블록을 이어 만드는 oracle로 L=1~5·M=0~8·H=1~3·상속 두 값의 270조합을 확인했습니다. 각 조합의 완료 직전/완료 시각 마감 540개도 확인했습니다. 마감 입력 자체가 유지됐는지와 그 입력에 대한 판정을 별도로 비교합니다.

## 알림과 payload

| 사건 배치 | resume만 사용하는 경로의 유실 | 알림 보존 경로의 유실 | 보존 경로의 소비 |
| --- | --- | --- | --- |
| PCW | false | false | `[42]` |
| CPW | true | false | `[42]` |
| CWP | false | false | `[42]` |

C는 큐 검사, W는 대기, P는 데이터 공개와 알림입니다. C가 W보다 앞선 세 순서를 열거했고, 단순 resume의 유실 조건을 별도로 `C < P < W`의 위치 관계로 비교했습니다. 수정 경로에서는 payload 보존을 판정했습니다. 생산자가 대기자를 깨우는 사건에는 소비자의 재실행을 추상적으로 묶었으므로 실제 스케줄의 모든 세부 단계와 같지는 않습니다.

두 payload `[42, 43]`와 알림 값 2가 있는 묶음에서도 비교했습니다. 알림을 모두 지운 뒤 한 건만 처리하면 `[43]`이 남고 다시 대기할 수 있었습니다. 큐를 비우는 경로는 `[42, 43]`을 처리하고 남은 항목이 없었습니다.

## 오류를 검출하는지 확인한 대조

| 일부러 어긴 계약 | 실제 검사 결과 |
| --- | --- |
| 상속 적용 요구에 상속 없는 기본 스케줄을 전달 | `priority trace: LMMMMMMMMLLH != LLLHMMMMMMMM`로 거부했습니다. |
| CPW에서 대기 직전 pending을 삭제 | `payload not consumed: []`로 거부했습니다. |
| 알림을 모두 지운 뒤 payload 한 건만 처리 | `payload left after notification cleared`로 거부했습니다. |
| 마감 필드를 100으로 바꾸고 판정도 true로 변경 | 요청한 마감 5와 다르므로 `requested deadline was changed`로 거부했습니다. |

추가로 명령행 결함 주입을 각각 독립 실행했습니다. `--inject priority-no-inherit`는 순회 중 `ContractError: priority trace: LMLH != LLHM`에서 실패했고, `--inject notify-clear`는 `ContractError: payload not consumed: []`에서 실패했습니다. 이 둘은 정상 실행의 통과 수에 더하지 않습니다. 검사 함수는 Python `assert`의 최적화 생략에 의존하지 않습니다.

## 공식 구현과의 대조 범위

2026-10-21에 FreeRTOS-Kernel V11.1.0의 [tasks.c](https://github.com/FreeRTOS/FreeRTOS-Kernel/blob/V11.1.0/tasks.c)에서 상속·복원과 `ulTaskGenericNotifyTake()`의 확인/대기 등록·소거/감소를 읽었습니다. [task.h](https://github.com/FreeRTOS/FreeRTOS-Kernel/blob/V11.1.0/include/task.h)의 suspend/resume 계약도 대조했습니다. 공식 웹 문서의 뮤텍스·ulTaskNotifyTake 설명과 고정된 커널 버전을 구분했습니다. 커널 전체·포트 코드·실행 바이너리를 검증한 것은 아닙니다.

타임아웃, 중첩 잠금, 여러 대기자, SMP, 실제 ISR 우선순위, 32비트 알림 카운터 순환과 메모리 모델은 포함하지 않습니다. 제품의 마감시간·스택·전력·실제 데이터 손실률은 별도의 타깃 시험이 필요합니다.

## English

The host model passed 270 priority parameter cases and 540 deadline boundaries against a separate block-order oracle. Three notification placements reproduced a resume-only lost wakeup and preserved payloads with retained notifications. Four deliberately broken contracts were rejected; two CLI fault-injection runs exited with failure as expected. Version-pinned FreeRTOS source was read, but no kernel or MCU binary was executed.
