## 환경과 실제 실행

Windows 11 build 10.0.26200·AMD64·Python 3.12.14, MSC v.1944 64 bit에서 실행했습니다. 소스·입력의 UTF-8/LF 정규화 뒤 2026-10-21 02:16:35 UTC에 최종 정상 실행을 시작했습니다. 실제 전체 명령·실행 파일·stdout·stderr·결과 해시·종료값은 비공개 `usb-pcie/verification.json`에 보존했습니다.

코드 폴더에서 아래 인수를 사용했습니다. 공개 명령의 C:/temp는 독자가 지정할 새 경로의 예입니다.

```powershell
python -X utf8 -B run_cases.py --output C:/temp/usb-pcie-normal-new
python -X utf8 -B -O run_cases.py --output C:/temp/usb-pcie-optimized-new
python -X utf8 -B -O run_cases.py --mutation usb-drop-timeout --output C:/temp/usb-prefix-fault-new
python -X utf8 -B -O run_cases.py --mutation usb-new-command-id --output C:/temp/usb-retry-fault-new
python -X utf8 -B -O run_cases.py --mutation pcie-ignore-byte-count --output C:/temp/pcie-count-fault-new
python -X utf8 -B -O run_cases.py --mutation pcie-finish-first --output C:/temp/pcie-early-fault-new
```

네 변이는 기본 모드로도 별도 실행해 정상 2회·변이 8회를 각각 새 폴더에 남겼습니다. 정상 두 실행의 checks가 같았습니다. require의 명시적인 예외를 사용해 -O에서 검사가 제거되지 않습니다.

## USB 결과

| 대조 | 실제 관측 |
| --- | --- |
| COMPLETED 3·TIMED_OUT 2·COMPLETED 1·COMPLETED 0 | AABBCCDDEEFF 레코드 1개·잔여 0바이트입니다. |
| requested 8을 유효 길이로 사용하는 오류 | 첫 레코드가 AABBCC000000으로 달라집니다. 0 padding은 자체 오류 대조의 가정입니다. |
| ACK-IN STALL 뒤 같은 command ID 41 재사용 | 장치 값 17·적용 1회·재사용 결과 17입니다. |
| 새 command ID 42로 재시도 | 장치 값 24·적용 2회입니다. |
| 같은 ID에 다른 delta | COMMAND_ID_CONFLICT입니다. |
| STALL 뒤 다른 전송이 pending인 채 clear | PENDING_ACTIVE로 거부합니다. |
| cancel 요청만 처리합니다. | pending1을 유지하며 callback 전 slot 재사용을 거부합니다. |
| CANCELLED callback의 prefix2바이트 | actual_length 2를 기록하되 자체 정책으로 공개하지 않습니다. |
| cancel 뒤 COMPLETED callback 경쟁 | stale=false·actual_length 1이지만 공개하지 않습니다. |
| 재연결 뒤 옛 callback | 옛 slot만 반환하며 새 전송은 pending을 유지합니다. |
| 옛 세대 NO_DEVICE와 현 세대 NO_DEVICE | 전자는 새 연결을 보존하고 후자는 연결 세대를 끝냅니다. |

BulkRecords와 UsbEndpoint는 자동 결합한 파이프라인이 아닙니다. collector의 기존 partial bytes는 NO_DEVICE/CANCELLED만으로 자동 소거되지 않으며 재연결 때 호출자가 새 객체를 만드는 계약입니다. slot도 실제 buffer 할당이 아닌 소유 표시입니다. 이 한계를 세대 검사의 결과와 구분합니다.

## PCIe 결과

| 리터럴 입력·경계 | 실제 관측 |
| --- | --- |
| tag 5·16바이트, tag 9·8바이트, tag 5·16바이트 | ACTIVE(받은 16/남은 16)·DONE(8/0)·DONE(32/0)입니다. |
| 첫 tag 5 응답 뒤 CPU 읽기 | DEVICE_OWNED입니다. |
| 같은 tag를 미리 재사용 | TAG_BUSY입니다. |
| 잘못된 Byte Count·Lower Address·중복 첫 조각·UR·빈/3/20바이트 | 7개 대조를 기대 이유로 거부하며 기존 16바이트는 유지합니다. |
| 완료 뒤 중복·retire 뒤 늦은 응답 | NOT_ACTIVE·UNKNOWN_TAG로 구분합니다. |
| `0x1070`부터 중간 4바이트만 끊습니다. | RCB_SPLIT입니다. |
| `0x1070`부터 단일 32바이트 전체 응답 | 원 요청 시작/끝 예외를 적용해 허용합니다. RCB를 무조건 크기 상한으로 쓰지 않습니다. |
| 최대 256바이트 요청·128+128 응답 | 정상 조립합니다. |
| MPS 128보다 긴 132바이트 조각 | PAYLOAD_LENGTH입니다. |
| `0x1FFC`부터 4바이트/8바이트 요청 | 전자는 4KiB 끝에 맞아 허용하고 후자는 경계 초과 입력 오류입니다. |

이 결과는 단일 Requester·tag 0~31·DW 정렬·전체 byte-enable·SC·MPS 128·RCB 128 계약입니다. 원시 wire TLP의 DW padding·BCM·0=4096 Byte Count·Requester ID 다중화·TC·AER·timeout·DMA cache/주소 mapping을 구현하지 않았습니다. tag를 새 요청에 재배정한 뒤 같은 tag의 비정상적인 옛 응답을 완전히 판별한다는 주장도 하지 않습니다.

## 의도한 구현 변이

| 변이 | 기본/-O 종료 | 실제 실패 이유 |
| --- | --- | --- |
| usb-drop-timeout | 1 / 1 | USB partial-record literal failed |
| usb-new-command-id | 1 / 1 | USB retry applied command twice |
| pcie-ignore-byte-count | 1 / 1 | PCIe malformed completion accepted: BYTE_COUNT |
| pcie-finish-first | 1 / 1 | PCIe per-completion state literal failed |

정상은 두 모드 모두 PASS·종료 0이었습니다. 위 ERROR·AssertionError는 정상 구현의 우발적 실패가 아니라 기대값을 고정한 채 결함을 주입해 검증기의 검출을 확인한 결과입니다.
