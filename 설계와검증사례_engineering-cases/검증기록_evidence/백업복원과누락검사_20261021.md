# 백업 복원과 누락 검사 실행 기록 / Backup restoration and missing-file checks

2026-10-21에 Windows·CPython 3.12.14에서 새 호스트 파일로 실행했습니다. [소스·입력](../../예제_examples/실무검증_practical-validation/backup_restore/README.md) · [사례](../백업세트의내용복원과완전성_backup-restore-integrity.md)

## 입력과 독립 기대값

세대는 7입니다. 원문은 config.bin=`01020304` 4바이트, models/model.bin=`1020304050` 5바이트, notes/readme.txt=`4f4b0a` 3바이트입니다. 합계는 12바이트입니다. 검증기는 이 경로와 bytes literal을 소스에 별도로 보유하며 복원 모델의 계산을 호출해 기대값을 만들지 않습니다.

원본에서 models/model.bin을 삭제하고 config.bin을 `09090909`로 바꿨습니다. 새 자식 프로세스가 별도 backup 폴더와 요청만 읽어 새 restored 폴더에 원문 세 개를 복원했습니다. 경로 집합과 각 payload가 literal과 같았으며 손상 원본·백업·요청은 실행 전후 같았습니다. 복원 CLI의 backup_integrity와 restored_content도 각각 VERIFIED였습니다. 요청의 세대·전체 목록·manifest SHA를 신뢰한다는 교육 실습 전제입니다.

## 실행 명령과 종료

각 명령은 아래 예처럼 새로운 출력 경로를 사용했습니다. 공개 명령에서는 독자가 선택하는 C:/temp 경로로 표시합니다. 실제 명령·환경·자식 stdout/stderr·SHA는 실행별 results.json에 저장합니다.

```powershell
python -X utf8 -B verify.py --output C:/temp/backup-normal-new
python -X utf8 -B -O verify.py --output C:/temp/backup-optimized-new
python -X utf8 -B verify.py --mutation missing-file-allowed --output C:/temp/backup-mut-missing-new
python -X utf8 -B verify.py --mutation skip-content-check --output C:/temp/backup-mut-content-new
python -X utf8 -B verify.py --mutation accept-old-generation --output C:/temp/backup-mut-old-new
python -X utf8 -B verify.py --mutation publish-before-complete --output C:/temp/backup-mut-publish-new
```

네 변이는 같은 인수에 -O를 추가하고 별도 새 출력으로도 실행했습니다.

| 실행 경로 | 기본 실행 | -O 실행 | 주요 관측 |
| --- | --- | --- | --- |
| 정상 | PASS·종료 0 | PASS·종료 0 | 각각 31 사례·163 대조·32 자식입니다. |
| missing-file-allowed | ERROR·종료 1 | ERROR·종료 1 | 12번째 대조에서 missing_payload: refused가 실패합니다. |
| skip-content-check | ERROR·종료 1 | ERROR·종료 1 | 17번째 대조에서 changed_payload: refused가 실패합니다. |
| accept-old-generation | ERROR·종료 1 | ERROR·종료 1 | 32번째 대조에서 old_generation: refused가 실패합니다. |
| publish-before-complete | ERROR·종료 1 | ERROR·종료 1 | 158번째 대조에서 partial output must not be published가 실패합니다. |
| 기존 검증 출력 재사용 | REFUSED·종료 2 | 별도 반복하지 않았습니다. | 기존 results.json SHA가 전후 같았습니다. |

변이는 불일치를 만나면 멈춥니다. 정상과 같은 검사 수를 수행했다고 계산하지 않습니다. 실패는 대상 코드가 의도한 오류를 받아들여 고정 검증 기대값과 달라졌다는 관측입니다. 변이의 거부 메시지 자체가 성공이라는 뜻은 아닙니다.

## 입력·경계 관측

누락 payload, 같은 길이 한 바이트 변경, 짧은 payload, 선언 길이 오류, 온전한 옛 세대, manifest 바이트 교체, 예상 밖 파일·빈 디렉터리, manifest/요청 inventory 누락을 거부했습니다. 상대 경로 탈출·절대 경로·Windows 드라이브·역슬래시·`.`·빈 구간·예약 이름·중복·파일과 디렉터리의 prefix 충돌·대소문자 충돌도 거부했습니다. bool 세대·bool 길이·4097바이트 선언·요청 JSON 중복 키·빈 목록·기존 목적지·기존 staging·백업 안의 출력도 확인했습니다.

첫 파일 뒤 결정적 중단은 INTERRUPTED·종료 4, 목적지 없음, staging의 config.bin=`01020304`였습니다. 같은 대상의 재실행은 OUTPUT_EXISTS로 거부하고 부분 자료를 보존했습니다. 이는 정해진 함수 반환점이며 실제 정전이나 강제 프로세스 종료 시험이 아닙니다.

symlink 생성 시도는 Windows 권한 오류 WinError 1314였습니다. capabilities.symlink.status=NOT_EXECUTED이며 link 거부 시험을 통과한 사례 수에 포함하지 않았습니다. Windows reparse 검사 코드도 모든 형태를 실제 생성해 시험한 것은 아닙니다.

## 해석 범위

실제 파일 읽기·쓰기·flush·fsync·같은 부모의 rename과 새 Python 자식 실행을 관측했습니다. 원시 장치·사용자 볼륨·클라우드 백업·PostgreSQL·SQLite 복원은 실행하지 않았습니다. 정전 내구성, 암호학적으로 인증된 출처, 경쟁 작성자의 경로 변경 방어, ACL·hard link·timestamp 복원도 입증하지 않습니다.
