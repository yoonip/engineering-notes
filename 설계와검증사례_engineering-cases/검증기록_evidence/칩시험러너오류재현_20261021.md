# 칩 시험 러너의 오류 재현 기록 / Chip-job runner controls, 2026-10-21

## 환경과 범위

2026-10-21에 CPython 3.12.14, Windows AMD64에서 [작업 러너](../../예제_examples/실무검증_practical-validation/chip_automation/run_validation_jobs.py)와 [자식 fixture](../../예제_examples/실무검증_practical-validation/chip_automation/fixture_child.py)를 실행했습니다. 표준 라이브러리만 사용하며 작은 정수 산술·결과 보고의 모형입니다. 실칩·ATE·RTL·계측기·외부 서비스는 사용하지 않았습니다.

같은 코드로 각각 새 폴더를 지정한 두 실행에서 같은 분류와 집계가 나왔습니다. 시도 ID·호스트 경과 시간·입력 hash는 각 실행에서 새로 기록하므로 결과 파일 전체가 동일한 바이트여야 하는 재현은 아닙니다.

## 명령과 결과

저장소 루트에서 다음과 같이 실행했습니다. `NEW_OUT`은 매번 아직 없는 경로로 바꿉니다.

```shell
python -B 예제_examples/실무검증_practical-validation/chip_automation/run_validation_jobs.py --out NEW_OUT
```

| 구분 | 관측 |
|---|---|
| 전체 fixture | 16개, 예상 분류 일치 16개, 전체 러너 종료 0 |
| 자식 종료 | 완료 15개, timeout 1개 |
| 잘못된 종료 0 기준 | 14개 수용 |
| 잘못된 종료 0 + PASS 부분 문자열 기준 | 14개 수용 |
| 결과 계약상 정상 | ACCEPT 1개 |
| 유효한 기능 실패 보고 | DUT_FAIL 1개 |

자식 16개는 의도적으로 고른 오류 대조 조건입니다. 확률 표본·생산품 16개·서로 독립된 실리콘 결함 16종으로 표시하지 않습니다. 한 자식의 세 산술 항목과 16개 프로세스도 같은 분모가 아닙니다.

## 잘못된 조건의 보존

| fixture | 관측 분류 |
|---|---|
| `normal` | ACCEPT |
| `dut_fail` | DUT_FAIL, 실제 첫 값 184, 자식 종료 0 |
| `lying_pass` | FALSE_VERDICT, 실제 첫 값 184 |
| `stdout_only` | MISSING_RESULT |
| `stale_result` | RUN_ID, 심어 둔 이전 결과 hash 유지 |
| `wrong_hash` | INPUT_HASH |
| `missing_case`, `unknown_case` | CASE_SET |
| `duplicate_case` | DUPLICATE_CASE |
| `schema_bool` | SCHEMA |
| `wrong_type` | FIELD_TYPE |
| `bad_json`, `duplicate_json_key`, `nan` | INVALID_JSON |
| `nonzero_exit` | EXIT_CODE, 자식 종료 7 |
| `timeout` | TIMEOUT, `timed_out=true`, returncode는 `null` |

timeout 경로는 자식이 5초를 기다리도록 하고 부모가 0.25초 제한으로 직접 자식을 종료한 결과입니다. 이 API 경로의 종료 코드를 임의 생성하지 않았습니다. 물리 출력 상태나 프로세스의 자손 트리 정리까지 확인한 결과는 아닙니다.

정상 자식의 세 출력은 손계산 기대값 185, 65,536, 0과 일치했습니다. 부모는 자식의 누산 함수를 import하지 않습니다. `job.json`에 실제 명령·run ID·입력 hash·종료 상태·판정·결과 hash가 있으며 stdout·stderr도 별도 파일입니다. 전체 결과는 `summary.json`에 기록했습니다.

## 재사용 거부와 파일 보존

두 번째 정상 실행의 출력 경로를 다시 지정했을 때 전체 CLI는 종료 코드 2로 거부했습니다. 재사용 시도 전후 결과 폴더의 모든 파일 hash가 같았습니다. 각 작업의 run ID 16개도 서로 달랐습니다. `stale_result`의 과거 결과 모형은 새 전용 폴더 안에 생성한 대조이며 다른 프로젝트의 과거 결과를 바꾸지 않았습니다.

해시는 기록의 동일성을 대조하기 위한 수단입니다. 코드 서명·원격 실행 인증·악의적인 자식에 대한 격리 기능은 아닙니다. 결과 파일 크기는 64KiB로 제한하지만 표준출력의 무제한 생성이나 모든 시스템 자원 고갈을 방어하는 러너로 시험하지 않았습니다.

## English summary

Two fresh runs classified all sixteen controlled subprocess fixtures as expected. Exit-zero and stdout checks each accepted fourteen jobs, while contract validation preserved one accepted job and one valid DUT failure. Reusing the output directory failed with exit code 2 and preserved all existing files. Direct-child timeout handling and source hashes were checked; no chip or instrument was used.
