# 저장장치 완료와 영속성 검사 / Storage completion and persistence checks, 2026-10-21

[실행 코드](../../예제_examples/실무검증_practical-validation/storage_protocols/README.md) · [NVMe 사례](../NVMe의쓰기완료와영속성_nvme-write-persistence.md) · [eMMC·SD 사례](../eMMC와SD의busy와쓰기실패_emmc-sd-write-status.md)

NVMe·eMMC·SD의 이미 해석한 요청과 상태를 Python 사전 기반 모델로 처리했습니다. 실제 저장장치·raw 명령·드라이버·파일시스템·전원 차단 장비를 실행하지 않았습니다. `power_loss()`는 휘발 상태를 제거하는 사건이며, 그 뒤 읽기는 내부 media 관측입니다. 교육 단위는 8개×4바이트이고 실제 sector 형식이 아닙니다.

## 환경과 명령

Windows 11 build 10.0.26200·AMD64·Python 3.12.14, MSC v.1944 64 bit, 표준 라이브러리에서 실행했습니다. UTF-8/LF 소스와 fixture를 확인한 뒤 2026-10-21 03:47:26 UTC에 최종 일반 실행을 시작했습니다. 최종 실행 12개의 JSON과 종료값·stdout·stderr·전체 명령은 비공개 `storage-protocols/verification.json` 및 각각의 출력 폴더에 보존했습니다.

코드 폴더에서 사용할 재현 명령은 다음과 같습니다. C:/temp는 독자가 정할 새 경로의 예입니다. 실제 실행의 전체 경로와 명령은 비공개 검증 JSON에 있으며, 실행 출력은 UTF-8로 처리했습니다.

```powershell
python -X utf8 -B run_cases.py --out C:/temp/storage-normal-new
python -X utf8 -B -O run_cases.py --out C:/temp/storage-optimized-new
python -X utf8 -B run_cases.py --mutation nvme-fua-flushes-all --out C:/temp/storage-fault-new
```

5개 변이는 각각 `--mutation <표의 이름>`을 추가하고 매번 별도 폴더에 일반·최적화 실행을 남겼습니다. 반복 시에는 독자도 새 경로를 지정해야 합니다. `-X utf8`은 UTF-8 처리를 선택하고, `-B`는 bytecode 파일 생성을 막으며, `-O`는 최적화 모드를 선택합니다. 검사기는 `assert` 구문 대신 명시적 예외를 발생시켜 `-O`에서도 동작합니다.

## 입력 거부와 결과 보존

기존 `final-normal` 폴더를 다시 지정한 실행은 exit 2로 끝났고 `result.json` 바이트가 그대로였습니다. `{"schema":1}`만 있는 잘못된 fixture도 exit 2였으며 해당 출력 폴더가 생성되지 않았습니다. 정상 실행 2회·변이 10회와 별개로 이 두 CLI 거부를 확인했습니다.

별도 private 검사에서는 공개 runner를 호출하지 않고 다른 payload·CID·LBA로 직접 API를 확인했습니다. `aa5500ff` 캐시 값과 `ff0055aa` FUA를 분리했고, 3블록 요청 중 2블록의 실패 효과, 지원 SD의 Flush 뒤 `decafbad`, busy가 남은 ready/TRAN, timeout 뒤 새 쓰기 거부를 리터럴로 대조했습니다. 이 항목들과 실행 종료·해시·LF·결과 보존 대조를 합친 private 검증은 47건, 실패 0건이었습니다. 공개 runner의 72단계와 중복 합산한 전체 적합성 수치로 쓰지 않습니다.

## English

Two normal runs passed with identical observations. Five implementation mutations failed with AssertionError in both normal and optimized Python, producing ten expected exit-1 results. Output-directory reuse and a malformed fixture were separately rejected with exit 2; the existing result was preserved. The public runner checks twelve literal scenarios, seventy-two steps, forty-two rejected inputs and twenty-four boundaries. Additional private checks use unseen literal data rather than invoking the public runner as an oracle. The evidence concerns decoded synthetic host contracts and internal media inspection, not physical storage commands or power-loss certification.
