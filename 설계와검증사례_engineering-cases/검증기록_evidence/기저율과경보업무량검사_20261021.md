## 실행 명령과 종료 상태

작업 폴더는 예제의 `ai_prevalence`입니다. 아래 `python`은 위 Python 3.12.14 실행 파일이며 `OUT`은 `tmp/ai-prevalence-20261021/ai`의 절대 경로입니다. 표기를 줄인 명령이며 실제 절대 인자 목록은 원시 실행 기록에 있습니다.

```powershell
python -X utf8 -B verify.py --out OUT/normal
python -X utf8 -B -O verify.py --out OUT/optimized
python -X utf8 -B verify.py --mutation precision-uses-all-samples --out OUT/precision-uses-all-samples
python -X utf8 -B -O verify.py --mutation precision-uses-all-samples --out OUT/precision-uses-all-samples-O
```

나머지 세 변이에도 같은 기본·`-O` 명령을 각각 실행했습니다. 기존 출력 거부 2회와 fixture 거부 3회까지 총 15회의 최상위 Python 프로세스를 실행했습니다.

| 실행 | 횟수 | 기대 exit | 실제 결과 |
| --- | ---: | ---: | --- |
| 정상 기본·최적화 | 2 | 0 | 모두 PASS, 각각 168개 검사·87개 계약 거부입니다. |
| 네 변이 × 두 모드 | 8 | 1 | 모두 ERROR이며 동일한 독립 기대값과 차이가 났습니다. |
| normal·optimized 출력 재사용 | 2 | 2 | `OUTPUT_EXISTS`이며 기존 폴더의 모든 파일 해시가 같습니다. |
| schema가 OTHER인 fixture | 1 | 2 | `SCHEMA`이며 결과 폴더를 만들지 않았습니다. |
| JSON 중복 키 fixture | 1 | 2 | `DUPLICATE_JSON_KEY`이며 결과 폴더를 만들지 않았습니다. |
| NaN을 가진 fixture | 1 | 2 | `NONFINITE_JSON`이며 결과 폴더를 만들지 않았습니다. |

정상 두 실행의 출력은 다음과 같았습니다.

```text
{"status": "PASS", "checks": 168, "rejections": 87, "issues": []}
```

`-O`에서도 실패 목록에 직접 비교 차이를 기록합니다. `assert` 문이 제거되어 검사가 사라지는 방식이 아닙니다. 두 정상 결과의 관측값·검사 수·거부 수·실패 목록은 같았습니다.

## 실제 집계값과 독립 기대값

| 항목 | A 관측값 | B 관측값 |
| --- | --- | --- |
| TP·FN·FP·TN | `90, 10, 10, 90` | `9, 1, 99, 891` |
| 정답 수 | 200개 모두 확인 상태입니다. | 1,000개 모두 확인 상태입니다. |
| 고정 threshold | `0.5`, 평가 전 고정입니다. | `0.5`, 평가 전 고정입니다. |
| 경보 수 | 100 | 108 |
| precision | `90/100 = 9/10` | `9/108 = 1/12` |
| recall | `90/100 = 9/10` | `9/10` |
| FPR | `10/100 = 1/10` | `99/990 = 1/10` |
| accuracy | `180/200 = 9/10` | `900/1000 = 9/10` |
| 실제 불량 비율 | `100/200 = 1/2` | `10/1000 = 1/100` |
| 자체 비용 | `10 + 20×10 = 210` | `99 + 20×1 = 119` |
| 표본당 자체 비용 | `210/200 = 21/20` | `119/1000` |

API는 약분 전 분자·분모와 float 값을 함께 기록합니다. 검증기는 계수에서 `Fraction`을 구성하여 직접 적은 분수 문자열과 비교하고 float 값도 따로 비교했습니다. 행 순서를 뒤집어도 결과가 같았습니다. TPR와 TNR을 모두 0.9로 직접 정했으므로 이번 자료의 accuracy가 같은 것이며, 기저율 변화에도 항상 accuracy가 일정하다는 결과가 아닙니다.

## 오류 변이의 실제 실패

아래 결과는 의도적으로 틀리게 만든 구현의 실패입니다. 정상 구현에서 이 오류가 관측되었다는 뜻이 아닙니다. 두 모드에서 각각 같은 실패 수를 기록했습니다.

| 변이 | 각 모드의 비교 실패 | 대표 관측 |
| --- | ---: | --- |
| `precision-uses-all-samples` | 7 | A precision이 기대 `9/10` 대신 `9/20`입니다. |
| `copy-validation-precision` | 3 | B precision이 기대 `1/12` 대신 A의 `9/10`입니다. |
| `missing-label-as-normal` | 10 | 무정답 상태를 `METRICS_ESTABLISHED`로 바꾸고 계수·비용을 만들었습니다. |
| `retune-on-test-labels` | 1 | 금지한 호출을 받아 threshold 0.49·비용 1을 반환했습니다. |

재선정 변이는 별도 네 행 `(0.9,1), (0.49,1), (0.6,0), (0.1,0)`을 사용합니다. 고정 0.5이면 계수 `1,1,1,1`, 비용 21입니다. 평가 정답을 보고 0.49를 고른 오류 경로는 계수 `2,0,1,1`, 비용 1입니다. 정상 실행도 이 오류 대조를 별도로 관측하되 정상 API가 `test-labels`를 거부하는지 확인했습니다. 변이를 고른 실행에서는 그 거부가 사라져 계약 비교 하나가 실패하고 거부 수가 86으로 줄었습니다.

## 경계와 입력 거부

| 검사 | 실제 판정 |
| --- | --- |
| 점수와 threshold가 같은 0.5 | 경보로 집계했습니다. |
| threshold 0·1, 점수 0·1 | 닫힌 구간을 허용했습니다. |
| 경보 0개 | precision 분모 0과 `value=None`입니다. |
| 실제 양성 0개·정상 0개 | 각각 recall·FPR 값이 `None`입니다. |
| 빈 집합 | 성능 미확정, 경보 비율은 분자 0·분모 0·값 None입니다. |
| label 모두 미상·일부 미상 | 전체 confusion·metrics·cost는 None, 경보 수는 각각 1입니다. |
| label 키 누락 | `FIELDS`로 거부하며 null과 구별했습니다. |
| 2,000행·전체 4,000행 | 경계는 허용했고 초과는 거부했습니다. |
| 비용 0·1,000,000 | 정수 경계는 허용했고 음수·초과·bool·float는 거부했습니다. |
| ID 누락·중복·집합 간 겹침 | 각각 거부했습니다. |
| schema 키 누락·추가·중복 | schema 검사 또는 JSON 훅에서 거부했습니다. |
| bool·문자열·범위 밖 점수와 class | 정해진 형·범위가 아니므로 거부했습니다. |
| NaN·Infinity·1e999 | 비유한 JSON 토큰 또는 점수로 거부했습니다. |
| 깨진 UTF-8·잘린 JSON·300,001바이트 | 결과로 평가하지 않고 거부했습니다. |

동결 전 시험에서는 깊이 1,500인 배열이 JSON 디코딩을 거친 뒤 schema 단계에서 거부되어, 검증기가 예상한 거부 코드와 달랐습니다. 파서 깊이에 대한 이식 가능한 보장을 이 예제의 결과에 넣지 않았으며 해당 기록은 비공개 `trial-normal/result.json`에 남겼습니다. 위 표와 해시는 수정 후 동결한 소스의 최종 실행입니다.
