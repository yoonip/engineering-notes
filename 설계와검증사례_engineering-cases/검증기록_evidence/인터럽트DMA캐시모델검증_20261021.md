# 인터럽트·DMA·캐시 모형 실행 기록 / Interrupt, DMA and cache model evidence

2026-10-21에 실행한 표준 라이브러리 Python 호스트 모형의 기록입니다. 레지스터·IRQ·DMA·캐시 유지 명령을 MCU에서 실행하지 않았습니다. 입력과 잘못된 경로는 직접 구성했으며 기존 제품에서 발견한 결함이라는 뜻은 아닙니다.

[W1C와 버퍼 소유권](../상태비트소거와완료버퍼소유권_irq-w1c-ownership.md), [캐시와 RAM](../캐시와RAM의데이터불일치_dma-cache-lines.md), [실행 방법](../../예제_examples/실무검증_practical-validation/interrupt_dma/README.md), [모형 소스](../../예제_examples/실무검증_practical-validation/interrupt_dma/models.py), [검사 소스](../../예제_examples/실무검증_practical-validation/interrupt_dma/verify.py), [입력](../../예제_examples/실무검증_practical-validation/interrupt_dma/fixtures.json)을 연결했습니다.

## 환경과 재현 명령

Windows 11 `10.0.26200`, x86-64, Python `3.12.14`, MSC v.1944 환경에서 실행했습니다. 외부 패키지를 사용하지 않습니다. 코드 폴더에서 아래처럼 새 출력 경로를 지정합니다. `-B`는 bytecode 파일 생성을 막고 `-X utf8`은 텍스트 입출력 인코딩을 고정합니다.

```powershell
python -X utf8 -B verify.py --output C:/temp/interrupt-dma-run-new
python -X utf8 -B verify.py --inject w1c-rmw --output C:/temp/interrupt-dma-w1c-new
python -X utf8 -B verify.py --inject tx-no-clean --output C:/temp/interrupt-dma-tx-new
python -X utf8 -B verify.py --inject allow-owned-reuse --output C:/temp/interrupt-dma-owner-new
```

로컬 재실행은 각각 `run-2`, `mutant-w1c-2`, `mutant-tx-2`, `mutant-owner-2`라는 새 폴더에 기록했습니다. 각 JSON은 시각·Python 실행파일·운영체제·명령 인수·소스/입력 SHA-256·실패 이유를 포함합니다. 정상 결과에는 실제 바이트와 버퍼 상태별 사건 목록도 있습니다. 로컬 경로는 공개 저장소의 필수 파일이 아니며 위 명령으로 결과를 새로 만들 수 있습니다.

## 기대값과 실제 출력

| 항목 | 기대값을 정한 방법 | 실제 결과 |
| --- | --- | --- |
| W1C 정적 조합 | 켜진 비트 위치의 집합에서 처리 위치를 뺍니다. | 256×256=65,536조합 일치 |
| 기본 pending=10, mask=2 | 처리하지 않은 비트 3은 남아야 합니다. | RMW는 0, 직접 mask는 8 |
| 버퍼 A=17, B=18, 새 입력=19 | CPU 소유 A의 재할당을 거부하고 두 완료값을 보존합니다. | 오류 경로 A=19, 수정 경로 A=17·B=18·할당 거부 |
| TX `11223344` | DMA가 읽는 바이트를 입력 자체와 비교합니다. | clean 생략 `00000000`, 적용 `11223344` |
| RX `31323334` | CPU가 읽는 바이트를 입력 자체와 비교합니다. | 사후 invalidate 생략 `00000000`, 적용 `31323334` |
| 사전 dirty RX 처리 | DMA 뒤 RAM이 새 입력과 같아야 합니다. | 생략 `07070707`, 적용 `31323334` |
| RX 16바이트·이웃 flag | payload와 flag=1을 별개로 비교합니다. | 공유 invalidate는 flag=0, 공유 사후 clean은 RX=0, line 분리는 둘 다 보존 |
| line 범위 | 모든 payload 바이트를 순회하며 해당 line 주소를 집합으로 만듭니다. | 128바이트 공간의 시작/길이 8,385조합 일치 |

W1C 기대값은 모형의 `pending & ~written` 식을 복사하지 않았습니다. line 기대값도 시작·끝의 반올림 식을 복사하지 않고 각 바이트를 방문합니다. TX/RX의 기대 바이트는 결과가 스스로 보고한 값이 아니라 입력 파일에서 가져옵니다. 독립 기대값은 이 유한 입력의 오류 검출에 쓰이며 실제 MCU 전체 동작의 증명은 아닙니다.

기존 캐시 본문에 추가한 짧은 코드도 실행했습니다. TX의 clean 전후 출력은 차례로 `00000000`, `11223344`였습니다. 별도 메모리 본문의 `0x2000101C`부터 12바이트 계산은 `[0x20001000, 0x20001040)`, 총 64바이트·앞 28·뒤 24바이트였습니다. 이 값은 주소 계산이며 실제 주소 접근 시험이 아닙니다.

## 검출기를 확인한 대조

정상 실행은 종료 0입니다. 내부의 의도적 오류 일곱 종류도 각각 `ContractError`로 검출했습니다. 잘못된 결과까지 성공으로 간주하는 검사가 되지 않도록, 명령행으로 정상 경로를 바꾼 세 실행은 전체 검사를 실패시켰습니다.

| 주입 경로 | 종료 코드 | 실제 기록된 오류 |
| --- | --- | --- |
| `w1c-rmw` | 1 | `ContractError: unhandled IRQ cause was cleared` |
| `tx-no-clean` | 1 | `ContractError: dma_hex: 00000000 != 11223344` |
| `allow-owned-reuse` | 1 | `ContractError: CPU-owned buffer was reused` |

같은 정상 출력 폴더로 다시 실행한 대조는 종료 2와 `output already exists`로 거부됐습니다. `results.json`의 전후 SHA-256은 모두 `3281f5631a64b93f1b14da842bc3eddfc88f4cff1dfde8657d57e6582eeb9aa2`였습니다. 성공 결과를 실패 실험으로 덮어쓰지 않는 동작도 실제 확인한 것입니다.

## 공식 자료의 판본과 읽은 범위

모두 2026-10-21에 대조했습니다. 직접 다운로드한 파일과 웹에서 읽은 자료를 구별합니다.

- [ST RM0368 Rev 6, 2025-01](https://www.st.com/resource/en/reference_manual/DM00096844.pdf): STM32F401의 §10.3.6 EXTI_PR, 211쪽에서 W1C를 읽었습니다. §9.5.1~9.5.4, 188~191쪽의 DMA_LISR/HISR와 LIFCR/HIFCR를 읽어 status와 별도 clear 레지스터를 구별했습니다. §9.3.9의 double-buffer 전환 조건도 읽었습니다. 자체 소유권 모형이 실제 double-buffer 중단 절차를 구현한다는 뜻은 아닙니다.
- [ST AN4839 Rev 2, 2018-03](https://www.st.com/content/ccc/resource/technical/document/application_note/group0/08/dd/25/9c/4d/83/43/12/DM00272913/files/DM00272913.pdf/jcr:content/translations/en.DM00272913.pdf): 공식 보관 PDF의 §2~4, 3~8쪽에서 write-back·32바이트 line·clean과 invalidate·DMA 전후 처리 범위를 대조했습니다.
- [ST 공식 기술 글, DMA is not working on STM32H7 devices](https://community.st.com/stm32-mcus-60/dma-is-not-working-on-stm32h7-devices-97): ST Employee 본문의 §2와 §5에서 DMA의 RAM 접근, 32바이트 line 공유 손실, TX 사전 clean·RX 사전 처리·전송 중 CPU 접근 금지를 읽었습니다. 댓글을 하드웨어 규격으로 사용하지 않았습니다.
- [Arm Cortex-M7 Devices Generic User Guide, DUI 0646B, 2015](https://documentation-service.arm.com/static/61efd6602dd99944d051417b?token=): §4.8, 4-61~4-62쪽의 by-address 유지 연산, PoC와 DMA 같은 외부 agent, 주소 비트 범위를 읽었습니다. 직접 받은 PDF의 SHA-256은 `4b474102e4dc490fdb759dde329715b1f348ebe433e97830f585bb92481f463a`입니다.
- [CMSIS_6 v6.3.0, armv7m_cachel1.h](https://github.com/ARM-software/CMSIS_6/blob/v6.3.0/CMSIS/Core/Include/m-profile/armv7m_cachel1.h): by-address 세 함수의 32바이트 범위 처리와 DSB·ISB를 직접 읽었습니다. 받은 헤더의 SHA-256은 `f7905d3e336feccda0647f214e791b424c5f92e788f1303e587cebca729b6dc3`입니다. Python 모형에서 이 헤더를 실행하거나 명령의 타이밍을 측정하지 않았습니다.

W1C 예제의 근거는 STM32F401의 RM0368이며, 캐시 예제는 Cortex-M7 자료를 사용합니다. 서로 다른 MCU의 사양을 구분하여 읽습니다.

## 범위와 남은 타깃 검증

W1C 65,536조합은 정적 8비트 pending/mask입니다. read/write 사이의 새 IRQ와 같은 비트에 합쳐진 여러 사건은 세지 않습니다. 버퍼 수정 경로는 새 전송 할당 거부이며 진행 중 DMA를 안전하게 멈춘 실행이 아닙니다. RX의 사전 처리 뒤 오래된 clean 사본은 명시적인 모형 사건입니다. cache way·교체·store buffer·버스·실제 speculation·NVIC·MPU·MCU별 errata는 실행하지 않았습니다.

실제 장치에서는 부품·DMA master의 RAM 접근성, 전용 line 배치, 전송 종료/오류 조건, 데이터 소유권과 cache 유지 구간을 드라이버·linker·map 파일 및 계측 결과로 추가 확인해야 합니다.

## English

The host suite passed 65,536 static W1C combinations, 8,385 bounded range cases, and seven internal fault controls. Three injected faulty paths failed with exit code 1; reuse of an existing output directory failed with exit code 2 and preserved the result hash. Source and input hashes identify the executed files. This record includes source reading and deterministic byte-array models, not MCU IRQ, DMA or cache-instruction execution.
