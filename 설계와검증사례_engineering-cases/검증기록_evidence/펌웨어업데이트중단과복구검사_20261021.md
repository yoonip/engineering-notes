# 펌웨어 업데이트 중단과 복구 검사 / Firmware update interruption and recovery checks

2026-10-21에 별도 Python 프로세스와 실제 파일 I/O로 실행한 교육용 기록입니다. [원리와 실패 사례](../중단된업데이트의슬롯선택과롤백_firmware-ab-update.md), [실행 방법](../../예제_examples/실무검증_practical-validation/firmware_update/README.md), [모형](../../예제_examples/실무검증_practical-validation/firmware_update/models.py), [검사](../../예제_examples/실무검증_practical-validation/firmware_update/verify.py), [입력](../../예제_examples/실무검증_practical-validation/firmware_update/fixtures.json)을 연결했습니다.

이미지는 자체 바이트열이며 firmware나 kernel로 실행되지 않습니다. `BOOT`는 파일 선택 결과입니다. MCU·MCUboot·실제 flash 전원 차단·production secure boot의 성공 기록이 아닙니다. 오류는 재현을 위해 직접 넣었습니다.

## 환경과 실제 명령

Windows 11 `10.0.26200`, AMD64, CPython `3.12.14`, MSC v.1944에서 표준 라이브러리만 사용했습니다. 부모와 자식은 `-X utf8 -B`로 실행하며 최적화 비교에서는 양쪽 모두 `-O`를 사용했습니다. 각 결과 JSON은 UTC 시각·실행파일·명령 인수·최적화 수준·소스/입력 해시를 남깁니다.

코드 폴더에서 아래 형태로 실행했습니다. 경로는 매번 새 폴더로 바꿉니다.

```powershell
python -X utf8 -B verify.py --output C:/temp/update-run-new
python -X utf8 -B -O verify.py --output C:/temp/update-optimized-new
python -X utf8 -B verify.py --mutation erase-active --output C:/temp/update-active-new
python -X utf8 -B verify.py --mutation confirm-early --output C:/temp/update-confirm-new
python -X utf8 -B verify.py --mutation skip-hash --output C:/temp/update-hash-new
python -X utf8 -B verify.py --mutation single-record --output C:/temp/update-record-new
```

네 mutation은 각각 `-O`를 붙인 새 경로에서도 실행했습니다. 로컬 정상은 `run-1`, 최적화는 `run-optimized-1`이며 mutant·optimized-mutant별 폴더를 따로 보존했습니다. 실제 전체 명령·종료·표준 출력은 private `verification.json`과 각 `results.json`의 child_commands에 있습니다. 공개 코드로 같은 산출물을 새로 만들 수 있습니다.

## 유한 중단 집합과 실제 재시작

자식은 선택한 prefix를 파일에 쓴 뒤 flush·fsync를 요청하고 `os._exit(23)`으로 중단합니다. 부모가 새 프로세스를 실행해 같은 파일을 다시 읽습니다. 선택한 prefix가 남는 결정적 중단 시험이며 임의의 OS syscall 중단·파일시스템 power-loss 보장이나 실제 flash fault를 재현하지 않습니다. 디렉터리 fsync·erase/program 단위·ECC·마모·컨트롤러 전원 캐시도 시험하지 않았습니다.

| 단계 | 중단 위치 수 | 완전 기록 전의 재시작 | 완전 기록 뒤의 재시작 |
| --- | ---: | --- | --- |
| B 이미지 | prefix0~12의 13개 | 모든 경우 A·stable·generation0입니다. | 이미지 전체만 기록한 경우도 아직 게시 전이므로 A입니다. |
| 이미지 검증 직후 | 1 | pending이 없어 A입니다. | 같은 지점입니다. |
| pending | 5 | A·stable·generation0입니다. | B·trial·generation2입니다. |
| trial 표시 | 5 | 이전 pending에서 B·trial·generation2로 다시 준비합니다. | A·rollback·generation3입니다. |
| confirm | 5 | A·rollback·generation3입니다. | B·stable·generation3입니다. |
| rollback | 5 | A·rollback·generation3을 다시 기록합니다. | A·stable·generation3입니다. |

메타데이터의 다섯 위치는 0·1·floor(N/2)·N-1·N이며 N은 직렬화한 전체 기록 길이입니다. 총 `13+1+4×5=34`개입니다. 선택한 집합을 모두 실행한 것이며 모든 metadata 바이트 위치와 모든 전원 오류를 포함한 시험이 아닙니다. cut 직후와 재선택 뒤의 기록 파일 길이도 JSON에 따로 남깁니다.

이번 입력에서 전체 pending 288바이트, trial 287바이트, confirm 289바이트, rollback 288바이트였습니다. 초기 record0은 195바이트입니다. 자체 JSON 형식의 상태·CRC 숫자 표현에 따른 값이며 장치의 flash trailer 크기나 일반적인 최대 크기가 아닙니다.

정상 기본/최적화는 각각 102개 비교·34개 cut·178개 자식 프로세스로 종료0이었습니다. 자식은 정상134개·의도한 거부 종료3 10개·중단 종료23 34개입니다. 비교 항목들은 같은 실행 근거를 공유하므로 독립 고장 수나 안전 coverage로 합산하지 않습니다.

## 기대값과 손상 대조

fixture의 selected·mode·generation·active·pending·attempted를 literal로 적어 관측과 비교했습니다. 결과의 generation을 다시 정답 generation으로 사용하지 않습니다. 예를 들어 pending 전체 기록 뒤 기대는 B·trial·generation2, confirm 전체 기록 뒤 기대는 B·stable·generation3입니다. CRC32의 `123456789 → CBF43926` 리터럴도 대조했습니다.

| 대조 | 실제 관측 |
| --- | --- |
| 새 이미지 한 바이트 변경·선언 해시 유지 | 설치를 종료3으로 거부하며 기존 A는 선택됩니다. |
| 선언12에 실제11/13바이트 | 길이 불일치로 거부합니다. 33바이트는 자체 입력 상한32를 넘어 거부합니다. |
| trial 전 confirm·checkpoint 없는 confirm | 상태/업무 전제가 없어 거부합니다. |
| 가장 최신 record의 CRC만 손상 | 이전 유효 record0·generation0을 사용합니다. |
| metadata 두 부 모두 미완성 JSON | 유효 기록이 없어 종료3·복구 필요로 거부합니다. |
| 동일 최대 generation의 서로 다른 CRC 유효 상태 | 충돌한 상태를 임의 선택하지 않고 거부합니다. |
| pending B 데이터 손상 | 후보를 거부하고 A·invalid_pending·generation2로 돌아갑니다. |
| 확정된 B의 데이터 손상 | 다음 선택을 거부합니다. 모든 손상에서 자동 A 복구를 구현한 것은 아닙니다. |
| 이미지와 입력 manifest 해시를 함께 교체 | 이 unsigned 모형은 B를 trial로 선택합니다. 인증의 부재를 보여 줍니다. |
| B 확정 뒤 이전 A 이미지를 재설치 | A·trial·generation5입니다. anti-rollback 정책을 구현하지 않았습니다. |

기존 Embedded Linux 본문에 추가한 metadata 조회 함수도 로컬 정상 `happy/store`로 호출해 `('B', 3)`을 확인했습니다. CRC 유효 기록 해석과 실제 kernel/firmware 실행은 다른 검사입니다.

## 검증기의 오류 검출과 결과 보존

| mutation | 기본/`-O` 부모 종료 | 실제 실패 이유 |
| --- | --- | --- |
| erase-active | 1/1 | `image prefix 0 preserves A`: 실제 빈 바이트열이 기존 A literal과 다릅니다. |
| confirm-early | 1/1 | pending 전체 뒤 stable B·generation1이 기대한 trial B·generation2와 다릅니다. |
| skip-hash | 1/1 | 손상 설치의 예상 거부3 대신 STAGED·종료0입니다. |
| single-record | 1/1 | pending 기록 중 유효 metadata가 없어 boot가 예상0 대신 거부3입니다. |

기본과 최적화 결과의 checks·cut_matrix·source/input 해시가 같았습니다. 실행 시각·명령 경로·최적화 표시는 다르므로 파일 전체 해시가 같아야 한다고 검사하지 않았습니다. 검사에는 `assert` 대신 명시적 예외를 사용했습니다.

## 출처와 읽은 범위

MCUboot [v2.2.0 design.md](https://github.com/mcu-tools/mcuboot/blob/v2.2.0/docs/design.md)의 이미지 형식·flash map·slots·test/revert·direct-XIP revert·신뢰 키·protected TLV·downgrade prevention을 2026-10-21에 읽었습니다. [v2.2.0 readme-zephyr.md](https://github.com/mcu-tools/mcuboot/blob/v2.2.0/docs/readme-zephyr.md)의 Device Tree partition·이미지 배치·서명 키·image OK와 복귀 절도 읽었습니다. MCUboot 빌드·보드 flash·서명 생성은 수행하지 않았습니다.

직접 받은 두 문서의 SHA-256은 각각 `a53903d565954b9f3393c1138ea7eb6b31229b69aa5f9e34f8efe514528a59e4`, `44b0ac72432285f25462110723cf2e2347e722eb3a7c6b2bd5f21a6e5927e5b5`입니다. tag는 읽은 판본을 고정하기 위한 것이며 최신 release라는 뜻은 아닙니다. JSON·CRC·generation·파일 cut과 관측 수치는 자체 설계·실행 결과입니다.

해시와 CRC는 권한 인증이 아니며 metadata generation은 신뢰된 보안 counter가 아닙니다. 모형의 슬롯당32바이트·세대0~1,000,000·고정8/12바이트 fixture는 교육 계약입니다. 실제 부팅 이미지 검증과 복구에는 실행 주소·저장장치·erase 배치·이미지 간 호환성과 신뢰 키·보안 counter·전원 상실 조건을 별도로 검증해야 합니다.

## English

Normal and optimized runs each passed 102 comparisons over 34 declared interruption checkpoints using 178 fresh model processes. Four faulty implementations failed in both modes. Corrupt-image/metadata controls, explicit trial confirmation, rollback, unchanged output protection and source/input hashes are recorded. Actual disk files were reopened across process exits; executable boot, MCUboot, arbitrary OS/flash power loss, authentication and anti-rollback were not executed or established.
