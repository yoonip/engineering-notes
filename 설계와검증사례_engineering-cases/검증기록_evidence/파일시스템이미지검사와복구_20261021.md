## 환경과 명령

Windows 11 build 10.0.26200·AMD64·CPython 3.12.14·MSC v.1944 64 bit에서 실행했습니다. 표준 라이브러리만 사용했습니다. 소스·fixture를 UTF-8/LF로 저장한 뒤 각 명령의 실제 인수·종료·stdout·stderr와 결과 SHA를 비공개 filesystem/verification.json에 기록했습니다. 결과 폴더마다 results.json에 자식 전체 명령, 이미지/manifest/plan SHA, 원본의 실행 전후 SHA와 관측이 있습니다.

코드 폴더에서 실행하는 C:/temp 아래 경로는 독자가 선택할 새 출력 경로의 예입니다.

```powershell
python -X utf8 -B verify.py --output C:/temp/fs-normal-new
python -X utf8 -B -O verify.py --output C:/temp/fs-optimized-new
python -X utf8 -B -O verify.py --mutation ignore-shared --output C:/temp/fs-shared-new
python -X utf8 -B -O verify.py --mutation guess-size --output C:/temp/fs-size-new
python -X utf8 -B -O verify.py --mutation drop-orphan --output C:/temp/fs-orphan-new
python -X utf8 -B -O verify.py --mutation skip-digest --output C:/temp/fs-digest-new
```

네 변이는 기본 모드에서도 실행해 최종 정상 2회·변이 8회를 남겼습니다. 초기 first-run은 29개 이미지·209개 대조·61개 자식 PASS였으며 덮어쓰지 않았습니다. 선언된 길이가 64인데 실제 바이트는 8개인 identity 경계를 추가한 뒤 최종 소스로 다시 실행했습니다.

## 거부와 정보 부족 대조

공유 블록 [3,4], 디렉터리 순환, 부모 둘, 고아 디렉터리, 같은 이름의 다른 대상, 없는 블록, 한 파일의 중복 블록은 계획 REFUSED였습니다. 이 중 여섯 그래프·블록 손상에서는 실제 repair도 종료 3이고 새 출력이 생기지 않았습니다. 할당됐지만 소유자를 모르는 블록 6과 근거 없는 길이 19도 계획에서 거부했습니다.

`OK\n`을 같은 길이의 `NO\n`으로 바꾸고 이미지·블록 checksum을 다시 계산한 입력은 구조 PASS입니다. 외부 목록을 주지 않으면 NOT_ESTABLISHED, 원래 digest를 주면 identity FAIL이며 복구 계획을 거부했습니다. inode 5·이름·payload를 함께 없애 현재 구조가 일치하는 입력도 외부 목록에서 MISSING_FILE로 검출했습니다. digest에는 없어진 원문이 없어 payload를 재구성하지 않았습니다.

선언 길이 64, 실제 블록 하나의 8바이트, 그 짧은 값의 digest를 함께 준 입력은 MISSING_PAYLOAD_BYTES·identity FAIL입니다. 빈 파일은 블록 0개로, 64바이트 경계는 블록 8개로 처리했습니다. bool 크기, 블록 8번, 잘못된 이름, 중복 inode/JSON 키, 미지원 feature, 두 종류의 checksum 손상, 65,537바이트 입력과 잘린 JSON도 거부했습니다.

오래된 계획과 동작을 바꾼 계획은 STALE_OR_MODIFIED_PLAN으로 거부했습니다. 기존 사본 및 원본 경로를 출력으로 지정하는 두 요청도 종료 3이며 파일이 보존됐습니다.

## 출력 보존과 범위

기존 정상 검증 폴더를 다시 지정하면 종료 2입니다. results.json의 전후 SHA는 `bbe737c3dd8473b3a41b832dc3fb88363b2e8baf6fd6b3c0e6452349c12ea2de`로 같았습니다. 시각·환경·절대 경로가 포함되므로 다른 사용자의 새 결과와 같은 해시를 요구하지 않습니다.

이미지는 최대 65,536바이트, manifest는 최대 16,384바이트이며 geometry와 기능은 고정입니다. directory 자료는 metadata에 따로 있고 root nlink=1, 다른 nlink=이름 참조 수인 자체 형식입니다. 실제 ext4의 dot/dotdot, 저널, extent, sparse/preallocation, inode bitmap 배치, 공유 기능, 동시 writer, 장치 내구성을 구현하지 않습니다. 외부 manifest의 서명·유통·권한 보호도 구현 범위 밖입니다. 사본의 flush·fsync 성공은 실제 전원 차단 복구의 증거가 아닙니다.

## English

The final normal and optimized executions each pass 215 comparisons across 30 synthetic image cases and 63 fresh child processes. Literal payloads, input-bound plans, unchanged sources and byte-identical second repair copies are checked. All four intentional mutations fail in both modes. Changed or missing historical content can coexist with structural consistency; an external inventory detects those differences but does not reconstruct payload bytes or old names. Existing output is rejected without changing its report. The scope is new EDUFS1 JSON host files, separate from ext4, e2fsck, mounted disks and power-loss recovery.
