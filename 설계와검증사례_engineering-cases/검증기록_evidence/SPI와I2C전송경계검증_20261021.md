# SPI·I2C 전송 경계 실행 기록 / SPI and I2C transaction checks, 2026-10-21

표준 라이브러리 Python으로 만든 합성 논리 파형과 요청 일정을 실행한 기록입니다. 실제 Flash·EEPROM·SPI/I2C adapter·GPIO·Linux API·전기 파형을 실행하거나 측정하지 않았습니다. 의도한 결함과 정상 경로, 검증기의 변이 검출을 구분합니다.

[코드·입력·실행 안내](../../예제_examples/실무검증_practical-validation/serial_buses/README.md), [SPI 사례](../SPI의선택선과더미클록_spi-cs-dummy-edges.md), [I2C 사례](../I2C의묶음읽기와NACK_i2c-combined-read.md)를 연결합니다.

## 환경과 실행

Windows 11 build 10.0.26200·AMD64·Python 3.12.14, MSC v.1944 64 bit입니다. 로컬 가상환경의 Python 실행 파일을 사용했습니다. 공개 소스와 입력을 UTF-8/LF로 정규화한 뒤 각각 새 결과 폴더로 실행했습니다. 명령의 결과 폴더 경로는 독자가 정하는 새 이름의 예입니다.

```powershell
python -B run_cases.py --output C:/temp/serial-review-new
python -B -O run_cases.py --output C:/temp/serial-review-optimized-new
python -B -O run_cases.py --mutation spi-no-dummy --output C:/temp/serial-spi-mutation-new
python -B -O run_cases.py --mutation i2c-final-ack --output C:/temp/serial-i2c-mutation-new
```

## 검증기의 실패 검출과 입력 예외

정상 실행과 `-O` 실행에서 SPI·I2C·입력 예외의 의미상 결과가 같았습니다. 일반 `assert` 대신 명시적으로 예외를 발생시키는 `check()`를 사용합니다.

`spi-no-dummy`는 master의 전송 길이를 줄이는 변이가 아닙니다. 장치 모형의 dummy 요구를8에서0으로 바꿔, 고정 RX 기대값과 다른 구현이 실패하는지 봅니다. 별도의 master 클록 부족 대조는48클록·8유효표본이고, 잘못된 데이터 추출은 wrong_offset 경로입니다. 변이 실행은 SPI literal receive oracle failed·AssertionError·ERROR·종료1이었습니다.

`i2c-final-ack`는 정상 경로의 마지막 controller NACK를 ACK로 바꿉니다. payload가 같아도 전체 trace 기대값이 달라 I2C literal trace oracle failed·AssertionError·ERROR·종료1이었습니다. 두 변이는 의도적으로 실패시킨 대조이고 정상 모델의 검증 실패로 섞지 않습니다.

입력 오류9종은 불완전 hex·비hex·빈 SPI전송·잘못된 CPHA·0바이트 CS경계·이미 이동한 I2C주소0xA0·음수 pointer·알 수 없는 NACK단계·숫자 open-drain상태입니다. 모두 기대한 `InputError`로 구분했습니다. 기존 결과 폴더를 다시 지정하면 종료2였고 이전 결과의 파일 해시는 바뀌지 않았습니다.

## 해석의 한계

SPI의5ns 출력 지연·10ns 늦은 표본·명령 중 입력1은 자체 가정입니다. 실제 wrong-mode 동작이 언제나4AB5가 된다는 예측이 아닙니다. W25Q64JV의 다른 opcode·용량 끝 주소 순환·보호·BUSY·전원·신호 무결성을 구현하지 않았습니다. I2C는 읽기·pointer 일부와 지정된 요청 순서를 구현하며 EEPROM 쓰기·controller arbitration·실물 timing·GPIO bus clear는 구현하지 않았습니다.

기존 I2C 내부 주소1바이트 예제와45클록 결과는 유지했습니다. 새2바이트 주소 모델의54클록·135µs는 다른 계약의 자체 계산입니다. 이 기록의 검사 항목 수를 실물 통신 성공률이나 표준 적합성으로 표현하지 않습니다.

## English

Normal and optimized host runs agree. Literal oracles expose SPI CS/dummy/edge boundaries and I2C pointer/NACK/open-drain distinctions. Two intentional implementation mutations fail with explicit assertion errors; nine malformed inputs are rejected and existing outputs remain intact. This is deterministic software evidence rather than hardware, driver, or electrical validation.
