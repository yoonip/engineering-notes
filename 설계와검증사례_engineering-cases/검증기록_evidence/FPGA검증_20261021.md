# FPGA 프레임·RTL·UART 모의 검증 기록 / FPGA frame, RTL and mocked UART verification

실행일은 2026-10-21 KST입니다. [사례 본문](../프레임오류와FPGA검증_fpga-frame-validation.md)의 새 실행 근거를 요약합니다. 기존 README의 통과 횟수를 새 결과로 옮기지 않았습니다. 물리 보드·ADC·UART 포트는 사용하지 않았습니다.

추가 확인에서 순번 0과 4096의 패턴이 같다는 점과, ADC 판정 함수가 순서만 뒤집은 무오차 입력을 수용한다는 점도 관측했습니다. 이 두 항목의 assertion 통과는 해당 기능이 정상이라는 보증이 아니라 한계를 재현했다는 뜻입니다. 24개에 앞 표의 시나리오 일부 재확인도 포함되므로 서로 독립된 24종의 결함을 검출했다는 의미가 아닙니다.

## stdout과 미완료 시도

프레임 프로그램의 핵심 출력은 다음과 같았습니다.

```text
clean       : 0 failing block(s)
byte_swap   : 1 failing block(s)
channel_swap: 1 failing block(s)
drop_frame  : 3 failing block(s)
short_read  : 1 failing block(s)
zero_fill   : 1 failing block(s)
timeout     : 1 failing block(s)
```

RTL의 성공 로그는 다음과 같았습니다.

```text
PASS: 64 samples, normal/injected errors, pause and reset checked
tb_validation_top.sv:61: $finish called at 7210000 (1ps)
```

64샘플을 모두 오류라고 세지 않습니다. 정상 구간 32샘플과 주입 구간 32샘플 중 실제 주입 오류는 2개입니다. testbench의 `TICK_CYCLES=10`은 실행 시간을 줄인 조건이며, 원래 RTL 기본 분주값 100000을 실물에서 시험한 결과가 아닙니다.

첫 컴파일과 이후 재시도 한 번은 모두 종료 코드 `3221225477`, 즉 `0xC0000005`였으며 stdout·stderr는 비어 있었습니다. 그 사이에 동일 내용의 RTL 사본을 상대 파일명으로 컴파일하고 VVP를 실행한 한 번은 성공했습니다. 절대 경로·상대 경로의 효과나 DLL·접근 위반의 원인은 확정하지 않았습니다. 도구 환경의 반복 실행 문제는 남아 있습니다. 마지막 Python 검사 묶음에서는 RTL 재실행을 생략했으며, 이 생략을 추가 RTL 성공으로 세지 않았습니다.

UART의 첫 실행은 `ModuleNotFoundError: No module named 'serial'`로 import 단계에서 실패했습니다. pyserial을 private 경로에 설치한 후 10개 검사를 실행해 통과했습니다. 물리 통신 실패를 고쳤다는 의미는 아닙니다. 정상 UART 프로그램의 `--port` 명령과 전체 `build_all.py`, Vivado 합성·보드 다운로드는 실행하지 않았습니다.

## 재현 명령

PowerShell에서 저장소 루트를 현재 위치로 둡니다. 실제 검사에서는 Python을 절대 경로로 호출하고 출력·의존성을 별도 private 폴더로 지정했습니다. 아래 변수는 같은 분리를 재현하기 위한 것이며, 실제 보드의 COM 포트를 열지 않습니다.

```powershell
$repo = (Get-Location).Path
$fpga = Join-Path $repo "프로젝트_projects/fpga-validation-harness"
$hostCode = Join-Path $repo "프로젝트_projects/embedded-validation-lab/host"
$run = Join-Path $env:TEMP ("fpga-check-" + [guid]::NewGuid())
New-Item -ItemType Directory -Path $run | Out-Null
python -B "$fpga/offline_fpga_measurement_lab.py" --out (Join-Path $run "frames")

$deps = Join-Path $run "deps"
python -m pip install --target $deps --no-compile pyserial==3.5
$previousPythonPath = $env:PYTHONPATH
try {
    $env:PYTHONPATH = $deps
    python -B -m unittest discover -s $hostCode -p "test_protocol.py" -v
} finally { $env:PYTHONPATH = $previousPythonPath }

# FAIL=1, TIMEOUT=2는 의도한 오류 주입의 판정일 수 있으므로 stdout도 확인합니다.
foreach ($scenario in @("healthy", "offset", "timeout", "data-loss")) {
    python -B "$fpga/validation_lab.py" --scenario $scenario --seed 42 --samples 128 --timeout-ms 50 --output (Join-Path $run "adc")
}
python -B "$fpga/validation_lab.py" --scenario healthy --decode unsigned --seed 42 --samples 128 --output (Join-Path $run "adc")
```

RTL은 새 사본 디렉터리에서 실행했습니다. 두 소스 사본의 SHA-256을 원본과 대조한 뒤 다음 방식으로 실행합니다. 이 환경에서는 반복 컴파일 실패도 관측됐으므로 성공을 전제하지 않고 종료 코드를 확인합니다.

```powershell
$rtlRun = Join-Path $run "rtl"
New-Item -ItemType Directory -Path $rtlRun | Out-Null
Copy-Item "$fpga/nexys4_ddr/validation_top.v" $rtlRun
Copy-Item "$fpga/nexys4_ddr/tb_validation_top.sv" $rtlRun
Push-Location $rtlRun
try {
    & C:/iverilog/bin/iverilog.exe -g2012 -s tb_validation_top -o validation.vvp validation_top.v tb_validation_top.sv
    if ($LASTEXITCODE -eq 0) { & C:/iverilog/bin/vvp.exe validation.vvp }
} finally { Pop-Location }
```
