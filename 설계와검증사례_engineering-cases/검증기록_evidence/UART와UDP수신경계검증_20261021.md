## Ethernet·IPv4·UDP 관측

22개 고정 캡처에서 정상 4개와 거부·미지원 18개의 결과가 리터럴과 같았습니다. 기본 입력은 port 4660/43981·IP 32·UDP 12·padding 14·payload 41424344입니다. little endian으로 잘못 읽은 출발지 port는 13330이며, padding까지 payload로 포함한 잘못된 18바이트도 별도로 계산해 확인했습니다.

61개 prefix 길이 0~60 검사에서 46바이트부터 IP/UDP 해석이 가능했습니다. padding 일부가 캡처에서 잘려도 IP payload가 온전하다는 뜻이며, 완전한 Ethernet 최소 길이·FCS 적합성 판정은 아닙니다.

길이 오류·잘린 입력·IP/UDP checksum 손상과 `UNSUPPORTED_*`를 구분했습니다. IPv4에서 UDP checksum 필드가 0이면 `omitted_ipv4`, 비 0인 UDP checksum을 검사한 정상 입력은 `checked`였습니다. 생략을 금지하는 별도 정책에서는 `UDP_CHECKSUM_REQUIRED`였습니다. UDP Options의 surplus area는 `UNSUPPORTED_UDP_SURPLUS`이며 보편적인 malformed로 표기하지 않았습니다.

## 실제 localhost UDP

정상과-O 실행 각각에서 127.0.0.1의 임시 포트로 4·0·7바이트를 순차 송수신했습니다. 수신 bytes는 `41424344`, 빈 값, `a55a0201112236`과 같았습니다. endpoint는 결과 JSON에 기록하고, `raw_ethernet_fixture_transmitted=false`로 합성 캡처와 구별했습니다. 빈 datagram을 수신한 0바이트 결과를 TCP의 EOF로 처리하지 않았습니다. 원격 경로·손실·작은 수신 버퍼 잘림·성능은 이 시험에 포함하지 않았습니다.

## 최적화·변이·예외·출력 보존

정상과 `-O`의 UART·Ethernet·입력 예외 섹션이 같았습니다. `require()`의 명시적인 예외는 최적화에서 없어지지 않습니다. UART 변이는 checksum을 생략해 손상 프레임까지 수락했고 `UART checksum rejection/recovery literal failed`로 실패했습니다. UDP 변이는 비 0 checksum 검사를 생략해 손상ABCE를 ACCEPT했고 `udp_payload_corruption` 고정 기대값과 달라 실패했습니다. 두 변이는 정상 구현이 아닌 의도한 결함 대조입니다.

문자열 UART 입력·문자열 캡처·문자열 checksum 입력·홀수 hex·비hex의 5종은 모두 `InputError`였습니다. 기존 정상 출력 폴더의 재사용은 종료 2로 거부했으며 이전 `results.json`의 SHA-256은 `63439926ee938e1f6f68c8bb8f39fa116ade86aa1a24b343a24c0ae233202377`로 유지됐습니다.

## English

Normal and optimized runs agree on deterministic semantic results. Two intentional checksum-bypass mutations fail at the intended corrupt-input checks. Five malformed inputs raise explicit input errors; existing output remains unchanged. Separate real localhost UDP runs receive 4-, 0-, and 7-byte datagrams. These results do not establish UART hardware operation, Ethernet frame conformance, physical-link quality, or reliable remote delivery.
