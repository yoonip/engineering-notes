# 저장 저널 중단과 복구 검사 / Interrupted journal recovery checks, 2026-10-21

실제 호스트 파일에 자체 DATA/COMMIT 형식을 기록하고, 별도 Python 자식 프로세스에서 다시 읽었습니다. 미리 정한 prefix를 flush·fsync한 뒤 자식만 명시 종료했습니다. 실제 장치 전원 차단·OS crash·SQLite·파일시스템 내구성을 시험한 기록은 아닙니다.

## 환경과 실행

Windows11 build10.0.26200·AMD64·Python3.12.14·MSC v.1944 64bit에서 실행했습니다. 소스·fixture를 UTF-8/LF로 정규화한 뒤 기본/-O를 각 새 출력 폴더에 실행했습니다. 비공개 `recovery/verification.json`에는 실제 절대 경로 명령·stdout·stderr·exit·소스와 결과 SHA를, 각 results.json에는 자식의 전체 인수·입력 파일·관측값을 보존했습니다. 입력과 출력은 합성 교육용 데이터입니다.

코드 폴더에서 실행하는 아래 명령의 C:/temp는 독자가 선택할 새 경로입니다.

```powershell
python -X utf8 -B verify.py --output C:/temp/journal-normal-new
python -X utf8 -B -O verify.py --output C:/temp/journal-optimized-new
python -X utf8 -B -O verify.py --mutation apply-uncommitted --output C:/temp/journal-early-new
python -X utf8 -B -O verify.py --mutation ignore-crc --output C:/temp/journal-crc-new
python -X utf8 -B -O verify.py --mutation ignore-sequence --output C:/temp/journal-sequence-new
python -X utf8 -B -O verify.py --mutation commit-first --output C:/temp/journal-order-new
```

네 변이는 기본 모드에서도 각 별도 폴더에 실행했습니다. 최종 정상 2회·변이 8회이며 이전 first-run 결과는 덮지 않았습니다. 일반 assert 대신 명시적 예외를 사용합니다.

## 정상 실행과 중단 행렬

기본/-O 정상 실행의 checks와 cuts가 같았습니다. 각각 PASS·종료 0·검사 178개·cut 60개·자식 237개·의도한 손상/모호성 파일 13개입니다.

| 관측 | 실제 결과 |
| --- | --- |
| seed·완전한 update·복구 | credit80·stock7·seq2·commits[1,2]·CLEAN입니다. |
| 같은 파일을 새 프로세스로 다시 복구합니다. | 결과와 저널 SHA가 같으며 원본을 바꾸지 않습니다. |
| DATA39바이트만 추가합니다. | credit50·stock10·seq1·UNCOMMITTED_DATA·ignored39입니다. |
| 그 꼬리 뒤 새 append를 시도합니다. | TAIL_NEEDS_REPAIR·종료3이며 파일 SHA가 같습니다. |
| 59바이트 update의 prefix0~58 | 모두 이전 seq1 상태입니다. |
| prefix59 | seq2 새 상태이며 확정 끝123·ignored0입니다. |

각 cut은 별도 seed 파일·prefix 기록 자식·복구 자식으로 실행했습니다. cut0/59는 CLEAN, cut39는 UNCOMMITTED_DATA, 나머지는 INCOMPLETE_FRAME입니다. 자식 종료값은 정상153개, 의도한 입력/손상 거부3이23개, 명시 중단23이61개입니다. 마지막 수에는 행렬60개와 별도의 DATA-only 대조1개가 포함됩니다. 성공 응답 없이 끝난 cut59에서도 확정된 새 값이 복구됐습니다.

## 손상·범위와 한계 대조

완전한 DATA/COMMIT CRC, 중간 CRC 뒤 정상 seq3, magic, 과대 length, seq 누락, COMMIT 선행, COMMIT 번호, DATA 결합값, 중복 JSON 키, bool, 두 DATA 연속의 12종을 기대 이유로 거부했습니다. 거부 결과에 응용 state가 없는지도 확인했습니다.

추가 13번째 파일은 한계 대조입니다. DATA length를 합법 범위인 128로 바꾸고 뒤 COMMIT·seq3까지 넣었습니다. 파일 182바이트보다 계산된 끝인 208이 커서 INCOMPLETE_FRAME·seq1·ignored118로 분류했습니다. 실제로 길이가 손상됐어도 부족한 꼬리처럼 보일 수 있다는 관측입니다. “중간 손상은 모두 거부한다”는 보장을 하지 않습니다.

값0/1000은 허용하고 bool·음수·1001·키 누락/추가·잘못된 seq/요청 필드를 거부했습니다. file header 누락/부분, 65536바이트 초과, payload0/129, COMMIT 길이3, seq65536도 거부했습니다. payload128과 seq65535를 담은 frame의 크기는144바이트였고 빈 유효 저널 JNL1의 상태는{}·seq0입니다. frame 길이 허용과 유효 JSON/전체 순번 허용은 별도 검사입니다.

## 의도한 구현 변이

| 변이 | 기본/-O 종료 | 검출한 차이 |
| --- | --- | --- |
| apply-uncommitted | 1 / 1 | DATA만 남은 파일에서 새 값80/7을 공개했습니다. |
| ignore-crc | 1 / 1 | CRC trailer가 손상된 완전한 기록을 정상으로 수락했습니다. |
| ignore-sequence | 1 / 1 | 확정 seq1 뒤 seq3을 수락했습니다. |
| commit-first | 1 / 1 | COMMIT→DATA 기록 순서가 고정 bytes와 달랐습니다. |

ERROR는 의도한 결함 주입에 대한 검증기의 실패 결과입니다. 정상 소스에서 우발적으로 발생한 파일 오류나 실물 장치 결함으로 기록하지 않습니다.

동기화 성공 뒤 고정 prefix를 남기는 시험입니다. directory fsync·전원 제거·동기화 도중 고장·sector tearing·장치 cache·재정렬·wear·동시 writer·checkpoint는 실행하지 않았습니다. 복구는 저널을 읽어 상태를 계산하며 원본의 tail을 수리하거나 잘라내지 않습니다. 기존 A/B 업데이트 코드·결과는 유지했습니다.

## English

Normal and optimized runs agree on 178 checks, 60 transaction prefixes and 237 child processes each. Four mutations fail in both modes. Twelve corrupt-file cases are rejected and a thirteenth file demonstrates damaged-length ambiguity. Existing-output reuse returns 2 with an unchanged result hash. These are actual host-file/process observations under a declared format, not SQLite, hardware power-loss or filesystem durability results.
