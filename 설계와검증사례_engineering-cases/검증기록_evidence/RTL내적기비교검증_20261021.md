## 도구와 입력

2026-10-21에 Windows AMD64, CPython 3.12.14에서 [RTL 비교 러너](../../예제_examples/실무검증_practical-validation/rtl_reference/run_compare.py)를 실행했습니다. HDL은 [dot4.sv](../../예제_examples/실무검증_practical-validation/rtl_reference/dot4.sv)·[tb_dot4.sv](../../예제_examples/실무검증_practical-validation/rtl_reference/tb_dot4.sv)입니다.

| 항목 | 실제 사용 |
|---|---|
| compiler | `C:/iverilog/bin/iverilog.exe` |
| runtime | `C:/iverilog/bin/vvp.exe` |
| 표시 버전 | Icarus Verilog·VVP 12.0 devel, `s20150603-1539-g2693dd32b` |
| compile 설정 | `-g2012 -gstrict-expr-width -Wall -s tb_dot4 -Ptb_dot4.BUG_MODE=N` |
| 실행 순서 | 6설정 순차 compile 후 해당 VVP 실행 |
| build·TEMP/TMP | 실행마다 새 ASCII 경로, 설정마다 별도 하위 폴더 |
| 미실행 | 합성·formal equivalence·STA·CDC·layout·실물 FPGA/칩·계측 |

입력은 signed int8 벡터의 고정·극값·stall·reset 시나리오와 seed 20261021의 32개 추가 벡터입니다. 총 288에지이며 기준 모델은 수락 tag 37개, 출력 소비 33개, reset 취소 4개를 기록했습니다. 취소는 임의로 버린 누락이 아니라 명시한 reset 계약의 결과입니다.

## 실제 명령

저장소 루트에서 실행한 CLI의 형태입니다. `NEW_OUT`은 아직 없는 경로로 바꿉니다. 실제 명령·작업 폴더·환경 경로는 각 실행의 JSON에 기록했습니다.

```shell
python -B 예제_examples/실무검증_practical-validation/rtl_reference/run_compare.py --out NEW_OUT --iverilog C:/iverilog/bin/iverilog.exe --vvp C:/iverilog/bin/vvp.exe
```

설정마다 아래 명령을 새 build 폴더에서 실행했습니다. `N`은 정상 0과 의도된 결함 1~5입니다. 상대 소스 파일과 별도 TEMP/TMP를 사용했습니다.

```shell
C:/iverilog/bin/iverilog.exe -g2012 -gstrict-expr-width -Wall -s tb_dot4 -Ptb_dot4.BUG_MODE=N -o sim.vvp dot4.sv tb_dot4.sv
C:/iverilog/bin/vvp.exe sim.vvp
```

최종 소스로 두 번 새 폴더에 실행했고, 각 설정의 compile·simulation 종료 코드는 모두 0이었습니다. 같은 입력·소스 hash와 각 설정의 trace 바이트가 두 실행에서 같았습니다. 앞선 초기 실행도 보존했습니다. 단순 종료 0이나 `SIMULATION_FINISHED` 글자가 아니라 CSV 전체를 기대값과 비교하여 판정했습니다.

| 설정 | 비교 판정 | 신호/에지 불일치 | 첫 차이 |

| ignore_ready | FAIL | 4 | 에지 6의 out_tag: 1 / 2 |

첫 차이의 숫자는 기대/실제 순서입니다. narrow의 다른 차이는 에지 14의 -65,024 / 512입니다. reset 설정은 같은 에지 19에서 out_valid 0 / 1도 다릅니다. 여러 에지에 같은 오류가 남을 수 있으므로 불일치 합계를 독립 결함 수·fault coverage·실패 확률로 바꾸지 않습니다.

전체 CLI의 PASS는 정상 1설정과 의도된 실패 5설정의 대조가 기대와 같다는 뜻입니다. 잘못된 RTL의 FAIL을 PASS로 변경하지 않았습니다.

## 실패를 숨기지 않는 검사

존재하지 않는 compiler 경로를 주는 별도 CLI 실행은 전체 `INFRA_ERROR`, 종료 2였습니다. 각 설정에 실행 오류가 기록됐으며 결함이 검출된 정상 비교로 집계하지 않았습니다.

parser의 별도 Python 대조에서는 결과 없음·마지막 행 누락·열 초과·열 부족·유효 출력 위치의 X 문자열을 거부했습니다. 열 초과로 CSV에 None key가 생기는 경우도 TypeError로 요약 없이 끝나지 않도록 검사합니다. 이 대조의 X는 CSV parser 입력을 만든 것이며 X를 출력하는 RTL 결함을 시뮬레이션한 결과가 아닙니다. 이 parser는 모든 필드를 정수로 요구하고 X/Z를 `INFRA_ERROR`로 분류합니다.

추가 보존·parser·반복 확인 13항목을 실행했습니다. 앞의 RTL 6설정과 일부 근거를 공유하므로 독립 기능 19종이라고 합산하지 않습니다.

## 과거 도구 실패와 새 성공의 관계

최소 RTL의 새 preflight는 한글 작업 경로·상대 소스 인자와 ASCII 경로 양쪽에서 compile·runtime 종료 0, `RTL_PREFLIGHT_OK`를 반환했습니다. 본 실행은 새 ASCII build, 작업별 TEMP/TMP, 순차 compile을 사용했습니다. 이번에는 간헐 실패를 재현하지 못했습니다. 이 조건만으로 과거 다른 RTL 실행의 원인을 Windows 경로나 병렬 실행이라고 확정하지 않습니다.

기존 [FPGA 실행 기록](FPGA검증_20261021.md)의 성공과 컴파일 실패는 그대로 보존합니다. 외부 Icarus 실행 파일이나 기존 결과를 변경하지 않았습니다. 새 성공을 근거로 이전 미해결 기록을 지우지 않습니다.

## English summary

Two final-source runs compiled and simulated six SystemVerilog variants with actual Icarus/VVP. The corrected design matched all 288 sampled edges; five deliberate arithmetic/control mutations failed comparison. Source/input/trace hashes were stable across repeats, output reuse was rejected, and unavailable tools or malformed traces blocked comparison. No synthesis, timing signoff, layout or hardware measurement was performed.
