# 비동기 FIFO 비교 실행 기록 | Asynchronous FIFO comparison record

검증일은 2026-10-21입니다. [깊이 4 FIFO의 DUT·TB·Python 비교기](../../예제_examples/실무검증_practical-validation/cdc_async_fifo/README.md)를 실제 Icarus Verilog compiler와 runtime으로 실행했습니다. [사례 본문](../비동기FIFO의Gray포인터와reset_cdc-async-fifo.md)에 포인터 판정·reset·독립 큐의 원리를 설명합니다.

## 환경과 명령

| 항목 | 실행 조건 |
| --- | --- |
| 운영체제 | Windows 11, `Windows-11-10.0.26200-SP0`입니다. |
| Python | 3.12.14, MSC v.1944 64비트이며 표준 라이브러리만 사용했습니다. |
| compiler/runtime | Icarus Verilog 12.0 devel, `s20150603-1539-g2693dd32b`입니다. |
| DUT | 32비트, 깊이 4, binary/Gray 포인터 3비트, 비동기 읽기 배열입니다. |
| 클록 | write 10ns, read 14ns, 각각 5ns·7ns에 첫 상승 edge입니다. |
| 관측 | 2200ns 전까지 write 220행·read 157행, 총 377행입니다. TB는 NBA 갱신 전에 기록합니다. |
| reset | common `[1,22)`, `[1002,1032)`ns와 write 요청 `[1502,1532)`ns입니다. 정상은 두 도메인을 함께 flush합니다. |
| build | ASCII 전용 새 폴더에서 상대 파일명으로 순차 컴파일하며 자식 `TEMP/TMP`를 해당 build 폴더로 지정했습니다. |

실행기는 `--out`으로 새 결과 폴더를 받습니다. 같은 소스의 최종 반복은 private 기록 `tmp/uart-reset-cdc-20261021/cdc-fifo/run-3`과 `run-4`입니다. 공개 소스에서는 [README 명령](../../예제_examples/실무검증_practical-validation/cdc_async_fifo/README.md#실행)으로 결과를 새로 생성할 수 있습니다. 각 설정의 실제 compile/sim 명령 형태는 다음과 같습니다.

```text
C:/iverilog/bin/iverilog.exe -g2012 -gstrict-expr-width -Wall -s tb_async_fifo -Ptb_async_fifo.BUG_MODE=0 -o sim.vvp async_fifo.sv tb_async_fifo.sv
C:/iverilog/bin/vvp.exe sim.vvp
```

`BUG_MODE`에 0/1/2/3을 넣어 네 설정을 실행했습니다. 각 자식 프로세스에 30초 제한을 적용하고 명령·작업 경로·표준 출력·표준 오류·종료 코드·timeout 여부를 JSON에 남겼습니다. 최종 두 실행에서 총 여덟 compile과 여덟 sim은 모두 종료 0이었고, 정상 회로의 결과는 두 번 모두 일치했습니다.

## 정상과 의도적 결함

| 설정 | 기능 결과 | 불일치 기록 수 | 대표 관측 |
| --- | --- | --- | --- |
| correct | PASS | 0 | 수락 64, 읽기 58, reset 취소 6입니다. |
| full_one_bit | FUNCTIONAL_FAIL | 160 | 85ns에 점유량 4인 거래 큐에 다섯 번째 쓰기를 수락합니다. |
| read_empty | FUNCTIONAL_FAIL | 66 | 217ns부터 empty gate 위반, 847ns에는 빈 거래 큐의 읽기를 검출합니다. |
| one_sided_reset | FUNCTIONAL_FAIL | 27 | 1505ns에 read reset이 적용되지 않아 요청 중 읽기를 수락합니다. |

불일치 수는 검사 규칙별 기록 수이며 서로 독립적인 결함 개수나 고장 확률이 아닙니다. 네 설정의 process 종료 0과 기능 판정을 분리했습니다. 정상에서 최대 점유량은 4, write/read 포인터의 `7→0` wrap은 각각 7회였습니다. reset이 아닌 동안 full로 차단한 쓰기는 58건, empty로 차단한 읽기는 52건입니다. 보수적 full 59edge·empty 36edge는 자료 또는 빈자리가 이미 존재해도 상대 포인터를 기다리는 구간의 관측 수이며 오류로 세지 않았습니다.

독립 큐는 수락된 자료만 저장합니다. 초기 쓰기 네 건 `(45,1003)`, `(55,1004)`, `(65,1005)`, `(75,1006)`과 첫 읽기 `(147,1003)`을 리터럴로 대조했습니다. common reset에서 `[1095,1096,1097,1098]`, write 요청에서 `[1144,1147]`을 취소하므로 `64=58+6`입니다. read/write 동시각은 NBA 전 값에 맞춰 read부터 큐에 적용했습니다.

reset release도 별도로 확인했습니다. 첫 요청이 22ns에 내려간 뒤 write는 25/35ns에 reset=1, 45ns에 0이고 read는 35/49ns에 1, 63ns에 0입니다. write 요청이 1532ns에 내려간 뒤에는 write 1535/1545ns·read 1533/1547ns까지 reset=1이며, 다음 edge인 1555/1561ns에 연산할 수 있습니다. 단순히 두 도메인이 동시에 release한다고 가정하지 않았습니다.

## 결과 수집기의 거절 경로

실제 정상 trace를 복사해 만든 여덟 대조는 RTL 결함 주입과 별도로 구분했습니다.

| 변경한 trace | 예상 판정 | 실제 판정 |
| --- | --- | --- |
| 파일 없음, edge 한 행 누락, 중복 edge, 추가 CSV 열 | INFRA_ERROR | 네 경우 모두 예상과 일치합니다. |
| control의 X, 입력 enable echo 변경 | INFRA_ERROR | 두 경우 모두 예상과 일치합니다. |
| 수락된 읽기 자료를 X로 변경, 자료를 0으로 변경 | FUNCTIONAL_FAIL | 두 경우 모두 예상과 일치합니다. |

실행 파일을 존재하지 않는 경로로 지정한 별도 CLI는 종료 2·`INFRA_ERROR`를 기록했습니다. 이미 존재하는 최종 결과 폴더를 다시 사용한 CLI도 종료 2였으며 기존 report 해시는 바뀌지 않았습니다. 최종 두 실행의 소스·입력·네 trace 해시와 고정 관측값을 대조한 별도 14항목 확인은 모두 일치했습니다. 원시 report와 guard 명령·종료·로그는 private `final-checks.json`에 보존했습니다.

초기 `run-1`에서는 TB가 reset의 초기값에만 의존해 첫 관측의 control/pointer가 X였고 `INFRA_ERROR`로 중단했습니다. 1ns에 명시적인 reset 상승 전이를 주도록 TB를 바꾼 뒤 `run-2`를 남겼으며, release·포인터·오류 trace 검사를 추가한 최종 소스는 `run-3/4`입니다. 이전 실패와 중간 기록을 최종 통과 기록으로 덮어쓰지 않았습니다.

## English

Two runs of the final source produce identical input and trace hashes. All actual compiler and simulator invocations return zero. The correct FIFO has no mismatches over 377 edge records and satisfies `64 accepted = 58 consumed + 6 reset-cancelled`. Three controlled functional defects yield 160, 66 and 27 mismatch records.

Eight altered-trace controls exercise infrastructure and data-failure classification. A missing compiler and reuse of an existing output directory both return exit code two; the existing report is preserved. An earlier initialization failure remains separate from final evidence. These are digital functional observations with fixed clocks, not analog CDC, physical timing, MTBF or hardware signoff results.
