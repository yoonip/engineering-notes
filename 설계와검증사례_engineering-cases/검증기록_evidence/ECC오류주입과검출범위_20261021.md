# ECC 오류 주입과 검출 범위 | SECDED injection results and limits

2026-10-21에 [고정 Hamming(13,8) Python 코드와 검사](../../예제_examples/실무검증_practical-validation/ecc_secded/README.md)를 실행했습니다. [사례 본문](../ECC의단일비트정정과이중비트검출_ecc-secded.md)에 비트 배치·syndrome·전체 parity·보장 밖 반례를 연결했습니다. 이번 실행은 소프트웨어 비트 반전이며 DRAM·NAND·FPGA·EDAC 장치를 시험하지 않았습니다.

## 환경과 명령

Python 3.12.14, MSC v.1944 64비트·Windows 11 `10.0.26200`에서 표준 라이브러리를 사용했습니다. 자료는 0~255, 코드워드는 0~8191이며 정수 bit0을 위치 1로 셉니다. 자료 위치는 3/5/6/7/9/10/11/12, Hamming parity는 1/2/4/8, 전체 parity는 위치 13입니다. 예제 폴더에서 실행한 명령 형태는 다음과 같습니다.

```powershell
python -X utf8 -B verify.py --out C:/temp/ecc-normal-new
python -X utf8 -B -O verify.py --out C:/temp/ecc-optimized-new
python -X utf8 -B verify.py --mutation omit-overall --out C:/temp/ecc-encode-new
python -X utf8 -B verify.py --mutation reject-overall-bit --out C:/temp/ecc-overall-new
python -X utf8 -B verify.py --mutation correct-double --out C:/temp/ecc-double-new
python -X utf8 -B verify.py --mutation leak-double-data --out C:/temp/ecc-leak-new
```

네 변이도 각각 `-O`를 붙여 새 경로에서 실행했습니다. 정상은 private `tmp/storage-recovery-ecc-20261021/ecc/run-1`, 최적화는 `run-optimized-1`입니다. 각 변이 폴더, `verification.json`, `report.json`에 실제 실행파일·인수·최적화 수준·표준 출력/오류·종료 상태·소스/입력 SHA256을 보존했습니다. 최적화 여부·경로 때문에 전체 report의 해시가 같아야 한다고 요구하지 않았습니다.

합계 32,035개 비교는 기본·`-O`에서 모두 PASS·종료 코드 0이었습니다. 최소 거리 계산에는 코드워드의 서로 다른 쌍 32,640개가 사용되지만 최소값과의 비교를 하나로 셉니다. 단일·이중 오류 조합과 수신값 8,192개 대조는 중복되는 자료를 다루므로 독립 시험 수나 실제 fault coverage로 더하지 않습니다.

모든 수신값 대조의 기준은 고정 generator 기저로 만든 코드북과 그 한 비트 이웃입니다. 8,192개를 검사한 결과는 이 정책과 일치했으며 모든 다중 오류의 원본 복구를 보장하지 않습니다. 구현의 위치별 parity 함수를 기준으로 다시 호출하지 않았습니다. 정상·최적화의 비교 그룹 개수·관측 반례·입력/소스 해시가 같았습니다.

## 리터럴과 반환 자료

A5는 코드워드 0A27입니다. 전체 parity 위치 13만 반전한 1A27은 `corrected`, 자료 165, 정정 위치 13이며 자료 위치 3·5를 반전한 이중 오류는 `uncorrectable`, 자료 None입니다. 분야 51의 예제 함수 호출도 따로 실행해 이 두 출력을 확인했습니다. 자료 0/1의 코드워드 리터럴은 각각 0000/1007입니다.

| 원본 0에서 반전한 위치 | 실제 수신 | 실제 선택 | 원본 복구 여부 |
| --- | --- | --- | --- |
| 1,2,3 | 0007 | corrected·자료 1·위치 13입니다. | 실패하는 보장 밖 반례입니다. |
| 1,2,4 | 000B | corrected·자료 8·위치 7입니다. | 실패하는 보장 밖 반례입니다. |
| 1,2,3,13 | 1007 | clean·자료 1입니다. | 검출하지 못하는 반례입니다. |
| 1,4,8 | 0089 | syndrome 13·uncorrectable·자료 None입니다. | 정정 위치를 선택하지 않습니다. |

`corrected`나 `clean`은 관측된 검사와 선택의 이름입니다. 세 비트 이상일 때 그 이름만으로 실제 오류 개수나 최초 자료를 단정하지 않습니다. 단일/이중 주입 행렬에서는 보장된 결과를 모두 확인했고, 위 반례는 별도 한계 관측으로 기록했습니다. uncorrectable의 정상 API는 data·corrected_word·corrected_position 모두 None입니다.

## 네 구현 결함을 검증기가 검출했습니다

| 변이 | 기본 / 최적화 종료 | 첫 실패 전 통과 비교 | 첫 불일치 |
| --- | --- | ---: | --- |
| omit-overall | 1 / 1 | 각각 10 | 자료 1의 부호화 7이 기대값 4103과 다릅니다. |
| reject-overall-bit | 1 / 1 | 각각 527 | 수신값 7의 위치 13 정정을 거절합니다. |
| correct-double | 1 / 1 | 각각 523 | 수신값 3을 uncorrectable 대신 정정합니다. |
| leak-double-data | 1 / 1 | 각각 523 | 수신값 3이 uncorrectable인데 자료 0을 노출합니다. |

이 네 변이는 의도한 잘못된 코드 경로입니다. 정상 보장 밖의 3/4비트 반례와 구분합니다. 검증기는 첫 불일치에서 멈추며, 변이의 작은 비교 수를 정상 행렬 전체의 결과로 표시하지 않습니다. 판정은 명시적 예외를 사용하므로 `-O`에서도 유지됐습니다.

기존 정상 출력 폴더를 다시 지정한 명령은 종료 코드 2였고 report SHA256 전후가 모두 `52503484baba605ca8c7e51df9e63bffd403c9320517c8119f7034d9b5754633`으로 같았습니다. 기본/최적화·오류 행렬·리터럴·변이·파일 보존을 대조한 private `verification.json`의 별도 14항목도 일치했습니다.

본문의 CRC 보조 계산은 32,035개 비교와 따로 실행했습니다. 16진수 자료 01의 CRC는 2768625435, 주소 1의 2바이트 표현+자료 CRC는 2438846661, 요청 주소 0을 묶으면 2286348676입니다. 자료만의 비교 True와 요청 주소를 묶은 비교 False를 `coverage-example.json`에 남겼습니다. 이 한 계산은 모든 주소 오류를 검출하거나 인증을 제공한다는 주장이 아닙니다.

## English

Normal and optimized executions each pass 32,035 comparisons. The matrix covers 256 encodings and clean decodes, all 3,328 single-error and 19,968 double-error origin/position combinations, and all 8,192 received words against an independent radius-one policy. These counts overlap. Four deliberately faulty paths fail in both modes; existing-output reuse returns exit2 and preserves the prior report.

Literal examples explicitly show three-bit miscorrection, four-bit undetected corruption, and an unused syndrome rejected without data. These observations do not contradict the single-/double-error guarantee. Uncorrectable results expose no payload. A separate CRC calculation illustrates why the covered address/identity bytes matter.

Sources and input hashes are fixed, and execution is limited to Python software injection. No physical memory, vendor ECC, BCH/LDPC, EDAC hardware or reliability qualification is executed or claimed.
